# EXAONE 경량 판단 모듈 성능 재점검

작성일: 2026-09-22

## 무엇이 개선됐나

**모델에 전달하는 정보를 그대로 유지하면서 입력 준비와 평가의 반복 작업을 줄였습니다.** GPU 없이 확인할 수 있는 개선을 적용했고, 기존 시뮬레이션의 실제 결정은 계속 큰 EXAONE이 담당합니다.

쉽게 말하면, 판단에 필요한 자료를 덜 읽게 만든 것이 아니라 **같은 자료를 여러 번 정리하던 비용을 줄인 것**입니다. 이번 결과는 CPU 보조 처리의 성능입니다. 실제 학습된 작은 모델의 예측력이나 전체 시뮬레이션 가속률을 뜻하지 않습니다.

## 측정한 결과

실제 `LGAI-EXAONE/EXAONE-4.0-1.2B` 토크나이저와 합성 입력을 사용했습니다. 모델 가중치, GPU, 모델 추론, 네트워크는 사용하지 않았습니다. 변경 전후 실행 순서를 번갈아 7회 측정한 중앙값입니다.

| 작업 | 변경 전 | 변경 후 | 해석 |
|---|---:|---:|---|
| 서로 다른 질문의 토큰화·선택 코드 검사 | 58.092ms/질문 | 19.459ms/질문 | 약 2.99배, 재사용 캐시를 끈 조건 |
| 긴 기억과 4개 이벤트의 학습 예시 생성 | 6.964ms/하루 묶음 | 1.378ms/하루 묶음 | 약 5.05배, 입력 구성 비용만 측정 |
| 정확히 같은 질문의 토큰화 재사용 | 23.254ms/질문 | 0.093ms/질문 | 이미 검사한 질문이 반복될 때만 적용 |

마지막 행의 큰 차이는 동일 입력이 재등장하는 실험 조건에서 나옵니다. 실제로는 사람·날짜·앞선 선택이 바뀌므로 재사용률이 낮을 수 있습니다. 전체 시뮬레이션의 예상 가속률로 환산하지 않습니다.

검사한 **35개 질문의 입력 토큰, 선택지 순서, 선택 코드 토큰이 모두 변경 전후 동일**했습니다. 긴 기억을 포함한 6개 하루 묶음의 학습 예시와 정답도 동일했습니다.

측정 조건:

- Windows 11, 논리 CPU 16개, Python 3.13.7, transformers 4.57.6, tokenizers 0.22.2.
- 토크나이저 revision: `3abf2810673c7c0778df64a73c2d52eab32d91c4`.
- 질문 길이 414~4,287토큰, 선택지 2~42개. 서로 다른 질문은 회당 35개, 반복 질문은 회당 40개.
- 긴 예시 생성은 기억 24~44건, 이벤트 4개, 판단 질문 17개인 묶음들을 회당 60번 생성.
- 긴 입력의 동일성까지 확인하기 위해 벤치마크만 `max_tokens=16384` 사용. 운영 기본값 4096은 유지하며 초과 입력을 자동으로 자르지 않음.
- 토크나이저 내부 병렬 처리를 사용. 여러 시뮬레이션 worker와 함께 실행할 때의 CPU 경쟁은 별도 측정 필요.

평가 도구는 별도의 합성 자료로 3회 측정했습니다.

| 작업 | 비교 기준 | 개선 경로 | 측정 범위 |
|---|---:|---:|---|
| 1,500건 평가 입력의 최대 메모리 | 목록 입력 29.054MiB | 순차 입력 0.252MiB | 현재 평가기에 두 입력 방식을 전달한 비교 |
| 온도 보정의 반복 손실 계산 | 이전 수식 0.4594초 | 준비 비용 포함 0.3036초 | 3,000개 질문·선택지 10개·온도 74개 |

메모리는 자료 생성과 평가 중 Python이 관리한 할당량의 최고치(`tracemalloc`)이며, 프로세스 전체 메모리나 GPU 메모리는 아닙니다. 건당 약 16,000자의 합성 프롬프트를 사용했고 JSONL 파일 읽기는 제외했습니다. 두 입력 방식의 최종 보고서는 동일했습니다. 손실 계산의 결과 차이는 최대 `1.096e-12`였습니다. 이 보조 측정은 별도 예열 없이 고정 순서로 3회 실행했으므로 참고값으로 사용합니다.

## 코드에서 바꾼 부분

### 1. 질문을 더 빠르게 준비

`backend.py`에서 각 선택 코드를 하나씩 검사하던 작업을 빠른 토크나이저의 묶음 처리로 바꿨습니다. 검사는 여전히 **전체 질문 뒤에 선택 코드를 붙인 실제 문맥**으로 수행합니다. 문맥을 잘라 검사하거나 단일 토큰 검사를 생략하지 않습니다.

완전히 같은 질문은 검증된 토큰화 결과를 재사용합니다. 저장 한도는 기본 128개 질문·합계 65,536개 입력 토큰입니다. 이전 음식점 선택이나 감정 판단을 재사용하는 기능은 아닙니다. 토크나이저를 의도적으로 수정한 경우 캐시를 비우는 API도 제공합니다.

`planner.py`에서는 하루 동안 같은 상태·기억·후보를 매 질문마다 다시 JSON으로 바꾸지 않습니다. 한 번 준비한 자료에 앞선 선택만 반영합니다. 장소를 선택한 뒤 그 장소에 맞게 지출과 만족도를 결정하는 순서는 유지합니다.

### 2. 결론이 이미 정해진 불필요한 작업 제거

하루 묶음에서 중복 방문 장소를 선택하면 현재 계약상 그 결과를 사용할 수 없습니다. 이를 발견한 즉시 보류해 이후 지출·만족도·요인 호출을 생략합니다. 기존에 유효하던 결과를 새로 제외하지 않습니다.

로컬 가중치를 읽지 못한 경우 같은 설정으로 최대 60초 동안 다시 로딩하지 않습니다. 동시 worker가 같은 실패를 반복하는 것을 막습니다. 설정 변경과 재시도 시간 경과 뒤에는 다시 시도합니다. 실패를 정상 예측으로 취급하지 않습니다.

### 3. 평가와 학습 자료 처리 개선

병행 평가기는 JSONL을 한 건씩 읽고 지표에 필요한 합계만 모읍니다. 긴 프롬프트와 거래 목록 전체를 메모리에 쌓지 않습니다. 정확한 중복 검사와 지연 백분위 계산에 필요한 ID·시간 목록은 여전히 유지하므로 완전한 고정 메모리 방식은 아닙니다.

학습 자료의 `--dry-run` 검사도 순차 처리합니다. 온도 보정에서는 같은 계산을 반복하지 않도록 점수를 한 번 정리하며, 큰 공통 점수 오프셋에서도 손실 계산이 안정적인지 검사합니다. 독립적인 보정 질문은 `--batch-size`로 묶을 수 있고 기본값은 1입니다. GPU에서 묶음 크기를 늘렸을 때의 메모리·수치 차이는 아직 검증하지 않았습니다.

자료 품질도 재점검했습니다. **후보 검색 범위를 넓힌 기록**과 **교사의 실제 선택을 사후 수정한 기록**을 구분합니다. 전자는 후보 포함 여부와 출력 계약 검사를 통과하면 유지하고, 후자는 학습 정답에서 제외합니다. 중복 학습 질문·중첩된 보정 흔적도 검사합니다.

## 검증 결과

최종 관련 테스트: **163개 통과, 1개 건너뜀**.

```powershell
sim_output/fast_decision/.venv/Scripts/python.exe -m pytest tests/unit/sim tests/unit/test_s1_contract.py -q -rs
```

검사에는 토큰화 전후 동일성, 캐시 한도·동시 접근·입력 변경, 단계별 이전 선택 반영, 중복 장소 조기 보류, 로딩 실패 재시도, 학습/평가 자료 분리, 부정적 경험 지표, CPU의 작은 무작위 EXAONE LoRA 학습·저장·재로딩이 포함됩니다. 이 작은 무작위 모델은 연결 검사 도구이며 실제 사용할 학습 모델이 아닙니다.

건너뛴 1개는 기존 Stage1 계약 검사로, 필요한 `SIM_DATA_ROOT` 자료가 연결되지 않아 실행하지 못했습니다. 무작위 테스트 모델의 사전학습 설정 파일이 없다는 PEFT 경고 1개도 발생했습니다.

## GPU 연결 후 무엇을 확인해야 하나

작은 모델의 실제 학습과 운영 적용은 남아 있습니다. 이번 최적화는 모델 입력 동일성에 근거해 CPU 비용을 줄였으며, **현실 예측 성능 보존을 증명한 것은 아닙니다.**

1. 실제 EXAONE 기록으로 학습하고, 학습에 참여하지 않은 사람·시기·지역으로 검증합니다.
2. 장소 선택뿐 아니라 지출 분포, 부정적 경험, 장기 감정·기억 변화, 정책 효과를 비교합니다. 큰 모델과의 일치율에 더해 관측 자료와의 차이도 확인합니다.
3. 동일 초기 상태의 별도 실행에서 전체 소요 시간과 지연의 중앙값·95백분위를 측정합니다. 작은 모델의 보류·실패 뒤 큰 모델을 호출한 시간까지 포함합니다.
4. 미리 정한 품질 허용 오차를 통과한 범위부터 실제 라우팅을 적용합니다. 현재는 `off/record/shadow`까지만 지원합니다.

기존 [설계 문서](SIMULATION_ACCELERATION_DESIGN.md)의 품질 기준과 [실행 안내](../scripts/sim/fast_decision/README.md)를 함께 사용합니다.

- `benchmark_preprocessing.py`: 캐시된 실제 토크나이저만 사용하는 재현 스크립트.
- `backend_before.py`, `planner_before.py`: 이번 최적화 직전 비교용 코드.
- `benchmark_data_perf.py`, `benchmark_data_perf.json`: 평가 입력 메모리와 온도 보정 수식의 재현 스크립트·측정값.

```powershell
sim_output/fast_decision/.venv/Scripts/python.exe sim_output/fast_decision/perf_review/benchmark_preprocessing.py
```
