# v53 출력 방식 기술 실험 사전등록 (모델 호출 전)

생산 온도 0.7에서 v53 첫 원시응답은 350/384(91.1%)로 엄격 형식 95% 관문에 실패했다. 실패 34칸 중 시간 오류가 20칸이다. 과거 v46/v47의 예시 정렬은 시간 오류를 안정적으로 줄이지 못하거나 악화시켰으므로, 결과를 보고 예시를 다시 편집하지 않는다. **v53 시스템 본문과 정책·시민 입력을 그대로 두고 출력 방식만** 시험한다.

`validation_v53_decode_20260926.json`의 네 조건은 일반 출력/JSON Schema × 온도 0.7/0.0이다. 기존 v53 실험의 동결 96개 문맥을 바이트 해시로 재사용하고 시드 1701을 한 번씩 적용해 총 **384개 첫 응답**을 무작위 순서로 호출한다. 모델, `top_p=1.0`, `max_tokens=2200`, thinking 비활성, 작업자 24명을 고정한다. JSON Schema는 허용 필드·타입·카테고리·zone 코드·집/직장 anchor 대응·이벤트 수만 제한하며 정책 행동, 소비 방향, 금액을 강제하지 않는다. 인접 이벤트 20분 간격과 시작·끝 집은 원시응답에서 별도로 검사한다.

우선 판정은 후보당 **96개 전부의 첫 원시응답**에 대한 v3 엄격 계약 통과 수, 요청 실패 수, 무정책 재정 팔의 허위 정책 귀속 플래그다. 95% 기술 화면은 92/96 이상이지만 표본이 작아 그 자체로 생산 채택 조건이 아니다. 같은 문맥의 통과/실패 불일치, 오류 종류, 종료 사유, 토큰, 지연, JSON Schema 외의 일정 계약을 함께 보고한다. 네 후보 전부 끝내며 실패 응답을 사후 보수해 최초 통과로 세지 않는다. 완결 원시응답·입력·매니페스트·요약을 별도 보관소에 SHA256 검증한다.

이 실험은 출력 방식의 기술 시험이다. Schema 통과율이 높으면 **제약 디코딩의 효과**로 표시한다. 그 결과를 v53 프롬프트 자체의 우수성, Stage2 선택 품질, 실제 결제액 또는 정책별 외부 효과 방향·크기로 해석하지 않는다. 개발에 쓰인 같은 12명·네 상황만 포함하며 P015를 재실행하지 않는다. 성능이 좋아 보여도 독립 시민·상황과 Stage2·쌍체 정책 ON/OFF 관문이 별도로 필요하다.
