# AI API 호출 로그 제출 준비

근거: 「국내 AI API 호출 로그 제출 가이드 v1.0」 (2026-10-19 확인)

## 가이드 요약

| 항목 | 요구 |
|---|---|
| 대상 | 국내 AI 연계 기업(업스테이지·KT·SKT·LG AI연구원·NC AI)의 **AI API** 호출. 로컬 서빙 모델과 일반 API(검색·공공데이터 등)는 제출 대상이 아니다 |
| 전제 | 프로젝트의 AI 모델·AI API는 **100% 국내 AI 연계 기업 모델**이어야 한다. 로컬 서빙도 포함된다 |
| 기간 | **2026-10-14 이후** 호출만 인정 |
| 한 건 | 요청 시각(KST)·엔드포인트(도메인 포함)·요청 모델·요청 전체 메시지 + 응답 시각(KST)·응답 본문(응답 ID·모델명·답변·토큰 사용량) |
| 민감정보 | API 키·Authorization 헤더·비밀번호·개인정보는 빼거나 마스킹하고 나머지 구조는 유지 |
| 제출 | 최종 결과 보고서의 **기능 단위로 파일 1개씩**, 파일명은 기능명과 같게. 기능마다 최소 1회. 전체를 zip 하나로. json/txt/csv(UTF-8) |

## 코드에 넣은 것

- `scripts/ai_call_log.py`: 요청과 응답을 한 줄로 묶어 `output/ai_call_logs/<기능명>.jsonl` 에 쌓는다.
  헤더는 받지 않고, 본문에 키 모양 문자열(`flp_…`·`Bearer …`·`sk-…`·`AIza…`)이 있으면 가린다.
  `output/` 은 gitignore 대상이라 로그가 커밋되지 않는다.
- 연결한 호출부:

  | 기능명(=파일명) | 위치 | 모델 |
  |---|---|---|
  | `1대1_인터뷰` | `web/api/interview.py` (전용 엔드포인트 경로와 공유 경로 모두) | K-EXAONE (Friendli 전용 엔드포인트) |
  | `보고서_해설` | `scripts/report/llm.py` `complete()` (기본 기능명) | K-EXAONE (같은 엔드포인트) |
  | `연결_점검` | `scripts/report/llm.py` `ping()` | 기능이 아니라서 제출에서 뺀다 |

- `scripts/ai_call_log_export.py`: 제출 zip을 만든다.
  - 10/14 KST 이후에 응답까지 받은 건만, 기능별로 최신 N건(기본 1건)을 고른다.
  - 국외 AI 도메인(`ai_call_log.FOREIGN_AI_HOSTS`)으로 간 기록이 하나라도 있으면 **zip을 만들지 않고 멈춘다.**
  - 마스킹 후에도 키 모양 문자열이 남아 있으면 멈춘다.
- 테스트가 부르는 가짜 호출은 `conftest.py` 에서 임시 폴더로 보낸다. 제출 로그에 섞이지 않는다.

## 국내 모델만 쓰도록 바꾼 것

- 보고서 해설: 국외 제공자 경로를 코드에서 지웠다. K-EXAONE만 부른다. 설정은 `.env` 의
  `REPORT_LLM_MODEL`(엔드포인트 ID)·`REPORT_LLM_API_KEY` 이고, 비어 있으면 인터뷰의 `INTERVIEW_*` 를 쓴다.
- 1대1 인터뷰: 전용 엔드포인트가 없을 때 넘어가는 곳도 K-EXAONE 해설 클라이언트뿐이다.
- 시뮬레이션 로컬 서빙: 모델 목록에 EXAONE(4.0·4.5)과 Midm만 남겼다. 기본값은 `exaone_4_5`.
  Dockerfile·compose·배치 스크립트의 `LLM_MODE` 도 같다.
- 보고서 해설·인터뷰·시뮬레이션 클라이언트는 국외 AI 도메인이 설정돼 있으면 **연결하지 않는다.**

## 아직 남은 것

- **저장소 밖의 K-EXAONE 호출**(`sim_data/nsz_final/k_exaone_client.py`: 입장 인터뷰·설문·감성 분석)이
  최종 보고서의 기능이라면 같은 로그가 필요하다. 기존 결과는 10/10~10/12에 호출한 것이라 인정되지 않으므로
  10/14 이후에 다시 호출해야 한다.
- 최종 보고서에 쓴 시뮬레이션 결과가 국내 모델로 돌린 실행인지 확인한다. 코드에서 이름을 지운다고
  과거 실행의 모델이 바뀌지는 않는다.

## 제출 절차

1. `.env` 에 K-EXAONE 엔드포인트 ID와 키를 넣는다 (`.env.example` 1절).
2. 보고서의 기능마다 실제로 한 번 이상 실행한다. 예: 콘솔에서 보고서 생성 1회, 인터뷰 질문 1회.
3. zip을 만든다.
   ```
   python -m scripts.ai_call_log_export
   ```
   `output/ai_call_logs/submission/AI_API_호출로그_<시각>.zip` 이 생긴다.
4. 최종 보고서의 기능명과 파일명이 다르면 `scripts/report/llm.py` 의 `DEFAULT_FEATURE`,
   `web/api/interview.py` 의 `FEATURE` 를 보고서 기능명으로 바꾼 뒤 다시 실행한다.
5. zip 안의 json을 열어 요청 내용에 실제 개인정보가 없는지 한 번 확인한다. 대상자 기록은 합성 페르소나다.
