## 판정: 기각

문턱 줄을 Stage2 헤더에 넣어도 금액이 안 달라진다. 본런에 올리지 않는다.

## 그러나 이 탐침이 **못 말하는 것**을 분명히 적는다

이 탐침은 **이벤트를 고정**했다. 모두에게 같은 하루(점심·장보기·필요한 것
사기)를 주고 금액만 봤다. 그런데 실제 +9.76% 는 **이벤트가 달라져서** 생긴
값이다 — 라운드2 런에서 이벤트 **수**는 그대로인데(11.5 → 11.5) 금액이 늘었고,
그 말은 같은 개수의 **다른 이벤트**를 골랐다는 뜻이다.

```
이 탐침이 기각한 것   "문턱 줄 -> Stage2 가 **같은 이벤트를** 더 비싸게 매긴다"
기각하지 못한 것     "정책 맥락 -> Stage1 이 **다른 이벤트를** 고른다"
```

게다가 내가 넣은 이벤트는 "필요한 것 사기" 같은 **일반적인 의도**다. 실제
런에서 Stage1 은 "드라이기 바꾸기"처럼 구체적인 의도를 `trigger:"policy"` 로
만들어 낸다(프롬프트 예시에 그대로 있다). 그런 이벤트를 Stage2 가 매길 때
문턱 줄이 붙으면 다를 수도 있다 — **이 탐침으로는 못 본다.**

## 그래서 표적을 옮긴다 — Stage1 의 이벤트 구성

Stage1 프롬프트는 이미 캐시백 기전에 맞춰져 있다.

```
p012.py:79-95  [정책·약속 반영] — 적립 실적·문턱까지 남은 금액·남은 일수를 읽는다
p012.py:133    예시: "문턱까지 얼마 안 남아 이번 달에 사면 캐시백까지 받겠다 싶어"
               trigger:"policy" 로 가전 구매 이벤트를 만든다
```

**그래서 반응한다.** 그리고 같은 프롬프트에 **감쇠 장치도 둘** 있다.

```
p012.py:85   "정책이 있다는 이유만으로 ... 기계적으로 [바꾸지 않는다]"
v5 성향 블록  "정책이 있다는 사실만으로 기계적으로 올리지는 않는다"
```

> **[정정 2026-09-24 09:00]** 본문을 열어 보니 **둘 다 대칭**이다 —
> "기계적으로 **더하거나 빼지** 않는다", "기계적으로 **올리거나 내리지는**
> 않는다". 올리는 쪽만 막는 것이 아니다. "한쪽 방향으로만 걸려 있다" 고 적은
> 것은 본문을 안 열어 보고 쓴 내 착각이다. 다음 후보의 근거는 감쇠의 비대칭이
> 아니라 **결제수단 줄이 만드는 빈자리**다(s1_ownership.md).

둘 다 환각성 인플레를 막으려고 넣은 것이고 그 목적에 맞다. **대칭이므로 이것을
근거로 후보를 만들지 않는다.**

**단, 감쇠를 그냥 빼는 것은 후보가 아니다.** 그러면 "정책 있으면 무조건 더
쓴다" 는 환각이 돌아오고, 그것은 맞힌 것이 아니라 망가뜨린 것이다. 균형을
어떻게 잡을지가 후보의 내용이어야 한다.

## 배운 것 — 탐침 설계

**고정한 것은 못 잰다.** 이벤트를 고정한 탐침으로 이벤트 채널을 물을 수 없다.
다음 탐침은 Stage1 을 부르고 **이벤트가 달라지는지**를 본다.
