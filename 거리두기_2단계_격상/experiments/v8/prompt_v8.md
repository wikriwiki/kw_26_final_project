# 실험 v8 — 양이 아니라 구성

**날짜 2026-09-20 사전등록 · 2026-09-21 완료** · **상태** — **v31 미채택. 그리고 주 지표 자체가 흔들렸다**

---

## v7 이 가르쳐 준 것

v30 은 구매 비율을 **+2.21 SE** 올려 사전등록 기준을 통과했다. 그런데 늘어난 구매가
전부 배달로 갔고, 정답지 지표는 **더 나빠졌다**.

```
                    v25    v30
부호 일치             1      0
부호 반대 (구간 0 제외)  0      2      ← DS-1, DS-3
```

**양을 늘리는 공정 지표로는 정답에 가까워지지 않는다.** 그래서 이번 주 지표는
양으로 이길 수 없는 것이어야 한다.

## 진단 — 기준선의 구성이 에이전트 자신의 설정과 다르다

무정책 192칸에서 산 것이 **71건**이고 그중 **46건이 같은 온라인 세제**다.
자원 시나리오가 `provided_laundry` 에 세제를 요구해서 사는 것이지 소비 행동이 아니다.

```
부여된 구성 (그 사람 입력)  식사 29.4 · 마트 25.0 · 쇼핑 14.2 · 건강 12.8 · 교육 6.5 · 편의점 6.0 ...
실제로 산 구성             쇼핑+마트 77.9 · 식사 22.1 · 나머지 0

한 번도 안 산 업종  건강 · 교육 · 기타 · 디저트 · 미용 · 여가 · 주점  (11개 중 7개)
```

정답지와 비교한 것이 아니다. **그 사람에게 부여된 구성과 그 사람이 산 것**을
비교한 것이므로 **순환이 아니다.**

이것이 DS-1(매장 취식 0건이라 제한이 물릴 대상 없음)·DS-4(카페 0원)·
P012-5(미용 0건)를 한꺼번에 설명한다.

## 무엇을 바꾸나 — v30 과 같은 수법, 다른 빗장

```
v25   평균 지출과 과거 비중은 오늘 채울 할당량이 아니다.
v31   평균 지출과 과거 비중은 오늘 채울 할당량이 아니라
      이 사람이 평소 어디에 돈을 쓰는지를 말해 준다.
```

빗장의 부정문(**할당량이 아니라**)은 남는다. 더하는 것은 **그 구성이 무엇인지**뿐이다.
지금 프롬프트는 "할당량이 아니다"까지만 말하고 그것이 무엇인지 말하지 않아서
모델이 통째로 무시한다.

**정답지가 재는 업종을 하나도 지목하지 않는다** — 음식점·카페·미용·여가·가전·준내구재가
전부 금지어다. 검사로 막았다(`test_it_names_no_sector_the_answer_keys_measure`).

- 세제 인공물을 어떻게 없앨지 — 그건 시나리오 설계이지 프롬프트가 아니다
- 최적 프롬프트 — 한 축이다

## 결과 — v31 미채택. 그리고 주 지표를 신뢰할 수 없다

두 후보 모두 계획 **384/384 유효**, 게이트 제외 0, 결제 4 seed 완료.

### 주 지표 — 계산법에 따라 답이 다르다

```
                        v25       v31      차이
4 seed 합산 (사전등록)   0.3517    0.4975   +0.1458   ← 역행
seed별 평균             0.4603    0.4593   -0.0010   ← 차이 없음
사람별 평균             0.6675    0.6490   -0.0185   ← 미세 개선
```

사전등록한 것은 **합산**이고, 그것으로는 판정선 0.078 을 **반대 방향으로 넘었다 = 역행**이다.
그런데 **seed별 평균으로는 차이가 사실상 0** 이다.

**같은 자료를 세 가지로 재면 답이 셋이다. 이 지표를 그대로 쓸 수 없다.**
합산 통계는 "어느 사람이 무엇이라도 샀는가"에 민감하고, 구매가 칸당 0.4건인
지금 상태에서는 그것이 구성보다 크게 작용한다.

### 행동은 무엇이 바뀌었나 — v30 과 같은 실패

```
        총 구매   세제   groceries   home_delivery
v25       69      45       11            6
v31       84      48       10           18     ← 3배
한 번도 안 산 업종: 양쪽 모두 건강·교육·기타·디저트·미용·여가·주점 (동일)
```

**v31 은 새 업종을 하나도 열지 못했다. 배달만 늘었다.**
v30 이 했던 것과 같고, 구성을 겨냥한 지표로 바꿨는데도 같은 곳으로 갔다.

### 취소 조건 — 걸리지 않았지만 의미도 없다

세제 비중은 65.2% → 57.1% 로 줄었으나 **건수는 45 → 48 로 늘었다.**
비중이 준 것은 분모(총 구매)가 늘어서다. 인공물이 빠진 것이 아니다.

### 정답지 17개 지표 — 블록 붓스트랩으로는 전부 미결

```
v25  DS-1 +484.6 [ +0.0, +1769.2]    v31  DS-1 +120.0 [ -25.6, +1003.8]
     DS-3 -464.0 [-1746.4, +61.9]         DS-3 -128.9 [-1065.5,  +76.3]
```

**아홉 지표 모두 두 후보 모두 구간이 0을 지난다.** 나아졌다고도 나빠졌다고도
말할 수 없다.

### 판정

**v31 을 채택하지 않는다.** 주 지표는 계산법에 따라 역행이거나 차이 없음이고,
행동으로는 배달만 늘었으며, 정답지 지표는 전부 미결이다.
**v25 를 유지한다.**

### 이번 라운드가 진짜로 알려 준 것

1. **구성 거리 지표가 설계 미달이다.** 칸당 구매 0.4건에서는 합산 통계가
   구성이 아니라 "누가 뭐라도 샀나"를 잰다. 지표를 쓰려면 **구매 건수가
   훨씬 많아야** 하거나, 사람별 거리처럼 덜 민감한 형태여야 한다
2. **빗장을 어느 쪽으로 겨냥하든 늘어나는 것은 배달이다.** v30(구매 빗장)과
   v31(구성 빗장)이 같은 곳으로 갔다. 배달은 집에서 할 수 있는 유일한 구매이고,
   하루가 집에 있는 한 늘릴 수 있는 것은 그것뿐이다
3. **그러므로 다음 표적은 프롬프트 문장이 아니다.** zone 비율 0.105 가
   여섯 라운드째 꿈쩍하지 않는다. 집 밖으로 나가는 하루를 만들지 못하면
   배달 외의 업종은 영원히 0 이다
