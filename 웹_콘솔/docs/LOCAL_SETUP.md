# 웹 콘솔 로컬 실행 (시연 노트북용)

시연은 버셀이 아니라 노트북에서 직접 띄운 콘솔로 한다. 이 문서는 **이미 데이터 폴더를 가지고 있는 노트북**에서
콘솔을 끊김 없이 띄우는 방법을 적는다. 명령은 저장소 안의 `웹_콘솔` 폴더(`web/`, `scripts/` 가 있는 곳)에서 실행한다.

## 한눈에 보기

| 언제 | 명령 | 걸리는 시간 |
|---|---|---|
| 처음 한 번 (인터넷 되는 곳) | `python web/run_local.py --data <데이터 폴더> --prepare` | 몇 분 (아래 측정 참고) |
| 시연할 때마다 | `python web/run_local.py --data <데이터 폴더>` | 켜는 데 10초 안팎, 그 뒤 화면 전환은 즉시 |

`<데이터 폴더>` 는 `runs`, `experiments`, `packs`, `policies` 네 폴더가 들어 있는 폴더다
(예: 10/22 에 받은 `kw_web_data`). 데이터를 새로 받을 필요는 없다.

## 1. 준비물

- Python 3.10 이상 (3.12 에서 확인)
- Node.js 20 이상 — 화면 빌드에 쓴다. 빌드가 최신이면 실행 중에는 쓰지 않는다
- 이 저장소 최신본: `git pull` (보고서 5개도 저장소에 들어 있다 — `output/sim/report/`)
- 데이터 폴더 (노트북에 이미 있는 것)
- `web/.env` — 인터뷰·보고서 해설에 쓰는 K-EXAONE 설정. **키는 저장소에 없다.** 팀장에게 따로 받아
  `web/.env` 로 저장한다. 이 파일은 커밋하지 않는다(`.gitignore` 에 들어 있음).

```bash
git pull
python -m pip install -r web/api/requirements.txt
```

## 2. 처음 한 번: `--prepare`

```bash
python web/run_local.py --data <데이터 폴더> --prepare
```

하는 일:

1. **3D 지도 저장본**을 `<데이터 폴더>/map_cache/` 에 만든다 (약 85MB, 인터넷 필요).
   - 지도 라이브러리(maplibre-gl, deck.gl)와 서울 일대 바탕 지도(확대 0~14단계)를 받는다.
   - 이것이 없으면 지도가 시연장 와이파이에서 매번 받아 와서 느리거나, 끊기면 아예 안 뜬다.
2. **화면 빌드**가 없거나 소스보다 오래됐으면 다시 빌드한다 (`web/ui/dist`).
3. **집계 캐시**를 데이터 폴더 안(`experiments/*/arms/*/_console/`, `experiments/*/_console/comparison.json`)에 만든다.
   - 정책 비교의 신뢰구간(부트스트랩 500회)을 정책마다 다시 계산하지 않도록 결과를 저장해 둔다.
   - 원본 일자 파일·대상자 파일·분석 코드 중 하나라도 바뀌면 저장본을 버리고 다시 계산한다.

마지막 줄에 `준비 끝 (NN초)` 가 나오면 끝이다. 다시 실행해도 안전하다(없는 것만 채운다).

## 3. 시연할 때

```bash
python web/run_local.py --data <데이터 폴더>
```

- 서버를 띄운 뒤 **모든 화면의 집계를 먼저 계산하고**(`미리 계산 중 12/46` 처럼 보인다),
  끝나면 `준비 완료` 를 찍고 브라우저를 연다. 주소는 `http://127.0.0.1:8765`.
- 창을 닫거나 `Ctrl+C` 를 누르면 서버가 멈춘다. 시연 내내 창을 열어 둔다.
- 이미 떠 있으면 새로 띄우지 않고 브라우저만 연다.

자주 쓰는 옵션:

| 옵션 | 뜻 |
|---|---|
| `--port 8770` | 8765 를 다른 프로그램이 쓰고 있을 때 |
| `--no-browser` | 브라우저를 열지 않는다 |
| `--runs`, `--experiments`, `--packs`, `--policies` | 네 폴더가 한곳에 없을 때 하나씩 지정 |
| `--reports <폴더>` | 보고서를 저장소 밖에 둘 때 (기본: 저장소 `output/sim/report`) |
| `--map-cache <폴더>` | 지도 저장본 위치 (기본: `<데이터 폴더>/map_cache`) |
| `--demo` | 공개 시연 제한(새 실행·보고서 생성·정책 수정 막기)을 켠다 |

## 4. 시연 전 점검 (전날 한 번)

1. 노트북 **전원 연결**, 윈도 전원 모드 **최고 성능**. 배터리로 돌면 그래픽이 느려져 3D 지도가 버벅일 수 있다.
2. 크롬 설정 → 시스템 → **가능한 경우 그래픽 가속 사용** 켜져 있는지 확인.
3. `--prepare` 를 했는지 확인: `<데이터 폴더>/map_cache/vendor/` 에 파일 3개가 있으면 된다.
4. **인터넷을 끄고** 콘솔을 띄워 다섯 정책의 결과·시민 인터뷰 목록·3D 지도·보고서를 한 번씩 연다.
   지도는 서울 안에서는 인터넷 없이 다 보인다.
5. 인터넷을 켜고 시민 인터뷰에 질문 하나를 해 본다. **인터뷰와 보고서 해설은 K-EXAONE 서버를 부르므로
   인터넷이 필요하다.** 시연장 와이파이가 불안하면 휴대폰 테더링을 준비한다.
6. 시연 직전에 콘솔을 미리 띄워 두고 첫 화면을 열어 둔다.

## 5. 무엇을 바꿨나 — 왜 빨라졌나

이 PC(AMD Ryzen 9 9900X)에서 잰 값이다. 노트북에서는 더 걸릴 수 있다. `--prepare` 와 실행 화면에
실제 걸린 초가 찍히니 그것을 기준으로 본다.

| 문제 | 고치기 전 | 고친 뒤 |
|---|---|---|
| 캐시 없는 데이터로 첫 목록 열기 | 82초 멈춤 | 켤 때 미리 계산, `--prepare` 뒤 켜는 데 약 10초 |
| 정책 결과 첫 열기(비교 계산) | 정책마다 약 2초, 그동안 다른 요청도 멈춤 | 저장본을 읽어 즉시 |
| 실행 일자 목록·실패 기록 | 열 때마다 0.15~0.3초 | 한 번 계산 후 기억 |
| 화면이 부르는 API 84개 전체 | 13초(처음) | 1.6초, 하나당 0.08초 이하 |
| 3D 지도 라이브러리·바탕 지도 | 인터넷(unpkg.com, openfreemap)에서 받음 | 노트북 디스크에서, 인터넷 요청 0건 |
| 3D 지도 재생(2배속) | — | 초당 75프레임, 가장 긴 프레임 14ms, 긴 멈춤 0건 |

바뀐 코드:

- `web/run_local.py` — 실행 스크립트 (위 명령)
- `web/api/warmup.py` — 켤 때 모든 화면 집계를 순서대로 미리 계산. 진행 상황은 `/api/warmup`
- `web/api/experiments.py` — 정책 비교 결과를 `_console/comparison.json` 에 저장·재사용
- `web/api/store.py` — 결과가 바뀌지 않는 실행에서 일자 목록·실패 기록 기억, 보고서 폴더(`SIM_OUTPUT_ROOT`)
- `web/api/map_cache.py`, `web/api/viz.py` — 지도 라이브러리·바탕 지도를 `/viz/vendor/`·`/viz/map/` 로 내줌.
  저장본에 없으면 한 번 받아 저장, 인터넷도 안 되면 그 칸만 비움
- `web/tools/prefetch_map.py` — 지도 저장본 채우기 (`--prepare` 가 부른다)
- `scripts/sim/visualization_3d/static/map_scene.js` — 서버가 알려 준 지도 주소를 쓴다

환경 변수 (실행 스크립트가 알아서 정한다. 직접 uvicorn 을 띄울 때만 필요):

| 변수 | 값 | 뜻 |
|---|---|---|
| `WEB_WARMUP` | `1` | 켤 때 미리 계산 |
| `WEB_CACHE_TRUST_SIZE` | `1` | 결과 파일이 바뀌지 않는다고 보고 캐시를 크기로 맞춘다. 시뮬레이션이 도는 중인 데이터에는 쓰지 않는다 |
| `SIM_MAP_CACHE_DIR` | `<데이터 폴더>/map_cache` | 지도 저장본. 없으면 예전처럼 인터넷에서 받는다 |
| `SIM_OUTPUT_ROOT` | 보고서 폴더의 상위 | 없으면 저장소 `output/sim` |

버셀 배포(simseoul.vercel.app)는 이 변수들을 쓰지 않으므로 동작이 바뀌지 않는다.

## 6. 문제가 생기면

| 증상 | 할 일 |
|---|---|
| `데이터 폴더를 찾지 못했습니다` | `--data` 경로 확인. 네 폴더가 흩어져 있으면 `--runs` 등으로 하나씩 |
| `포트를 이미 쓰고 있습니다` | 떠 있는 콘솔 창을 닫거나 `--port 8770` |
| `화면 빌드가 없거나 오래됐습니다` | Node.js 20 이상 설치 후 다시 실행 (빌드는 자동) |
| 켤 때 `미리 계산 중` 이 몇 분 걸린다 | 캐시가 없는 상태다. `--prepare` 를 한 번 하면 다음부터 빠르다 |
| 3D 지도 바탕이 비어 있다 | `--prepare` 를 안 했거나 서울 밖으로 멀리 끌고 간 경우. 인터넷이 되면 그 자리에서 받아 저장한다 |
| 보고서 목록이 비어 있다 | `git pull` 로 `output/sim/report/` 를 받았는지 확인 |
| 인터뷰가 꺼져 있다 | `web/.env` 가 있는지, 인터넷이 되는지 확인 |
| 3D 지도가 버벅인다 | 전원 연결·최고 성능 모드·그래픽 가속 확인, 다른 무거운 프로그램 종료 |

정상인지 빠르게 보는 주소: `http://127.0.0.1:8765/api/warmup` — `"state":"done"` 이고 `"failed":[]` 면 정상이다.
