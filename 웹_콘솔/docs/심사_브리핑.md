## 0. 시연 전에 꼭 맞춰 둘 것 (포스터와 화면이 어긋나는 곳)

심사위원이 포스터를 읽고 화면을 보면 바로 걸리는 숫자들이다. **누가 물어도 같은 답이 나오게 팀 안에서 먼저 맞춘다.**

| 어디 | 포스터 | 실제 | 이렇게 답한다 |
|---|---|---|---|
| 시민 수 | B2 "15,000명", C "합성 시민 14,881명" | 웹 화면은 정책마다 2,000명(서울시 재난긴급생활비 1,855명) | 합성 시민은 15,000명을 만들었고, 그중 그래프에 올라간 14,881명이 후보다. 정책마다 그 시기 서울 인구 분포(동·성별·연령)에 맞춰 2,000명을 뽑아 돌렸다. 서울시 재난긴급생활비는 실제 신청자 성·연령에 맞추느라 40대 후보가 모자라 1,855명이 됐다. |

| 금연구역 | C 하단에 실내 금연구역 결과가 있음 | 웹 콘솔에서는 금연구역 실험을 뺐다 | "금연구역은 같은 엔진으로 따로 돌린 실험이라 포스터와 보고서로만 보여 드린다"로 답한다. 화면에서 찾으려 하지 않는다. |
| AI 시민 대화 예시 | B2 "처음엔 주로 마트에서 장을 보는 데 썼어요…" | 실제로 물으면 매번 답이 다르다. 10/28 녹화 때 70대 6명은 대부분 "특별히 더 쓴 건 없다"고 답했다 | 포스터의 대화는 예시다. 실제 답은 고치지 않고 보여 주며, 판단은 결제 기록의 숫자로 한다. |

## 1. 시연 전에 해 줄 설명 (1분)

심사위원이 화면을 보기 전에 이 네 가지만 알면 나머지가 다 읽힌다.

1. **무엇을 비교하나**: 같은 시민, 같은 날을 정책이 있을 때와 없을 때로 두 번 돌린다. 정책 전 1주는 한 번만 돌리고, 시행일부터 두 갈래로 나눈다(포스터 B1 "가상 서울을 둘로 복사"). 그래서 날씨·요일·성향이 섞이지 않는다.
2. **효과 숫자의 뜻**: "정책 있음 ÷ 없음 − 1". +12.5%는 같은 시민이 지원금이 있을 때 12.5% 더 썼다는 뜻이다.
3. **'유의'와 '—'**: 시민 단위로 500번 다시 뽑아 95% 구간을 냈다. 구간이 0을 지나면 차이를 말할 수 없으므로 화면에 숫자 대신 '—'나 '유의하지 않음'으로 둔다. **화면에 숫자로 보이는 효과는 모두 유의한 것이다.**
4. **실측과의 대조**: 실제 연구(KDI·IZA·서울연구원 등)의 추정치는 모델 입력에 한 번도 넣지 않았다. 시뮬레이션을 다 돌린 뒤 채점에만 썼다.

## 1-1. 심사위원 앞에서 쓰는 말

분석 용어를 그대로 말하지 않는다. 화면 자막도 이 말로 바꿨다.

| 쓰지 않는 말 | 대신 하는 말 |
|---|---|
| 방향이 맞았다 / 방향 일치 | 실제로 늘어난 곳은 시뮬레이션에서도 늘고, 줄어든 곳은 줄었다 |
| 크기까지 맞았다 | 증가율까지 실제와 거의 같았다 (예: 13.9% 대 14.1%) |
| 95% 신뢰구간 안 | 오차 범위 안 |
| 지원금 1원당 0.25원 | 지원금 1만 원당 2,500원어치가 새 소비가 됐다 |
| 실측 | 실제 연구, 실제 통계 |
| 유의하다 / 유의하지 않다 | 통계적으로 확실하다 / 차이가 있다고 말할 수 없다 |
| 정책 있음·없음 두 갈래 | 같은 시민을 정책이 있을 때와 없을 때로 두 번 |
| 상관 0.91 | 상관계수 0.91, 1에 가까울수록 실제와 같이 움직인다는 뜻 |

## 3. 정책별로 얼마나 믿을 수 있나 (시연에서 강조할 곳을 정하는 기준)

시연에서 "이렇게 나왔다"고 강조하는 결과는 **실측으로 뒷받침되는 것만** 쓴다. 실측이 없거나 어긋나는 결과는 한계로 말한다.

| 등급 | 정책 | 근거 (시뮬레이션 대 실측) | 시연에서 |
|---|---|---|---|
| 크기까지 맞음 | 서울시 재난긴급생활비 | 총지출 +14.1 대 +13.9 (차이 0.2%p), 소매 +25.1 대 +24.7 (0.4%p). 둘 다 실측값이 시뮬레이션 95% 구간 안. 음식점 +18.0 대 +27.3 (작게) | 주인공. 총효과 → 실측 비교 → 소득별 → 인터뷰 |
| 크기까지 맞음 | 서울시 재난긴급생활비 · **소득별** | 실측(IZA DP 14662 표 5, 4~8월): 연소득 3천만 원 미만 +34%, 3천만~6천만 원 +17.6%, 6천만 원 이상 +9.5%. 시뮬레이션: 하+중하 +14.2%, 중+중상 +12.1%, 상 +9.5% | 순서가 같고 고소득층은 크기까지 같다. 저소득층은 실측의 절반쯤. **소득 기준(카드 신청 때 신고한 연소득 대 시민 소득 구간)과 기간(4~8월 대 3주)이 다르다는 점을 함께 말한다** |
| 크기까지 대체로 맞음 | 긴급재난지원금 1차 | 음식업 +2.7 대 +3.0 (0.3%p), 필수재 +12.9 대 +8.0. 둘 다 실측값이 95% 구간 안 | 실측 비교 두 줄 |
| 방향 맞음 | 사회적 거리두기 2단계 | 4항목 방향 모두 같음. 크기는 실측의 0.4~1.5배 (카페 −39.8 대 −26.0, 음식점업 −7.1 대 −14.0) | 카페 감소 + 실측 비교 표 |
| 방향만 맞음, 크기 다름 | 상생소비지원금(캐시백) | 총소비 +4.6 대 +11.3 (0.4배), 여행·레저는 방향 반대 | 한계로 한 줄 |
| 방향만 맞음, 크기 다름 | 민생회복 소비쿠폰 | 사용처 지출 +13.4 대 +4.9 (2.7배) | 한계로 한 줄 |

**실측이 없는 결과는 강조하지 않는다.**
- 연령별 차이(70대 이상 +19.5% 대 30대 +9.1%): IZA 논문에 연령별 결과가 없다. 묻지 않으면 꺼내지 않고, 물으면 "실측과 대조하지 못한 시뮬레이션 신호"로 답한다.
- 캐시백의 '고령층은 소비처만 옮겼다': 실제로는 제외 업종 결제도 +2.8% 늘었다. 시뮬레이션이 옮겨 가는 효과를 세게 잡았을 수 있다. 시연에서 "허점"이라고 말하지 않는다.
- 거리두기 70대 이상 카페 −62.3%: 연령별 실측이 없다.

## 3-1. 웹 시연 순서와 강조할 곳

메인 페이지에서 시작해 클릭으로만 이동한다. 영상 `simseoul_demo_20261028_1726.mp4`가 이 순서다.

1. **메인 페이지**: 점 하나가 시민 한 명의 집. 정책 다섯 개 줄마다 총소비 효과와 유의 여부.
2. **새 시뮬레이션 만들기**: 정책 고르기 → 설정 → 검증(15개 항목 통과) → 실행 단계. "서비스가 되면 여기서 실행하면 GPU 서버의 EXAONE이 시민 한 명 한 명의 하루를 계획하고 결제한다. 시연에서는 미리 돌린 결과로 넘어간다." → '이 정책의 결과 보기'.
3. **서울시 재난긴급생활비 — 실측부터**: 총소비 +12.5% → 바로 '실측 연구와 비교'로 내려가 총지출 +14.1 대 +13.9, 소매 +25.1 대 +24.7. **"이 숫자를 믿을 수 있는지부터 보여 드린다"가 핵심 문장.** 실측 수치는 모델에 넣지 않았다.
4. **소득별**: 집단별 표에서 '소득' 단추. 소득 하 +15.6%(1원당 0.25원), 소득 상 +9.5%(0.18원). → "실측도 같은 순서였다. 고소득층은 크기까지 같다(9.5% 대 9.5%)."
5. **인터뷰**: 소득 하 줄의 '인터뷰' → 질문 예시 "이 지원금이 없었다면 이번에 산 것들을 그래도 샀을까요?" → 6명. 답은 그대로 보여 준다.
6. **3D 지도**: 재생 → 시민 `AGT_11110700_F_70대이상_001`(포스터 B2의 종로구 73세) 검색 → 서울 전체. '정책 발효' 챕터는 누르지 않는다.
7. **보고서**: 한 문서로 정리된다.
8. **긴급재난지원금 1차**: 음식업 +2.7 대 +3.0 (0.3%p).
9. **거리두기**: 카페 −38.9%. "실제 통계와 비교한 네 항목 모두, 줄어든 곳은 줄고 늘어난 곳은 늘었다. 어떤 업종이 피해를 보고 어떤 업종이 버티는지 시행 전에 가려낼 수 있다."
10. **한계와 마무리**: "캐시백과 소비쿠폰도 소비가 늘어난다는 것은 맞혔다. 다만 얼마나 늘지는 실제의 0.4배·2.7배로 차이가 있었고, 이런 한계도 숨기지 않는다." → "주요 업종 14개 결과를 실제와 비교하면 상관계수 0.91, 1에 가까울수록 실제와 같이 움직인다는 뜻" → "정책에 예산을 쓰기 전에, 가상 서울에서 먼저 확인하세요."

## 4. 외울 숫자

**정책별 (웹 화면 값)**

**전체 성능**
- 주요 업종(지출의 95.4%) 효과 14쌍: 시뮬레이션과 실측의 상관 **r = 0.91** (95% 구간 0.73~0.97), 순열 20,000회 중 넘는 경우 0, 기울기 1.09, 정책 하나씩 빼도 0.74~0.92.
- 소액 업종 13쌍은 r = 0.12, 전체 27쌍은 0.46. **업종 기준을 결과를 보고 정했으므로 전체 값도 반드시 같이 말한다.**
- 통합 평가에서 방향이 반대인 4쌍: 상생소비지원금 여행·레저(실측 +14% / 시뮬 −24%), 서울시 재난긴급생활비 의류(+39% / −31%), 서울시 재난긴급생활비 오락여가(+2.7% / −0.5%, 유의하지 않음), 금연구역 당구장 매출(+13.5% / −6.4%).
- 금연구역 3지선다 인터뷰: 응답 분포 유사도 92%(시행 전)·93%(시행 후), 전후 변화 평균 오차 1.5%p. **흡연자 찬성은 시뮬레이션이 실측보다 23%p 높게 잡았다.**

**시간**
- 민생회복 소비쿠폰 본런: 76.9시간, 모델 호출 113,339번, 토큰 입력 4.93억·출력 0.96억.
- 서울시 재난긴급생활비 3주 연장분: 1,855명 × 두 갈래 × 14일 = 51,940 사람-날, 58.2시간, 호출 139,584번.
- 원화 비용은 실제 결제액 기준 정리(Notion '정책 시뮬 결과 총정리' 비용 절)를 보고 답한다. 여기서 추정해 말하지 않는다.

## 5. 함정 질문과 답

### 정확도·검증

**Q1. 모델이 이미 결과를 알고 있는 거 아닌가? 2020년 재난지원금 효과는 학습 데이터에 있을 텐데.**
- 실측 수치는 모델 입력 어디에도 없다. 시민이 받는 것은 자기 프로필, 정책 안내문, 그날의 상황뿐이다.
- 같은 모델로 정책 있음·없음을 둘 다 돌리므로, 모델이 가진 일반 지식은 양쪽에 똑같이 들어간다. 효과는 그 차이다.
- 지급 전 위약 대조: 민생회복 소비쿠폰에서 쿠폰을 받기 전 날들의 차이는 +0.96%로 0을 포함했다. 정책이 없으면 차이도 생기지 않는다.
- 맞히지 못한 것도 있다(여행·레저 반대, 캐시백 크기 절반, 소비쿠폰 2.7배 과대). 답을 외웠다면 이런 어긋남이 없어야 한다.
- 다만 일반 지식의 영향을 완전히 배제했다고는 말하지 않는다.

**Q2. 방향만 맞히는 건 쉽지 않나? 지원금 주면 소비 느는 건 당연하다.**
- 총소비가 늘었는지만 본 것이 아니다. 어느 업종이 늘고 어느 업종이 줄었는지(거리두기: 카페 감소·소매 증가), 그리고 얼마나 늘었는지까지 실제와 비교했다(상관계수 0.91, 기울기 1.09).
- 서울시 재난긴급생활비 총지출은 크기까지 13.9% 대 14.1%로 맞았다.
- 반대로 크기가 틀린 정책도 그대로 공개한다(캐시백 절반, 소비쿠폰 2.7배).

**Q3. r = 0.91은 좋은 업종만 골라서 나온 숫자 아닌가?**
- 맞다. 업종 기준(지출 95%)은 결과를 본 뒤 정했다. 그래서 전체 27쌍 0.46과 소액 업종 0.12를 함께 공개한다.
- 소액 업종이 낮은 이유: 2,000명 중 그 업종에 돈을 쓴 사람이 적어 구간이 아주 넓다(잡음).

**Q4. 포스터에는 18/20인데 화면에는 다르던데?**
- 0절의 표대로 답한다. 확인되지 않은 숫자를 지어내지 않는다.

**Q5. 캐시백은 실측의 절반밖에 안 나왔다. 실패 아닌가?**
- 실측(KDI)은 10월 한 달, 시뮬레이션은 7일이다. 캐시백은 한 달 실적이 3%를 넘어야 받으므로, 7일 창에서는 문턱에 닿는 사람이 적다.
- 그래서 소비가 늘어난다는 것까지만 말하고, 얼마나 늘었는지는 한계로 밝힌다.

**Q6. 소비쿠폰은 실측보다 2.7배 크게 나왔다.**
- 시뮬레이션 시민이 쿠폰을 실제보다 약 3배 빨리 써서(하루 소진율 24% 대 실측 7% 안팎) 7일 창에 지출이 몰렸다.
- 사용처 결제를 전부 지원금에서 먼저 빼는 구조 때문이다. 알려진 한계로 기록해 두었다.

**Q7. 같은 조건으로 다시 돌리면 같은 결과가 나오나?**
- 정책마다 있음·없음을 한 번씩 돌렸다. 반복 실행으로 흩어짐을 잰 것은 아니다.
- 대신 시민 단위 부트스트랩 500회로 구간을 냈고, 같은 시민·같은 날을 짝지어 비교해 날마다의 흔들림을 줄였다.

**Q8. 2,000명으로 서울을 대표할 수 있나?**
- 동·성별·연령을 그 시기 서울 주민등록 분포에 맞춰 뽑았다.
- 표본이 작아 생기는 한계도 쟀다. 일부 지표는 실측 효과가 잡음보다 너무 작아서, 0과 가르려면 1만 명 이상이 필요하다. 그래서 그런 지표는 판정에 쓰지 않았다.

**Q8-1. 집단별 차이도 실측과 맞나? 시뮬레이션이 그냥 그럴듯하게 나눈 것 아닌가?**
- 서울시 재난긴급생활비의 소득별 효과는 실측이 있다(IZA DP 14662 표 5, 신한카드 자료, 4~8월).
- 실측: 연소득 3천만 원 미만 +34%, 3천만~6천만 원 +17.6%, 6천만 원 이상 +9.5%.
- 시뮬레이션: 소득 하+중하 +14.2%, 중+중상 +12.1%, 상 +9.5%. 순서가 같고, 고소득층은 크기까지 같다. 저소득층은 실측의 절반쯤으로 작게 잡혔다.
- 소득 기준(카드 신청 때 신고한 연소득 대 시민의 소득 구간)과 기간(4~8월 대 3주)이 달라 크기를 1대1로 견주지는 않는다.
- 연령별 실측은 이 논문에 없다. 그래서 연령별 차이는 시연에서 강조하지 않는다.

**Q9. 7일, 3주로 몇 달짜리 효과를 말할 수 있나?**
- 서울시 재난긴급생활비는 실측 연구와 같은 정의(받은 날부터 3주)로 다시 셌다. 그래서 크기까지 비교했다.
- 다른 정책은 기간이 달라, 얼마나 늘었는지보다 늘었는지 줄었는지를 본다.

### AI 시민·인터뷰

**Q10. 인터뷰 답은 AI가 지어낸 것 아닌가?**
- 시민은 자기 프로필, 정책 안내문, 그 기간의 실제 결제 기록만 받고 답한다. 근거로 쓴 기록 번호를 함께 받아 확인한다.
- 그래도 기록에 없는 숫자를 말할 때가 있다(상생소비지원금 인터뷰 15건 중 3건). 숫자 판단은 모델의 말이 아니라 결제 기록에서 계산한 값으로 한다.

**Q11. 인터뷰 답이 숫자와 다르면?**
- 그대로 보여 준다. 자기 보고와 실제 행동은 사람도 다르다.
- 10/28 시연 녹화에서 70대 이상은 숫자로 +19.5%인데 답은 대부분 "특별히 더 쓴 건 없다"였다. 30대는 3명 중 2명이 "원래 생활비를 대신했다"고 답했다.

**Q12. 포스터에 "찬반과 그 이유를 시행 전에 확인한다"고 썼는데, 정말 되나?**
- 자유롭게 물었을 때는 1,154명 중 98.5%가 중립으로 답해 찬반을 가를 수 없었다.
- 실제 설문과 같은 찬성·반대·모름 3지선다로 물었을 때 응답 분포 유사도 92~93%가 나왔다.
- 흡연자 찬성은 실측보다 23%p 높게 잡았다. **찬반을 정확히 예측한다고 말하지 않는다.** "실제 설문과 같은 형식으로 물으면 분포가 비슷하게 나온다"까지만 말한다.

**Q13. 15,000명의 '자아'는 어디서 왔나? 개인 카드 데이터를 쓴 건가?**
- 실제 개인은 없다. 서울시 빅데이터캠퍼스 데이터를 참조해 반출 기준에 맞추어 합성한 가상 시민이다.
- 공개 데이터셋: 허깅페이스 `mimseong/seoul-synthetic-personas-15k`.
- 자료 번호, 카드사·통신사 이름, 계산식은 말하지 않는다.

**Q14. 시민끼리 영향을 주고받나? 소문이나 약속은?**
- 그래프에 시민 사이의 관계(KNOWS)와 단골 가게(KNOWS_POI)가 있고, 밤마다 기억·단골·대화가 갱신된다(포스터 C의 하루 사이클).
- 3D 지도의 '들은 소문', 일정의 '약속 식사'가 그 흔적이다.

### 서비스·상용화

**Q15. 화면에서 실행이 안 되던데, 진짜 서비스인가?**
- 실행은 GPU 서버(A100)에서 EXAONE 모델로 돈다. 공개 시연 사이트는 누구나 들어오므로 실행 시작만 막았다. 정책 고르기·검증·설정은 실제로 동작한다.
- 결과·인터뷰·지도·보고서는 실제로 돌린 다섯 정책의 기록이다.

**Q16. 한 번 돌리는 데 얼마나 걸리고 얼마나 드나? 용역 1억보다 싼가?**
- 시간은 4절의 기록대로(정책 하나 수십 시간, GPU 기준).
- 원화 비용은 정리해 둔 실제 결제액 기준으로만 답한다. "용역보다 싸다"는 비교 근거를 정리하기 전에는 단정하지 않는다.
- 같은 시민으로 여러 대안 정책을 나란히 돌려 볼 수 있다는 점이 용역과 다르다.

**Q17. 왜 국산 모델(EXAONE)인가? 성능 차이는?**
- 시민 계획·가게 선택·결제는 EXAONE-4.5-33B, 인터뷰는 K-EXAONE이다.
- 한국어 생활 맥락(동네, 가게 이름, 정책 안내문)을 다루고, 공공 데이터를 국내에서 처리하기 위해 국산 모델을 썼다.
- 다른 모델과 같은 조건으로 성능을 비교한 실험은 아직 없다.

**Q18. 새 정책도 넣을 수 있나? 아직 시행 안 한 정책은?**
- 정책은 파일(JSON) 하나로 정의된다. 대상·금액·사용처·기간을 바꾸면 그대로 들어간다(웹 '새 시뮬레이션 만들기'의 새 정책 작성).
- 다만 시행 전 정책은 대조할 실측이 없으므로, 지금까지 검증된 범위(지원금·캐시백·영업 제한)와 비슷한 정책부터 믿을 수 있다.

**Q19. 기존 연구(AgentSociety 등)와 무엇이 다른가?**
- 실제 정책을 다시 돌려 실측 연구와 숫자로 대조했다. 같은 계열의 Hewitt 외(2024) 서베이 실험 재현은 r = 0.85, AgentSociety(2025)는 정량 검증을 내놓지 않았다.
- 같은 시민·같은 날로 정책 있음·없음을 짝지어 비교한다.

**Q20. 지도는 실제 가게인가?**
- 소상공인 상가정보 기반 실제 상점(그래프의 POI)만 후보로 고른다. 없는 가게를 만들어 내지 않는다.

- 유의하지 않은 값을 결과처럼 말하지 않는다. 화면에서 '—'인 칸은 "차이를 말할 수 없다"로 읽는다.
