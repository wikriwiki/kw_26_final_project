## 왜 이 라운드인가

120명 구간에서 되짚으면 **닿을 수 있는 지표가 하나뿐**이다.

```
지표      실측    현재 점추정   현재 반폭   필요 칸 수
EM-3     +7.3     +23.0       160.6      19,234    지금의 40배 — 불가능
DS-2     +4.2     +75.9       491.7      16,549    불가능
P012-1  +20.8    +100.0       150.0         886    도달 가능
```

*(반폭 ∝ 1/√n 근사. 분모가 수십 건인 지금은 낙관적인 값이고 실제로는 더 필요하다.)*

**P012-1 은 부호도 이미 맞다.**

```
실측 +20.82 (적립업종 지출, 개인 내 쌍체차)
시뮬 +100.0  [+0.0, +300.0]   ← 하한이 정확히 0. 짝 394칸
```

886칸이 필요한데 394칸을 갖고 있다. **씨앗 하나를 더 돌리면 대략 두 배가 된다.**

## DS-1 은 왜 빠졌나

[POWER_WITHOUT_ALIGNMENT.md](../POWER_WITHOUT_ALIGNMENT.md) 에 적었다 —
실측이 재는 매장 취식이 우리 계획에 1~2건뿐이라 **정렬이 깨져 있다.**
표본을 키우면 틀린 답이 더 확신할 뿐이다. 그래서 표적에서 뺀다.

# 정정 (23:45, 실행 전) — 전제가 틀렸다

위에서 "886칸이 필요한데 394칸을 갖고 있으니 씨앗 하나를 더 돌리면 두 배가 된다"고

같은 프롬프트(v25)로 돌린 두 라운드를 **블록으로 묶어** 재 봤다.

```
              캐시백 칸
v18 · 60명       80  (off 39 · on 41)
v20 · 120명     115  (off 62 · on 53)

P012-1   v20 짝만 단독     +100.0  [ +0.0, +300.0]
         v18+v20 블록      +150.0  [-50.0, +800.0]   ← 넓어졌다
```

**칸을 더했는데 구간이 넓어졌다.** 라운드 간 분산이 칸 간 분산보다 크기 때문이다.
v7 에서 배우고 v18·v22 에서 다시 확인한 것이 여기서도 그대로다.

## 그래서 이 라운드는 어떻게 되나

**성공선은 그대로 둔다.** 두 씨앗을 블록으로 묶은 구간이 0을 제외하는 것이
여전히 옳은 판정 방식이고, 그게 어려워졌다는 사실이 기준을 바꿀 이유는 아니다.

**다만 기대를 낮춘다.** "886칸이면 닿는다"는 계산은 폐기한다. 씨앗 하나를 더
돌려도 구간이 좁아진다는 보장이 없고, **넓어질 수도 있다.**

이 라운드가 답하는 것은 이제 이렇게 바뀐다.

> **P012-1 의 부호가 씨앗을 바꿔도 양수로 남는가.**
> 구간이 0을 제외하면 그때 비로소 "갈렸다"고 적고, 안 되면
> **"두 씨앗에서 부호는 양수였으나 가릴 수 없었다"**로 적는다.
