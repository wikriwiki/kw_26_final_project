## B. MPC (신규 소비 유발 비중)

정의(29항, Kan et al. 2017): 총 쿠폰 사용액을 ①기존 소비 대체분 ②신규 소비 유발분으로 나눈 뒤 **②의 비율**.

| 구분 | MPC |
|---|---|
| 전체(1·2차 가중평균) | **0.20** |
| 1차 지급 | 0.21 |
| 2차 지급 | 0.18 |
| **소득 1분위(하위 20%)** | **0.25** |
| 소득 5분위(상위 20%) | **0.17** |

- 31항: "소득이 낮을수록 MPC가 높아지는 경향" — 1분위 0.25 > 5분위 0.17, **1·2차 서베이 모두에서 일관**.
- 즉 **모든 분위가 0.17~0.25의 좁은 띠**에 있다(어느 분위도 0이 아니다).

### B-1. 품목별 신규 소비 유발 효과 (그림 19)
- **큰 쪽**: 내구재 > 준내구재 > 여가 > 개인미용·숙박음식
- **작은 쪽**: 비내구재 > 병원 > 학원
- 33항: "필수재의 경우 쿠폰 사용액 중 **기존 소비 대체 비중이 높아** 신규 소비 유발 효과가 제한적,
  수요의 소득탄력성이 높은 품목은 가처분 소득 증가에 민감하게 반응"

## ★ G. 치명적 주의 — 소진율·MPC는 현재 "시뮬 결과"가 아니다

`consumption.py` 확인 결과:
```
intended_grant_today = 잔여지갑 × (1 / grant_spread_days)      # grant_spread_days = Stage1 LLM 자기신고
additional_from_grant = min(intended, eligible_base) × grant_extra_spend  # grant_extra_spend = Stage1 LLM 자기신고
```
- 소진 곡선의 기하감쇠는 **코드에 내장된 배급 규칙**이고, 관측 일간소진율 9.19% ≈ `E[1/spread_days]`다.
- 3~10분위(전체 79.4%)는 `intended ≤ eligible_base`라 **소비 제약이 한 번도 구속하지 않는다**
  → 소진 곡선에 소비 행동 데이터가 사실상 들어있지 않다.
- 분위별 MPC도 `mean(grant_extra_spend)`의 재출력이며, 3~10분위 5,952명 **전원이 정확히 0.0000**인 것은
  필드 미출력 시 기본값 0.0이 적용된 흔적이다.

**따라서 이 두 지표를 "실측과 일치한다"는 타당성 근거로 제시하면 안 된다.**
현재로서는 "에이전트가 신고한 사용계획의 회계적 전개"로 기술해야 하며,
행동에서 창발하도록 만들려면 아래 근본 원인을 먼저 고쳐야 한다.

### 근본 원인 후보
1. **소비수준 앵커 과대** — 시뮬 인당 평일 소비 ~12만원. 실측 가계 인당 소비의 약 2~3배.
   이 때문에 쿠폰 15만원이 "1.2일치"로 축소되어, 배급 규칙 없이는 하루 만에 소진된다.
2. **쿠폰 가맹 POI 비중 91%** — 실제는 대형마트·프랜차이즈 직영·온라인이 제외되어 훨씬 낮다.
   가맹 비중이 현실화되면 소진 속도가 자연히 느려진다.
3. **생활 이벤트 다양성 부족** — 병원·약국·미용실 방문이 거의 없어 업종 구성이 음식·식료품에 91% 집중.

| 시도 | 질문 방식 | 결과 MPC(1분위→5분위) |
|---|---|---|
| R17 | "굳은 돈으로 더 쓰는 정도" | 0.21 → 0.26 (역진) |

**페르소나에 "미뤄둔 필요"의 개인차 정보가 없기 때문**으로 보인다.

### 남은 구조적 한계 (프롬프트로 해결 불가)

1. **군집별 소진율 불일치** — 저소비 분위 4.9% vs 상위 8.6%.
   실측은 큰 금액 군집(1차 15~55만)이 작은 군집(2차 10만)보다 **빨랐다**(70.6% vs 55.6%). 부호 반전.
   원인: 우리 소비 5분위 격차가 **12.7배**(22,000원 vs 280,000원)로 실제(5~6배)보다 과도하게 벌어져,
   최하위 계층이 40만원을 쓸 거래 자체를 만들지 못한다.
2. **MPC 기울기 부재** — 위와 같은 원인. 저소득의 쿠폰 사용액 자체가 작다.
3. **재현 불가 지표** — PSM-DID 매출효과·지역효과(서울 단일, 실측 수도권 효과는 −0.04% 비유의).

### 진단 — 프롬프트 문제가 아니다

건강 이벤트는 하루 **0.4~0.5%**(395명 중 21건) 발생한다. 이는 한국 성인 외래 이용(연 15회 ≈ 하루 4%)
과 비교하면 낮지만 극단적이지는 않다. 문제는 **금액 비중**이다.

- 시뮬 의료 지출: 건당 약 23,000원 × 방문율 → 인당 하루 **약 970원** (총소비의 0.9%)
- 실제 가계 보건 지출: 인당 하루 **약 3,500원** (총소비의 약 8%)

즉 **의료 지출 자체가 상대적으로 9배 적다.** 프롬프트로 방문 빈도를 늘리려는 시도(R21~R23)는
오히려 수치를 떨어뜨렸다 — 문구가 길어질수록 희석되고, 건강 이벤트가 20건 내외라 표본 변동이 크다.

### 더 근본적인 원인 — 쿠폰 가맹 POI 비중 91.5%

BOK 표3은 **쿠폰 사용액** 기준이다. 실제 쿠폰은 대형마트·백화점·프랜차이즈 직영·온라인에서 쓸 수

우리 시뮬은 상거래 POI의 **91.5%**가 쿠폰 사용 가능이고(실측 가맹점 매칭은 26.2%뿐, 나머지는 업종

- **6항 (기전)**: "1차 지급의 MPC(0.21)가 2차 지급(0.18)을 소폭 상회… 가능한 설명으로는
  **2차의 1인당 지급액(10만원)이 1차 지급액(15~55만원)에 비해 줄어들면서 정책의

(표1=6개사·지급개시일 버킷, 표2=KB·주별), **금액→속도 방향을 말하는 것은 표2와 14항 서술이다.**

### 확정된 판정 기준 (§K를 대체)
1. **방향**: 40만/30만 tier의 소진율이 15만 tier보다 **높아야** 한다(순진). 역진은 실패.
2. **크기**: 실측 2주차 누적 70.6% vs 55.6%는 지급액 4~5배 차이 구간의 값이다. 우리 tier 차이는
   40만/15만 = 2.7배이므로 그보다 완만한 순진이 타당하다.
3. **기전**: 지급액이 클수록 체감도(salience)가 높아 결제 때마다 떠올라 더 적극적으로 쓴다(6항).
   저소득일수록 MPC가 높다(5항) — 우리 40만 tier가 곧 소비 1분위이므로 두 근거가 같은 방향이다.
4. 전체 궤적은 §A-4의 hazard 대역(1차 6.6~7.5%/day)을 유지한다.

### 프롬프트 반영
`stage1_intent.py`의 `grant_spread_days` 블록에 6항의 salience 기전을 사실로 서술했다 —
금액이 클수록 체감이 커서 결제할 때마다 떠오르고, 적으면 있다는 사실을 자주 잊는다.

방향이 반대였으므로 이 근거로 철회한다.

## §N. 순진(順進)의 산술 구조 — 왜 프롬프트로 안 되는가 (2026-07-28)

### N-1. 항등식
```
일일 소진율 = min( 지갑/spread , 하루지출 × 가맹률 ) / 지갑
```
tier별로 대입하면 (R41 실측, 600명):

| tier | 지갑 W | 하루지출 D | 가맹률 ρ | ρD/W = **구조적 천장** | 실제 hazard |
|---|---|---|---|---|---|
| 40만 | 400,000 | 28,075 | 0.99 | **6.9~8.7%/day** | 7.64% (천장 도달) |
| 30만 | 300,000 | 39,032 | 0.97 | 12.6%/day | 11.72% |
| 15만 | 150,000 | 160,816 | 0.99 | **106%/day (무의미)** | 12.89% = **1/spread** |

- **15만 tier는 포착 제약을 전혀 받지 않는다** → hazard ≡ 1/spread (정확한 항등식, 포착률 98.6~99.9%)
- **40만 tier는 항상 천장에 걸린다** → hazard ≤ ρD/W

### N-2. 따라서
```
h(40만) > h(15만)  ⟺  min(1/s₄₀, ρD/W) > 1/s₁₅  ⟹  s₄₀ < s₁₅
```
**spread가 tier에 무관하면 역진은 수학적으로 확정된다.** 40만 tier의 hazard는 1/s를 절대 넘을 수 없고

## §P. 소득별 지원금 사용계획 prior 도입 (2026-07-28)

### P-1. 왜 넣었나
계층별 소진 속도의 방향(지급액이 큰 군집이 더 빠름)이 **프롬프트로는 재현되지 않았다.**
13종의 프롬프트·컨텍스트 변형에서 EXAONE-4.5-33B는 지급액·소득·잔고와 무관하게
`grant_spread_days`를 15~21일 근처로 답했다(시도 이력은 §N-4).

| 시도 | 결과 |
|---|---|
| 사용처 사실 추가 / mental accounting / salience 서술 / 유동성 서술 | 방향 불변 |
| 강도 배급(grant_use) | 붕괴 (15만 tier 65.97%/day) |
| 편향 지시문·예시 앵커 제거 | 전 tier 급락, 방향 불변 |
| "N일치" 컨텍스트 재도입 | 15만만 단축 → 역진 확대 |
| 필드 순서 반전 | 전 tier 지연, 방향 불변 |
| 계획 고정(수령 시점) | 궤적 모양 해결, 방향 불변 |
| 이월 상한 제거 | +0.05%p/day — 교차까지 15일 소요 |

### P-2. 구현
`consumption.py`
```python
GRANT_PLAN_PRIOR = {"하": 15, "중하": 17, "중": 20, "중상": 21, "상": 22}
GRANT_PLAN_BAND = 4      # LLM 출력이 움직일 수 있는 폭(일)
```
LLM의 `grant_spread_days`를 소득 등급별 중심값 ± 4일로 클램프한다. 소비성향의
`INCOME_PRIOR`(Jappelli & Pistaferri 2014 인용)와 동일한 방식이며, 클램프는 **지원금을
받은 날 한 번만** 적용되고 이후에는 그 계획이 고정된다.

근거: BOK 32항 각주29 (Sahm 2019 — 1인당 지급액이 커질수록 salience↑, 정책효과가 지급액에
비례), BOK 31항 (소득 1분위 MPC 0.25 > 5분위 0.17), Jappelli & Pistaferri (2014).
본 정책은 저소득일수록 지급액이 크므로(수급자 40만 / 차상위 30만 / 일반 15만) 두 근거가
같은 방향을 가리킨다.

### P-3. ★ 해석상 제약 (보고서 필수 기재)
이 prior는 **실측에서 관측된 방향을 모형 입력으로 넣은 캘리브레이션**이다. 따라서

- **계층별 소진 속도의 방향은 본 시뮬의 예측이 아니라 설정값이며, 재현 대상에서 제외한다.**
- 반면 **소진 궤적(4주 76.4% 등)·업종 구성·전체 MPC·곡선 모양**은 이 prior와 독립적으로
  산출된 결과이므로 재현 성과로 보고할 수 있다.
- 소비앵커(§J·§O)와 같은 성격의 입력 캘리브레이션이며, 결과를 직접 지정하는 계수는 아니다
  (LLM 출력이 ±4일 범위에서 여전히 작동한다).

# §R. 계층별 소진 방향 — 재현 실패의 구조적 원인 (2026-07-30)

## R-1. 결론
**data leakage 없이 EXAONE-4.5-33B로 순진(큰 금액 = 빠른 소진)을 재현하지 못했다.**
확정 구성의 방향값은 **−0.3 ~ −0.5%p**(40만 tier가 15만 tier보다 느림)에서 평탄화된다.

## R-4. 폐기한 방법과 그 이유
- **소득별 계획 prior** (`GRANT_PLAN_PRIOR`) — 순진을 만들어냈으나 **소진 일수를 소득으로 직접
  지정**하는 것이라 검증하려는 값을 입력으로 넣는 data leakage. 폐기.
- **다른 LLM(Qwen3-32B) 검증** — 사용자 지시로 EXAONE 단일 모델 유지. 미실시.
- **비가맹 채널(대형마트·온라인) 도입** — 실측상 고소득일수록 소상공인 결제 비중이 낮아
  이 경로가 순진을 만들 수 있으나, 그래프의 비가맹 POI 45,814개가 대부분 공인중개사·법률·
  세무 사무소라 **소비 채널이 존재하지 않는다**. POI 데이터 확장이 선행돼야 하며 범위 밖.

## R-5. 보고 시 분류
- **재현 불가**: 계층별 소진 속도의 방향, MPC 기울기(방향만 일치, 크기 1/4)
- **재현 성과**: 소진 궤적(4주 76.9% vs 76.4%), 곡선 모양(hazard 평탄, 6일 시점 오차 0.1%p),
  전체 MPC(0.20 vs 0.20), 업종 구성, 사용처 준수 100%
- **부분 유도**: 업종 구성은 예시 JSON에 의료·미용·마트 이벤트를 넣어 개선한 것이므로
  순수 재현이 아니다(수치는 넣지 않았으나 어떤 업종을 예시로 보일지가 표3의 영향을 받음).

# §S. 온라인(배송) 소비 채널 도입 + 계획 프레이밍 전환 — 2026-07-30

## S-1. §R-4의 "비가맹 채널 부재" 진단 정정

§R-4는 "그래프의 비가맹 POI 45,814개가 대부분 공인중개사·법률·세무 사무소라 소비 채널이
존재하지 않는다"고 적었다. **틀렸다.** 브랜드명으로 직접 조회한 결과 대형유통 POI는 이미
비가맹으로 정확히 분류돼 있었다.

|---|---|---|---|

대형유통으로 갈 이유가 만들어지지 않는다.

## S-2. 조치: 온라인(배송) 지출 채널

POI 추가 없이, **집에서 주문해 배송으로 받는 지출**을 별도 채널로 만들었다. 근거는 모델
가정이 아니라 정책 문언이다 — 소비쿠폰은 **온라인 결제에 쓸 수 없다**(P010 사용처 조건).

- `Stage1Output.online_share` (0~1) — 오늘 지출 중 배송으로 받는 몫. 본인이 판단한다.
- `consumption.py` — `personal_total`을 온라인/오프라인으로 나눈다. 온라인분은 POI 배분과
  지원금 정산을 거치지 않고 **자기 돈에서만** 나간다(잔액 한도). 안전장치로 `ONLINE_SHARE_CAP=0.60`.
- `plan_writer.py` — 배송 주문은 INCLUDES 엣지가 없어 `today_spent` 합계에 안 잡히므로
  야간 정산에서 `$today_online_spent`를 별도로 차감한다. `State.online_spent`에 기록.

**측정된 한계(중요).** 온라인 채널만으로는 소진율이 바뀌지 않는다. 단위검증에서 온라인 비중을
0 → 0.3 → 0.6으로 올려도 지원금 결제액은 20,000원으로 불변이었다. 일일 인출 한도
(지갑 ÷ 계획일수)가 가맹점 지출보다 훨씬 낮아 병목이 아니기 때문이다.
→ **이것은 소비 현실성 교정이지 역진 해결책이 아니다.** 효과는 1인당 가맹점 지출·업종 구성·
MPC 분모에 나타난다.

## S-3. 역진의 산술적 뿌리 (§N 보강)

포착률이 양 tier 모두 98%대로 붙은 뒤 `hazard = 1/계획일수`이므로, 순진은 오직
`계획일수(40만) < 계획일수(15만)`일 때만 나온다.

**소진 시간을 "돈이 떨어지는 데 걸리는 시간"으로 보는 한 순진은 산술적으로 불가능하다.**
순진 조건 `400,000/E₄₀ < 150,000/E₁₅` 는 `E₄₀ > 2.67 × E₁₅` 를 요구한다 — 저소비 계층이
고소비 계층보다 가맹점에서 2.67배 **더** 써야 한다는 뜻이다. 온라인 채널로 E₁₅를 낮춰도
비율이 2.67배까지 벌어지지 않는다.

즉 실측의 순진은 **소진 속도(drain rate) 현상이 아니라 행동(behavior) 현상**이다. BOK 32항
각주29가 인용한 Sahm(2019)의 salience 기제가 이것이다 — 지급액이 클수록 그 돈이 "무언가를
할 돈"으로 인식되어 의도적으로 쓰이고, 작은 금액은 평소 결제에 섞여 흘러간다.

## S-4. 조치: 수동적 소진 추정 → 능동적 사용 계획

기존 프롬프트는 `grant_spread_days`를 **"며칠에 걸쳐 다 줄어들지"**로 물었다. 이것은 수동적
소진 추정이며, 여기에 **"여러 주에 걸쳐 천천히 줄어드는 것이 보통이다"**라는 문장이 붙어
있어 금액과 무관하게 21일 근처로 답이 수렴했다(측정: 40만 22.2±0.8 / 15만 21.0±0.3).

바꾼 내용 — 수치는 넣지 않고 판단의 형태만 바꿨다:
- **"며칠에 걸쳐 다 쓸 생각인지"** (능동적 계획)
- 이 돈이 **내 하루 씀씀이로 며칠치인지** 먼저 가늠하게 한다
- 여러 주를 감당할 크기면 → 무엇을 할지(미뤄둔 병원·바꿔야 할 것·아이 물건) 떠올리게 되고
  그 일들은 몇 주 안에 치러진다 / 며칠치도 안 되면 → 평소 결제에 섞여 나간다
- 결제할 때 **실제로 꺼내 쓰는 것을 챙기는지** — 대수롭지 않은 금액이면 평소 카드로 그냥
  계산하고 지나가는 날이 섞이고, 그만큼 기간이 길어진다
- "여러 주에 걸쳐 천천히 줄어드는 것이 보통" 앵커 **삭제**

**스모크 4명 즉시 관측**: 계획일수 답이 10 / 10 / 20 / 30 으로 벌어졌다(기존 21 근처 수렴).
앵커가 분산을 죽이고 있었다는 직접 증거.

## S-5. 이 변경이 leakage가 아닌 이유
- BOK의 어떤 **수치**도 프롬프트·코드에 들어가지 않았다(표1/2/3, MPC, 그림18 모두 미사용).
- 소득 등급으로 사용 일수를 지정하지 않는다(§P에서 폐기한 `GRANT_PLAN_PRIOR`는 그대로 폐기 상태).
- 온라인 채널의 근거는 실측이 아니라 **정책 문언**(온라인 결제 불가)이다.
- 계획 프레이밍은 방향을 지시하지 않는다. "큰 돈이면 짧게 답하라"가 아니라 "이 돈으로 무엇을
  할지 생각하게 된다"는 **행동 서술**이며, 며칠로 답할지는 에이전트가 자기 형편에서 정한다.

# §T. 결제 선택 구조로의 전환 — 2026-07-30

## T-1. 지금까지 소진율은 에이전트의 결정이 아니었다

`settle_policy_spend_priority`가 Stage2의 건별 결제 선택(`policy_spend`)을 **진단값으로만
기록하고 버린 뒤**, `actual_spent × 1.0`으로 모든 가맹 거래에 지원금을 비례 배정하고 있었다.
그때 지갑은 이미 `잔액 ÷ 계획일수`로 깎여 들어오므로, 소진율은 항상 정확히 `1/계획일수`였다.

단위검증 (지갑 400,000 / 계획 20일, 선택만 바꿈):

| 에이전트의 선택 | 기존(배급) | 선택 반영 |
|---|---|---|
| 전부 지원금으로 | 5.00% | 18.51% |
| 절반만 | 5.00% | 8.49% |
| 거의 안 씀(0.05) | 5.00% | 1.66% |

**무엇을 고르든 5.00%였다.** §R의 개입 16건이 모두 실패한 구조적 이유가 이것이다 — 프롬프트가
무엇을 바꾸든 결과가 나눗셈으로 덮여 있었다.

## T-2. 프롬프트 3곳이 "네 선택은 무시된다"고 명시하고 있었다
- `stage2_poi.py` 규칙: "policy_spend에는 예상 결제액을 기록하되 **최종값은 시스템이 정산한다**"
- `run_simulation.py` 정책 요약(프롬프트 헤더): "결제는 정책지갑을 자기자금보다 먼저 사용하며,
  **최종 policy_spend는 시스템이 정산한다**"
- `dawn_context.py` 판단 원칙: "정책 사용처이면 정책지갑을 **자기자금보다 먼저 결제**"

셋 다 제거하고 "결제 건마다 본인이 정하며, policy_spend에 적은 금액이 실제로 그 지갑에서
나간다"로 교체. `consumption.py`에 `EXP_PAYMENT_CHOICE=1` 모드 추가(건별 선택 비율을 최종
금액에 그대로 적용, 일일 배급·이월 없음).

## T-3. 잔액은 계층을 가르지 못한다 (§R-16 역효과의 진짜 원인)
에이전트 잔액이 **144만~242만원**으로 전 계층이 하루 지출의 20일치 이상을 보유한다.
"자기 돈이 빠듯한 사람은 챙겨 쓴다"류의 유동성 제약 신호를 넣으면 **전원이 '여유 있음'으로
읽혀** 사용률이 0으로 무너진다(SMOKE77: 20명 중 17명 0%). 유동성 제약은 이 데이터에서
쓸 수 없는 축이다.

## T-4. 기회는 100%다 — 안 쓴 것이 아니라 안 고른 것
40만 tier가 계속 0%로 나와 사용처 부족을 의심했으나, 결제선택과 무관하게 조회한 결과:

| tier | 거래 | 쿠폰 사용가능 | 1인당 가능액/일 |
|---|---|---|---|
| 40만 | 15건 | **15건 (100%)** | 21,340원 |
| 30만 | 37건 | 37건 (100%) | 29,544원 |
| 15만 | 180건 | 179건 (99.4%) | 59,020원 |

## T-5. 목표 행동이 산술적으로 확정된다
- 40만: 21,340 ÷ 400,000 = **5.34%/일 → 4주 78.6%** — 쓸 수 있는 결제를 **전부** 얹으면
  실측(76.4%)과 거의 일치한다.
- 15만: 59,020 ÷ 150,000 = 39%/일(사흘 소진). 4.7%/일이 되려면 **약 12%만** 얹어야 한다.

즉 순진은 "40만이 더 많이 쓴다"가 아니라 **"40만은 거의 전부 얹고, 15만은 가끔만 얹는다"**로
달성된다. 그 이유도 자연스럽다 — 15만원은 자기 씀씀이로 2.5일치라 다 얹으면 사흘이면 끝나므로
아껴 쓰게 되고, 40만원은 19일치라 매일 써도 한참 간다.

**§S-4(R74)의 실패와의 차이**: R74는 같은 인식("며칠치인가")을 *소진 추정*에 물어서 15만이
"사흘이면 없어짐" → 계획일수를 짧게 답해 역효과였다(갭 −0.55 → −1.53%p). 이번에는 같은 인식을
*아껴 쓸지의 결정*에 붙인다. 인식은 같고 그것이 무엇을 결정하느냐가 반대다.

## T-6. 진행 중
R80(400명 × 1일)으로 방향 측정 중. 이 문서의 §R "재현 불가" 판정은 T-1이 밝혀진 이상
재검토 대상이다 — 16건의 개입은 결과에 도달할 수 없는 경로에서 시도된 것이었다.

# §U. BOK 원문 재독 — 판정 기준 정정 (2026-07-30)

## U-1. 그림18·31항·32항은 소진율이 아니라 MPC다

그동안 salience(Sahm 2019)를 **소진 속도**의 근거로 인용해 왔으나, 원문에서 그 논의는
전부 **MPC(신규 소비 유발 비중)**에 붙어 있다.

- **31항**: "소득수준별로는 소득이 낮을수록 소비쿠폰의 **MPC**가 높아지는 경향" —
  1분위 0.25 > 5분위 0.17, 1·2차 서베이 모두에서 일관.
- **32항**: 1차 MPC 0.21 > 2차 0.18. 설명 — "1인당 2차 지급액(10만원)이 1차(15~55만원)에
  비해 줄어들면서 정책의 **가시성**(salience) 또는 체감도가 약화되었을 가능성".
  각주29 Sahm(2019): "1인당 지급액이 커질수록 정책의 가시성이 높아지고 **내구재 등 소비
  유발효과가 더 큰 품목의 소비로 이어질 수 있는 만큼 정책효과가 지급액에 비례**".
- **그림18 주2)**: "▲ 표시는 총 소비쿠폰 지급액 대비 사용 비중" — 분위별 소진 데이터는
  이 마커가 유일한데 **표로 제공되지 않고 렌더된 이미지에서도 값을 읽을 수 없다.**
  본문에는 분위별 소진율의 방향에 대한 서술이 없다.

→ **분위(계층) 차원에서 원문이 명시적으로 단언하는 지표는 MPC 기울기뿐이다.**

## U-2. 순진(지급액↑ → 소진↑)의 근거는 표2다
표2(KB 주별) — 1차(지급액 15~55만원) 2주차 누적 **70.6%** vs 2차(10만원) 2주차 **55.6%**.
지급액이 클수록 빨리 소진됐다는 근거는 여기이며, 소득분위가 아니라 **1차/2차 지급 회차**
비교다. 지급액 비율 ≈2.5배에 대해 일 hazard 갭 ≈ **+2.7%p**(8.36% vs 5.65%).

**교란 요인(보고서에 명시할 것)**: 1차는 전국민·여름·집중 홍보, 2차는 소득 하위 90% 선별·
10월 말~11월. 시기와 대상이 달라 순수한 지급액 효과로 볼 수 없다.

| **MPC 소득 기울기 +0.08** | **31항 (명시)** | **강** | +0.011~0.022 [NG] |
| 업종 구성 | 표3 | 중 | 대체로 일치 |
| 계층별 소진 방향(순진) | 표2 1차/2차 유추 | **약(교란)** | 역진 [NG] |

지금까지 "약(교란)" 지표를 주 목표로 삼고 "강" 지표인 MPC 기울기를 부차로 다뤄 왔다.
최종 보고서는 이 강도 차이를 명시해야 한다.

# §V. 역진의 실제 생성기 — pick_reason 직독 (2026-07-30)

R80(400명) 결과: 선택몫이 **0.19 / 0.21 / 0.18**(40만/30만/15만)로 **전 계층 동일**.
0% 비율도 60/55/58%로 같다. 소진율 차이(1.57 / 3.35 / 9.19%)는 전부 구조적 비율
(가맹지출÷지갑 = 0.070 / 0.099 / 0.404)에서 나온 것이고 LLM의 기여는 0이었다.

`소진율 = 선택몫 × (가맹지출/지갑)` 이므로 순진 조건은 `선택몫₄₀/선택몫₁₅ > 5.7`.
실제는 **1.06**.

## V-1. 모델이 발명한 규칙
pick_reason을 직접 읽으니 프롬프트에 없는 휴리스틱이 지배하고 있었다:
- "작은 지출은 개인 카드로 처리. **지원금은 큰 결제(₩₩₩ 이상)에 활용**"
- "소액은 자기 돈으로 결제하는 경향 반영"
- "다른 이벤트에서 지원금을 더 효율적으로 사용할 계획이므로 오늘 첫 결제는 자기 카드로"
- **"지원금은 여유 있으니 일부 건에만 사용"** (40만 tier — salience의 정반대)
- "건강 관련 지출은 자기 돈으로 처리하는 경향" (임의의 업종 규칙)

**거래 크기 기준**이므로 지갑 크기와 무관하게 작동하고, 40만 tier의 거래가 3천~1.3만원으로
작아 한 번도 발동하지 않는다. 이것이 역진의 직접 생성기다.

## V-2. 조치 (R81)
1. 판단 기준을 "결제 하나의 크기"가 아니라 **"오늘 결제들 중 몇 건을 이 지갑으로 내는가"**로
   명시. "소액이니 내 카드로, 지원금은 나중에 큰 데" 휴리스틱을 명시적으로 부정.
2. "남은 금액이 넉넉하다"를 **골라 쓸 이유가 아니라 편히 쓸 이유**로 교정.
3. **`남은 지원금 ÷ 평소 하루 씀씀이 = N일치`를 컨텍스트로 계산해 제시**(40만 17일치 /
   15만 2일치). 모델이 프롬프트 안에서 이 나눗셈을 스스로 하지 않는다는 것이 R80에서
   측정됐기 때문이다. BOK 수치가 아니라 **에이전트 자신의 지갑과 자신의 소비규모**로
   계산한 값이므로 leakage가 아니다.

# §Z. 순환 구조 제거 — MPC 재현 주장 철회 (2026-07-30)

## Z-1. MPC는 출력이 아니라 입력이었다 — 철회
`consumption.py`가 이렇게 돼 있었다.
```
추가소비 = substituted × (1 − grant_kept_share)      # 기존
추가소비 = substituted × m/(1−m)                     # §U 이후 도입
총지출  = 평상지출 + 추가소비
```
**MPC 값을 받아 그만큼 소비를 만든 뒤, 그 소비에서 다시 MPC를 측정하고 있었다.** 넣은 값이
나오는 순환이다.

→ **"전체 MPC 0.20 = 실측 0.20"은 재현이 아니다. 이 주장을 철회한다.** LLM이
`grant_kept_share ≈ 0.8`을 답하고 코드가 이를 기계적으로 추가소비로 변환한 결과였다.

BOK의 `MPC = Σ sᵢ(cᵢ/C)`(참고3 ⑤)는 **사후 측정 정의**다. 이를 소비 생성기로 쓴 것이
오류였다. 측정 공식은 검증 단계에서만 써야 한다.

**같은 계열의 오류가 소진율에도 있었고 이미 고쳤다** — `소진율 = 1/계획일수`였을 때
LLM이 답한 일수가 소진율을 직접 지정했다(§T). 지금은 건별 결제 선택의 결과다.

## Z-2. 조치
1. **`additional_from_grant` 경로 삭제.** `desired_total = personal_total`. 쿠폰으로 소비가
   늘어난다면 에이전트 자신의 결정(`daily_propensity` 상승, 이벤트·금액 증가)으로만 나타난다.
2. **MPC는 사후 측정 전용.** 결제 건별 `would_buy_anyway`(쿠폰 없어도 샀을까)를 지원금
   결제액으로 가중평균. BOK와 **같은 도구(자기보고)·같은 한계**(BOK 34항이 명시).
3. **결제선택 모드 기본 켜짐.** 끄면 옛 순환 경로가 되살아나므로 기본값을 켜짐으로 고정.
