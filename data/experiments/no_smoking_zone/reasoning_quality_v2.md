# 자기 상황에 근거한 정책 입장: v2

목표는 긴 답변이 아니라 **해당 시민의 관련 상황, 근거와 입장의 연결, 중요하게 보는 기준**이 드러나는 공개 설명이다. 짧은 유보 응답도 자료가 부족하다면 적절할 수 있다. 이 문서와 진단 사례는 실제 시민의 답변이나 LG 모델의 실측 성능이 아니다.

## 발견한 문제와 변경

기존 입력 선택은 최근 항목을 우선하고 개인 프로필 일부만 전달했다. 이 방식은 직업·시간·예산·취향·기억을 누락하고, 실제 경험보다 호출 메타데이터를 많이 담을 수 있었다. 기존 응답 검사는 인용 문자열의 존재를 확인했지만 그 사실이 왜 이 사람의 선택이나 입장에 중요한지 요구하지 않았다.

낮 계획·장소 선택에도 개인 정보가 실제로 도달해야 한다. 금연 실험용 개인 정보 렌더링은 생활 서술의 첫 줄이나 취미를 숨기지 않고 기록된 값을 전달한다. 누락된 지출·체류시간을 0으로, 직장 정보 미상을 직장 없음으로 바꾸지 않는다. 하루의 선택 설명도 관련된 개인 상황과 선택의 관계를 밝히도록 했다. 가계 상태 등 모형 내부 수치는 임상 상태나 실제 사람의 관측값이 아니다.

`stance_context.py`는 원문에 있는 생활·자원·근무·취향·개인 상황과 상태를 출처가 연결된 항목으로 전달한다. 모르는 필드는 미확인으로 남긴다. 사건·영수증·공개 설명·기억의 자료 종류와 시점을 유지하고, 기간과 경험 종류를 나눠 선택한다. 정책 관련성은 확인 가능한 시설·지역 정보에 근거하며 단순 여가 지출을 정책 시설 이용으로 간주하지 않는다. 만족도나 구매 성공 여부는 선택 범위를 다양하게 하기 위한 기록 값이며 찬반 판정에 쓰지 않는다.

전체 원본 packet은 별도로 보존한다. 토큰 한도 때문에 제외한 항목·기간·종류와 선택 작업량 제한을 표시한다. 선택되지 않은 경험을 없었던 경험으로 해석하지 않는다. 실제 본 실행의 모든 개인 상황이 입력창 안에 들어간다는 보장은 아니며, 파일럿에서 누락 분포를 확인한다.

## 응답과 검사

문항 ID는 `indoor_sports_smoking_ban_attitude_v2`, 응답 schema와 공개 근거 계약은 버전 2다. 이전 v1 응답은 보관·읽기가 가능하지만 같은 분석 설계에 섞지 않는다. 네 측정 셀(OFF/ON × 시행 전/후)은 같은 v2 질문을 사용한다.

| 응답 항목 | 확인할 내용 |
| --- | --- |
| `personal_situation` | 인용된 자신의 어떤 상황이 이 문제에 관련되는가 |
| `considerations` | 기록된 사실, 예상되는 영향, 현재 가치판단을 구분했는가 |
| `personal_relevance` | 그 고려사항이 자신의 생활에서 왜 중요한가 |
| `weighing` | 중요하게 보는 기준과 최종 입장이 연결되는가 |
| `conditions` | 입장이 달라질 조건이 있다면 가정임을 분명히 했는가 |
| `uncertainties` | 판단에 중요한 미확인 사항을 드러냈는가 |

경험을 주장하면 원문 인용이 필요하다. 영수증은 결제 사실의 근거이며 연기 노출·건강 개선·방문 동기·찬반의 근거로 자동 확장하지 않는다. 모델이 만든 밤 상호작용이나 당시 공개 설명도 실제 녹취와 구분한다. 고정된 흡연 라벨로 찬반을 정하지 않는다.

목록 개수에는 상한만 있다. 최소 분량, 양쪽 입장, 반론, 입장 변경 조건을 억지로 채우지 않는다. 장문·인용 개수·높은 자기 확신을 논리성 점수로 쓰지 않는다. 본문은 보통 4~7문장, 상황이 단순하거나 정보가 부족하면 더 짧게 답할 수 있다.

`stance_argument.py`는 구조와 정확 인용을 검사하고 공개 연결이 빠진 부분을 `argument_quality`에 남긴다. `needs_enrichment`는 검토할 연결 누락이 있다는 뜻이며, 답변을 재생성하거나 누락 정보를 만들어 채우라는 지시가 아니다. 원래 답변과 입장을 그대로 남기고 품질 상태별 분포를 따로 집계한다. 문법적으로 완전한 응답도 **인용의 의미적 뒷받침·논리적 일관성·진정한 개인 관련성**은 추가 검토 대상이다. 코드가 이를 검증했다고 표시하지 않는다.

인터뷰 출력 예약은 700에서 **1,600토큰**으로 늘렸다. 입력 + 출력 예약 + 여유 128토큰은 여전히 8,192 이하로 제한한다. 이는 최대 출력 허용량이지 실제 사용량이 아니다. 30,000건 수집 비용과 시간은 수정된 계약으로 파일럿에서 다시 측정한다. 실제 응답이 잘리면 오류로 기록하며 내용을 보충하거나 찬반을 바꾸지 않는다.

## 작은 비교 진단 후 본 수집

`probe_stance_reasoning.py`에는 손으로 만든 네 진단 사례가 있다. 같은 흡연 여부지만 생활·예산·취향이 다른 쌍, 같은 생활에 흡연 여부만 다른 쌍, 개인 정보가 거의 없는 사례다. 특정 찬반을 정답으로 정하지 않으며 서로 다른 사람의 입장이 같다는 이유만으로 실패 처리하지 않는다.

```bash
# 기본은 오프라인 계획. 로컬 고정 tokenizer를 지정하면 실제 입력도 렌더링한다.
python scripts/experiments/probe_stance_reasoning.py --out /workspace/no-smoking-results/reasoning_probe_plan --tokenizer-path output/experiments/no_smoking_zone/runtime/tokenizer
# LG SGLang 서버 준비 후 새 폴더에 네 건만 실제 호출한다.
python scripts/experiments/probe_stance_reasoning.py --out /workspace/no-smoking-results/reasoning_probe_live --tokenizer-path output/experiments/no_smoking_zone/runtime/tokenizer --execute
```

생성된 `review.json`의 여섯 기준은 개인 구체성, 인용의 실제 관련성, 논리적 연결, 사실·예상·가치 구분, 관련 상충·불확실성, 상황 변화에 대한 설명의 민감성이다. 점수는 처음에 모두 미평가 상태다. 입력과 공개 응답을 함께 읽고 주장 단위로 확인한다. 구조 검사 통과만으로 논리 품질을 통과 처리하지 않는다. 합성 진단 응답은 본 실험 결과·찬반 정답·실증 성능에서 제외한다.

이번 변경의 로컬 검사 결과는 `validation_reasoning_quality_v2.json`에 기록한다. 실제 LG 응답 품질과 7,500명 전체 기록은 별도의 GPU 실행에서 확인해야 한다.

최종 로컬 회귀 검사는 시뮬레이션 934개와 persona/배포 36개(총 970개), 하위 검사 7개가 통과했다. 7개는 건너뛰었고, 메인에서도 재현된 기존 외출 필요도 테스트 3개만 실패했다. 정적 감사는 Python 248개·프롬프트 모듈 52개·생성 호출 15곳을 포함한다. 활성 입력 사례 46개는 고정 LG 토크나이저와 출력 예약을 합한 8,192토큰 한도를 통과했다. 실제 연결 가능한 LG 서버는 확인되지 않아 GPU 응답을 생성하거나 논리성 점수를 부여하지 않았다.
