# 본런 전 점검 — A100 + Colab G4 (2026-10-06)

원칙(사용자): Colab 세션 때문에 에이전트 기억이 빠지면 안 된다. 결과는 A100 서버에 실시간으로 쌓이고, 빠르고 **정확하게** 나와야 한다.
구조: 시뮬·Neo4j·원장·기억은 모두 A100 에. Colab 은 언어모델 계산만 하고, 중계(`/data/gpu_pool`, 포트 30100)가 A100 과 설정이 같은 일꾼에게만 일을 준다.
Colab 단위는 쓰지 않았다(무료 T4·A100 안 흉내로만 시험).

## 1. Colab ↔ A100 설정 일치 — 통과
- A100 `/get_server_info` 의 생성 관련 24항목 = 노트북 EXPECTED (random_seed 762156816, A100 SGLang 2026-10-03 05:55 기동 그대로).
- 노트북은 생성기로 다시 만들어도 같은 바이트(e08497fc), 브랜치 판과 같다.
- 노트북의 패키지 목록 231줄 = A100 `/data/venv_sgl` 실제 목록.
- **주의:** A100 은 시드 지정 없이 떴다. 본런 중 A100 SGLang 을 재시작하면 시드가 바뀌어 Colab 일꾼이 모두 거부된다(잘못된 답은 안 섞이고 느려질 뿐).

## 2. G4(sm_120) 즉석 컴파일 — 확인 중(미완)
- A100 첫 기동 때 즉석 컴파일된 것: sgl_kernel_jit 6개(gptq_marlin bf16·repack, kvcache 2048, fused_rope, clamp_position, resolve_future_token_ids) + flashinfer sampling.
  G4 에서는 Colab 의 nvcc 로 sm_120 용을 다시 만든다. A100 의 nvcc 는 12.0(sm_120 미지원) — Colab 쪽 nvcc 판이 관건.
- 무료 T4 에서 sglang `override_jit_cuda_arch(12,0)` 로 같은 함수를 교차 컴파일하는 칸을 넣었으나, 원격 접속 중 브라우저가 끊겨 결과를 아직 못 읽었다.

## 3. 중계 — 고침 3개, 시험 통과
| 고침 | 이유 |
|---|---|
| 접속 대기열 5 → 1024 (`PoolHTTPServer`) | 본런은 수백 개 요청이 동시에 열린다 |
| Colab 쪽 대기 900 → 300초 (config) | 시뮬 시간 초과보다 짧아야 멈춘 Colab 을 A100 으로 넘긴 답이 시간 안에 온다 |
| 실행기 시뮬 시간 초과 180 → 600초 (`AB_LLM_TIMEOUT`, 실행 기록에 남김, 실행 지문 밖) | 180초면 중계가 넘기기 전에 시뮬이 포기해 시도 예산만 닳는다 |
| 끊긴 터널 정리 `tunnel_reaper.sh` (tmux tunnelreaper) | 서버 sshd 가 죽은 Colab 을 늦게 안다(ClientAlive 0, keepalive 7200초) → 포트가 최대 약 2시간 묶여 재접속 불가. 세션이 쥔 포트가 **모두** 80초 응답 없을 때만 그 세션을 끊는다. PID 읽기만 sudo, 끊기는 사용자 권한 |
- 단위 시험 16개 통과(새: 요청 300개 동시 — 모두 한 번씩만 처리).
- 정리 스크립트 시험: 포트 하나만 죽음 → 안 끊음 / 둘 다 죽음 → 그 세션만 끊고 포트 풀림.

## 4. 'Colab 이 시뮬 도중 죽는' 실전 시험 — 통과 (`/data/ab3w/p010_t10proxy`, 15:07~15:15)
P010, 10명, 정책 전 1일 → 갈래 1일씩, 중계 경유. A100 과 설정이 같은 가짜 Colab(A100 으로 넘김)을 계정 6 포트에 띄우고,
두 갈래가 돌며 Colab 쪽에 요청 13건이 걸린 순간 강제 종료(kill -9).
- 중계: 즉시 두 일꾼 제거, 걸린 13건 모두 A100 으로 다시 보내 200. 실패 0, 늦은 답 0, 같은 요청 두 번 처리 0.
- 시뮬: 재시도 0(죽은 줄 모름). 출력 점검표 25 통과 / 실패 0.
- 기억 모음: 정책 있음 10명·상태 20·기억 102, 정책 없음 10명·상태 20·기억 95 — 빠짐없음.

## 5. 기타
- Neo4j 1번 인스턴스에 메모리 상한이 없었다(기본값) → 2번과 같게 힙 8g·페이지캐시 8g 고정(다음 복원 때 적용). 3~14번은 4g/4g.
- 밤 단계 기록은 트랜잭션 하나라 반쯤 쓰다 멈추지 않는다. 막히는 경우는 기록 직후·완료 표지 전 사망뿐이고, 그때 실행기가 멈추며 알린다.
- 대형마트·SSM 구분: 결제 기록(계획→가게)이 그래프 덤프에 남으므로 본런 뒤 가게 이름으로 다시 계산할 수 있다(본런을 막지 않음).
- 서버: 메모리 235GB, CPU 16코어, 디스크 여유 689GB.
