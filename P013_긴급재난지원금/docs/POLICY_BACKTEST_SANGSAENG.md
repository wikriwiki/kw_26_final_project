## 0. 정책이 뭔가

**상생소비지원금**은 2021년 10~11월, 코로나19로 위축된 소비를 진작하기 위해 정부가 시행한 카드 캐시백 사업이다.

- **(시행시기)** 2021.10.1 ~ 11.30 (2개월)
- **(사업규모)** 7천억원 계획 → 실제 집행 8,054.2억원
- **(지원대상)** ❶만 19세 이상(2002.12.31 이전 출생) ❷2021년 2분기(4~6월) 중 본인 명의 신용·체크카드 사용실적 있는 자(외국인 포함, 비소비성 지출 제외)
- **(지원방식)** 월간 카드 사용액이 **2분기 월평균 대비 3% 이상 증가 시, 초과분의 10%를 캐시백**으로 환급
  - 예: 2분기 월평균 100만·10월 153만 → 증가 53만 중 3만(3%) 제외한 50만의 10% = **5만원**
- **(지원한도)** 1인당 월별 **10만원 한도**
- **(대상소비)** 적립업종만 실적 산정(네거티브 방식). 제외 = 대형마트·대형백화점(아울렛·복합몰 포함)·면세점·대형전자전문점·대형종합온라인몰·홈쇼핑·유흥·사행·신차구입·명품전문매장·실외골프장·비소비성지출(연회비·세금·보험·상품권 등) — 비소비성 제외 카드사용액의 약 80%가 실적 인정 대상
- **(지급 타이밍)** 10월 소비 → 캐시백 **11/15** 지급 / 11월 소비 → 캐시백 **12/15** 지급. 유효기간 ~2022.6.30
- **(전담기관)** 9개 카드사(롯데·비씨·삼성·신한·우리·하나·현대·KB국민·NH농협)

## 1. 정책의 취지 — "돈 지급"이 아니라 "가격 유인"

상생소비지원금은 정액 현금을 주는 정책이 **아니다**. 2분기보다 더 쓰면 초과분의 10%를 돌려주는 **가격 유인** 정책이다.

- **목적**: 피해 누적 업종(=적립업종, 소상공인 중심)의 소비 회복 + 전체 소비 진작.
- **메커니즘**: 적립업종의 상대가격을 사실상 10% 낮춤 → 적립업종으로 소비 이동(대체효과) + 실질소득 증가(소득효과). 제외업종은 소득효과(+)와 대체효과(−)가 상쇄되어 부호가 이론상 불확실.
- **핵심 타이밍**: 캐시백은 다음 달 15일 지급. 쓰는 시점엔 아직 돈을 손에 쥐지 않는다. 10월 소비 증가가 있다면 그건 "받은 돈" 때문이 아니라 **"10% 돌려받을 기대(anticipation)"** 때문 — **우리가 재현할 것은 이 기대효과다.**

### 버는 쪽 vs 쓰는 쪽 (혼동 주의)

| 단계 | 규칙 |
|---|---|
| 버는 것(실적 산정) | 제외업종 소비는 실적에 **안 잡힘** — 거기서 써도 캐시백이 늘지 않음 |
| 쓰는 것(받은 캐시백 사용) | **제한 없음** — 모든 국내 가맹점(제외업종 포함) 사용 가능 |

### 실제 관측 효과 (보고서 실측, 요약부)

- 적립업종: **크게 증가**
- 제외업종: **≈0 (그대로~미세 증가)** — "감소"가 아님
- 총량: **증가**(승수 165%, 다만 §5.3에서 채점 대상 제외 사유 설명) — "총량 그대로 방향만 전환"이 아니라 순증가

## 2. 소비쿠폰(EXP-001 / P010)과의 결정적 차이

EXP-001(민생회복 소비쿠폰, 정책 ID **P010**, `type: "grant"`)을 이미 완주했지만, 상생소비지원금은 그것과 **다른 능력**을 시험한다.

| | 민생회복 소비쿠폰 (P010, grant) | **상생소비지원금 (본 백테스트)** |
|---|---|---|
| 돈 성격 | 선지급 정액 쿠폰(정책지갑) | 사후 캐시백(더 쓴 만큼, 익월 지급) |
| 금액 결정 | 외생 = 입력값(소비 10분위별 15/30/40만) | 내생 = 행동의 출력(사후 계산) |
| 사용처 제한 | `poi_restricted=true` → 쿠폰 사용처만 결제 가능 | 버는 쪽만 제한, 쓰는 쪽은 무제한 |
| 측정 대상 | 받은 돈을 얼마나 쓰나 (**MPC**) | 인센티브에 반응해 **얼마나 더 쓰나** (기대효과) |
| 지배 역학 | 정책지갑을 **개인부담 대신 우선 결제**(사후 정산) | **한계 인센티브 / 상대가격 반응**(대체+소득효과) |
| 우리 엔진 주 채널 | 정책지갑 사후 정산(`settle_policy_spend_priority`) | 선택 유인(자연어 신호 → 대체효과) |
| 시뮬 시험 능력 | 지급 자산의 결제·정산 충실도 | **행동 반응 충실도 = LLM 자연어 채널의 진짜 테스트** |

### ⚠️ 소비쿠폰 메커니즘이 21일 커밋으로 바뀐 점 (§2 논리의 근거)

EXP-001 역사 결과에서 시뮬 MPC가 실측(0.20) 대비 ≈1.0으로 발산했다([EXP001_VALIDATION_vs_BOK.md](EXP001_VALIDATION_vs_BOK.md), [EXP001_CAVEATS.md](EXP001_CAVEATS.md)). **이 발산을 고치려고** 21일 커밋이 소비모델을 바꿨다:

- `available_today`는 정책지갑 잔액을 **총소비 예산에 더하지 않는다**(`p × 지원금잔액` 강제 인출 폐기).
- `spend_today`는 `grant_part=0`을 반환 — 총소비는 오직 개인예산(성향×평상 소비앵커)에서 나온다.
- 정책지갑은 **실제 거래가 확정된 뒤** `settle_policy_spend_priority`(+ max-flow `_allocate_policy_capacity`)로 사후 정산되어, **이미 정해진 거래의 개인부담만 대체**할 뿐 총액을 늘리지 않는다.

즉 이제는 **소비쿠폰조차 "지갑을 비워서 총소비를 부풀리는" 모델이 아니다.** 그럼에도 상생소비지원금은 여전히 **다른 것**을 시험한다: 소비쿠폰은 관측창 안에 지급된 자산을 "결제·정산"하는 채널을 검증하지만, 상생지원금은 **관측창 안에 아무 돈도 없는 상태에서 가격 유인(기대효과)만으로 소비를 얼마나 늘리는가**를 검증한다. 정책지갑 자체가 없으므로 사후 정산 경로도 개입하지 않는다. → 자연어 채널이 상대가격 신호를 소비 행동으로 옮기는지가 이 백테스트의 차별적 가치다.

## 4. 정책 주입 설계 (우리 엔진 맞춤)

소비쿠폰과 다르게 — 정책지갑 사후 정산이 아니라 **선택 유인(대체효과)이 주 채널**이며, **관측창 안에서 정책지갑을 아예 만들지 않는다(현금 0).**

```
전기간 (OFF / A런):  정책 없음 → 각 에이전트 평소 소비 = baseline 관찰
주입 (day 0):        정책지갑 없음(캐시백 0). 전원에게 "유인 신호"만 제공
                      ⓐ 라벨: sangsaeng_eligible 백필 (제외리스트 = §0 규칙)
                      ⓑ Dawn 컨텍스트: 에이전트별 실제 숫자를 자연어로 고지
                         "네 2분기 월평균 카드소비 X원, 이번 달 누적 Y원,
                          3% 문턱 Z원. 적립업종(대형마트·백화점·대형온라인몰
                          제외 대부분)에서 더 쓰면 초과분 10%를 다음 달에
                          돌려받아(월 최대 10만원). 지금 W원만 더 쓰면 자격 시작 —
                          못 넘기면 이 혜택은 사라져."
                         (X=s_daily_wd 기반 월평균 앵커, Y=적립업종 한정 이번달
                          누적[신규 필드 — 기존 State.month_spent는 전체소비라
                          그대로 못 씀, §9 G2b], Z=X×1.03, W=max(0, Z−Y)=문턱까지
                          남은 거리[§4.5 ②], "못 넘기면 사라져"=손실 프레임[§4.5 ①])
                      ⓒ 정렬 가점·강제 넛지 없음(POLICY_POI_SORT_BOOST=0 유지) —

후기간 (ON / B런):    같은 시드로 유인 신호만 걸고 재실행 → 반응 관찰
```

### 4.1 왜 "정책지갑"도 "정렬 가점"도 안 쓰는가

- **정책지갑(캐시백 즉시 지급) 배제**: 실제로도 캐시백은 익월 지급이라 관측창 밖이다. 21일 커밋 이후엔 지갑이 총소비를 부풀리진 않지만(`settle_policy_spend_priority`는 개인부담을 사후 대체만 함), 지금 지갑을 만들면 검증 채널이 "가격 유인 반응"이 아니라 "지급 자산의 결제·정산"으로 바뀌어 §2의 차별점 전제가 깨진다. → 상생 정책 JSON에는 `decile_grants`/`income_grants`/`poi_restricted`(쿠폰 지갑 트리거)를 **넣지 않는다**(§9 G3).
- **정렬 가점(Stage2 적립매장 순위 부스트) 배제**: 이건 C1/D1이 검증하려는 답("적립업종 선택 증가")을 우리가 직접 손으로 심는 것이라 **순환논증**이다. 현 코드는 정렬 가점을 `POLICY_POI_SORT_BOOST` 환경변수로 노출하고 **기본값이 "0"**이다(`stage2_poi.py:273`, `run_simulation.py:307`). 본런은 이 기본값(0)을 그대로 유지한다 — `=1`은 별도 민감도 실험 전용이며 백테스트 본런에서는 절대 켜지 않는다.

### 4.2 무반응(null) 리스크 대응 — 프리플라이트 없이 단발 런에서

프리플라이트(소규모 탐침)를 생략하기로 했으므로, "반응 없으면 조건부로 보강한다"는 트리거 자체가 없다. 그래서 안전장치를 **본런 설계 자체에 사전 내장**한다. 단, "결과를 유리하게 만드는" 장치가 아니라 **"신호 전달력·통계적 검출력"만 높이는** 장치여야 순환논증을 피한다.

1. **구체 숫자 주입 (신호 전달력)**: 뭉뚱그린 정책 설명이 아니라 에이전트별 실제 2분기 월평균·이번달 누적·문턱 숫자를 Dawn 프롬프트에 직접 준다(§4 ⓑ). 무반응의 실제 흔한 원인은 "이해를 못 했다/못 봤다"이지 "이해했는데 무시했다"가 아니다 — 이걸 최소화한다. 이 숫자들은 정책이 정한 고정 파라미터(1.03배, 10%, 10만원)이지 우리가 결과 보고 조정하는 값이 아니다.
2. **관측창·표본 크기 (검출력)**: **전 1주(A런) + 후 1주(B런), 총 2주로 고정**(비용·일정상 확정, 더 이상 열린 결정 아님). 1주는 EXP-001(소비쿠폰)의 관측창 과소 교훈에 비춰 짧은 편이라, 표본을 `spending_level_wd`(소비 10분위) 균형표집으로 충분히 키워(§5.3, 2,000~3,000명) 검출력을 보완한다. 결과를 만드는 게 아니라 실제로 있는 효과를 "놓치지 않는" 조치.
3. **하지 않는 것**: 실제 10% 상대가격을 소비모델 수식에 직접 반영하는 방식(가격탄력성 내장)은 **채택하지 않는다** — 탄력성 파라미터 자체가 답을 내장할 위험이 있고, 검증할 트리거(프리플라이트 null 확인) 없이 넣으면 "왜 넣었는지"를 사후에 정당화하기 어렵다. 반응이 없다면 그것 자체가 유효한(부정적) 결과로 §8에 기록한다.

### 4.3 카테고리 매핑 + "제외 arm 부재"라는 구조적 현실

우리 POI는 **소상공인 물리매장 12 L1 분류**다(`categories.yaml`). 상생 적립/제외를 우리 카테고리에 얹으면:

**(1) KDI 8개 적립 업종 → 우리 L1(L2) — D1/D2 채점용 매핑**

| KDI 적립 업종 | 우리 L1 (L2 예시) |
|---|---|
| 가전·가구 | 쇼핑(가구, 가전·통신) |
| 학원 | 교육(학원, 교육지원, 기타교육) |
| 이·미용 | 미용(미용실·네일·피부관리 등 전체) |
| 여행·레저 | 여가(여행사·스포츠·유원지·오락·볼링·당구·노래방) + 기타(숙박) |
| 요식 | 식사 + 카페 + 디저트 + 주점(일반주점·호프) |
| 유통 | 마트 + 편의점 + 쇼핑 일반소매(의류·생활용품·화장품·문구 등) |
| 기타 | 건강(병원·약국·의원·치과) + 기타 서비스(주유소·세탁·수리·차량정비) |

**(2) 상생 제외 업종 → 우리 데이터: 실제 매핑 (mapping_upjong_to_sub.json·03_pois.py 실측)**

실제 원본 매핑(247개 업종코드)과 적재 코드를 직접 확인한 결과다. **핵심: POI 적재 시 원본 업종코드(`upjong_l3_cd`)를 저장하지 않고 `sub`만 남긴다**(`03_pois.py:82-95`). 그래서 제외업종이 물리적으로 존재해도 sub 레벨에서 적립업종과 병합돼 못 떼어내는 경우가 많다.

| 상생 제외 | 우리 데이터 실태 | 분리 가능? | 대조군 |
|---|---|---|---|
| **시계·귀금속(명품 proxy)** | G21701, **2,404개** 존재, sub로 바로 분리됨 | ✅ | **주력 제외 arm(확정, 아래 (3))** |
| 유흥주점 | I21101(2,269)+I21102(96), **주점>일반주점에 병합** | ❌ 업종코드 폐기 | 상호명 룰로 일부만·오염 |
| 사행(복권) | R10410(1,038), **여가>유원지·오락에 병합** | ❌ 업종코드 폐기 | 상호명 룰로 일부만·오염 |
| 대형마트·백화점·면세·대형전자 | 업종코드 자체가 매핑에 **없음**(소상공인 DB=대규모점포 미등록) | — | 재현 불가 |
| 대형종합 온라인몰·홈쇼핑 | 물리 POI 없음 | — | 재현 불가 |
| 신차구입 | 없음(자동차부품·차량정비는 적립) | — | 재현 불가 |
| 실외골프장 | 없음(골프**연습장** R10311은 적립) | — | 재현 불가 |

→ **구조적 현실: 우리 POI ≈ 전부 적립업종이다.** 대형 업태는 개수가 적은 게 아니라 **소스(소상공인시장진흥공단 상가 DB)에 대규모점포가 처음부터 미등록**이라 아예 없다. 유흥·사행은 물리적으로 있으나 적재 때 업종코드가 폐기돼 적립 버킷에 섞여 분리가 어렵고, 잡히는 것도 오염된 대조군(유흥 소비는 캐시백 메시지에 반응할 업종이 아님)이다. **유일하게 sub로 깨끗이 분리되는 제외 arm이 시계·귀금속(2,404)**이며, 이걸 상생 제외로 확정해 약한 C1(적립≫제외 부등식)을 되살린다(§6.1b).

**(3) 라벨 규칙 (`sangsaeng_eligible`, §9 G1)**: 상생 적립/제외는 POI의 `coupon_eligible`(소비쿠폰용)과 **다르다** — 상생 적립이 훨씬 넓다. `coupon_eligibility.py`의 상호명 룰을 재사용하되 상생 기준으로 조정한다:
- `_NAME_VICE`(유흥·사행) → **제외 유지**(상생도 제외). 단 상호명에 키워드가 박힌 일부만 잡히는 한계.
- `_NAME_EXCLUDE`의 대형마트/백화점/전자 브랜드 → **제외 유지**(있으면 뺌, 실제론 거의 없음). 단 **프랜차이즈 직영(스타벅스·올리브영·다이소)은 적립으로 되돌린다**(소비쿠폰만 뺐던 것, 상생은 적립).
- **시계·귀금속(`_SUB_EXCLUDE`) → 제외 유지, 단 상생에선 "환금성"이 아니라 "명품 proxy"로 재해석**. 동네 금은방을 명품매장으로 근사하는 오차가 있으나(§8), 유일한 깨끗한 제외 arm이라 감수하고 placebo로 쓴다. **이 근사 오차를 리포트에 명시**한다.
결과는 새 속성 `sangsaeng_eligible`로 별도 기록. **백필 결과는 시계·귀금속·유흥 상호명 극소수를 뺀 거의 전부가 True가 정상**(데이터 현실).

### 4.4 기대효과만으로 반응할까 — 이 백테스트의 근본 리스크와 대응

**현금을 관측창 안에 한 푼도 안 주고 자연어 신호만으로** 소비를 유도하는 설계라, 에이전트가 실제로 반응할지가 근본적으로 불확실하다. 실측 보고서와 대조했을 때 부호조차 안 맞는 결과가 나올 수 있다. 이 리스크를 없앨 수는 없고, **정직하게 다룬다**:

1. **애초에 이게 시험 대상이다**: "LLM 자연어 채널이 순수 가격 유인(기대효과)을 소비 행동으로 옮기는가"가 본 백테스트가 던지는 질문이다. 반응이 약하거나 없다면, 그건 백테스트의 버그가 아니라 **에이전트에 대한 유효한 발견**이다(§8-7). null도 결과다.
2. **크기는 절대 안 맞춘다**: 우리 관측창(전1주+후1주, 기대효과만) vs 보고서(2개월+캐시백 이월사용까지). 부호·방향·순위만 본다(§6). "서울 +14.57%"를 우리가 재현한다는 주장은 애초에 하지 않는다.
3. **신호 전달력만 최대화(순환논증 회피)**: 구체 숫자(2Q 월평균·이번달 누적·문턱)를 프롬프트에 직접 준다(§4.2). "이해 못 함"으로 인한 무반응만 줄이고, 반응의 크기·방향은 손대지 않는다. 이 신호 전달력을 더 높이는 3종 장치는 §4.5.

### 4.5 "텍스트만으로 인지될까" 대비 — 신호 전달 3종 장치

이 백테스트의 핵심 리스크는 **"돈은 안 주고 글로만 알려주는데, 에이전트가 그 뜻을 제대로 알아들을까"**다(§4.4). 정책 문구를 던져줘도 LLM이 "그래서 나한테 얼마 이득인데?"를 스스로 계산 못 하면, 반응이 없는 게 정책 무효 때문인지 그냥 못 알아들어서인지 구분이 안 된다. 그래서 **반응의 방향·크기는 절대 안 건드리고, "알아듣게만" 만드는** 장치 3개를 둔다. (전부 순환논증 회피 — 답을 심는 게 아니라 이해를 돕는 것뿐)

| 장치 | 무엇 | 어디에 들어가나 | 코드 변경 |
|---|---|---|---|
| **① 손실 프레이밍** | "3% 문턱을 못 넘기면 이 혜택을 놓친다"는 문장을 이득 문구와 나란히 | 정책 JSON `description`(공통 문구, 개인 숫자 아님) | 없음 — 데이터만(§9 G3) |
| **② 문턱 근접도 실시간 고지** | "이번 달에 X원만 더 쓰면 자격 생김" — 남은 거리를 매일 갱신 | Dawn 프롬프트, **cashback 분기 안에만**(§9 G2) | 작음 — cashback 분기 안 |
| **③ 반응 로그** | 에이전트가 "이 소비는 정책 때문"이라고 스스로 꼽았는지 집계 | 이미 저장됨(Stage1 `trigger="policy"`), 채점기가 읽기만 | 없음 — 채점기(§9 G5) |

**②가 이 3종의 핵심이자 유일한 능동 장치다. 성격을 정확히 이해할 것:**
- **"매 구매마다"가 아니라 "하루 한 번"** 본다. 아침에 그날 계획을 세울 때(Dawn→Stage1) 프롬프트에 한 번 실린다(`process_one` = 에이전트1명×하루, `build_dawn_context`가 하루 1회). 그날 안에 여러 번 사도 그 문구를 다시 보진 않는다.
- **에이전트마다 숫자가 다르다.** 각자 자기 2분기 월평균·자기 `sangsaeng_month_spent`(이번달 적립업종 누적, §9 G2b)로 계산하므로 "X원 남음"의 X가 사람마다 다르다.
- **날마다 줄어든다.** 소비가 쌓이면서 남은 거리가 매일 갱신돼, 문턱에 가까운 사람일수록 "조금만 더 쓰면 된다"를 본다(목표 근접 효과).
- **다른 정책엔 안 들어간다.** ②는 오직 `cashback` 타입 분기 안에서만 조립된다. 소비쿠폰(grant)·보조금(subsidy) 등 다른 정책을 돌릴 땐 각자 분기로 가므로 이 문구가 절대 섞이지 않는다. "정책마다 넣는 게 다르다"는 건 버그가 아니라 타입별 분기 구조가 원래 그러라고 있는 것이다(§9 G2).
4. **검증 항목을 실현 가능한 것으로 좁힌다**(§6): **C2(총소비 방향)를 축**으로, **C1(적립 ≫ 제외[시계·귀금속] 부등식)을 C2 해석 보증 보조 게이트**로 둔다(§6.1b). D1(업종 순위)·D2(소득 재배분)는 나오면 보고하는 탐색적 관찰이다.

## 5. 검증 방법 — 보고서 DiD를 재현하는 게 아니라 정답으로 대조

### 5.1 대조군 설계: B−A가 보고서 DiD보다 깨끗하다

보고서는 같은 집을 두 번 못 돌리니 **받은 집(수급) − 못 받은 집(미수급)**을 비교한다. 하지만 수급/미수급은 원래 다른 사람들이라 자기선택 편향이 생기고, 보고서는 DDD·IV로 힘들게 보정한다.

**우리는 이럴 필요가 없다.** 시뮬이라 같은 에이전트를 두 번 돌릴 수 있다:
- **A런** = 정책 끔 / **B런** = 정책 켬 (같은 시드, 같은 에이전트)
- **B − A = 정책효과 + 잔여 표본노이즈** ← 이게 우리의 "DiD"(단, 아래 단서 참고)

같은 시드로 OFF/ON을 돌리는 근거는 엔진에 이미 있다: `dawn_context.py:POLICY_CYPHER`가 활성 정책을 자동 픽업하므로, 정책 노드 존재 여부만으로 반사실(OFF/ON)이 성립한다. 대조군이 "못 받은 다른 집"이 아니라 **"정책 없는 평행우주의 같은 집(A런)"**이라 자기선택 편향은 없다.

> ⚠️ **주의**: "같은 에이전트를 같은 시드로 두 번 돌리면 차이(B−A)는 오직 정책 때문"이라고 생각하기 쉽지만, 완전히는 아니다. LLM은 같은 질문에도 매번 살짝 다르게 답할 수 있다(코드 확인: `--seed`는 표본을 뽑을 때만 쓰이고, 정작 LLM 호출에는 이 시드가 전달되지 않는다). 그래서 시드가 같아도 A런과 B런 사이에 정책과 무관한 우연한 차이가 섞인다 — 자기선택 편향은 없지만 이 "우연"은 남는다. "B−A가 0보다 크다"만 보면 이 우연을 정책 효과로 착각할 수 있다. 걸러내는 방법은 §5.4.

| | 보고서 | 우리 |
|---|---|---|
| 대조군 | 미수급가구(다른 집) | A런(같은 에이전트, 정책 없음) |
| 방법 | DiD / DDD / IV | 같은 시드 **B − A** |
| 편향 | 자기선택 있음 → 보정 필요 | 없음(같은 사람) |
| 결과물 | 계수 = 정답 | B − A = 우리 예측 |

→ **수급/미수급으로 나눌 필요 없음.** 우리 정책 신호는 전원에게 동일하게 노출되므로 자연적 미수급군이 없다. 우리는 보고서의 *방법*을 재현하는 게 아니라, 보고서가 그 방법으로 *이미 낸 정답*을 우리 B−A와 대조한다.

### 5.2 3층 구조 (메모리 `backtest-policy-cases` 승계)

- **Layer 1 (정답 벡터)**: KDI PDF 표에서 직접 추출 = §3. 원자료(KCB·신한) 미보유 → 우리가 DiD를 재계산하지 않는다. PDF 표 자체가 정답지.
- **Layer 2 (시뮬 예측 벡터)**: 같은 시드 A(OFF)/B(ON) 2런 → B−A.
- **Layer 3 (채점)**: Layer2를 §6 벡터로 산출 → Layer1과 대조 + 내적 타당성(§7).

### 5.3 시간축·규모

baseline(2Q 월평균)은 **데이터 앵커(`s_daily_wd`)라 시뮬 불필요** → A/B런은 처치기간만 돌리면 된다. 관측창은 **전 1주+후 1주(총 2주)로 고정**(§4.2). 표본은 `spending_level_wd` 10분위 균형표집(비용 대비 검출력 확보를 위해 2,000~3,000명 선에서 시작, 필요시 확대).

**승수(165%, 표4-11)는 채점하지 않는다** — 우리 관측창(전1주+후1주)과 보고서 시간축(2개월+캐시백 이월사용까지 포함)이 달라 절대 크기 대조가 무의미하다. §3에 참고로만 남긴다.

### 5.4 노이즈와 진짜 효과를 가르는 법 (신규)

재실행할 예산은 없지만, **표본 자체가 이미 여러 번의 반복이다.** 2,000~3,000명의 에이전트 각각에서 (B−A) 값이 하나씩 나온다. 정책 효과가 진짜 0이라면 이 수천 개의 (B−A)는 우연히 양수·음수가 섞여 평균이 대략 0 근처여야 하고, 진짜 효과가 있다면 평균이 0에서 뚜렷하게 벗어나야 한다. 즉 **"한 명의 B−A가 양수냐"가 아니라 "수천 명의 평균이 우연이라기엔 너무 일관되게 양수냐"를 본다** — 통계학에서 쓰는 쌍체(paired) 검정이다.

- **하는 일**: 에이전트별 (B−A) 값을 전부 모아 평균이 0보다 유의하게 큰지 검정한다(쌍체 t검정 또는 부호검정, p<0.05).
- **바뀌는 것(§6.1 C2)**: "합계가 양수면 통과"가 아니라 **"평균이 통계적으로 유의하게 양수여야 통과"**로 기준을 올린다.
- **한계**: 이 방법은 "사람마다 다른" 노이즈는 걸러내지만, "한 사람 안에서 그날그날 LLM이 살짝 다르게 답하는" 노이즈까지 완전히 없애진 못한다. 더 확실히 하려면 LLM 응답의 무작위성을 줄이는 보강도 있다(§9 G6, 필수 아님) — 표본이 2,000~3,000명으로 충분히 크면 이 검정만으로도 웬만한 효과는 잡아낸다.

## 6. 무엇을 예측·검증하나

**쉽게 말해, 우리가 실제로 보는 건 세 가지다.**

1. **전체 소비가 느는가(C2, 필수)** — 우리 POI가 사실상 다 적립업종(§4.3)이라, 이건 곧 "적립업종 소비가 느는가"와 같은 말이다.
2. **적립이 제외(시계·귀금속)보다 훨씬 더 느는가(C1, C2 해석 보증)** — 적립만 쏠리고 제외는 잠잠해야 "가격 유인 때문(대체효과)"이라 말할 수 있다. 제외까지 같이 확 늘면 "그냥 메시지 봐서 다 늘린 것".
3. **적립 안에서 업종별로 차등 있게 느는가(D1, 창발이면 보너스)** — 예를 들어 가전·가구가 학원보다 더 크게 느는지.

**과거엔 "제외 대조군이 없어서 C1 불가"였는데, 시계·귀금속(2,404개)을 제외 proxy로 확정(§4.3)하면서 약한 C1이 되살아났다.** 대형마트·백화점 같은 대형 업태는 소상공인 소스에 아예 없어 못 넣지만, 시계·귀금속 하나로 "적립 쏠림 ≫ 제외"라는 핵심 부등식은 검증할 수 있다. 텍스트로만 정책을 알려주고 돈은 안 준다는 설계 자체는 그대로다.

시뮬 예측 = 같은 시드 **B(ON) − A(OFF)**. 비교는 **숫자 크기가 아니라 부호·순위·방향**만 본다(크기 대조 안 함, §4.4-2).

### 6.1 필수(축) — 이거 하나면 1차 성공 판정 가능

| # | 검증 | 정답 | 판정 기준 |
|---|---|---|---|
| **C2** | **총소비가 정책 ON에서 증가하는가**(부호 +) | 가장 근접 앵커 **1인 가구 +11.16%**(표4-5, 우리=개인), 참고 서울 열 +14.57%(표4-6)·전국 +11.25%(표4-4) | 에이전트별 쌍체차 `d_i = B_i − A_i`의 평균이 **0보다 크고 통계적으로 유의**(단측 쌍체 t검정 또는 부호검정, p<0.05, §5.4). 단순 합계 > 0만으로는 통과 아님 — LLM 샘플링 노이즈(§5.1 단서)를 신호와 구분하기 위함. 크기는 대조 안 함(시간축·기대효과 한정) |

우리 POI가 사실상 전부 적립이므로 상생 효과는 시뮬에서 **적립업종 소비 순증 = 총소비 순증**으로 환원된다(§4.3). 따라서 C2가 이 백테스트의 실질 헤드라인이다. §5.4의 검정을 통과하지 못하면(방향은 +이나 유의하지 않음 포함) "무반응"이 아니라 **"노이즈와 구분 불가"**로 별도 기록한다 — §8-7의 무반응과는 다른 결론이므로 리포트에서 혼동하지 않는다.

### 6.1b 보조 게이트 — C2 해석 보증(적립 ≫ 제외)

| # | 검증 | 정답 | 판정 기준 |
|---|---|---|---|
| **C1** | 적립 쏠림이 제외(시계·귀금속)보다 뚜렷이 큰가 | 표4-7: 적립 총결제 **+20.82%** vs 제외 총결제 **+2.85~5.35%** (적립이 제외의 **약 4~7배**). 제외는 **0~소폭 +가 정답**(감소 아님, 소득효과 누출) | 적립 B−A(에이전트별 쌍체 평균)가 제외(시계·귀금속) B−A보다 **유의하게 큼**. **제외가 소폭 +인 것은 빨간불 아님**(정답 재현) — 제외가 적립과 **비슷한 크기로 같이 튈 때만** 경보(=일반 수요효과 의심 → C2 신뢰도↓). 단독 실패 판정엔 쓰지 않음(1주 창·재량재라 변동 큼) |

C1은 독립 헤드라인이 아니라 **C2가 "가격 유인 때문"이라는 해석을 지켜주는 보조 게이트**다. 시계·귀금속은 재량 내구재라 1주 창에서 노이즈가 크므로, "제외 = 정확히 0"을 요구하지 않고 **"적립 쏠림 ≫ 제외"라는 부등식**만 본다. `trigger="policy"` 반응 로그(§4.5 ③)와 함께 C2 해석의 이중 안전장치가 된다.

### 6.2 보조(창발이면 보고, 게이트 안 함)

| # | 검증 | 정답 | 판정 기준 |
|---|---|---|---|
| **D1** | 업종 순위 | 표4-7 10월열 | 카테고리별 B−A를 정렬 → 가전·가구(내구재)가 상위군, 학원·이·미용이 하위군인지. 상위군/하위군 구분만(1·2위 정밀 일치 불필요). **창발이면 강한 증거**, 단 1주 창은 짧아 내구재 거래가 특히 희소해 노이즈 큼(표본을 키워 보완, §5.3) |

### 6.3 탐색적으로만 (게이트 아님)

- **D2(소득별 재배분)**: 탐색적으로만. `spending_level_wd`(소비 10분위)로 소득 차등 반응을 확인. 정답 방향(표4-7·그림4-3~14):
  - 고소득 → **가전·가구·학원** 집중
  - 저소득 → **요식·유통** 집중
  - 중간소득(3·4분위) → **여행·레저**
  - **이·미용 → 소득 무관**(고른 반응)
  이론상 판별력 최상이지만 소득 차등 반응이 기대효과만으로 창발하기는 가장 어렵다. 나오면 보너스, null이어도 실패로 판정하지 않는다.

**핵심**: 1차 성공 = **C2 통과**(총소비 방향 + 이며 §5.4 쌍체검정 유의) **+ C1 부등식 확인**(적립 쏠림 ≫ 제외, 또는 최소한 제외가 적립만큼 튀지 않음). C2만 통과하고 C1 경보가 뜨면(제외도 같이 확 늚) "가격 유인 재현"이 아니라 "일반 반응성"으로 신뢰도를 낮춰 기록한다. D1이 창발로 함께 나오면 강한 증거, D2는 탐색적 관찰. 무반응(§4.4·§8-7)도, "방향은 +이나 노이즈와 구분 불가"(§5.4)도 각각 유효한 결과로 구분해 기록한다.

## 7. 내적 타당성

- **평행추세**: 처치 직전 pre-period(A런 관측 구간)에서 카테고리별 소비 분포가 안정적인지 확인.
- **Placebo**: 실적**제외**업종(주력=시계·귀금속 2,404, §4.3) 효과가 적립보다 뚜렷이 작은지(C1, §6.1b). 정답은 "0~소폭 +"(감소 아님)이므로 제외가 미세하게 +인 것은 placebo 통과. 제외가 적립과 비슷하게 튀면 실패 신호. 유흥·사행 상호명 매칭분은 오염된 대조군이라 참고로만.
- **중립성 게이트**: `scripts/sim/policy_preflight.py`로 주입 전 점검. 이 스크립트는 docstring에 "행동 파라미터(소비성향 클램프·가격 탄력·정렬 가점 등)는 절대 건드리지 않는다"를 명문화하고 입력 표현·주입 배선만 점검한다. 상생 JSON에 정렬가점·지갑 필드가 없음을 코드 리뷰로 재확인하고, `check_db_wiring`으로 `applied_to`>0(정책 노출 배선)을 실측 게이트한다.

## 8. 한계 (반드시 리포트에 명시)

1. **서울 전용 정밀 정답은 C2(표4-6 서울 열) 하나뿐** — 업종(D1)·소득(D2)은 전국 풀링 수치라 순위·방향만 대조 가능, 크기 대조 불가.
2. **시간지평 불일치**: 시뮬 전1주+후1주 vs 보고서 2개월+이월사용 → 절대 크기(승수 165%, DDD 정밀치) 검증은 하지 않음(§5.3).
3. **제외 arm 대폭 축소(가장 큰 구조적 한계)**: 대형 업태(대형마트·백화점·면세·대형전자·온라인몰·신차)는 소상공인 소스가 대규모점포를 미등록해 **아예 없다**(개수 부족이 아니라 소스 부재, §4.3). 유흥·사행은 적재 시 업종코드 폐기로 적립 버킷에 병합돼 분리가 어렵고 오염된 대조군이다. → 제외 arm은 **시계·귀금속(2,404) 하나로 축소**되며 C1은 "적립 ≫ 제외" 부등식(§6.1b)으로만 약하게 검증한다. 상대가격의 업종 간 전환 크기는 검증 불가.
3b. **시계·귀금속 = 명품 근사(placebo 오차)**: 상생 제외의 "명품전문매장"에 우리는 명품관이 없어 동네 금은방(시계·귀금속)을 제외 proxy로 근사한다. 동네 금은방은 엄밀히는 명품매장이 아니므로 이 근사는 오차를 가지며, C1은 이 오차를 감수한 **약한** placebo다.
4. **공간(자치구별)·재정승수(크기)는 이 케이스 몫이 아님** — 다른 백테스트 케이스(소비쿠폰/상권분석)가 담당.
5. **페르소나 시점(2023~24) vs 정답 시점(2021)** 격차 존재.
6. **가구원수 속성 부재**: 표4-5의 가구원수별 효과(4인가구 최대) 검증은 스코프 밖. 단 표4-5의 **1인 가구 열(+11.16%)은 우리 에이전트=개인의 C2 근접 앵커**로 활용한다(§3·§6.1).
7. **무반응 리스크(§4.2)**: 프리플라이트를 생략한 단발 런이므로, D1/D2가 null로 나올 가능성을 배제할 수 없다. null 자체도 "현재 자연어 채널로는 상대가격 유인이 전달되지 않는다"는 유효한 결과로 기록하고, 사후에 사후분석(신호가 실제로 프롬프트에 도달했는지 로그 확인, `timing_metrics.py`의 정책 블록 렌더 확인 포함)으로 원인을 진단한다 — 이 경우에도 사후에 정렬 가점을 소급 적용해 "성공"으로 재포장하지 않는다.
8. **카드=전체지출 프록시**: 에이전트 스키마에 결제수단 필드가 없어 `actual_spent`를 카드결제로 근사(현금 구분 불가).
9. **LLM 샘플링 비결정성(§5.1 단서·§5.4)**: `--seed`는 표본추출에만 적용되고 Stage1/Stage2 LLM 호출은 seed 미전달의 확률적 디코딩이다. 같은 시드 B−A라도 순수 정책효과가 아니라 잔여 노이즈가 섞여 있으며, §5.4 쌍체검정으로 완화하되 완전히 제거하지는 못한다(에이전트 내 변동성은 §9 G6 보강 전까지 잔존).

G2 작업 시 이 라벨도 타입에 맞게 고친다.

  - **D1/D2**: 카테고리별·소득분위별 B−A 정렬(탐색적).

1. **M1 업종 맵**: `sangsaeng_eligibility.py` + `industry_map.json` + `sangsaeng_eligible` 백필 → 자체 테스트(코드 내 케이스, `coupon_eligibility.py` 자체테스트 패턴 승계).

**성공 기준**: **C2(총소비 방향 + 그리고 §5.4 쌍체검정 p<0.05) 통과 + C1 부등식 확인(적립 쏠림 ≫ 제외, 최소한 제외가 적립만큼 안 튐) = 1차 성공.** 방향은 +이나 유의하지 않으면 "노이즈와 구분 불가"로 별도 기록(§6.1).
