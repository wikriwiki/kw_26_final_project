# P012 A100 진단 런 10월 16일 체크포인트

2021-10-01~28 진단 런은 P012가 10월 15일 시작하는 내부 점검이다. KDI의 10월 전체 월별 정책효과와 직접 비교하지 않는다. 이 문서는 완료된 10월 16일 500명에 대한 **회계·관측성 관문**이다.

근거 사본은 `output/recovery_20260926/p012_completed_oct01_15.tar.gz`와 `p012_completed_oct16.tar.gz`다. 후자의 SHA256은 `6597ed918be9dd3cf8dcebdeb31e95b431aed765db063cf5671897c532fb59c4`이며 서버·로컬이 일치한다. `scripts/report/audit_p012_checkpoint_accounting.py`의 세부 결과는 `output/recovery_20260926/p012_oct16_accounting_audit.json`, 그래프의 적립 적격 판정 대조는 `p012_oct16_eligible_audit.json`에 보존했다. 둘 다 읽기 전용 추출이며 Neo4j 복원 덤프가 아니다.

| 관문 | 관측 |
|---|---:|
| 10월 16일 정상 시민·State | 각각 500/500 |

관측 가능한 POI 매출의 대부분이 적립 적격이지만, 시민당 평균 **그래프 밖 지출 100,170원/일**이 별도 합계로만 저장된다. 이는 시민당 POI 매출 33,663원/일보다 크며 상품·가맹점·적격/제외 업종으로 쪼개지지 않는다. 따라서 KDI의 제외업종 소비 효과(P012-2)를 현재 원장의 `POI.sangsaeng_eligible=false` 거래만으로 평가하면 분모가 너무 좁다. 모델의 그래프 밖 지출을 임의로 모두 제외업종이라고 간주해서도 안 된다. 업종 분류가 붙은 거래 원장이 필요하다.

10월 16일 시민당 평균 총지출은 133,834원, 기존 `anchor` 보충액은 86,897원이어서 잔액은 평균 약 46,936원 줄었다. 이는 지갑 회계 오류가 아니라 `anchor`가 당일 소비 의향·가격에 의존하며 총지출과도 같지 않은 설계 문제다. 10월 1~14일 정책 전 7,000개 시민-일 중 2건은 Stage1 JSON 파싱 실패였고, 나머지 정상 행에서 정책 노출·정책 결제·수령은 0이었다. 이 중립 기간으로만 개인별 보충액 맵을 고정해 다음 **별도** 정책/무정책 팔에 동일하게 쓰는 수정안을 `P012_FULL_MONTH_PREREG_20260926.md`에 기록했다. 이 맵은 실제 소득 자료가 아니며 외부 지출 규모를 보정했다는 뜻도 아니다.

현재 A100 서버의 옛 실행기는 10월 3일·10일 Stage1 파싱 실패를 각각 한 건씩 남기고 다음 날로 진행해, 첫 15일 State는 7,498/7,500행이다. 따라서 이 런 전체를 ‘500명 × 28일 완전 관측’으로 표기하지 않는다. 새 로컬 실행기는 실패한 날을 넘기지 않고 재개 후 원시 시도 로그를 별도 보존하며, 소비자별 최종 정상 결과 하나씩만 정규 metrics 파일에 원자적으로 게시하도록 수정했다. 현재 실행 중인 서버에는 이 코드를 덮어쓰지 않았다.
