## 등록한 기준에 대면

```
"이벤트 수는 안 늘어야 한다"          통과 — 오히려 -5.6%, 사실상 불변(p=0.864)
```

**기계적 증가는 없었다.** 실제 런의 모양(수는 그대로, 금액이 는다)과 어긋나지
않는다. 감쇠 두 줄이 제 일을 한 것으로 보인다.

## 그러나 유의하지 않다 — 그리고 기준을 사후에 낮추지 않는다

내구재가 **6:1** 로 갈렸지만 p=0.125 다. 관례선 0.05 를 못 넘는다.

**같은 잣대를 앞서 이미 썼다** — 후보 case_trend 를 복제 p=0.094 에서 기각했다
(`../case_trend/replicate_result.md`). 거기서 0.05 를 지켰으므로 여기서 0.125 를
통과시키면 그건 잣대가 아니라 편의다. **통과라고 적지 않는다.**

## 왜 유의가 안 나오는지는 진단된다 — 무효가 아니라 **무전력**이다

```
동점 31 / 38 (82%)
```

내구재는 드문 사건이다(평균 0.16~0.29건/일). 대부분의 쌍이 **0 대 0** 이라
부호검정에 들어가는 실질 표본이 **7** 뿐이다. 효과가 없어서가 아니라
**셀 것이 없어서** 안 나온다.

```
지금      불일치 쌍 7 (6:1)        p=0.125
두 배면   불일치 쌍 14 (12:2 가정)  p≈0.013
```

## 그래서 복제한다 — 판정은 복제가 한다

> **[정정 2026-09-24 10:10 — 돌리기 전]** "쌍 약 78" 은 틀렸다. 실제로 쓸 수
> 있는 칸은 60 이고 고유 쌍은 **48** 이다. 동점률 82% 를 그대로 대면 불일치 쌍이
> **약 9** 뿐이라, 0.05 를 넘으려면 8:1 같은 거의 완벽한 쪽수가 필요하다.
> **그 설계는 사실상 무의미하다.** 그래서 결과를 보기 전에 설계를 고친다.

칸이 모자라므로 **시드로 채운다.** 같은 칸을 새 시드 셋으로 돌리면 각각 독립된
쌍이 된다(case_trend 복제에서 쓴 방식과 같다).

```
칸 60 x 시드 3 = 쌍 약 180 · 호출 360
동점률 82% 가정 -> 불일치 쌍 약 32 -> 6:1 비율이 유지되면 p < 0.001
                                    5:3 정도로 흐려져도 판정은 가능하다
```

새 시드(7717·8821·9931)로 돌리고 **이번 38쌍과 합치지 않는다.** 합치면 두 번
세는 것이다.

```
등록하는 가설   내구재 이벤트가 v5own 에서 더 많은 쌍이 더 많다
등록하는 판정   **새 표본만으로 양측 p < 0.05**
```

방향은 이번에 고정됐지만 **단측으로 바꾸지 않는다** — 1차에서 방향을 보고
단측으로 옮기면 그것도 두 번 세는 것이다.
