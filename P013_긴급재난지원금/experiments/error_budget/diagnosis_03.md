# 우리 에이전트에게는 제외업종이 없다 — 원장을 열어 본 결과

**2026-09-24 04:20** · p013_ruler arm A 라이브 그래프 · 계획 2,897 · POI 지출행 12,909

diagnosis_02 이 세 층이 모두 상수라고 했다. 그 중 **②가 무엇을 지우는지**를
원장에서 직접 세어 보니, 한 대목이 틀렸고 나머지가 훨씬 또렷해졌다.

## 먼저 정정한다

diagnosis_02 은 "파이가 고정이므로 적립업종이 오르는 유일한 길은 제외업종에서
빼 오는 것" 이라고 썼다. **틀렸다.** 원장의 실제 비율은 이렇다.

```
적격(sangsaeng_eligible=true)   92,408,471원   12,825행   98.65%
제외 전체                        1,261,816원        84행    1.35%
   excluded_other                1,086,613원      68행
   excluded_vice                   156,661원      11행
   excluded_nonconsumption          18,542원       5행
```

**둘은 파이의 두 쪽이 아니다.** 98.65 대 1.35 다. 제로섬으로 묶을 수 없다.

## 그러면 제외업종은 어디로 갔는가

정답지가 말하는 제외업종은 **백화점·대형마트·온라인쇼핑**이다. 우리 그래프에서
그것을 세면:

```
백화점·대형마트·면세 POI      337 개 / 전체 543,924 개 = 0.06%
온라인 채널                    POI 로 존재하지 않는다
```

그리고 ②가 하는 일이 바로 그 뭉치를 지우는 것이다.

```python
_off = 1.0 - ELIGIBLE_SHARE_SEOUL      # 0.7465
online_planned = personal_total * _off  # 원장에 들어오기 전에 걷어 낸다
```

**정답지가 재라고 한 바로 그 뭉치를, 우리는 측정 전에 통째로 삭제한다.**
그리고 빠져나간 1.35% 잔여물(84행)을 "제외업종" 이라 부르며 잰다.
그것이 P012-2 의 관측 23명이고, −13.90% 대 실측 +2.85% 의 정체다.
**표본이 작은 것이 아니라 다른 것을 재고 있었다.**

## 적립업종 쪽도 같은 이유로 막힌다

우리 원장은 이미 98.65%가 적격이다. 적립업종이 커지려면 **원장 자체가**
커져야 하는데, 원장 크기는 `총액 x 0.2535` 이고 총액은 `spend_today(p) x basket`
이며 `p` 는 사실상 상수다(고유값 19개 · 0.68 이 54% · 표준편차 0.045).

```
정답지의 기전        제외업종에서 적립업종으로 소비를 옮긴다
우리 모델의 상태     제외업종이 선택지에 없다 · 경계는 상수 0.2535
결과                 옮길 곳이 없으므로 기전이 작동할 자리가 없다
```

**이것이 오차 46.27%p 중 P012 두 지표 35.67%p(77%)의 원인이다.**
프롬프트 문장으로 닫히는 자리가 아니다.
