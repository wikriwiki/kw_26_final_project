# DS-6 은 **백필 누락이 아니라 자료 부재**다

**2026-09-25 07:10** · 채점표에 "그래프에 hub_type 0건" 으로만 적혀 있어 백필을
안 돌린 것처럼 읽힌다. 아니다. **가진 자료로는 못 만든다.**

---

## 정답지가 재는 것

```
DS-6   관광특구 감소폭 > 발달상권 감소폭   (실측 −8.7% vs −4.4%)
```

두 분류가 다 필요하다. 그 분류는 **서울시 상권분석서비스의 `상권영역`**
데이터셋에 있는 `상권_구분_코드` 다.

```
A 골목상권 · D 발달상권 · R 전통시장 · U 관광특구
```

## 우리가 가진 것 — 닮았지만 다르다

```
data/raw/행정동별 상권발달 개별지수.csv
   "일자","행정동코드","매출지수","인프라지수","가맹점지수","인구지수","금융지수"
   -> 발달 **정도**의 연속 지수다. 발달상권/관광특구 **분류**가 아니다

data/neo4j_load/pois/소상공인시장진흥공단_상가(상권)정보_서울_202603.csv
   -> 상가 단위. 상권 구분 칼럼이 없다

그래프의 POI

      "장소에 상권 유형 태그가 없다. 동 코드만 있다")
```

## 대체물을 만들면 안 되는 이유

지수로 "상위 N개 동 = 발달상권" 을 만들 수는 있다. **그러면 자를 바꾸는 것이다.**
정답지는 서울시가 지정한 구역을 쟀고 우리는 우리가 만든 분류를 재게 된다. 두 수는
같은 이름을 갖지만 같은 것이 아니다 — `project_ruler_moves_are_not_progress`.

관광특구는 다르다. 서울 7곳(명동·남대문·북창 / 이태원 / 동대문패션타운 /
종로·청계 / 잠실 / 강남마이스 / 홍대문화예술)은 **고시된 목록**이라 동으로 옮겨
적는 것이 추정이 아니다. 그러나 **발달상권 쪽이 없으면 순위 비교가 성립하지 않는다.**

## 그러므로

```
DS-6 을 내려면   서울시 상권분석서비스 `상권영역` (상권_구분_코드 포함) 을 받아
                 POI 에 공간조인으로 붙인다. **자료를 구하는 일이지 코드 일이 아니다**
그전까지        "못 잼" 으로 세고 이 문서를 가리킨다. 빼지 않는다 —
                 빼면 못 내고 있다는 사실이 사라진다
```

같은 성격의 것이 하나 더 있다: **P012-2** 도 코드가 아니라 판의 문제다
(`p012_2_why_unproducible.md`). 둘을 구분해 둔다 — P012-2 는 자료가 있는데 판에
안 올라와 있고, DS-6 은 자료 자체가 없다.
