# 실험별 전체 검증지표 보고

`output/report/convergence.html`은 과거 채점표의 대표 런을 골라 만든 정적 화면이다. 새 실험의 후보 점수나 실측 효과 검증으로 사용하지 않는다. 새 보고서는 **실험 직후 보존한 `score_policy.py --json-out` 파일**에서 만든다. 채점기는 JSON 옆에 `<이름>.comparison.html`과 `<이름>.comparison.json`을 자동 생성한다. 기존 실행 중인 런이나 그래프를 변경하지 않는다.

여러 정책을 같은 실험 묶음에서 평가했으면 각 정책 채점 파일을 먼저 독립적으로 저장한 다음 한 장으로 묶는다.

```bash
python scripts/report/build_experiment_comparison.py \
  --experiment frozen_candidate_vXX \
  --score output/frozen_candidate_vXX/score_p010.json \
  --score output/frozen_candidate_vXX/score_p012.json \
  --out output/frozen_candidate_vXX/policy_comparison.html
```

이 명령은 HTML과 같은 이름의 JSON도 저장한다. 입력 채점 파일이 같은 정책에 두 개면 중단한다. 서로 다른 프롬프트 후보를 하나의 실험으로 합치지 말고 후보마다 별도 보고서를 만든다. 채점표와 입력 파일의 SHA256, 사용처 적격 정책 파일·채점기 지문을 JSON에 남겨 재현과 검토에 쓴다. 과거 채점 파일은 지문이 없거나 지표 정의가 바뀔 수 있어 그 상태를 그대로 표시한다.

현재 채점표에는 정책·위약 10개에 등록 지표 **38개**가 있다. 보고서는 38개 전부를 행으로 내며, 해당 실험에 정책이 없으면 `미실행`, 정책은 있지만 지표값이 없으면 `관측부족`/`결과 누락`으로 적는다. `expect=info` 두 지표도 `참고 지표`로 남긴다. 정책 파일은 있지만 등록 지표가 없는 P008·P011도 별도 목록에 표시한다. 둘을 최적화 대상에 넣으려면 **실험 전에** 검증지표·관측창·실측 출처와 추정량·채점 구현을 등록해야 한다. 목록에 없는 지표를 결과를 보고 사후 추가해 후보 선택에 쓰지 않는다.

실측과 시뮬 값을 나란히 보여 주는 것과 **차이를 계산하는 것**은 다르다. 차이는 `empirical_audit.comparison=matched_estimand`, 원문 출처, 양쪽 추정량·기간·대상·분모·단위 설명, 수치, 해당 채점 파일의 정확한 `simulation_off`/`simulation_on` 창, 채점표 지문, 측정 완결성까지 맞을 때만 나온다. 방향도 `matched_direction` 또는 `matched_estimand`의 원문 대응 감사와 같은 실험 창이 있을 때에만 ‘외부 방향’으로 판정한다. 원문과 비교 대상이 다르면 두 값을 각각 표시하고 차이와 같은 축의 실측점은 비운다. `hit`은 내부 사전등록 판정이며 외부 실측 효과의 방향·크기 적중으로 승격하지 않는다. 그래프의 수평축은 **지표마다** 범위를 잡으므로 다른 행의 막대 길이를 서로 비교하지 않는다.

프롬프트 선택은 모든 등록 지표의 **관측·측정·정합 상태**를 먼저 나란히 검토한다. 값이 없거나 측정 관문에 실패한 지표를 0점이나 적중으로 채우지 않는다. 직접 비교 가능한 지표에 한해 실측 효과의 방향과 대략적 크기를 평가하고, 외부 추정량이 없는 지표는 기전·위약·내부 안정성으로 따로 본다. 후보 비교는 동일 시민·환경·시드·정책 입력·관측창·채점 코드와 Stage2 품질 관문을 갖춘 별도 사전등록 쌍체 실험이어야 한다. 보고서는 이를 자동으로 입증하지 않으며, 하나의 `label`이나 채점 JSON만으로 후보 우열을 선언하지 않는다. 실측 수치·방향·보고서 차이값은 공통 프롬프트와 정책 입력에 넣지 않는다.

현재 과거 결과의 **직접 차감 가능한 지표는 0개**다. 이는 보고 기능이 빈 것이 아니라 원문 추정량과 시뮬 추정량이 아직 일치하지 않기 때문이다. 원문 정의와 측정 파이프라인을 맞춘 뒤 지표별 감사를 사전등록해야 실제 방향·크기 최적화에 쓸 수 있다. Neo4j 복원 덤프를 위한 서비스 중단·재시작과 그래프 초기화는 별도 사용자 승인이 오기 전에는 하지 않는다. P015 홀드아웃은 재실행하지 않는다.
