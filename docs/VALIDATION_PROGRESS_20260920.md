# 범용 프롬프트 검증 진행 기록

## 목적과 해석

정책 사실은 별도 입력으로 제공한다. 범용 지시문에는 특정 정책에서 소비를 늘리거나 줄이라는
지시, 실측 정책 효과, 효과를 맞추는 계수를 넣지 않는다. 개인의 필요·자금·시간·사용처에 따른
선택을 생성하고, 실제 on/off 거래 차이를 사후에 측정한다. 형식 통과율은 정책 효과 검증이 아니다.
P010 원본은 불변이며 P015는 재실험하지 않았다.

## 완료한 개발 실험

어느 후보도 확정하지 않았다. 개발에 사용한 12명과 네 정책 사례는 새로운 외부 검증 자료가 아니다.

## v7 추론 설정 비교

기존 실험은 EXAONE-4.5-33B-AWQ에서 `enable_thinking=false`를 사용했다.
기존 SGLang 프로세스에는 reasoning parser 설정이 없었다.
[EXAONE 공식 실행 예시](https://github.com/LG-AI-EXAONE/EXAONE-4.5)와
[SGLang 구조화 추론 문서](https://docs.sglang.io/docs/advanced_features/structured_outputs_for_reasoning_models)에 따라
`--reasoning-parser qwen3`를 추가한 별도 실행 스크립트 `/data/start_sglang_reasoning.sh`를 만들었다.
모델·가중치·양자화·GPU·메모리 비율은 동일하다. `/data/start_sglang.sh`는 그대로 보존했다.
실행 중인 실험 및 8000 포트 연결이 없음을 확인한 뒤 기존 PID 55277을 TERM으로 종료하고
새 PID 1092079로 기동했다. 데이터베이스는 재시작하지 않았다.

먼저 네 합성 사실 준수 사례에서 v11 동일 문구·스키마·온도·토큰 상한으로 thinking만 비교한다.
명시적 `/no_think` 표식은 양쪽 입력에서 동일하게 제거한다. 원본 응답 전체, reasoning_content,
종료 사유, 토큰 사용, 처리 시간을 남긴다. 상한 도달 출력은 실패다. 실패 보수·재시도는 하지 않는다.
이 결과를 보고 개발용 96개 조건 비교를 별도 사전등록한다.

최초 v7 probe는 추론 4개 중 2개가 8,192 토큰 상한에서 잘렸다. 완성된 2개는 제약을 통과했다.
v7b에서는 공식 텍스트 권장 sampling(temperature=1, top_p=.95, presence_penalty=1.5),
16,384 토큰 상한으로 v11과 간결한 v15를 비교했다. 각각 4/4 일정·사실 제약을 통과했다.
평균 completion tokens는 v11 6,835, v15 7,086.75였다. 이 작은 표본에서 v15가 더 빠르다는
증거는 없다. v7과 v7b는 sampling과 토큰 상한이 함께 달라졌으므로 개선을 한 요인에 귀속하지 않는다.

v8은 동일한 96개 개발 조건에서 v11 추론 / v15 추론 / v15 비추론을 새 seed 6701로 비교한다.
288회 전부를 실행하고, 사실 준수와 원문 일정 계약을 통과한 후보 사이에서 비용을 비교한다.
상세 등록은 `data/experiments/validation_v8_reasoning_screen.json`에 있다. 현재 실행 중이다.

## 보류한 확인 자료

- 기존 12명과 겹치지 않는 24명, 192개 조건을 read-only로 준비했다.
- 입력 SHA256: `a7624baa07d0e689d2af7c08baec12ffe741f115acfc98fe1b1d261cae27dbb0`.
- 아직 모델 호출하지 않았다. 후보를 동결한 다음 새로운 seed에서 확인한다.
- 네 합성 제약 사례는 개발용 capability probe에 사용하기 시작했으므로 이후 결과도
  **이미 본 제약 사례의 반복 확인**으로 표현한다. 독립적인 새 정책 검증이라고 부르지 않는다.

### 참고 파일 누락과 확인 입력 재준비

격리 사본에 `output/stats`가 빠져 있었다. v3~v8의 고정 입력은 가격이나 공간적 일반화의
검증 자료로 인정하지 않는다. 해당 개발 조건에서의 형식·사실 준수 비교 기록은 보존한다.
원래 서버 사본에서 가격 상대계수, 동 중심좌표, 광역상권 목록·특성 파일 다섯 개를 복사하고
바이트 해시를 기록했다. 신규 입력 준비에는 파일 누락/빈 데이터의 fail-closed 검사를 추가했다.

24명 확인 입력은 **어떤 모델 응답도 보기 전에** 동일한 사람·정책·날짜·선정 seed로 다시 준비했다.
새 파일 `confirmation_source_with_references.json`의 SHA256은
`f189664bd4f6571137cce563a161a2317d15a08a268b627956e78d3ea7691fed`이다.
이 새 입력 역시 아직 모델 호출하지 않았다. 이전 파일은 덮어쓰지 않는다.

가격 파일에는 상대 동 계수만 있고 업종별 원 단가 및 개별 POI 메뉴 가격은 없다.
따라서 역사적 fallback 값을 실측가격이라고 부르지 않는다. 제공된 2025년 서울 추정매출 ZIP의
67,113개 행에서 별도 **건당 결제 참고표**를 만들었다. 4개 분기, 425개 동, 기존 매핑 기준 11개
업종을 포함한다. 건당 결제액은 상품 한 개의 가격이나 개인 하루 예산이 아니며, 이 파일은
기존 calibration에 덮어쓰거나 실행 중인 실험에 주입하지 않았다.

참고표 SHA256: `83bedd6ef44772a59ae2f5411814a83afe9f6d3921d8e6c7c7acaaeca2581825`.

## 소비 검증에 남은 아키텍처 문제

Stage2의 정책별 행동 지시, 0원 방문을 유료 소비로 바꾸는 fallback, 모든 방문을 상거래로 보는
가정, 소비 앵커/정책별 clamp/고정 비방문 소비 몫을 분리해서 검토해야 한다.
개선 문구 `transaction_v1.py`는 초안이며 아직 production 경로에 적용하지 않았다.
후속 `transaction_v2.py` 및 `transaction_contract.py`는 상점 방문이 필요 없는 활동의
`poi_id=null`/0원 선택을 명시하고, order별 후보와 실제 구매·결제 합계를 검증한다.
`transaction_ledger.py`는 개인 현금과 정책지갑, 온라인/오프라인 합계 보존만 검증한다.
금액 보정, 자동 정책지갑 사용, 고정 온라인 비중은 없다. 이 별도 실험 경로는 아직
기존 production 엔진을 대체하지 않았다. 원장 단위검사 추가 후 서버 전체 unit 196개가 통과했다.
Stage2 최근 방문 조회에 `m.day < today` 상한을 추가해 오늘·미래 방문이 과거 기억으로
읽히는 것을 방지했다. 이 수정만으로 shared DB 경로 격리가 완료되는 것은 아니다.

추가로 Stage2 후보 쿼리에서 처음 가는 POI의 거리 누락, 집·직장 기준점으로 인한 중복을
고쳤다. fallback 쿼리도 DISTINCT 및 POI ID tie-break를 적용했다. 실 DB에서 임시 데이터가
있는 트랜잭션을 항상 롤백하는 검사로 비인지 장소의 거리, 중복 없는 후보, 안정적 순서를 확인했다.

v8 중간 원문 검토에서 v15 비추론의 필수 약/약국 방문 습관 날조를 발견했다.
`experiment_evidence/validation_v8_manual_review.json`에 입력과 출력의 차이를 기록했다.
v16은 과거 소비 경향과 오늘의 확인된 필요를 구별하도록 만든 후속 초안이며 아직 호출하지 않았다.

외부 효과값은 `EXTERNAL_EVIDENCE_AUDIT_20260920.md`에서 실제 KDI 표와 비교했다.
로그계수/수준 변화, 가구/개인, 감염병 전체 충격/특정 규제의 차이를 해소하지 않은 크기 점수는 사용하지 않는다.

완전한 경로 격리, 원장 보존, 실제 지출 단위와 외부 자료의 기간·모집단 일치가 확인되기 전에는
거시 효과나 최적 프롬프트가 검증됐다고 보고하지 않는다. `VALIDATION_ROLLOUT_DESIGN.md`의
전체 실행 조건을 적용한다.

## v9: 추론 분량과 비용

추론 예산을 먼저 고정하고, 그 추론을 닫은 뒤 JSON을 생성하는 명시적 2회 호출 방식을 만들었다.
첫 단계 요청·응답은 두 번째 단계 실패 전에도 저장한다. 강제로 추론을 닫았는지 기록하며
이 방식을 최초 1회 응답 성공률이나 숨겨진 보수로 표현하지 않는다. 서버의 임의 코드 실행
기능은 활성화하지 않았다. 두 단계의 생성 토큰 합계를 비용으로 사용한다.

네 기존 개발 제약 사례에서 1,024토큰 추론은 형식 4/4, 사실 제약 2/4를 통과했다.
2,048토큰 추론은 형식·사실 4/4였다. 이에 같은 v11/2,048 설정을 원래 개발 입력 96개에서
별도 실행했다. 작은 시험만으로 후보를 확정하지 않았다.

이 96개 비교의 중간 원문에서 건강 업종 비중을 매일의 약 복용 습관으로 바꾼 응답을 확인했다.
따라서 이 후보도 형식 통과율만으로 승격하지 않는다. v8 긴 추론 후보에서도 없는 회사 규칙,
가구 구성, 소문 trigger를 확인했다. 정확한 행과 근거는 `experiment_evidence`의 v8/v9
manual_review 파일에 있다. 종료 전 실패를 발견해도 등록된 행렬과 원문은 그대로 완료·보존한다.

## v10: 사실 근거를 구별하는 프롬프트 비교

v11 대조군, v16(관측 사실과 선택 구분), v17(1인칭 시민 선택)을 같은 8개 개발 사례×2 seed에서
비교하도록 등록했다. 이전 4개 제약과 건강 지출 비중·가구 구성·근무 정보 충돌·정상 작동하는
오래된 물건의 4개 사례다. 이는 새 홀드아웃이 아닌 오류 분석에 따른 개발 자료다.

공통으로 추론 2,048토큰, 답변 2,400토큰, presence_penalty=0을 사용한다. 동일 용어를 정확히
반복할 수 있게 하는 새 개발 설정이다. 이전 실험과의 차이를 문구 하나의 효과로 귀속하지 않는다.
공통 문구에는 특정 정책 이름·효과 수치·소비 증감 정답이 없다. 새 활동 선택은 허용하지만,
그 선택을 정당화하려고 입력에 없는 질병·약속·회사 규칙·가족 정보를 만들어내면 실패다.
v9 종료 후 v10이 시작되며 24명 확인 자료는 아직 호출하지 않았다.

## 보존과 점검

실행 중인 v8/v9의 완성된 JSONL 행과 동결 입력을 3분마다 로컬로 복제하고 해시·시각을 남긴다.
앞선 백업과 다른 기록으로 바뀌면 덮어쓰지 않는다. 서버 재시작 중의 미완성 요청이나
Google Drive 동기화까지 보장한다는 뜻은 아니다. 개별 추론 요청·응답 디렉터리는 완료 후
별도로 복제한다. v9 probe의 두 단계 원문은 로컬에도 복사했다.

시장 스냅샷은 동일 24명의 후보 6,384그룹/48,586개이며, 빈 그룹 194개를 그대로 기록했다.
기간에 맞는 실제 상품 가격이 없다는 제한을 보존한다. 현재 POI DB의 목록이 과거 시점의
실제 영업 목록이라는 주장도 하지 않는다.

서버 전체 unit 검사는 211개 통과했다. 이 검사는 회계·후보 조회·기록 보존 등의 코드 검증이며
프롬프트의 사실 준수나 정책 효과를 대신하지 않는다. 7개 결제 사실 사례×2 모드×2 seed는
v8 종료 후 별도 `development_contract2` 경로에서 실행하도록 준비했다.

## v8/v9/v10 종료 결과와 후속 프로토콜

- v8: v11 추론 96/96, v15 추론 96/96, v15 비추론 89/96 형식 통과.
  추론 후보도 확인된 사실 오류 때문에 승격하지 않았다. 자동 요약의
  `factual_review_required=false`는 기존 정규식이 경고를 못 찾았다는 뜻일 뿐이며,
  수동 사실 감사 결과가 최종 적격 판단에 우선한다.
- v9: v11/2,048토큰의 2회 호출 방식은 96/96 형식 통과, 평균 생성 2,677.6875토큰.
  복약 습관 날조가 있어 사실 기준은 실패다. v8 v11 추론의 평균 생성은 8,629.1146토큰이다.
  두 실행은 seed와 API 프로토콜도 달라서 순수 예산 효과로 단정하지 않는다.
- v10: v11 대조군 16/16, v16 13/16, v17 9/16 형식 통과.
  자동 사실 검사까지는 각각 15/16, 10/16, 8/16이었다. v11에서도 카페만 휴업하는
  조건을 모든 외부 식사가 불가능한 것으로 넓힌 응답이 있어 세 후보 모두 확정하지 않았다.

v10의 검진 검사는 이벤트 시작 시각이 정확히 예약 시각인지 검사했다. 일찍 도착해 기다리는
표현은 이 검사에서 실패할 수 있으므로 `missed_appointment`라는 기계 라벨만으로 실제
불참했다고 단정하지 않는다. 등록된 문자적 검사 결과를 보존하고 원문 해석은 따로 기록한다.
후속 평가에서는 도착 시각·활동 시작 시각·이벤트 구간의 의미를 명확히 해야 한다.

v11 실험은 v18 문구와 새 출력 제약을 결합한 **프로토콜** 비교다. 시작·종료가 집인 조건을
스키마로 보장하고, reasoning에는 입력 구절 원문 또는 `오늘의 일상 선택`만 허용한다.
이는 문구만의 개선이나 비제약 모델의 사실 준수라고 부르지 않는다. 인용 자체가 선택을
뒷받침하는지, intent에 없는 필요를 만들어내지는 않는지 별도 검사한다. 행동과 소비 방향,
이벤트 수의 기존 범위, 무외출 선택은 유지한다. 추론·답변 상한은 각각 4,096으로 등록했다.
SGLang 실제 문법 검사기의 수용/거부 검사 4개와 전체 unit 검사 225개가 통과했다.

- 24명 확인 입력: `f97194747a6920d86dbccaffaa995e379c12f283604090ecba5cac1b81cfa714`.

- 새 확인 입력에 대한 모델 호출은 아직 없다. 준비 시점에 확인 결과를 보고 바꾼 것이 아니다.

## v12/v13에서 드러난 표현과 시간 검증 범위

v12(v19+근거 인용+공백 제한)는 형식 15/16이었다. 한 일정의 두 활동 사이가 10분이었고,
다른 응답에서는 회사 근무 사실을 여전히 공공 정책 trigger로 표시했다. 공백 반복은 재발하지 않았다.

v13은 입력에 실제로 존재하는 약속·소문·공공 규제만 해당 trigger의 선택지로 제공하고,
최대 10분 이내 최소 시간 조정 프로토콜을 명시적으로 등록했다. 원문 16/16 형식 통과,
시간 조정 0건, 기존 자동 사실 검사 16/16이었다. **그러나 수동 검토에서 work_conflict /
seed 17001의 17:00 퇴근→17:30 귀가가 주어진 통근 40분과 모순됨을 발견했다.**
따라서 이 결과를 전체 사실 검증 통과로 부르지 않는다.

연속된 집·직장 사이의 주어진 통근 시간을 추가한 검증·최소 변경 계산을 만들었다.
기존 원문 16건을 재생했을 때 이 한 건만 17:40 귀가로 +10분 변경되었다. 이는 **새 모델
실험이 아닌 사후 결정적 재계산**이며 `validation_v13_commute_replay.json`에 원문 해시와
모든 변경을 보존했다. 활동·순서·장소·금액·근거를 바꾸지 않는다. 지정된 시간이나 이동
조건을 최대 변경 범위 안에서 만족시킬 수 없으면 실패한다. 중간 POI를 거치는 전체 경로의
소요시간까지 검증하는 완성된 이동 모형은 아니다.

## v14: 96개 정책 개발 조건으로 확대

v19 문구를 유지하고 입력 근거의 출처도 출력 제약에 연결한다. 공공 정책 trigger는 정책·
공공 규제 채널의 근거만 인용할 수 있다. 개인의 직업이나 현금 보유 사실을 인용하며 정책이
원인이라고 표시하는 경우를 제한한다. 출처가 맞는 인용도 행동과 관련 있는지는 별도 검토한다.

v14는 기존 12명×4개 알려진 기전×동일 날짜 on/off=96개 **개발** 조건이다.
9~10개 지역 후보, 일관된 합성 초기 상태, 입력 원문 근거, 문법·시간·인접 통근 조건을
사용한다. 프로토콜 통과율과 원문 통과율, 모든 시간 조정과 실패를 별도로 보고한다.
형식 적격·사실 근거·비용으로만 판단하며, 정책 효과의 부호나 크기로 프롬프트를 고르지 않는다.

최종 typed 개발 입력 SHA256:
`97649b099b94f3fa2a4040795eb2c8bcb06b85ef6f8730d245bf4c1fb2a8c5bf`.
아직 모델 호출하지 않은 24명 확인 입력 SHA256:
`798fda2accffe4e9589fa9c8e47c5cb15f15c48420aead62cfdb53ce360e5a2d`.
이전 준비 파일은 유지하며, typed 메타데이터를 붙여도 시민에게 보이는 본문은 바꾸지 않았다.

서버 전체 unit 검사 235개, 실제 XGrammar 통합 검사 6개가 통과했다. 원문 보존과

## 구매·자산 연결 개발 실험

`activity_purchase_bridge.py`는 무료 활동을 상점으로 바꾸지 않고, 각 유료 후보에 명시 가격과
가격 출처·채널·지갑 사용 자격이 있어야 한다. 가격 누락을 평소 하루 지출로 채우지 않는다.
예약의 비용이 불명확하면 무료라고 가정하지 않고 거부한다. `asset_day_checkpoint.py`는
고정 시민 전원의 원문 선택과 회계를 다시 확인한 뒤 일별 파일을 원자 커밋한다. 날짜·시민·
초기/종료 잔액이 이어져야 하며 실패자를 0원으로 채우지 않는다. 소득·재고·기억의 종단
전이까지 구현한 것은 아니다. 서버 전체 단위 검사 276개가 통과했다.

`validation_purchase_v1`은 v18의 96개 일정을 가상 상품 가격표에 연결해 구매 seed
32001/33001로 192개 응답을 얻는다. 가격은 결과를 보기 전에 고정했으며 개인별 하루
소비 앵커나 외부 효과 크기에서 만들지 않았다. 가상 가맹점·개인 참여 자격·상품권 단위는
입력의 **실험 가정**으로 명시한다. 새로운 실제 가격 관측이나 역사적 정책 효과 검증은 아니다.
공통 결제 문구는 특정 정책의 반응을 지시하지 않고 구매 없음, 현재 자금, 지갑 취득과 소비를
구별한다. 전체 가격·잔액 계약을 통과한 완전한 on/off 행렬만 대비를 계산한다. 실패가 있으면
해당 기전 대비는 계산하지 않고 원문을 보존한다. 상위 일정은 고정되어 있으므로 두 구매 seed를
독립적인 전체 시뮬레이션 반복으로 세지 않는다. 입력 SHA256:
`0f7066cb01baa55b2810568f7c2b89e6600c41fafbe3e8e31d2b729c75ee10a5`.

v19와 구매 실험은 SSH와 분리해 실행하며 응답마다 fsync한다. 완료 원문·입력·manifest를
3분마다 로컬로 복제한다. 이 보호 범위는 복사 완료분이며, 서버 회수나 Drive 클라우드
동기화까지 보장하는 것은 아니다. P010 원본 및 P015 재실험 금지는 그대로 유지한다.

## 후속 확인 실패와 저비용 후보

v19 완료 결과는 원문 304/384, 최대 10분 조정 후 362/384(94.27%)다. 사전 등록한
95% 실행 기준에 미달하여 긴 추론 v23을 승격하지 않았다. 58개 응답의 시간이 조정됐고
22개 실패는 그대로 남겼다. 실패는 주로 긴 통근 시간을 확보하지 못하거나 시간이 뒤집힌
경우다. 22개 실패 행동열을 읽었으며 전체 성공 행동열의 수동 검토를 마쳤다고 주장하지 않는다.
이제 이 24명은 수정 후보의 미사용 확인 표본이 아니다. 원본 압축본 SHA256:
`e6090813bfb77a3f3f4e2c2ab3509c9e7ac2ee73b562f0bd44c2d1035a681f48`.

출근 시작만 검사하면 중간에 집으로 돌아가는 오류를 놓친다. 명시된 장소 유지 구간을
별도 검사한 결과 repair_v1의 기존 6/6 중 하나가 거짓 통과였다. 이 표기를 반영한
repair_v2는 4/8에 그쳤다. 단순히 실패 설명을 길게 되먹이는 방법은 채택하지 않았다.
과거 원문·당시 채점은 그대로 두고 추가 감사 결과를 구분해 저장했다.

adaptive_v1은 v23·첫 추론 512토큰·실패 시 단 한 번 2,048토큰 사실 수정으로 31/32였다.
같은 입력·seed·문구에서 온도만 1에서 0.2로 낮춘 adaptive_v2는 원문과 최종 모두
32/32, 수정 호출 0회, 평균 783.31토큰이었다. 전체 32개 행동을 읽었고 오후 취침 준비
3개를 포괄성 경고로 남겼다. 기존 12명×4기전×on/off=96개로 확대한 adaptive_v3는
원문 87/96, 공개한 시간 조정 후 96/96, 수정 호출 0회, 평균 800.48토큰이다.
96개 행동을 모두 읽었으며 마지막 활동이 18시 전인 경우 16개, 그중 취침 준비 5개다.
근무 방식이 관측되지 않은 시민의 재택/출근 선택과 학생의 학교 활동 부재도 남는다.
실행·비용 기준 통과를 사람의 하루 전체나 정책 효과 타당성 통과로 대체하지 않는다.

## 시간 문법과 하루 구성 문구의 분리 실험

temporal_choice_grammar는 30분 간격 및 명시된 고정 시각에서 일정 선택을 생성한다.
시간순, 제공된 집/직장 통근 하한, 확정 시작과 장소 유지 구간을 표현 단계에서 지킨다.
정책 효과의 방향·크기는 입력하지 않으며 폐쇄 여부 검사는 문법에서 제거하지 않는다.
모든 장소 사이의 이동·활동 지속시간·근무 가능성을 보장하지는 않는다.
실제 문법 검사 2개의 소요시간은 표현 중복 제거 후 102.135초에서 1.864초로 줄었다.

temporal_v1은 기존 16개 개발 입력×seed 40001/41001, v23·512토큰·온도 0.2로
원문 32/32, 시간 조정 0회, 평균 730.97토큰이었다. 전체 행동을 읽었으며 18시 전
마지막 활동이 8개였다. 작업 정합성은 구조적 성질이므로 프롬프트 단독 추론 성공이 아니다.
압축본 SHA256: `9af77176dac9d02a7a91a418dd25eed3c6428d83aa634b6f486f88dcf4bdb8b4`.

temporal_v2는 같은 입력·seed·시간 문법·예산에 v24만 바꾼 비교다. v24는 확정 의무와
오전·오후·저녁을 먼저 배치한 뒤 변화 지점을 출력하도록 한다. 집 체류 시간을 재택근무
허용으로 읽지 말고, 취침과 짧은 휴식을 구별한다. 정책별 행동·정답 수치는 없다.
실행·사실 기준을 모두 통과하고 이른 종료가 대응 v23보다 나쁘지 않을 때만 개발 확대한다.
지표와 후보는 호출 전 등록했으며 이 실험을 새 정책 검증이라고 부르지 않는다.

## 결제 구조 후속 결과

purchase_v1은 183/192였다. 실패 9개 중 8개는 이벤트 순서, 1개는 소비와 결제 합계
불일치다. purchase_v2와 v3는 각각 31/32였다. v2는 현금과 지갑으로 가격을 이중 지불했고,
v3는 취득을 0개로 고르면서 보유하지 않은 지갑을 사용했다. 실패를 0원으로 바꾸지 않았다.

v3부터 모델은 상품·취득 수량·지갑 사용만 선택한다. 현금은 가격에서 지갑 사용을 뺀
정확한 나머지로 계산한다. 이는 모델의 선호를 보정하지 않는 결정적 회계다. 정적 하루
제안과 일중 소득 0 가정을 입력에 명시하고, 취득한 지갑은 최초 사용 전에 처리한다.
v4는 실제 보유했거나 양의 취득 수량을 선택한 지갑만 사용 표현에 허용한다. 누적 현금·
지갑 부족은 여전히 독립 원장이 검사하며, 문법이 모든 회계를 보장한다고 주장하지 않는다.

purchase_v4는 32/32 회계 통과, 그중 14개는 선택지가 없어 호출을 생략한 유일한 0원,
18개가 모델 생성이다. 18개 선택 원문을 모두 읽었다. 같은 시민이 seed에 따라 선불 취득
1개와 10개를 선택한 차이가 있어 재무적 실행 가능성과 수요 적정성은 별개다. 그대로
96조건으로 확대한 purchase_v5를 등록·실행했다. 가격·가맹점·개인 자격은 가정이고
고정된 상위 일정에 대한 조건부 실험이다. 정책 대비 값은 프롬프트 선택에 사용하지 않는다.

모든 완료 원문·추론·요청·입력·코드는 서버와 로컬의 전체 압축본 해시를 대조했다.
개별 결과와 원본 해시는 `docs/experiment_evidence/validation_*_review.json`에 보존한다.
후속 코드의 전체 단위 검사 303개 및 실제 구매 문법 검사 5개, 시간 문법 검사 2개가 통과했다.
