# 2020년 11월 거리두기: 동일 날짜 쌍체 비교 사전등록

현재 P012 A100 진단 런의 완료와 서버 밖 원장·그래프 보존 전에 이 실험으로 그래프를 초기화하지 않는다. P015 holdout은 재실행하지 않는다. 범용 시스템 프롬프트에는 거리두기 결과의 목표 부호·크기를 넣지 않는다.

## 입력과 두 환경 팔

- **같은 500명, 같은 2020-11-24~11-30(화~월), 같은 초기 State·장소·모델·코드·난수 설정**을 사용한다. `DAY_ZERO=2020-11-23`에서 각 팔을 새로 초기화하고 매일 완전한 정상 metrics와 State를 요구한다. 동일 날짜 쌍체 설계라 기존 11/17~18 대 11/24~25 비교의 요일 차이를 정책 효과로 세지 않는다.
- 제한 팔은 `SIM_ENVIRONMENT=covid_2021`, 대조 팔은 `SIM_ENVIRONMENT=covid_no_distancing`이다. 후자는 같은 날짜의 서울 신규 확진과 추이 계산을 공통 함수에서 가져오고, **추가 방역 영업시간·매장 이용·사적모임 제한이 없다는 반사실**만 전달한다. 매장의 고유 운영시간은 유지한다. 두 팔 모두 현금 지급 Policy 노드는 없어야 한다. 환경 ID 차이는 의도된 유일한 실행 지문 차이로 보존한다.
- 두 팔 모두 `EXP_DAILY_INCOME=baseline`과 동결된 공통 시민별 예산 맵 `data/experiments/p012_baseline_income_20260926.json`을 쓴다. 이는 2021년 정책 전 지출에서 만든 합성 예산이고 2020년 실제 소득이 아니다. 7일 창에서 잔고 안정성 장치로만 사용하며 결과에 맞춰 바꾸지 않는다.
- 첫 검증 후보는 정책 중립 v51이다. 역사적 v5와 프롬프트 효과를 비교하려면 v5도 같은 제한·대조 **두 팔**로 별도 실행한다. 형식 관문 결과나 기존 짧은 전후 창의 정답지 근접값을 크기 유효성으로 전용하지 않는다. 어느 후보를 추가하든 팔과 채점 정의를 결과 전에 고정한다.

## 출력과 판정

일별 `INCLUDES.actual_spent`와 State의 온라인 금액을 실현 지출로 보존한다. 음식점(원문의 **한식**과 식사 전체를 분리), 소매, 카페 거래를 동일한 POI 분류표로 두 팔에서 집계한다. 시민별 7일 지출의 제한−대조 쌍체차와 대조 지출 대비 비율을 내고, 시민 단위 재표집 95% 구간과 반복 런 간 변동을 따로 보고한다. 카페 포장·배달과 매장 취식은 실제 출력에 결제 유형 필드가 있을 때만 분리한다. 분류가 없는 거래를 임의로 업종에 넣지 않는다. 매일 정책 사실 노출, 제한 위반, Stage2 전체 실패·부분 보정·금액 대체, 누락 원장을 함께 감사한다.

서울연구원 원문의 한식 `−14.1%`는 **전년 대비**이고 소매 `+4.2%`는 팬데믹 기간 평균 변화다. 본 실험은 같은 2020년 주간에 제한이 있을 때와 없을 때의 **모형 내부 반사실**이다. 음식점 전체/한식의 범위, 카드 매출/기록 총지출, 연간 기준선/주간 ON·OFF가 모두 맞기 전에는 두 숫자를 빼서 오차나 적중으로 표시하지 않는다. 대신 업종별 부호·상대 순위와 모형 효과의 크기·불확실성을 제시하고, 원문 값은 다른 추정량의 맥락으로 나란히 둔다. 직접 크기 검증에는 2019년 동기간 같은 업종·상권 카드매출 또는 그에 상응하는 반사실 자료와 모형의 결제수단 표기가 추가로 필요하다.

현재 `covid_no_distancing`의 사실 분리는 단위 시험을 통과했지만, 이 7일 두 팔의 A100 실행·원장 내보내기·외부 크기 검증은 **아직 수행하지 않았다**. 실행 전에는 환경을 제외한 코드·설정 일치, 양팔 정책 노드 0개, 동일 시민 명단, 연속 날짜, 원장 해시를 강제하는 전용 내보내기/채점 관문을 구현해야 한다.

업종 분류 사전점검: 현재 P012의 2021-10-17 완료 원장에서 `data/neo4j_load/mapping/mapping_upjong_to_sub.json`으로 매장 코드가 해석되지 않는 금액은 계획상 식사 거래의 **19.3%**, 카페 **12.2%**, 쇼핑 **19.5%**였다. 이는 다른 날짜·정책의 진단값이며 DS 결과가 아니다. `INCLUDES.sub_category`의 '한식'은 시민의 **의도**이고 실제 매장 업종이 아니다. 따라서 엄격 지표는 실제 POI 업종코드 또는 Category 관계로 확인된 거래만 쓰고, 미분류 금액과 의도 라벨 기반의 넓은 보조 추정치를 따로 보고한다. 한식 의도 981건을 한식 매장 981건으로 간주하지 않는다.
