# 동일 시민의 하루를 먼저 고정하는 검증

현재 실행 가능한 v24가 정책 효과까지 타당하다는 증거는 부족하다.
입력 복원 시험 이후에는 같은 시민·같은 날의 선행 조건을 고정한 상태에서 범용 문구를
비교한다. 정책별 소비 부호나 실측 효과 크기를 프롬프트 선택 기준으로 쓰지 않는다.

## 정책 전에 공유하는 상태

개인의 직업·생활 서술은 출처가 일치해야 한다. 당일 근무/수업·이미 확정된 약속,
집에 남은 물품·직전 구매·식사 필요·자금과 기존 지갑을 별도 상태로 받는다.
모든 상태에는 관측/합성 가정/미제공 구분과 출처를 붙인다. 빈 근무 POI를 무직으로,
집 체류 시간을 재택근무 허용으로 변환하지 않는다.

미관측 일상 조건을 실험에서 보충할 경우, 별도 시나리오 생성 단계에서 정책 결과를
보지 않고 생성·고정한다. on/off는 그 동일 파일에서 출발하고, 정책으로 실제 바뀌는
사용 자격·자금·제약만 다르게 적용한다. LLM seed의 일치만으로 하루의 필요와 근무
방식이 같다고 간주하지 않는다. 반대로 정책으로 바뀔 수 있는 구매·방문·외출·근무 선택
자체를 on/off에 강제로 같게 만드는 것도 피한다.

기존 자료에는 이 모든 상태의 실측 분포가 없다. 특정 직업은 매일09시 출근한다거나
모든 시민이 오늘 외식/생필품 구매를 원한다고 실제 사실로 채우지 않는다.
가정을 둔 조건부 실험과 모집단·역사적 효과 검증은 별도 결과로 표시한다.

## 활동·구매 선택의 범위

직장 주소가 없는 취업자와 학생도 자신의 역할을 표현할 수 있어야 한다.
현재 `office_work`와 `remote_work`를 둘 다 근무 POI 존재에 묶는 부분은 확장 대상이다.
주소 미제공 역할 활동에는 관측된 출근시간이나 근무지를 임의로 붙이지 않는다.
확정 의무가 제공될 때는 활동을 선택할 수 있을 뿐 아니라 실행 계약이 그 시간을 검사한다.

구매가 필요하다면 무료/보유 재고 이용, 연기, 온라인, 이용 가능한 오프라인 대안을
같은 판단 단계에 제시한다. 각 구매안에는 단위·수량·가격·배송/이동/시간 비용·사용 자격과
이용 가능 시점이 필요하다. 한 업종에 한 품목만 둔 현재 목록과 음식 중심의2026년 메뉴는
가계 전체 소비나2020~2021년 가격을 대표하지 않는다. 더 많은 구매가 나오도록 목록을
선별하지 않으며, 품목 선정 규칙과 누락된 영역을 효과를 보기 전에 고정한다.

## 비교 순서와 판정

1. 입력의 출처·상태·메뉴·회계 일관성을 통과시킨다. 이 단계는 LLM 성적과 독립이다.
2. 같은 입력/출력 계약 아래 현재v24와 더 간결한 범용 문구를 비교한다. 사실 위반,
   자금·시간 불가능 선택, 실제 제공된 선호/의무와의 모순, 실패 원문을 평가한다.
   활동 수·오프라인 구매·소비 증가 그 자체는 정답으로 삼지 않는다.
3. 시민×날짜×반복×on/off의 완전한 행렬을 실행한다. 실패가 있으면 탈락 경로를 숨기거나
   0원으로 대체하지 않는다. 하루별 상태 전이는 구매와 자금뿐 아니라 재고·기억·다음 의무를
   갱신해야 하며, 이후 날의 상태를 처음 날로 재설정하지 않는다.
4. 시민 단위로 짝지은 소비 차이와 반복 간 분산을 보고한다. 동일 시민의 반복을 독립적인
   시민 표본으로 세지 않는다. 총 소비와 상품권 구입 같은 자산 이전은 계속 분리한다.
5. 외부 자료와 비교하려면 단위(개인/가구), 기간, 대상, 자격, 비교군, 가격 시점과 추정량을
   먼저 맞춘다. 정렬되지 않은 실측 부호·퍼센트를 정답표로 붙이지 않는다.

새 정책의 홀드아웃은 위 구성과 후보를 고정한 후 사용한다. 이미 본4개 기전과 이미
사용한 시민은 개발 또는 재현 표본이며, 새 확인 표본으로 다시 부르지 않는다.
최종 판단은 선언한 실험 범위의 적격성과 한계다. 전역 최적이나 모든 정책의 현실 예측을
입증했다고 표현하지 않는다.
