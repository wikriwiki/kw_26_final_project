# 최종 보고서 엔진 v2

> 정책 시뮬레이션 run 산출물만 읽어 **상세 분석 보고서 단일 HTML** 을 만든다.
> Neo4j·GPU·시뮬레이션 엔진을 건드리지 않는다. 읽기만 한다.

---

## 1. 왜 만들었나

기존 보고서 경로(`scripts/report/menu.py` → `generate_final_report`)는 Neo4j 원본이
선택한 run snapshot 에 binding 되어 있어야 실행됐다. 그런데 실제 산출물에는 그 binding 을
증명할 manifest 가 없어 **어떤 run 으로도 보고서를 만들 수 없는 상태**였다. 그리고 산출물은
`FINAL_REPORT_5D_FULL.html` 처럼 그림 몇 장짜리 정적 파일 하나뿐이었다.

v2 는 두 문제를 같이 푼다.

| 문제 | v2 의 해법 |
|---|---|
| manifest 가 없어 보고서를 못 만든다 | **결제 기록(`events.jsonl`의 정책 지급 내역)** 을 결합 근거로 쓴다. manifest 보다 강한 실물 증거다 |
| 그림이 적고 해석 근거가 약하다 | 27개 인라인 SVG, 8개 표, 업종별 이중차분, 전후 겹쳐보기, 사전추세 검증 |
| 섹션 간 숫자가 어긋나도 모른다 | 항등식 21건을 **다시 계산해 대조**하고 결과를 보고서 안에 싣는다 |
| 해설 LLM 이 숫자를 지어낸다 | 생성 문장의 숫자를 계산 결과와 대조해, 근거 없는 문단은 채택하지 않는다 |

## 3. 이중차분(DID) 정의

**보고서·화면·문서·테스트가 모두 이 하나의 정의를 쓴다.**

- 처치군 **T** = 정책 대상 업종 집합
- 대조군 **C** = 그 외 업종 집합
- 사전 **P0** = 시행일 이전 일자 / 사후 **P1** = 시행일 당일 이후 일자
- 모든 값은 기간 길이를 맞추기 위한 **일평균 금액**

```
반사실      T1* = T0 × (C1 / C0)
DID(절대)   = T1 − T1*
DID(상대)   = (T1/T0) − (C1/C0)
```

업종 `c` 하나에 대해서도 **같은 대조군 성장률**로 반사실을 만든다. 그래서

```
Σ (대상 업종 c 의 DID)  =  처치군 전체 DID
```

가 항등식으로 성립하고, `consistency.py` 의 `did_category_sum` 이 이것을 실제로 검사한다.
이 성질 덕분에 "어떤 업종에서 금액이 늘었는가"를 전체 효과의 **분해**로 읽을 수 있다.

### 처치군을 정하는 순서

1. 정책 JSON 의 `benefit_categories` / `target_cats` 중 **실제 관측된** 업종
2. 없으면 `events.jsonl` 에서 **정책 지급이 실제로 발생한** 업종
3. 둘 다 없으면 처치군을 만들지 않는다 — 임의로 고르지 않고 "판정 불가"로 적는다

### 인과로 읽기 위한 조건

이중차분은 **대조군이 처치군과 같은 추세를 따랐을 것**이라는 가정 위에서만 인과다.
보고서의 `사전추세 검증`(event study) 그림에서 시행 전 구간이 평평하지 않으면 그 가정이
깨진 것이고, 보고서는 그 사실을 경고로 적는다.

### 값이 나왔다고 믿을 수 있는 건 아니다

DID 는 **대조군의 성장률**로 반사실을 만든다. 그래서 대조군이 작으면 반사실 전체가
소수의 거래에 끌려간다. 숫자는 계산되지만 그 숫자는 정책 효과가 아니다.

`analytics.did_reliability` 가 두 조건을 본다.

| 조건 | 기준 | 왜 |
|---|---|---|
| 대조군 비중 | 사전 거래액의 5% 이상 | 이 아래면 반사실이 몇 건에 좌우된다 |
| 사후 기간 | 7일 이상 | 한 주가 안 되면 요일 구성이 사전과 달라 요일 효과가 섞인다 |

하나라도 못 넘기면 6절 맨 위에 **"이 값을 정책 효과로 인용하면 안 됩니다"** 를 사유와
함께 싣는다. 값을 지우지는 않는다 — 무엇이 어떻게 어긋났는지 보여야 다음 실행을
어떻게 설계할지 정할 수 있다.

> 실측 예: `EXP7500`/`P010` 은 대조군이 사전 거래액의 **0.09%** 였다. P010 은 전 분위에
> 지급하고 가맹점 98% 가 대상이라 **run 안에 대조군이 없다.** 보편 지급 정책은 업종
> 분할로 DID 가 성립하지 않는다는 뜻이고, 보고서가 그렇게 적는다.

## 3-1. 조각난 산출물 합치기

DID 는 시행일 **이전** 일자를 요구하는데, 실험은 한 디렉터리에 쭉 쌓이지 않는다.
무정책 구간을 돌려 산출물을 닫고 → 그래프를 정산·덤프하고 → 정책을 주입하고 →
다음 구간을 **새 디렉터리**에 돌린다(`chain_p3r.sh`). 그래서 사전과 사후가 다른
폴더에 있고 어느 쪽도 혼자서는 DID 를 못 만든다.

`scripts/report/merge_run_segments.py` 가 같은 그래프 상태를 이어받은 조각들을
하나의 run 스냅샷으로 합친다.

```bash
python scripts/report/merge_run_segments.py \
  --out <합칠 경로>/out_EXP7500 \
  --segment <사전구간>:events.jsonl \
  --segment <사후구간>:events_2025-07-21.jsonl
```

- 조각마다 내보낸 스크립트가 달라 필드가 어긋난다. **공통 필드만 남긴다.** 예를 들어
  하루치 내보내기는 `poi_dong`(POI.dong_code)을, 구간 전체 내보내기는 `dong`(POI.adm_cd)을
  담는데 후자는 값이 비어 있다. 그대로 두면 *"사전에는 지역 정보가 없고 사후에는 있다"* 가
  되어 정책이 지역 데이터를 만들어낸 것처럼 읽힌다.
- 버린 필드와 출처는 `merge_manifest.json` 에 남는다.
- 같은 날짜가 두 조각에 있으면 **합치지 않고 멈춘다.** 어느 쪽이 옳은지는 사람이 정한다.
- `metrics`/`timing`/`checkpoints` 의 일자별 파일과 `poi_summary.json` 도 함께 가져온다.
  빠지면 스냅샷 검사가 보고서 생성을 막는다 — 막는 게 맞다.

## 4. 절 구성

| ID | 절 | 담는 것 |
|---|---|---|
| s1 | 분석 개요 | run·정책·기간·처치군 정의, 지렛대·사중손실 (**항상 포함**) |
| s2 | 정책 사양 | 정책 JSON 요약, 지급 구간 막대, 정책별 실제 지급액 |
| s3 | 소비 총량 추이 | 일자별 총액/정책지급/자기부담/추가지출, 건수·객단가, 전체 표 |
| s4 | 시행 전후 겹쳐보기 | 같은 길이 구간 겹침 + **차이 면 채색**, 상위 8개 업종 소형 겹쳐보기 |
| s5 | 업종별 전후 비교 | 일평균 그룹 막대, 증감률 발산 막대, 결제 구성 100% 누적 |
| s6 | 이중차분 | 슬로프 차트(반사실 점선), 2×2 표, 변화 분해 폭포, 사전추세 검증 |
| s7 | 업종별 이중차분 | 업종별 DID 발산 막대, 표, 업종×일자 증감 히트맵 |
| s8 | 분위별 효과 | 분위별 1인당 소비 전후, 증감률, 지급/소진 표 |
| s9 | 소비 구조 | 결제·업종 도넛, 주중/주말, 업종 위치 산점도, 지역 분포 |
| s10 | 일관성 검증 | 항등식 검사 표 (**항상 포함**) |
| s11 | 근거와 한계 | 출처 링크, 해설 생성 방식, 해석 한계 (**항상 포함**) |

`s1 / s10 / s11` 은 사용자가 빼도 서버가 되돌려 넣는다. 근거와 검증이 없는 보고서를
만들지 않기 위해서다.

절이 **적용 불가능**할 때는 잠기고 이유가 표시된다. 예를 들어 정책 시행일이 없으면
`s4 / s6 / s7` 이 잠기고 "정책 시행일이 없어 사전/사후를 나눌 수 없습니다"가 붙는다.
화면이 임의로 DID 를 강제하지 않는다.

## 5. 일관성 검증

같은 값을 여러 경로로 계산하면 언젠가 어긋난다. 그래서 항등식을 **다시 계산해 대조**하고
결과를 보고서 마지막 절에 싣는다.

| 검사 | 내용 |
|---|---|
| `daily_sum_amt` / `_events` / `_policy` | 일자별 합 = 총계 |
| `category_sum_amt`, `category_share_100` | 업종별 합 = 총계, 구성비 합 = 100% |
| `mix_components` | 정책지급 + 자기부담 = 총 소비금액 |
| `policy_id_sum`, `policy_le_amount` | 정책 ID별 합 = 총 지급액, 지급 ≤ 소비 |
| `period_partition` | 사전 ∪ 사후 = 전체, 교집합 = ∅ |
| `did_counterfactual` / `did_identity` / `did_bias` / `did_relative` | DID 정의식 4종 |
| `did_category_sum` | **업종별 DID 합 = 처치군 전체 DID** |
| `category_did_alignment` | 업종 비교표와 DID 표가 같은 사전 일평균을 쓴다 |
| `overlay_window` / `_pre_total` / `_post_total` / `_category_total` | 겹쳐보기 구간과 합계가 원장과 일치 |
| `event_study_points` | 이벤트 스터디 관측 일수 = 분석 일수 |
| `decile_treated_present` | 지급 분위가 하나 이상 존재 |

허용 오차는 반올림 누적분(항목 수 × 1원)뿐이다. 하나라도 실패하면 CLI 는 exit code 3 을
돌려주고, job 은 완료로 표시하되 **"어긋난 항등식 있음"** 을 함께 남긴다.

## 6. 해설 LLM

`.env` 에 키 한 줄만 넣으면 켜진다.

```dotenv
GEMINI_API_KEY=...
GEMINI_MODEL=gemini-2.5-flash     # 선택
```

사내 OpenAI 호환 서버(vLLM/SGLang)를 쓰려면:

```dotenv
REPORT_LLM_PROVIDER=openai
REPORT_LLM_BASE_URL=http://127.0.0.1:30000/v1
REPORT_LLM_MODEL=exaone-4.5
```

**숫자 가드.** 프롬프트에는 계산 결과 JSON 만 들어가고 "여기 없는 숫자를 쓰지 말라"고
지시한다. 그리고 생성된 문장의 모든 숫자를 계산 결과의 숫자 집합(원값·반올림·만/억 축약·
백분율 표현 포함)과 대조한다. 근거 없는 숫자가 하나라도 있으면 그 문단을 **버리고**
결정론적 문장으로 되돌린 뒤, 그 사실을 보고서 `근거와 한계` 절에 기록한다.

키가 없어도 보고서는 그대로 생성된다. 해설만 규칙 기반 서술로 바뀌고, 각 해설 아래에
출처가 명시된다.

연결 확인: 콘솔 보고서 화면의 `연결 확인` 버튼 또는 `POST /api/llm/ping`.

## 7. 실행

### CLI

```powershell
python scripts/report/build_report_v2.py `
  --run-id FINAL `
  --run-root "C:\Users\srdyh\gpu_exp_data\20260802\out_FINAL" `
  --policy-json data/neo4j_load/policies/P010.json `
  --policy-from 2025-07-21 `
  --out output/sim/report/FINAL_REPORT_V2.html
```

옵션

| 인자 | 뜻 |
|---|---|
| `--data-root` | `--run-root` 대신 루트만 주면 `out_<RUN_ID>` 를 찾는다 |
| `--start` / `--days` | 분석 창을 자른다. 생략하면 관측된 전 구간 |
| `--section s6 --section s7` | 담을 절만 고른다 (필수 절은 자동 포함) |
| `--no-llm` | 해설 LLM 을 호출하지 않는다 |

출력

```
<out>.html        단일 HTML — 인라인 SVG, 외부 리소스 0
<out>.md          같은 내용의 Markdown
<out>.data.json   계산 결과 원본 + 일관성 검사 결과 (재현·검증용)
```

exit code: `0` 정상 · `2` 계산 불가 · `3` 생성됐지만 일관성 검사 실패

### 웹 콘솔

`/runs/<runId>/report` 에서 기간·절·엔진·LLM 사용 여부를 고르고 `보고서 생성`.
서버는 report lock 을 잡고 자식 프로세스로 CLI 를 돌린다. 진행 단계와 로그가 화면에
그대로 보이고, 끝나면 본문이 같은 페이지에 펼쳐진다.

## 8. 안전 규칙

- **시뮬레이션 엔진을 바꾸지 않는다.** `scripts/sim/*`, `scripts/neo4j_load/*` 를 읽기만 한다.
- **임의 shell 명령을 받지 않는다.** API 는 구조화된 필드만 받아 인자 벡터를 만든다.
- **실행 중에는 보고서를 만들지 않는다.** 시뮬레이션 lock 이 있으면 409 로 거절한다.
- **보고서 job 은 한 번에 하나.** `web/.report.lock` 을 원자적 생성으로 잡는다.
- **완료된 run snapshot 만.** 진행 중인 mutable 산출물로 결론을 만들지 않는다.
- **정책 결합을 증명한다.** 선택한 정책이 그 run 의 결제 기록에 없으면 409 로 거절한다.
  지급 기록이 아예 없는 run(대조군)은 허용하되 그 사실을 `policy_binding.source` 로 남긴다.

## 9. 테스트

```bash
python -m pytest tests/unit/report -q
```

44건. 핵심은 "돌아간다"가 아니라 **넣은 값을 정확히 되찾는가**다.

- 합성 run 에 시장 추세 1.10 과 정책 효과 1.25 를 따로 넣고, DID 가 정책 효과만
  분리해 내는지 소수점까지 확인한다 (`test_did_recovers_the_injected_policy_effect`)
- 대조군 업종의 DID 가 정확히 0 인지, 대상 업종 DID 합이 전체 DID 와 같은지
- 값을 일부러 어긋나게 만든 번들에서 일관성 검사가 **실제로 실패를 잡는지**
- LLM 이 없는 숫자를 쓰면 그 문단이 거절되고 기록되는지
- API job 을 끝에서 끝까지 돌려 HTML·Markdown·data.json 이 실제로 나오는지
