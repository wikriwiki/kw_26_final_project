# 종단 정책 검증 설계 — 사전 검증 뒤 실행할 단계

작성: 2026-09-20. 이 문서는 후속 설계이며 실행 완료 기록이나 표본 수 사전등록이 아니다.
후속 개발 실험 상태는 `VALIDATION_PROGRESS_20260920.md`에 기록한다.
Stage1 개발 검사는 실제 지출의 종단 정책 검증과 구별한다.

## 질문과 비교

1. 정책 사실과 개인 상태만 바꿨을 때 시민의 실제 구매·결제·이동이 어떻게 달라지는가?
2. 그 차이가 반복 실행에서 유지되는가? 방향과 대략적인 크기가 외부 자료와 호환되는가?
3. 범용 프롬프트 변경의 효과와 소비 엔진이 강제하는 효과를 구분할 수 있는가?

정책별로 v5와 사전 검증을 통과한 후보를 동일 엔진에서 비교한다. 두 후보를 모두
본 검증에 포함하려면 둘 다 실행 계약을 충족해야 한다. 실패한 기준선을 성공한 것처럼
취급하지 않는다. 각 후보에서 같은 시민·초기 상태·날짜를 사용하는 on/off 경로를 만든다.
프롬프트 비교량은 `(후보 on-off) - (v5 on-off)`이며 정책 효과 자체와 별도로 보고한다.
개인 간 대화가 있으면 run 전체가 하나의 상호작용 집단이다. 개인을 서로 독립인
처치 단위로 취급하지 않고, 두 경로 사이에는 기억·대화·소문을 공유하지 않는다.

| 항목 | 등록할 내용 |
|---|---|
| 정책 | P012, P013, P014, 거리두기: 이미 알려진 개발 사례. P015 재사용 금지 |
| 개입 | 정책 파일 및 개인별 수급 상태. 거리두기는 질병 배경을 유지하고 규제만 변경 |
| 시간 | 외부 연구의 관측 기간과 일치. 기전 비교만 하는 짧은 창은 별도 탐색 분석 |
| 표본 | 동일한 고정 시민 명단, 소비 분위별 할당·모집단 가중치·난수 seed 저장 |
| 초기 상태 | 공통 warmup 후 모든 상태·기억·계획·대화·지갑 스냅샷에서 on/off 복제 |
| 반복 | 시민 표본과 독립된 실행 seed 여러 개. 호출 순서·온도·모델·엔진·코드 해시 고정 |

| 보조 결과 | 개인 부담액, 정책 재원 사용, 구매량·방문수, 소득/소비 분위별 이질성 |

## 필요한 실행 구조

현재의 공유 DB 초기화 기반 stage8 런처는 사용하지 않는다. 별도 Neo4j 인스턴스나
검증된 run namespace가 필요하다. namespace 방식은 모든 read/write가 run을 격리함을
검사해야 하므로 환경변수 하나 추가한 것만으로 완료라고 보지 않는다.

- Day t의 대상 시민 전원과 예정된 Night 단계가 완료된 뒤에만 Day t+1로 이동한다.
  실패 시 즉시 해당 경로를 멈추고 오류를 보존한다. 실패를 0원이나 정상 무외출로 채우지 않는다.
- 사전 명단×날짜 원장에 완료 여부, raw LLM 응답, 보정 전후 계획, 구매·결제 내역,
  정책 적격 여부, 온라인 지출, 시작/종료 현금·지갑을 기록한다.
- 완료 원장과 DB 상태를 같은 날 경계에서 검증한다. 현금 및 지갑 입출금 보존,
  총소비=개인 재원+정책 재원, 온라인 중복 없음, 완료 0원 보존을 확인한다.
- DB 쓰기 도중 실패한 agent-day를 단순 재호출하지 않는다. 스냅샷 복원 또는 검증된
  원자 커밋으로만 재개한다. 실패 시도와 재시도는 별도 식별자를 가진다.
- 일별 완료 스냅샷과 SHA-256 manifest를 서버 밖으로 복제한다. SSH 단절 시험은
  성공해도 서버 회수 시 데이터 보존 계약을 대신하지 않는다.
- 어제의 방문 기억이 오늘의 Dawn 입력에 들어가는지 단계 순서를 검사한다.
  `night_finalize_yesterday`를 Dawn보다 먼저 실행하도록 수정했고, 재실행 시 같은 방문을
  중복 집계하지 않도록 했다. 이 수정은 별도 검증 checkout에 적용했다. 실 DB에서 롤백되는
  통합검사를 통과했으며, 종단 전체 경로에 대해서는 별도의 완료 장벽과 상태 검사가 필요하다.

## 외부 비교 계약

수치별 출처, 지역·대상·기간, 대조군, 결과 정의, 분모, 단위, 추정 불확실성을 먼저
표로 등록한다. `%`, `%p`, 원/인/일을 혼합하지 않는다. 개인 모형과 가구 지원금 연구,
방문 지출과 카드 매출, 2일과 월간 결과는 자동으로 같은 추정량이 되지 않는다.

호환되는 항목에 한해 상대 효과의 부호와 사전 정한 대역(예: 외부 추정치의 0.5~2배)을
보고한다. 외부 효과가 0에 가까우면 배수 기준은 사용하지 않고 수준 차이/동등성 범위를
등록한다. 범위는 이번 후보의 결과를 본 뒤 넓히지 않는다. 호환되지 않는 항목은
비교 불가로 남긴다. 거시 정답과 비교표는 프롬프트 입력과 분리한다.

## 표본과 불확실성

이번 12명 파일럿은 실제 지출 분산이나 거시 효과를 추정하지 않으므로 여기서 나온
소비 의향의 차이로 본 실험 표본 수를 결정하지 않는다. 먼저 고정된 후보로 비용 및
지출 분산을 측정하는 별도 엔진 파일럿을 등록하고, 최소 탐지 효과(MDE), run 간 분산,
소비 분위 가중치와 실패율을 사용해 표본·반복 수와 예산을 확정한다. 작은 실행 오차를
보장할 수 없으면 n만 늘리기보다 독립 경로 반복을 늘린다.

각 반복의 정책 효과와 분포를 먼저 제시한다. 동일 반복 안의 시민쌍을 유지하는 표본
불확실성과 반복 간 실행 변동을 구분한다. 여러 지표 중 좋은 결과만 고르지 않고
정책별 주 지표와 다중 비교 규칙을 사전에 고정한다. 방향이 같은 비유의 점추정과
유의한 결과를 구별하고, CI가 0을 포함한다는 이유만으로 무효과를 승인하지 않는다.

## 엔진 민감도와 범용성

기준 엔진의 소득별 propensity clamp, 비방문 소비 몫, 계획 금액/앵커 결합 규칙이
원문 선택을 얼마나 바꾸는지 먼저 기록한다. 합리적인 대안 설정의 민감도 실험은
본 비교와 별도 요인으로 등록하고 양쪽 on/off에 동일하게 적용한다. 결과에 잘 맞는
설정만 채택하지 않는다. 범용 프롬프트의 장점은 원문 미시 행동과 실제 거래에서
함께 확인한다. 새 정책으로의 외부 검증은 아직 사용하지 않은 정책·자료를 확보하고
후보를 동결한 뒤 실시한다.

## 시작 조건

사전 검증 통과, 경로 격리, 완전성 장벽, 전체 원장, 외부 비교 계약, 표본·반복 및 비용
등록까지 완료한 뒤 본 실험을 시작한다. 사용자에게 실행 권한은 이미 받았다.
조건을 만족시키기 전에는 단순히 많은 호출을 실행한 것을 본 검증이라고 보고하지 않는다.
