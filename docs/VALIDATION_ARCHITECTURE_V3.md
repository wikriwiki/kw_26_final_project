# 검증 아키텍처 재검토 — 2026-09-19

## 판단

현재 v5는 기존 개발 실험에서 선택된 기준선이다. 지금까지의 결과만으로 범용 정책 효과나
효과 크기까지 검증된 최적 프롬프트라고 부르기는 어렵다. 목표는 동일 시민의 환경과 정책
조건에서 나오는 미시 선택을 모아 방향과 대략적인 크기를 설명하는 것이다. 정확한 효과
수치를 맞추도록 프롬프트를 조정하지 않는다. 아래 수정부터 새 실험 세대로 구분한다.

점추정이 달라졌다는 이유만으로 '표본을 늘리니 참값에 수렴했다'거나 '결함이 없었다'고
단정하지 않는다. 과거 결과는 해당 설정에서 관측한 결과로 보존한다.

## 크기 검증의 계약

동일 시민 i, 같은 평가 기간 W에서 효과는 `mean(Y_i,on(W)-Y_i,off(W))`로 정의한다.
모든 완료 표본에 대한 평균이며 양쪽에서 소비한 사람만 남기지 않는다. 완료한 시민의
0원은 관측이고 실패·미완료는 결측이다. 두 경우를 혼합해 0으로 채우지 않는다.

- 수준 변화: 원/인/일 또는 기간 합계. 정책 전후·반사실 경로를 모두 보존한다.
- 상대 변화: 차이를 동일 표본 off 평균으로 나눈 값. 평균 개인 변화율과 구분한다.
- 비중 변화: percentage point. '상대 비중이 21.5% 증가'와 '+21.5%p'를 구분한다.
- 총소비: 방문 및 비방문 지출 합계. 자금 출처 변경과 소비 증가를 구분한다.
- 무효과: 사전 동등성 범위와 신뢰구간으로 판단한다. 0을 포함하는 CI만으로 통과시키지 않는다.

실측의 0.5~2배라는 범위는 분모·지역·대상·정책·기간·결과 정의가 호환될 때만 적용한다.
2일 모형과 한 달 실측의 불일치를 기간 때문이라고 단정하거나 임의 선형 환산하지 않는다.
기간이 다르면 크기 비교는 '비교 불가/탐색적'으로 보고하고 동일 기간 검증을 설계한다.
2025년 서울 매출 앵커를 2020년 조건에 적용하는 점도 시간적 전이 가정으로 기록해야 한다.

`MAGNITUDE_CRITERION`의 이전 수치와 해석은 실험 이력으로 보존한다. 새 감사 주석이
현재 판정의 우선 근거다. '두 기간이 다르므로 효과가 작을 수밖에 없다'는 원인 단정은
철회한다. 캐시백·상품권의 총소비가 반드시 불변이어야 한다는 방향도 프롬프트나 엔진의
정답으로 넣지 않는다. 그러한 결과가 외부 연구에서 관측됐다면 해당 연구의 대상과
추정량에 한정한 검증 가설로만 사용할 수 있다.

## 단계별 실행과 판정

1. 코드·사실 입력 검사: P010 불변, 지급/적립/사용처 사실 정합성, 현금·정책지갑 보존,
   출력 실패와 결측의 구분. 모든 군에 같은 엔진을 적용한다.
2. 이번 실행: `validation_v3.json`에 사전등록한 384개 Stage1 호출. 같은 페르소나·날짜·
   합성 Day0·zone를 고정하고 v5/v10, on/off, 2개 seed를 교차한다. 실제 EXAONE으로
   수행하되 Neo4j는 읽기만 한다. 이는 무기억 초기 상태에서의 기전 해석 파일럿이다.
3. 원문 일정 계약 통과율 95% 이상, 요청 실패 0건, fiscal off의 혜택 귀인 경고 0건일 때만
   다음 단계 적격. 경고는 규칙 기반이므로 원문도 수동 검토한다. 후보를 이번 결과에 따라
   수정해 같은 사전등록 실험으로 다시 넣지 않는다.
4. 후속 종단 검증: 일자별 완전성 장벽과 전체 원장 스냅샷을 먼저 구현한다. warmup 후
   동일 사전 상태에서 fork한 on/off를 독립 DB/namespace에서 실행한다. 정책별로 두
   후보·반복 경로·무정책 대조를 고정한다. warmup 수렴은 3일이라는 숫자만 믿지 않는다.
5. 충분한 반복과 표본으로 방향, 크기, 개인 이질성, 엔진 민감도를 보고한다. n은 이번
   파일럿 효과에 맞춰 마음대로 정하지 않고 MDE·비용·실패율을 사용해 새로 사전등록한다.
6. 범용성 판정은 새로운 외부 정책/자료로 한다. P015는 다시 호출하지 않는다.

이번 Stage1 파일럿에는 POI 선택·지출 정산·Night 기억 전이가 없으므로 성공하더라도
실제 지출이나 사회 전체 정책 효과 검증이 완료된 것은 아니다. 이는 장기 실험을
시작하기 전에 통과해야 하는 첫 단계이며, 최적 프롬프트를 확정하는 최종 순위표가 아니다.
