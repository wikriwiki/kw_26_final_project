# 고정한 범용 후보의 반복 변동 확인

daily_v1의 v25 계획·결제 전96조건이 독립 검사를 통과하면, 같은 문구와 동일한 입력을
유지한 채 seed56001/57001의 계획192조건을 추가한다. 입력 SHA256은
`78961fc28d0f27915a58b2db58c22d3fdc888f3e4be4bbfc6d56dbf054e29000`이다.
`validation_daily_v2_v25_repeats.json`에 실행 전에 등록한다. 기존12명·알려진 정책이며
새 홀드아웃이라고 부르지 않는다. 이전 seed52001은 재실행하지 않는다.

계획별512추론 토큰·온도0.2·같은 시각/장소 문법·상품 목록·의무·선택적 필요를 유지한다.
모든 실패 원문을 보존하고 원문·실행·사실·요청 적격성과 평균 생성량을 확인한다.
각 완전한 적격 반복에서 결제96조건을 따로 생성해 원래 v7/v4/잔액 입력으로 연결한다.
결제 seed53001을 유지해 구매 난수 설정을 고정하되, 실제 경로가 바뀌면 모델 출력이
달라질 수 있음을 명시한다. 조건을 줄이거나 성공한 행만 골라 점수를 만들지 않는다.

확인할 것은 같은 시민·같은 조건의 반복 변동, 동일 seed의 on/off 차이,
각 반복의 좁은 상품 목록 내 소비 차이다. `plan_variation_audit.py`의 행동열 거리와
원문 기반 연결 소비 보고서를 함께 읽는다. 행동열 거리를 소비 효과 크기로 쓰지 않는다.
두 반복에서 정책 부호가 다르더라도 실패를 숨기거나 원하는 부호로 재생성하지 않는다.
관찰 결과에 따라 공통 문구에 특정 정책의 행동·수치·기대 부호를 추가하지 않는다.

이 시험에서 확인 가능한 것은 조건부 반복 안정성이다. 두 추가 반복만으로 통계적 유의성,
인구 대표성 또는 현실 정책 효과의 크기를 입증하지 않는다. 현재 하루·합성 재고·좁은
상품 목록·합성 자격·미완성 환급 및 다일 상태 전이의 한계는 그대로다.
그 한계를 해결할 때까지 반복 횟수나 시민 수 확대만으로 외부 타당성 판정을 대신하지 않는다.

## 계획 완료와 발견한 물리적 실패

192/192 원문·시간/장소 실행 적격, 시각 보정0, 평균715.42토큰이다. 실제 요청384개를
감사했고 입력·원문·기록 대조 오류는0건이다. 출력 검사 전에 고정한48개 검토 표본
(실행 시작 후 지정, 시민12명×양쪽arm×두seed, 기전은 시민 순서에 따른 순환 배정)을
읽었다. 나머지144개에 대해서는 자동 원문 검사를 했으며 전부 수동 검토했다고 하지 않는다.
인접 중복4건, 근무 시작 뒤 준비0건, 의무 반복1건이었다. 이른 저녁 취침 표기와 늦은
집 준비 등 표현 한계도 남았다. 계획 전체 압축본은 서버 밖 복사 및 해시 대조를 마쳤다.
SHA256: `20740208fc997ed6bd81d8ce4e864b942884b33e0809ec7eb835c13980575cfd`.

동일 조건의 반복 간 행동열 거리는0.366~0.416, 같은seed의on/off 거리는0.381~0.448이다.
비슷한 규모라는 기술 관찰이며 소비 효과·신뢰구간·유의성 판정은 아니다. 조건부 결제와
원본 연결까지 통과해야 소비 대조를 계산한다. 반복을 새로운 시민으로 세지 않는다.

**자원 사용 활동9개를 추가 확인하면서 실행 불가능한 계획1개를 발견했다.**
seed57001, AGT_11620565_F_70대이상_001, distancing/on에서 초기 세제0회분인데
14:00 주문 검토 뒤15:00 세탁을 골랐다. 입력의 배송 시간은90분이다. 어떤 결제 선택을
하더라도 세탁 시작 전에 세제가 도착하지 않는다. raw/time valid는 이 물리적 타당성을
포함하지 않았으므로192/192를 전체 미시 타당성 통과로 해석하면 안 된다.

새 `resource_feasibility.py`로 모든 후보를 전부 구매할 수 있다고 낙관해도 필요한
시점의 자원이 부족한지 확인했다. seed56001에서는0개,57001에서는1개가 불가능했다.
이는 원래 주어진 배송/재고 규칙 위반을 찾은 것이며 정책 효과 합격선을 바꾼 것이 아니다.
이 검사 통과는 자금이나 상호 배타적인 상품 선택의 실현 가능성을 증명하지 않는다.
4개 표적 검사 통과. 원문은 수정하지 않았고 두 반복의 등록 결제 검증을 그대로 보존한다.

현재 v25는 확대 물리적 실행 검증을 통과한 최적판이 아니다. 후속에서는 알려진 자원
불가능성을 계획과 결제 사이에 검사하고, 수정 실험이 필요하면 오류와 수정 요청을 모두
기록한 별도 프로토콜로 시험해야 한다. 실패한 한 행을 삭제하거나 세탁 시간을 자동으로
밀어 기존 결과를 성공으로 바꾸지 않는다. 실제 결제 실패가 있는 전체 반복은 비교 보고서가
거부하며, 나머지 성공한 행만으로 효과를 만들지 않는다.
