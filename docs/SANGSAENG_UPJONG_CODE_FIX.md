# 상생 제외업종 판정 — 상호명 룰 → 원천 업종코드 전환 (SANGSAENG_UPJONG_CODE_FIX)

> 대상: `scripts/sim/sangsaeng_eligibility.py`, `scripts/neo4j_load/11_sangsaeng_eligibility.py`
> 선행 문서: `docs/POLICY_BACKTEST_SANGSAENG.md` §4.3 (카테고리 매핑·제외 arm)
> 실행 환경: **원천 CSV·Neo4j가 있는 머신** (작성자 로컬 아님 — §7 참조)

## 0. 요약

상생소비지원금 백테스트의 제외군(C1 대조군)을 **상호명 정규식이 아니라 소상공인시장진흥공단
표준 업종 L3 코드**로 판정하도록 바꾼다.

- 유흥주점 2,365개·복권 1,038개가 지금 **적립업종으로 잘못 분류**되어 있다. 상호명 룰로는
  원리적으로 분리 불가능하다 (§2).
- 원천 코드는 `data/neo4j_load/mapping/mapping_upjong_to_sub.json`에 이미 다 있다 (§3).
- **그래프 재적재 불필요.** POI id가 `C_{상가아이디}`로 결정론적이라 백필 스크립트에서
  원천 CSV를 직접 조인하면 된다 (§5).
- 페르소나가 보는 프롬프트·후보 순위·카테고리 체계는 **일절 바뀌지 않는다** (§6).

기대 결과: C1 대조군이 시계·귀금속 2,404개 하나 → **3개 arm**으로 확장, 판정 근거가
룰 근사에서 결정론적 코드 조인으로 승격.

### 0.1 최종 결론표 — 상생 제외업종을 우리 데이터에서 어디까지 발라낼 수 있나

| 상생 제외업종 (정부) | 우리 데이터 | 분리 방법 | 최종 상태 |
|---|---|---|---|
| 명품전문매장 | `G21701` 시계·귀금속 (2,404) | **업종코드** | ✅ `excluded_luxury` |
| 유흥 | `I21101`+`I21102` (2,365) | **업종코드** (L2는 `일반주점`에 병합돼 있으나 코드로 분리) | ✅ `excluded_vice` |
| 사행 (복권) | `R10410` (1,038) | **업종코드** (L2는 `유원지·오락`에 병합) | ✅ `excluded_vice` |
| 비소비성지출 | `L10203`·`M103**`·`M104**` (40,614) | **업종코드** | ✅ `excluded_nonconsumption` (위약군, §4.1 단서) |
| 사행 (카지노·경마·경륜) | 전용 코드 없음 → 타 코드에 섞여 있을 수 있음 | **상호명 룰만** | ⚠️ 코드 분리 불가 (§3.4) |
| 유흥 (성인용품점·안마방 등 성인업소) | 전용 코드 없음 (`G22199`·`S20802`에 섞임) | 코드·상호명 **둘 다 불가** | ❌ 포기 — 적립으로 둠 (§4.3 실측) |
| 대형마트·백화점·면세·대형전자 | 전용 코드 없음 (`G20404 슈퍼마켓`만 존재) | **브랜드 룰만** | ⚠️ 코드 분리 불가 (§3.4) |
| 대형온라인몰·홈쇼핑 | 물리 POI 아님 | — | ❌ 구조적 부재 |
| 신차구입 | 판매 코드 없음 (부품·정비는 적립) | — | ❌ 코드 부재 |
| 실외골프장 | 연습장(`R10311`)만 존재 | — | ❌ 코드 부재 |

**변경 전 대비**: 유흥·사행(복권) 2행이 `⚠️ 상호명 룰만 / 일부·오염` → **`✅ 업종코드 / 완전 분리`**로
바뀌는 것이 이 작업의 핵심이다.

> ⚠️ **표 읽는 법 — "코드로 분리 불가"와 "존재하지 않음"은 다르다.**
> `mapping_upjong_to_sub.json`은 **업종 분류 체계**(L3 코드 247종)이지 POI 목록이 아니다.
> "카지노 코드가 없다"가 말해주는 것은 **"업종코드로는 못 가려낸다"**까지이고, 상호명에
> '카지노·경마·룸살롱'이 들어간 POI가 다른 코드로 등록돼 **실재할 수 있다**.
> 따라서 ⚠️ 행(카지노·대형업태)은 **상호명 룰을 유지해야 하는 영역**이다 (§4.3).
> 반대로 성인업소는 상호명으로도 포착이 안 된다는 것이 실측으로 확인되어 ❌로 내렸다.

**결과: 업종코드로 확정되는 제외군 = 명품 2,404 + 유흥·사행 3,403 + 비소비 40,614 ≈ 46,421.**
여기에 상호명 룰이 잡는 잔여분(카지노·대형업태)이 소량 더해진다.

## 1. 지금 무슨 일이 일어나고 있나

`scripts/sim/sangsaeng_eligibility.py`의 현행 판정:

```python
_NAME_VICE = re.compile(r"단란주점|유흥주점|룸살롱|나이트클럽|카지노|복권|로또|성인|안마방")
...
if _NAME_VICE.search(n):
    return ARM_EXCLUDED_OTHER, "vice_or_gambling"
```

**상호명에 저 단어가 글자로 박힌 가게만** 잡는다. 실제 유흥주점 상호는 "황금성", "블루문",
"가라오케○○" 같은 식이라 대부분 걸리지 않는다. 즉 유흥주점 2,365개 중 극소수만 제외되고
**나머지는 전부 `eligible`(적립)로 새어나간다.**

시뮬 런타임에도 그대로 전파된다 — `stage2_poi.py`가 이 판정으로 `[적립]` 태그를 붙이므로,
**페르소나에게 유흥주점이 "실적 인정 매장"이라고 잘못 고지되고 있다.** 상생소비지원금
정책 기준(유흥·사행 제외)과 어긋난 상태이며, 백테스트 정답 대조 이전에 입력이 틀렸다.

## 2. 왜 상호명 룰로는 원리적으로 안 되나

우리 L2 `일반주점` 하나에 **성격이 정반대인 L3 셋**이 뭉쳐 있다:

| L3 코드 | 원 업종명 | 원천 건수 | 상생 판정 |
|---|---|---|---|
| `I21104` | 요리 주점 | **10,193** | 적립 (일반음식점) |
| `I21101` | 일반 유흥 주점 | 2,269 | **제외** |
| `I21102` | 무도 유흥 주점 | 96 | **제외** |

적립 10,193개와 제외 2,365개가 같은 L2 라벨을 달고 있다. 카테고리로는 못 가르고,
상호명으로도 못 가른다 (요리주점 이름에 "주점"이 들어가면 오탐, 유흥주점 이름에
"유흥"이 없으면 미탐 — 양방향으로 틀린다).

**L3 코드만이 유일하게 정확한 분리 축이다.**

사행도 같다. `유원지·오락` L2 안에 복권판매점(`R10410`, 1,038)이 전자게임장·낚시터·
바둑기원과 섞여 있다.

### 3.4 업종코드로 분리되지 않는 것 (상호명 룰의 잔여 영역)

> **이 절의 전제 — 매핑 파일이 말해주는 것과 말해주지 않는 것**
>
> `mapping_upjong_to_sub.json`은 **업종 분류 체계**다 (L3 코드 247종 → 우리 L1/L2).
> POI 목록이 아니다. 따라서 "카지노 코드가 없다"에서 도출되는 결론은 정확히
> **"업종코드로는 카지노를 가려낼 수 없다"**까지다.
>
> 상호명에 '카지노·경마·룸살롱'이 들어간 POI가 **다른 코드로 등록되어 실재할 수 있다**
> (예: 상호 "○○카지노바"가 `I21104 요리주점`으로 등록). 실재 여부와 규모는
> **DB 상호명 조회로만 확인 가능**하다. 다만 룰 패턴은 §4.3에서 이미 확정했으므로
> **추가 실측 없이 인계 가능**하다. 백필 후 §8.5 T4-⑥ 한 쿼리로 룰이 잡은 것을 훑어보면 된다.

매핑 247개를 전수 조회한 결과, 아래 항목은 **전용 L3 코드가 없어 코드 조인으로 분리할 수 없다.**

| 상생 제외 항목 | 코드 조회 결과 | 대응 |
|---|---|---|
| 사행 — 카지노·경마·경륜·경정·토토 | `카지노/경마/경륜/경정/토토/도박` 키워드 매칭 **0건** | **상호명 룰 유지** (오탐 없는 고유어라 검증 불필요) |
| 대형마트·백화점·아울렛·복합몰·면세점·대형전자전문점 | 전용 코드 없음. `G20404 슈퍼마켓`(7,862)에 대형/소형이 뭉쳐 있음 | **브랜드 앵커 룰 유지** |
| 유흥 — 성인용품점·성인오락실·안마방 등 성인업소 | 전용 코드 없음. `G22199 그 외 기타 상품 전문 소매업`(3,484)·`S20802 마사지/안마`(1,060)에 일반 업소와 뭉쳐 있음 | **포기 — 상호명으로도 포착 불가** (§4.3 실측) |

> **성인업소를 코드로도 상호명으로도 뺄 수 없는 이유**: `G22199`·`S20802`는 잡화 통이라
> 코드로 제외하면 멀쩡한 소매점 3,484개·마사지샵 1,060개가 함께 날아간다. 그렇다고 상호명도
> 안 된다 — 실측상 `성인용품`·`안마방` 등 복합어 매칭이 **0건**이고 `성인` 단독은 100% 오탐
> ("삼성인쇄", "성인피아노학원")이기 때문이다 (§4.3 실측 박스). **적립으로 두고 §10에 명시한다.**

아래 항목은 코드도 없고 **물리 POI로 존재할 수도 없어** 상호명 룰로도 대응 불가하다.
이것만이 "포기 확정"이다:

| 상생 제외 항목 | 사유 |
|---|---|
| 대형 종합 온라인몰·홈쇼핑 | 물리 POI 아님. 우리 시뮬은 이동 기반이라 발생 자체가 불가 |
| 신차 구입 | 자동차 **판매** 코드 없음 (부품 `G20202`·정비 `S20301`·세차 `S20302`만 존재, 전부 적립) |
| 실외골프장 | 연습장(`R10311`, 1,478)만 존재. 실외골프장은 서울 모집단에 없음 |

→ 리포트 한계 절에 명시할 것 (§10).

## 4. 해결 설계

### 4.1 arm 정의 (4종)

| arm | 정의 | 규모 | 통계적 성격 |
|---|---|---|---|
| `eligible` | 그 외 전부 | 대다수 | 처치군 |
| `excluded_luxury` | `G21701` | 2,404 | 제외 + **반응 가능** (windfall 사치 반응 여지) |
| `excluded_vice` | `I21101`,`I21102`,`R10410` | 3,403 | 제외 + **반응 가능** |
| `excluded_nonconsumption` | `L10203`, `M103**`, `M104**` | 40,614 | 제외 + **반응 원천 차단** = 순수 위약 |

`excluded_other`는 잔여 버킷으로 유지한다 (브랜드 룰이 잡은 대형업태 등).

**arm을 셋으로 나누는 이유**: C1의 논리는 "제외군은 캐시백에 반응하면 안 된다"인데, 세 arm의
반응 가능성이 다르다. 부동산·법무·세무는 캐시백 때문에 세무사를 찾아갈 이유가 구조적으로
없으므로 **가장 강한 위약**이다. "명품·유흥은 조금 움직이는데 비소비는 안 움직인다"는 패턴이
나오면 C1 통과를 넘어 windfall 반응의 성질을 보여주는 결과가 된다.

> ⚠️ `excluded_nonconsumption`은 **정책 원문의 '비소비성 지출' 정의와 정확히 일치하지 않는다.**
> 정책의 비소비성 지출은 보험료·세금·공과금·등록금 같은 *거래 유형*이지 매장 업종이 아니다.
> 이 arm은 **"정책상 제외라서"가 아니라 "캐시백에 반응할 수 없어서"** 대조군이다.
> 리포트에서 이 성격으로 서술할 것. `sangsaeng_eligible=False`는 현행 유지.

### 4.2 판정 우선순위

상호명 룰은 **폐기가 아니라 역할 재배치**다. 코드가 닿는 영역에서는 물러나고,
코드가 닿지 않는 영역(§3.4)에서는 유일한 수단으로 남는다.

```
① L3 코드 조인 (제외 코드 목록에 해당)  → arm 확정            src="upjong_code"
② 상호명 룰 — 코드가 분리 못 하는 항목만  → arm 확정            src="rule_name"
     · 카지노·경마·경륜·경정·토토    (사행,   코드 부재)
     · 대형마트·백화점·면세점 브랜드  (대형업태, 코드 부재)
     ※ 성인업소군은 상호명으로 포착 불가라 다루지 않는다 (§4.3 실측 박스)
③ 코드가 있고 ①②에 안 걸림             → eligible 확정        src="upjong_code"
④ 코드 미확보 POI                      → 기존 L2 룰 fallback  src="rule_fallback"
```

②를 ①보다 **뒤에** 두는 이유: 코드로 확정된 arm이 상호명 오탐에 덮이면 안 된다.
단 ②는 ③보다 **앞**이다 — 코드가 `요리주점`이어도 상호가 "○○카지노"면 사행으로 잡아야 한다.

### 4.3 상호명 룰 정리 — 무엇을 빼고 무엇을 남기나

**원칙: 업종코드가 커버하는 패턴만 뺀다. 코드가 못 닿는 패턴은 남긴다.**

| 패턴 | 조치 | 이유 |
|---|---|---|
| `단란주점\|유흥주점\|룸살롱\|나이트클럽` | **삭제** | `I21101`/`I21102` 코드가 정확히 대체 (2,365개 완전 포착) |
| `복권\|로또` | **삭제** | `R10410` 코드가 정확히 대체 (1,038개 완전 포착) |
| `성인` · `안마방` (성인업소군 전체) | **삭제 — 추가하지 않음** | **실측 결과 효용 0, 오탐만 발생** (아래 박스). 성인업소는 상호에 업태명을 쓰지 않아 상호명으로 포착 불가하며, 규모도 대조군 46,421 대비 무시 가능 |
| **`카지노\|경마\|경륜\|경정\|토토` (신규 보강)** | **유지·추가** | **코드가 존재하지 않는 유일한 사행 포착 수단** (§3.4) |
| `_NAME_LARGE` 고유 브랜드 | **유지** | `이마트(?!24)\|홈플러스\|롯데마트\|코스트코\|이케아\|트레이더스\|하이마트\|전자랜드` — 오탐 0, 코드로 분리 불가한 대형업태의 유일한 수단 |
| `_NAME_LARGE`의 `백화점\|면세점\|아울렛` | **브랜드 앵커화** | 일반명사 그대로 두면 "고기백화점·정육백화점·백화점약국"이 오탐. 앞에 브랜드를 붙여 `(롯데\|신세계\|현대\|갤러리아\|AK)백화점` 형태로 좁힌다 |
| `_NAME_LARGE` 전체에 **상호 맨앞 앵커(`^`)** | **추가 적용** | 구현 중 실측으로 발견 — 부분일치는 "국대떡볶이**이마트**목동점"·"깐부치킨 압구정**현대백화점**"처럼 **대형점 입점·인근 소상공인**을 대량 오탐한다 (§9-7). 140,140건 대조 시 190건 → **10건** |
| `_SUB_LUXURY` / `_SUB_NONCONSUMPTION` | **유지** | 코드 미확보 POI(④)의 fallback으로 계속 필요 |

> ### 성인업소군을 다루지 않기로 한 근거 (실측)
>
> 서울사랑상품권 가맹점 실측 데이터(`data/coupon/seoul_love_merchants.csv`, 140,140건)에서
> 관련 패턴을 전수 조회한 결과:
>
> | 패턴 | 매칭 | 실물 |
> |---|---|---|
> | `성인용품`·`성인오락`·`안마방`·`키스방`·`휴게텔` | **0건** | — |
> | `성인` 단독 | 34건 | **전부 오탐** — 삼성**인쇄**, 삼**성인**지감성연구소, 동대문여**성인**력개발센터, **성인**취미미술학원, **성인**피아노학원 |
>
> **복합어는 아무것도 잡지 못하고, 단독어는 100% 오탐이다.** 성인업소는 간판에 업태명을
> 쓰지 않으므로(‘○○샵’ 형태) 상호명으로는 원리적으로 포착되지 않는다.
>
> 규모 면에서도 무의미하다 — 설령 수백 개를 잡아낸다 해도 제외군 46,421개 대비 1% 미만이라
> C1 검정 결과를 바꾸지 못한다. 반면 `성인` 단독 패턴을 넣으면 "삼성인쇄" 같은 적립업종이
> 대조군에 섞여 **오염 손실만 발생**한다.
>
> → **성인업소는 적립(`eligible`)으로 둔다. §10 한계에 명시한다.**
> 이 결정으로 **서버 측 상호명 튜닝 단계가 통째로 사라진다** (별도 실측 쿼리 불필요).
>
> ---
>
> `백화점\|면세점\|아울렛`은 브랜드 앵커화한다 — 일반명사 그대로면 "고기백화점·정육백화점"이
> 오탐이기 때문이다. 제외군은 C1 대조군이라 **오염이 미탐보다 해롭다**는 원칙을 일관되게 적용한다.

### 5.1 `scripts/sim/sangsaeng_eligibility.py`

```python
# 신규: L3 코드 → arm 확정 테이블
_CODE_LUXURY = {"G21701"}
_CODE_VICE = {"I21101", "I21102", "R10410"}
_CODE_NONCONSUMPTION = {
    "L10203",                                                    # 부동산 중개
    "M10301", "M10302", "M10303", "M10306", "M10307", "M10399",  # 법무
    "M10401", "M10402", "M10499",                                # 회계·세무
}

ARM_EXCLUDED_VICE = "excluded_vice"
ARM_EXCLUDED_NONCONSUMPTION = "excluded_nonconsumption"


def arm_from_code(code: str | None) -> tuple[str, str] | None:
    """L3 업종코드로 arm 확정. 제외 코드가 아니면 None (=상위에서 eligible 처리 or 룰)."""
    c = (code or "").strip().upper()
    if not c:
        return None
    if c in _CODE_LUXURY:
        return ARM_EXCLUDED_LUXURY, "code_luxury"
    if c in _CODE_VICE:
        return ARM_EXCLUDED_VICE, "code_vice"
    if c in _CODE_NONCONSUMPTION:
        return ARM_EXCLUDED_NONCONSUMPTION, "code_nonconsumption"
    return None


def sangsaeng_arm(name, sub, l1=None, upjong_l3=None) -> tuple[str, str]:
    """코드가 있으면 코드 우선, 없으면 기존 상호명/L2 룰."""
    if upjong_l3:
        hit = arm_from_code(upjong_l3)
        if hit:
            return hit
        return ARM_ELIGIBLE, "code_eligible"   # 코드가 있고 제외목록에 없으면 확정 적립
    # ... 기존 룰 (fallback) ...
```

**하위호환**: `upjong_l3` 는 키워드 기본값 `None`. 기존 호출부
(`stage2_poi.py`, 자체 테스트)는 수정 없이 그대로 동작한다.

```python
C_ID_COL, C_UPJONG_COL = 0, 7    # 상가아이디, 상권업종소분류코드 (03_pois.py C_COL 과 동일)

def load_upjong_index(csv_path: Path) -> dict[str, str]:
    """상가 원천 CSV → {POI id: L3코드}. POI id = f"C_{상가아이디}" (03_pois.py 규약)."""
    idx = {}
    for enc in ("utf-8-sig", "cp949", "euc-kr"):
        try:
            with io.open(csv_path, encoding=enc, newline="") as f:
                rd = csv.reader(f)
                next(rd, None)                      # 헤더
                for row in rd:
                    if len(row) > C_UPJONG_COL and row[C_ID_COL]:
                        idx[f"C_{row[C_ID_COL]}"] = row[C_UPJONG_COL].strip()
            break
        except (UnicodeDecodeError, UnicodeError):
            idx.clear()
            continue
    return idx
```

## 6. 그래프에 무엇이 들어가고, 무엇이 안 바뀌나

### 6.0 "속성"과 "구조"의 구분 (혼동 주의)

적립/제외 판정 결과는 **그래프에 들어간다.** POI 노드의 속성으로 기록된다:

```cypher
SET p.sangsaeng_eligible = true/false,   // 적립 여부
    p.sangsaeng_arm = 'excluded_vice',   // 어느 제외군인지
    p.sangsaeng_kdi = '요식',             // KDI 8분류 (적립 POI만)
    p.sangsaeng_src = 'upjong_code'      // 무엇을 근거로 판정했는지
```

이건 **새로 생기는 일이 아니다.** `11_sangsaeng_eligibility.py`가 원래부터 하던 일이고,
지금도 `p.sangsaeng_eligible`을 쓰고 있다. 이번 변경은 **그 값을 무엇을 보고 정하느냐**만
바꾼다 — 상호명 정규식 → 업종코드.

따라서 두 가지를 구분해야 한다:

| | 내용 | 이번에 |
|---|---|---|
| **구조 변경** | 노드 추가·삭제, 관계 추가·삭제, Category 체계 변경, `03_pois.py` 재적재 | ❌ **안 함** |
| **속성 쓰기** | 이미 존재하는 POI 노드에 라벨 값을 `SET` | ✅ **함** (원래 이 스크립트의 역할) |

비유하면 — 건물(노드)과 도로(관계)는 그대로 두고, 각 건물 대문에 붙은 스티커(속성)의
내용만 다시 쓰는 것이다. 건물을 새로 짓거나 도로를 다시 깔지 않는다.

### 6.1 안 바뀌는 것 (안전 보증)

이 변경이 **무엇을 바꾸지 않는지** 명시한다. 재적재 우려에 대한 답이다.

| 항목 | 영향 |
|---|---|
| `03_pois.py` / POI 노드 / 관계 | **수정 없음, 재적재 없음** |
| `categories.yaml` / `Category` 노드 / `IN_CATEGORY` | **변경 없음** — 유흥주점은 여전히 L2 `일반주점` |
| desire 파라미터 / 후보 생성 / Huff prior | **변경 없음** |
| 페르소나 프롬프트 렌더 (`stage2_poi.py:459-464`) | **`upjong_l3`는 프롬프트에 안 들어감** |
| 후보 정렬 순위 | **변경 없음** — `POLICY_POI_SORT_BOOST=0` 기본이라 태그가 순위에 무영향 |
| `coupon_eligible` / P010 소비쿠폰 | **변경 없음** — 별도 속성, 다른 정책 기준 |
| OFF(대조) 런 | **완전 동일** — `sangsaeng_active=False`면 태그 자체가 안 붙음 |

**유일하게 바뀌는 런타임 동작**: ON 런에서 유흥주점 2,365개·복권 1,038개에 `[적립]` 태그가
안 붙는다. 이는 임의 변경이 아니라 **정책 기준에 맞추는 버그 수정**이다.

## 8. 테스트 계획

### 8.0 역할 분담 — 누가 무엇을 확인하나

이 작업은 **작성 머신**(코드를 쓰고 넘기는 쪽, 원천 CSV 없음)과 **실행 서버**(CSV·DB가
있고 실제 백필을 돌리는 쪽)로 나뉜다. 테스트도 그렇게 나뉜다.

| | 테스트 | 명령 | 필요한 것 | 뭘 보나 |
|---|---|---|---|---|
| **작성 머신** | **TA** | `python scripts/sim/sangsaeng_eligibility.py --audit` | **없음** | ★ **적립/비적립이 제대로 갈리는지 전수 확인** |
| **작성 머신** | **T1** | `python scripts/sim/sangsaeng_eligibility.py` | **없음** | `ALL OK` 한 줄 |
| 실행 서버 | T2 | `... 11_sangsaeng_eligibility.py --check-csv` | CSV | 컬럼·인코딩이 맞는지 |
| 실행 서버 | T3 | `... 11_sangsaeng_eligibility.py --dry-run` | DB(읽기만) | 커버리지·arm 분포 |
| 실행 서버 | T4 | Neo4j 쿼리 (§8.5) | DB(백필 후) | **②번이 최종 합격 판정** |
| 실행 서버 | T5·T6 | 시뮬 런 / 프리플라이트 | DB(+GPU) | 무영향 회귀 (선택) |

> **작성 머신에서는 TA·T1 두 개만 돌리면 된다. 둘 다 DB·CSV 없이 도는 순수 함수 테스트다.**
> 판정 로직(`sangsaeng_eligibility.py`)은 입력 `(업종코드, 상호명, L2)` → 출력 `arm`인
> 순수 함수라, DB 없이도 로직 검증이 완결된다. 나머지는 인계 후 서버 담당이다.

> **서버 측 작업도 최소화했다.** 필수는 T2·T3·T4 세 개(명령 3줄 + 쿼리 붙여넣기 1회)이고,
> **눈으로 볼 것은 T4-② 하나**다. 상호명 패턴을 실측으로 튜닝하는 단계는 **두지 않았다** —
> 남긴 패턴(카지노·경마류, 대형마트 브랜드)이 전부 **오탐이 나올 수 없는 고유명사**라
> 검증이 불필요하기 때문이다 (§4.3). 성인업소군을 포기한 것도 같은 맥락이다.

> ⚠️ 아래 플래그는 **이번 작업으로 신설**되는 것이다 (현재 파일에는 `--dry-run`만 있음):
> `--audit`, `--check-csv`, `--commerce-csv`.

기대값을 미리 박아둔다. **실측이 범위를 벗어나면 원인 규명 전까지 진행 금지.**

> 주: §3의 건수는 원천 CSV(매핑 `_count`) 기준이다. DB 적재 시 좌표·행정동코드 누락 행이
> 탈락하므로 **DB 실측은 원천보다 약간 적을 수 있다**(수 % 이내). 그래서 허용 범위를 둔다.

### 8.5 T4 — 백필 후 DB 검증 쿼리 (실행 서버)

```cypher
// ① arm 분포
MATCH (p:POI {type:'commerce'})
RETURN p.sangsaeng_arm AS arm, count(*) AS n ORDER BY n DESC;

// ② ★ 최종 합격 판정 — 같은 L2 안에서 코드로 갈렸는가
MATCH (p:POI {type:'commerce'})-[:IN_CATEGORY]->(c:Category {name:'일반주점'})
RETURN p.sangsaeng_arm AS arm, count(*) AS n;
// 변경 전: eligible 12,558  (한 줄)
// 변경 후: eligible ≈ 10,193 / excluded_vice ≈ 2,365  (두 줄)  ← 두 줄이면 성공

// ③ 백화점 앵커화 결과
MATCH (p:POI {type:'commerce'})
WHERE p.name CONTAINS '백화점'
RETURN p.sangsaeng_arm AS arm, count(*) AS n;
// 기대: "고기백화점"류는 eligible, 브랜드 앵커가 붙은 진짜 백화점만 excluded_other

// ④ 브랜드 룰 잔존 확인
MATCH (p:POI {type:'commerce'})
WHERE p.name CONTAINS '이마트' AND NOT p.name CONTAINS '이마트24'
RETURN p.name, p.sangsaeng_arm LIMIT 20;

// ⑤ src 분포
MATCH (p:POI {type:'commerce'})
RETURN p.sangsaeng_src AS src, count(*) AS n;

// ⑥ 상호명 룰이 잡은 잔여분 전수 — 눈으로 검수
MATCH (p:POI {type:'commerce'})
WHERE p.sangsaeng_src = 'rule_name'
RETURN p.name, p.sangsaeng_arm ORDER BY p.name LIMIT 200;
```

**②가 이 작업 전체의 합격 판정이다.** `일반주점` L2 하나가 두 arm으로 갈리면 성공.

**⑥은 눈으로 봐야 한다.** 상호명 룰 판정은 코드 근거가 없으므로, 목록이 납득 가능한지
(진짜 카지노·대형마트인지) 직접 확인한다. 이상하면 §4.3 패턴을 다시 좁힌다.

## 9. 판단이 갈릴 수 있는 지점 (의도적 선택)

기록해둔다. 나중에 "왜 저렇게 했지" 소리 안 나오게.

1. **`R10404` 전자게임장·`R10405` 기타오락장(1,184)을 사행에 안 넣은 이유**
   상생 제외의 '사행'은 카지노·복권·경마 등 명확한 사행산업이다. 전자게임장에는 일반
   아케이드·키즈카페가 다수 섞여 있어 대조군 오염 위험이 이득보다 크다. 복권(`R10410`)만
   보수적으로 채택.

2. **`excluded_nonconsumption`을 정책 제외군이 아니라 위약군으로 명명한 이유**
   §4.1 경고 박스 참조. 정책 원문의 '비소비성 지출'은 거래 유형 기준이라 매장 업종과 개념이
   어긋난다. 통계적 역할(무반응 대조)로 정의하는 편이 정직하고 해석도 명확하다.

3. **상호명 룰을 폐기하지 않고 역할만 재배치한 이유**
   매핑 파일은 **분류 체계**이지 POI 목록이 아니다. "카지노 코드가 없다"는 "코드로 못 가른다"를
   뜻할 뿐, 상호명에 '카지노'가 든 POI가 다른 코드로 실재할 수 있다(§3.4). 코드가 닿지 않는
   사행(카지노·경마)·대형업태는 **상호명이 유일한 수단**이므로 남긴다. 코드가 정확히 대체하는
   부분(유흥주점·복권·안마방)만 뺀다.

4. **`sangsaeng_eligible`(bool) 정의는 그대로**
   arm만 세분하고 bool은 `arm != eligible` 유지. 다운스트림(`plan_writer.py:449`,
   `aggregate_period.py`, `stage2_poi.py`) 호환을 깨지 않기 위함.

5. **성인업소군을 아예 다루지 않기로 한 이유** (§4.3 실측 박스)
   상생 유흥 제외 취지에는 해당하지만, **코드로도 상호명으로도 잡을 수단이 없다.**
   코드는 `G22199`(잡화 3,484)·`S20802`(마사지 1,060)라는 통에 섞여 있어 빼면 일반 업소가
   함께 날아가고, 상호명은 실측 결과 복합어 매칭 0건 / 단독어 100% 오탐이다.

   설령 잡아낸다 해도 제외군 46,421개 대비 1% 미만이라 C1 검정 결과를 바꾸지 못한다.
   반면 `성인` 단독 패턴을 넣으면 "삼성인쇄" 같은 적립업종이 대조군에 섞여 **오염 손실만**
   발생한다. 제외군은 C1 대조군이므로 **오탐이 미탐보다 해롭다** — 적립업종이 섞이면
   "제외군도 캐시백에 반응한다"는 가짜 신호가 되어 판정 자체를 무너뜨리기 때문이다.
   같은 원칙으로 `백화점|면세점|아울렛`에는 브랜드 앵커를 붙였다.

   부수 효과로 **서버 측 상호명 튜닝 단계가 통째로 사라졌다.** 남긴 상호명 패턴은
   카지노·경마류와 대형마트 고유 브랜드뿐이고, 둘 다 오탐이 나올 수 없는 고유명사라
   실측 검증이 필요 없다.

6. **정책 100% 일치를 목표로 하지 않는다**
   관측 가능한 제외군은 정책 리스트의 부분집합이며(§10), 그것으로 충분하다. C1은
   "제외군 전체가 무반응"이 아니라 "**관측 가능한** 제외군이 적립군보다 유의하게 낮게
   움직인다"를 검정한다. 커버리지를 억지로 늘리려다 오탐을 들이는 것은 이 검정에
   오히려 손해다.

7. **`_NAME_LARGE` 에 상호 맨앞 앵커를 건 이유** (구현 중 실측)
   서울사랑상품권 가맹점 140,140건에 부분일치로 돌려보니 **190건이 매칭됐고 대부분
   오탐**이었다. 대형점에 입점했거나 인근임을 지점명으로 표시한 소상공인들이다:

   | 오탐 유형 | 실제 상호 |
   |---|---|
   | 대형점 입점 | 국대떡볶이**이마트**목동점 · 깐부치킨 압구정**현대백화점** · 던킨 목동**홈플러스**점 · 롯데리아 **홈플러스** 금천점 |
   | 인근 표시 | 다비치안경 시흥**홈플러스**앞점 · 강서**홈플러스**미플피부관리 |
   | 입점 편의점 | CU 금천**홈플러스**점 · CU 용산**전자랜드** 본관점 |
   | 부분일치 | 마곡 아**이마트** 안경원 |

   상호 맨앞(법인 접두어·그룹 표기만 허용)에서만 매칭하도록 바꿔 **190건 → 19건**,
   여기에 개별 오탐 3건을 교정해 **최종 10건**이 되었다:
   - `노브랜드(?!버거)` — 노브랜드**버거**는 SSG 가맹 햄버거집 (4건 오탐)
   - `이마트\s*에브리데이` — "에브리데이샐러드"·"에브리데이짐" 단독어 오탐 (4건)
   - `이마트(?!\s*24)` — 공백 낀 "이마트 24 관악조원점"이 lookahead를 우회 (1건)

   남은 10건은 롯데마트·롯데슈퍼·LG하이마트·홈플러스 익스프레스·현대아울렛 등으로
   대체로 타당하다. 전체의 0.007%라 몇 건이 오탐이어도 대조군에 영향이 없다.

   **트레이드오프**: "성수이마트"처럼 지역명이 앞에 오는 진짜 대형점은 놓친다.
   제외군은 C1 대조군이라 오탐이 미탐보다 해롭다는 원칙(§9-5)을 여기에도 적용했다.
   이 오탐들은 전부 §8.2 T1 회귀 케이스로 고정해 두었다.

## 10. 한계 (리포트에 반드시 명시)

> 본 백테스트의 제외군은 상생소비지원금 제외 리스트의 **부분집합**이다. 명품(시계·귀금속),
> 유흥·사행(유흥주점·복권), 비소비 서비스는 **표준 업종코드로 정확히 식별**되나,
> 대형마트·백화점·면세점·대형전자전문점과 카지노·경마 등은 **전용 업종코드가 없어
> 상호명 근사에 의존**하며 완전한 포착을 보장할 수 없다. 온라인몰·홈쇼핑·신차구입·
> 실외골프장은 모집단(소상공인시장진흥공단 상가 DB)에 물리 POI로 존재하지 않는다.
> 따라서 C1은 "제외군 전체가 반응하지 않는다"가 아니라 "**코드로 확정된 제외군 3종**이
> 적립군보다 유의하게 낮게 움직인다"로 해석해야 한다.

추가로:
- **성인업소(성인용품점·성인오락실·안마방류)는 제외하지 못하고 적립으로 집계된다.**
  전용 업종코드가 없어 `G22199 그 외 기타 상품 전문 소매업`·`S20802 마사지/안마`에
  일반 업소와 섞여 있고, 상호명으로도 포착되지 않는다(§4.3 실측: 복합어 0건, 단독어
  100% 오탐). 규모는 제외군 46,421 대비 1% 미만으로 추정되어 C1 결과에 영향이 없다.
- `excluded_nonconsumption`은 정책 제외 정의와 개념이 다르다 (§4.1).
- **상호명 룰이 잡은 잔여분(`src='rule_name'`)은 코드 근거가 없는 판정**이다.
  §8.5 T4-⑥으로 목록을 훑어보고, 민감도가 우려되면 이 부분을 뺀 집계도 함께 보고할 것.
- 코드 미확보 POI(`src='rule_fallback'`, §8 T3의 비율)는 기존 L2 룰 근사가 유지된다.
- 원천 CSV 기준일(202603)과 정책 시점(2021)의 시차 — 업종 코드 자체는 안정적이나
  폐업·신규 개업분 불일치는 남는다.

```bash
git revert <commit>
python scripts/neo4j_load/11_sangsaeng_eligibility.py    # 이전 룰로 재백필
```

시뮬 산출물(`output/sim/`)은 영향받지 않는다 — 이미 끝난 런의 결과는 그대로 유효하고,
재해석이 필요한 건 이 변경 이후 새로 도는 ON 런부터다.
