# P012 달력 월 검증 사전등록 (2026-09-26)

이 설계는 현재 진행 중인 `2021-10-01~10-28` 진단 런의 결과를 보거나 프롬프트를 고르기 전에 기록했다. 그 런은 정책이 10월 15일 시작되어 10월 지급 통계의 검증 팔로 재해석하지 않는다. 현재 런의 원장·최종 그래프를 백업하고 해시를 확인하기 전에는 새 런으로 그래프를 초기화하지 않는다.

## 고정할 입력과 두 팔

- 프롬프트: 범용 v5. P012 결과를 보고 문구를 바꾸지 않는다. 정책 JSON의 시행 정보와 `covid_2021` 배경은 별도 입력으로 전달한다. 실측 효과 부호·수치는 모델 입력에 넣지 않는다.
- 같은 시민 500명(현재 `fetch_agents(limit=500)`의 고정 층화추출), 같은 날·환경·모델(`EXAONE-4.5-33B-AWQ`)·코드·난수 설정으로 **정책 팔**과 **무정책 팔**을 독립 실행한다. 팔 사이에는 그래프의 일일 산출물과 Policy를 초기화하고, 시민·장소 원본을 보존한다.
- `DAY_ZERO=2021-09-27`, 시뮬레이션 `2021-09-28~2021-10-31` 34일. 9월 28~30일은 양팔 공통 예열이며 정책효과 추정에는 넣지 않는다. 월 경계 회계 수정으로 10월 1일 누적 실적을 0에서 시작한다. `EXP_DAILY_INCOME=anchor`, `EXP_SEED_SANGSAENG=0`, 나머지 실행 변수는 두 팔에서 동일하게 고정하고 매니페스트에 기록한다.
- 정책 팔은 **별도 사본**에서 P012의 `effective_from`만 실제 시행일 `2021-10-01`로 둔다. 원본 `P012.json`과 현재 런의 `P012_28d.json`은 변경하지 않는다. 무정책 팔은 Policy 노드 0개를 관문에서 확인한다. 정책 팔은 P012 한 개가 대상 지역에 연결되고 10월 1일 이후 정책 노출이 양수인지 확인한다.
- 두 팔의 시민 ID 집합 일치, 매일 시민 500명 정상 완료, 10월 1~31일 State 누락 0건, 지갑/실적 월초 초기화, 적립 적격 업종 및 지급 공식 일치를 채점 전 관문으로 둔다. 실패하면 결측 원인을 보존하고 외부 크기 점수를 내지 않는다.

## 사전에 정한 출력·판정

1. **기전·방향:** 시민별 10월 적립업종 월 지출을 정책 팔과 무정책 팔에서 쌍체 비교한다. 함께 전체·제외업종 지출, 10분위별 변화, 월내 문턱 접근·초과 시점, 정책 노출·실패율을 기록한다. 시민 단위 부트스트랩 95% 신뢰구간으로 효과 부호와 불확실성을 표시한다. 이 차이는 KDI의 가구·연도·월 삼중차분 계수와 다른 추정량이므로 `0.2082` 또는 `0.0285`와 직접 빼지 않는다.
2. **10월 지급액:** 10월 31일 적립 실적에서 문턱·지급액을 계산한다. 양의 지급액을 받은 시민만 분모로 한 평균을 보고, 수령자 0명이면 `관측부족`으로 둔다. KDI 표 3-1의 10월 수령자당 약 **47,828원**과 **비율**로 규모를 병기한다.
3. **10월 상한 비율:** 같은 수령자 중 월 한도 도달 비율을 보고, KDI 표 3-1의 약 **20.87%**와 **%p 차이**를 병기한다. 지급액·한도 비교는 서울 시민 합성 표본 대 전국 카드회원의 차이 때문에 `규모 참고`로 라벨링하며 외부 효과의 직접 오차 합계에는 넣지 않는다.
4. **반복 안정성:** 먼저 동일 코드·입력의 짧은 관문 런에서 정책 전달과 월 경계만 확인한다. 본 런 두 팔 후, 시간·비용이 허용하면 동일 설정 복제 런의 시민별 부호·규모 분산을 추정한다. 결과를 본 뒤 표본이나 지표를 골라 성공으로 표시하지 않는다.

현재 28일 런의 끝 상태는 이후 팔의 초기 상태로 사용하지 않는다. 두 팔을 새로 초기화하고, 각 팔 종료 직후 원장·실행 로그·정책 파일 해시·월말 State·시민별 결과·환경변수 매니페스트를 서버 밖에도 복사한 뒤 다음 팔로 넘어간다. 이 설계의 두 외부 규모 지표가 통과하더라도 범용 최적 프롬프트 확정에는 다른 정책·시기에서 같은 수준의 비교가 추가로 필요하다.

## 2026-09-26 사전등록 수정 — 정책과 함께 움직이는 소득 제거

위 원래 설계의 `EXP_DAILY_INCOME=anchor`는 `consumption.py`의 **그날** 소비 의향과 선택한 POI 가격이 반영된 `_anchor_total`을 다시 시민 소득으로 넣는다. 정책이 행동을 바꾸면 소득도 함께 달라질 수 있으므로, 정책/무정책 팔의 순수한 비교 조건이 아니다. 10월 1~14일 정책 노출 전 자료에서도 평균 지출은 약 13.0만원/일이고 기존 보충액은 평일 약 12.0만원, 주말 약 8.4만원으로 달라 장기 잔액이 중립적으로 유지되지 않는다. 이는 실측 효과 수치를 보지 않고 원장 회계에서 발견한 설계 결함이다.

본 런 두 팔의 보충액 설정을 `EXP_DAILY_INCOME=baseline` 및 **동일한** `EXP_DAILY_INCOME_MAP`으로 수정한다. `data/experiments/p012_baseline_income_20260926.json`은 현 진단 런의 **정책 전** 2021-10-01~14일의 시민별 총 지출(`cm_today_total_incl_online`) 평균만 사용해 고정했다. 500명 × 14일 중 정상 관측 6,998건, Stage1 파싱 실패 2건은 누락으로 표시하고 두 시민은 각각 13일 평균이다. 모든 정상 관측은 `policy_hits=0`, 지원금 결제·수령 0이었다. 기존 정책 시작일 10월 15일 이후의 출력과 KDI 실측 수치는 이 보충액 산정에 쓰지 않았다. 파일 SHA256은 `e0ffa83e87aa3d635e719d377bc7855dc01a8704d1ec85dd17fdbfbd37a61f05`다.

실행 전 두 팔 모두 동일한 500개 시민 ID가 맵에 있고 파일 해시가 일치하는지 검증한다. 이 값은 실제 소득 추정치가 아니라 **합성 지갑의 정책 독립적인 보충액**이다. 따라서 잔고 붕괴를 줄이는 실험 장치일 뿐, 외부 소비 규모의 교정이나 실측 크기 적중의 증거로 삼지 않는다. `anchor` 설정은 별도 민감도 분석에서만 병기하고, P012 결과에 유리한 설정을 사후 선택하지 않는다.

현 A100 옛 실행기에서는 Stage1 파싱 실패 2건이 있어도 다음 날짜로 진행해 첫 15일 State가 7,498/7,500이었다. 본 런에는 일별 500명 정상 커밋 관문이 있는 로컬 실행기를 사용하고, 실패하면 같은 날을 재개한다. 재개 때의 원시 metrics 시도 내역은 보존하되 최종 metrics는 시민당 한 행으로 원자적으로 확정한다. 관문 실패 상태의 부분 월 자료는 외부 크기 채점에 넣지 않는다.

## 2026-09-26 추가 관문 — Stage2의 실제 의사결정이 있는가

진행 중인 28일 **진단 런**의 완료일 10월 1~16일을 서버 밖 원본으로 감사했다(`output/recovery_20260926/p012_stage2_quality_oct01_16.json`). 8,000개 metrics 행 중 정상 7,998개, Stage2 LLM 호출 11,569회(첫 호출 외 추가 3,571회)였다. 선택적 리뷰 DB가 A100에 없는데 조회한 오류 2,296회, `max_tokens=1400`에서 정확히 잘린 JSON 파싱 오류 1,775회가 있었다. **500명·일은 모든 Stage2 시도가 실패했는데도 자동 POI 선택으로 정상 처리됐다.** 별도로 유효한 응답 뒤 빠진 선택 124개를 자동 채우고, 후보 밖 선택 409개를 보정했다. 이 런은 정책 회계·장기 거동의 진단 자료이지 v5 효과 크기의 유효한 검증 팔이 아니다. 현재 실행 프로세스에는 수정 코드를 배포하지 않는다.

새 본 런은 범용 프롬프트 v5 문구를 그대로 두고 실행 계약을 고친 로컬 버전을 사용한다. 리뷰 DB가 없으면 선택적 조회를 비우고 이미 유효한 첫 선택을 보존한다. Stage2 출력 상한은 첫 호출 2,200토큰, 길이 초과 재시도 3,200토큰으로 높이고 실제 재호출 토큰도 비용에 합산한다. 이 상한의 효과는 A100에서 아직 측정되지 않았으므로, 본 런 전 같은 시민·환경의 짧은 기술 점검으로 JSON 절단·추가 호출·후보 보정·완전 실패율을 확인한다. 모든 LLM 시도가 실패한 날은 자동 선택을 **정상 성공으로 기록하지 않고 실패로 처리**한다(`SIM_ALLOW_STAGE2_FALLBACK=1`은 탐색용 명시적 예외이며 검증 런에서는 금지). 두 팔 각각 `scripts/report/audit_stage2_generation.py --metrics-dir ... --expected-per-day 500 --strict`를 통과하고 `stage2_fallback_only_agents=0`임을 확인한 다음에만 정책 지표를 채점한다. 감사 결과의 누락 선택·후보 보정도 함께 보고한다. 이는 정책별 정답 수치에 따른 프롬프트 조정이 아니라 출력·관측 품질을 바로잡는 변경이다.

## 2026-09-26 해석 정정 — v5는 범용 프롬프트가 아님

위 원래 사전등록은 v5를 '범용'으로 불렀지만, 렌더된 공통 본문에는 캐시백·문턱·쿠폰·바우처 문구가 남아 있다. [프롬프트 재감사](PROMPT_GENERALITY_AUDIT_20260926.md)에 근거해 **v5 두 팔의 명칭을 역사적 기준선**으로 정정한다. 원래 지정한 v5 문구와 팔 정의는 바꾸지 않는다. 지급액과 한도 지표는 회계·규모 참고로 보고할 수 있으나, 두 팔이 통과해도 '정책 중립 프롬프트가 검증됐다'고 주장하지 않는다. 정책 중립 후보의 팔은 결과를 보고 사후에 v5 팔로 바꾸어 부르지 않고 별도로 등록한다.
