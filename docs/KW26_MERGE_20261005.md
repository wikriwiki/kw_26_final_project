# doinggyu 엔진과 우리 엔진 병합 (2026-10-05)

## 왜 다시 했나

첫 이식(`P012_simulation` 7bc8e45)은 doinggyu 엔진(`claude/colab-gpu-integration-999c0b`)을 그대로 두고 우리 고침 9가지를 골라 옮긴 것이었다.
옮기지 못한 것이 남았다. 원장 도구가 요구하는 실행 기록(프롬프트 종류·지문)이 없었고, doinggyu 기본 프롬프트(p010)에는 정책 효과의 방향을 알려 주는 문장이 들어 있었다.
그래서 두 엔진을 git 으로 진짜 병합했다. 양쪽이 각자 더한 기능은 둘 다 살렸다.

- 우리 쪽: 서버에서 실제로 돈 엔진(`/data/pilot_repo_20260927/scripts/sim`, 10/05 시점) — 커밋 81e45b4 로 고정
- doinggyu 쪽: af066e9(엔진). 그 뒤 423592f 는 GPU 풀 스크립트만 바꿔 함께 넣었다.
- 넣지 않은 것: doinggyu 의 `No_SmokingZone_EXP` 브랜치. 재시도·밤 처리 복구 쪽 엔진 변경이 있지만 금연구역 실험용이고, 사용자가 고른 브랜치가 아니다.

## 병합 뒤 고친 것

1. 사람-날 하나의 시도 예산(`EXP_AGENT_DAY_MAX_ATTEMPTS`, 기본 6)과 건너뛰지 않기(`EXP_NO_SKIP=1`). 건너뛰면 그 사람의 그날 행동·기억이 비므로, 본런은 건너뛰지 않고 멈춘다.
2. 판단 원칙에서 소비를 줄이는 쪽으로 미는 문장 2개를 뺐다: "정책이 있다는 것이 소비 자체를 새로 만들라는 뜻은 아니다", 캐시백의 "이번 달 소비 예산을 늘려주지 않는다".
3. 금연구역 실험 경로에서 병합 중 빠졌던 시설 규칙 블록을 doinggyu 원본 위치로 되돌렸다.
4. 계획 통로가 실제로 켜졌는지 행마다 기록한다(`cm_plan_ratio`, `cm_plan_baseline`, `cm_plan_channel_on`). 기준선 파일이 없으면 엔진이 조용히 옛 공식(평소 소비와 계획 중 큰 값)으로 돌기 때문이다. 계산은 바꾸지 않았다.
5. 사용처 표시·지원금 결제 허용·즉시 할인을 **고른 가게 자신의 업종**으로 판정한다. 예전에는 Stage1 이 계획한 업종으로 판정해서, 같은 동에 그 업종 가게가 없어 넓혀 가져온 가게(예: 슈퍼마켓을 계획했는데 수산 가게)도 계획 업종으로 판정됐고 원장과 어긋났다.
6. 즉시 할인 규칙이 읽는 가게 이름·세부업종 코드를 이벤트에 싣는다(이전에는 비어 있어 이름 기준 제외가 한 번도 작동하지 않았다).
7. 업종 할인권 원칙 문장에서 "그 업종의 일을 앞당길지, 평소대로 할지는 본인이 정한다"를 뺐다(늘리거나 그대로인 쪽만 주는 문장).
8. 거리두기 대조 환경 `covid_2020_hold_1123`: 2020-11-23 의 1.5단계 규칙을 이어 가고 확진 소식은 그날 것(2026-10-06).
9. 카페가 종일 포장·배달만인 날 시간제한 줄을 "식당 매장 취식 …"으로 고쳤다(바로 아래 카페 줄과 모순이었다).
10. 할인·환급 회계 일반화(`instant_discount.py`, 2026-10-06): 결제 때 깎이는 것(정률·정액, 금액 구간별 정액)과 나중에 돌려받는 것(환급, 기간 누적 환급, 횟수를 채우면 다음 결제에서 환급)을 나눠 기록한다. 업종별 시작일·종료일, 요일·시각 창, 하루 인정 횟수, 같은 가게 하루 1회. 발행 구 상품권(P014)은 구별 할인율·구별 월 한도, 사는 구·직장 구. 업종 하나짜리 정률 할인(P016)은 이전과 같은 값이 나온다. 환급은 거래 기록(`INCLUDES.policy_rebate`)·하루 지표(`policy_rebate_today`)에 남고 오늘 자기부담에는 들어가지 않는다.
11. 할인 구매 상품권의 "새로 생긴 돈이 아니다"를 상태 줄·원칙에서 뺐다.

시험: `tests/unit/sim` 1,591개 중 1,588개 통과, 실패 3개. 2개는 doinggyu 원본에서도 실패하는 시험이고, 1개는 작업 사본에 `output/stats` 자료가 없어서 실패한다.

## 3주 A/B 실행기 (`tools/run_ab3w.sh`, 정책별 설정 `tools/ab3w_cases.sh`)

사용자 설계(2026-10-05): 정책 주입 전 1주(공통) → 주입 시점부터 정책 적용/미적용 1주씩.

1. 깨끗한 그래프를 Neo4j 1 에 넣고 Day0 를 놓는다(정책 없음)
2. 정책 전 주를 돈다(계획 기준선 파일 없음 = 계획 배수 1)
3. 정책 전 날들의 계획액으로 사람별 평일/주말 기준선을 만든다. 주말 칸이 비면 사람 하나의 값을 쓴다
4. 그래프를 덤프해 Neo4j 2 에 그대로 넣고, 두 그래프의 라벨·관계 수와 명부 사람들의 상태가 같은지 확인한다
5. 정책은 Neo4j 1(정책 있음)에만 넣는다
6. 두 갈래를 동시에 돌린다. 실행 ID 는 정책 전 주와 두 갈래가 같다 — 엔진은 전날 상태·기억이 다른 실행 ID 에서 오면 멈추고, 두 갈래는 같은 정책 전 주의 기억을 이어받는 같은 경험이다
7. 원장·기억 모음(정책 전 주부터 끝까지)·그래프 덤프·체크섬

공통 설정: 프롬프트 v53, 하루 소득 = 평소 소비 수준(앵커 x 1/2.40, 잔액 유지), 사용처 몫 경로, 계획 통로, 건너뛰지 않기(시도 예산 12).
명부: 정책 시점 서울 주민등록(성·연령·행정동)에 맞춘 2,000명(`output/cohort/<정책>_ab3w_2000.json`).

```
AB_CASE=p013 AB_TAG=small AB_ROSTER=<명부> AB_PRE_DAYS=3 AB_POST_DAYS=4 bash tools/run_ab3w.sh     # 소규모(A100)
AB_CASE=p013 AB_TAG=main AB_ROSTER=output/cohort/p013_main_2000.json \
  AB_LLM_BASE_URL=http://localhost:<GPU 풀 중계 포트>/v1 AB_WORKERS=64 bash tools/run_ab3w.sh       # 본런
```

서버 전용 비밀번호는 저장소 밖 `/data/ab3w/neo4j_credentials.sh` 에 둔다(`NEO4J_PASSWORD_ON`, `NEO4J_PASSWORD_OFF`).
정책별 검수 결과와 남은 일은 `data/experiments/AB3W_REVIEW_20261005.md`.
