## 1. 지금 무엇을 하고 있나

**목표** — 정책이 바뀌어도 쓸 수 있는 **소비행동 프롬프트 한 벌**을 만든다.

정책마다 프롬프트를 따로 쓰면 새 정책에서 어느 프롬프트가 좋을지 알 수 없다.
그래서 소비행동 프롬프트는 **정책과 무관한 사람의 성질**만 담고, 정책·사회배경은
그 사람에게 들어가는 **입력**이 되도록 갈랐다. 여러 정책을 같은 프롬프트로 돌려
**크기가 아니라 방향(부호)** 이 실측과 맞는지로 고른다.

**현재 결론** — `v5` 가 홀드아웃까지 통과한 확정판이다. 채점 가능했던 12개 지표에서
부호가 12/12 실측과 일치하고, 홀드아웃(8대 소비쿠폰)에서 대상 업종 몫이 환경
드리프트를 넘어 +21.5%p (p=0.042) 올랐다.

**2차 선별 A단계는 끝났고 판정은 v5 유지다**(§7.2). 문장을 더한 후보 셋은 v5 를
이기지 못했고, 겨냥한 결함 둘은 둘 다 실체가 없었다. **B단계는 기동하지 않았다** —
여기서부터 이어받으면 된다(§7.3).

### 2.2 실험 설계 규칙

**① 사전등록.** 지표·창·후보 집합을 **돌리기 전에** `data/experiments/scoring_table.json`
에 적는다. 결과를 보고 지표를 고르면 실효 자유도가 늘어난다. 후보를 단계마다
추가하는 것도 같은 문제다 — 후보 집합은 한 번에 못 박는다.

**② 홀드아웃은 한 번.** 8대 소비쿠폰(P015)은 **이미 썼다**(2026-09-16~17). 다시
돌리지 마라. 그 결과를 보고 프롬프트를 고치면 그 순간 홀드아웃이 아니게 되고
앞의 검증이 같이 무효가 된다. 새로 쓸 봉인 정책도 없다 — 인정 기전은 이번에 다
쓰였고 유류세 인하는 주유소가 Category 어휘에 없다. **그래서 2차 승자는 홀드아웃
검증을 받지 못한다. 이 사실을 결과와 반드시 함께 적어라.**

**③ 순환 검증 금지.** 측정에 쓰는 공식·수치를 모델 입력에 넣지 마라. 구체적으로
**"크기"를 겨냥하지 마라** — P012 적립업종이 실측 +20.82% 의 절반이지만, "더 크게
반응하라"를 프롬프트에 넣는 것은 우리가 재어서 얻은 답을 되먹이는 짓이다.
사전에 **부호만 맞춘다** 고 정해 두었다.

**④ 크기가 아니라 부호.** 하루 총액이 페르소나 앵커에 묶여 있어 실측의 총소비
−14% 같은 크기는 구조적으로 못 낸다. 게다가 **같은 설정 두 런의 점추정이 +10.1%
대 +15.1% 로 50% 차이** 가 났다(복제런). 우리가 재현하지도 못하는 정밀도를 실측과
견주지 마라.

**⑤ 실패를 그대로 적어라.** 위약 무반응, 섭동 부호 반전, 지역화폐 장소 이동
비유의 — 전부 기록에 남아 있다. 정직한 실패가 한 정책에 맞춘 성공보다 낫다.

**⑥ 배관 결함과 프롬프트 실패를 구분하라.** 지금까지 "프롬프트가 틀렸다"로 보였던
것의 상당수가 배관 결함이었다(§6). 실패를 보면 **에이전트가 실제로 본 프롬프트를
렌더해서** 확인하는 습관을 들여라.

## 4. 확정판 프롬프트 v5

바꾼 것은 시스템 프롬프트의 `daily_propensity` 블록 **하나** 다. 나머지 본문(카테고리

**파일** `scripts/sim/prompts/candidates.py` 의 `_CONDITION`
**선택** 환경변수 `SIM_PROMPT_VARIANT=v5`

```
정책은 오늘의 조건을 바꾼다. 쓸 수 있는 돈이 늘기도 하고, 같은 돈으로 더 살 수 있게
되기도 하고, 할 수 있는 일이 줄기도 한다. 먼저 오늘 무엇이 달라졌는지 보고, 그것이 내가
하려던 일에 닿는지 판단한다. 닿지 않으면 평소와 같다.
닿는다면 무엇을·언제·어디서 할지가 달라질 수 있다. 미뤄두었던 일이 앞당겨지기도 하고,
하려던 일이 뒤로 밀리기도 하고, 같은 일을 다른 곳에서 하기도 한다.
```

## 9. 작업 방식

### 9.1 런 한 번 돌리는 법

```
export SIM_PROMPT_VARIANT=v5 SIM_OUTPUT_DIR=/data/out/TAG
python scripts/neo4j_load/97_reset_run_artifacts.py         # 이전 런 흔적 삭제

DAY_ZERO=2021-10-17 python scripts/neo4j_load/08_initial_state.py
python -u scripts/sim/run_simulation.py --start 2021-10-18 --days 9 --limit 200 \
    --workers 48 --environment covid_2021
python scripts/sim/score_policy.py --policy P012 \
    --off 2021-10-21:2021-10-22 --on 2021-10-25:2021-10-26 \
    --label v5 --json-out /data/out/TAG.json
```

공통 환경변수:

```
EXP_SANGSAENG_BASE_RATIO=0.268  EXP_SEED_SANGSAENG=1  EXP_BALANCE_DAYS=39
EXP_DURABLES=1  EXP_CATLINE=fold  EXP_POLICY_ANONYMOUS=1  POLICY_POI_SORT_BOOST=0
```

`EXP_POLICY_ANONYMOUS=1` 은 정책 이름을 지우고 기전 라벨만 남긴다(lookahead 완화).

**소요 시간 기준** — n=200 × 9일 ≈ 4h, n=200 × 12일 ≈ 4.4h, n=500 × 12일 ≈ 10.5h.
**워밍업 3일을 반드시 창 앞에 두어라.**

### 9.2 결과 읽는 법

```
python3 /data/show.py /data/stage7/v5_thr105.json
```

- `hit` 판정은 **부호** 기준. 기대 `0` 인 지표는 **동등성 검정**(CI 가 base ±10% 밴드
  **안** 에 들어야 적중). "CI 가 0 을 포함하는가"로 보면 잡음 큰 후보가 저절로 통과한다
- `split_agree` — 표본을 반으로 갈라 양쪽 부호가 같은지. **깨지면 그 값은 믿지 마라**
- `base` 는 off 구간 평균. 두 런의 base 가 가까우면 조건이 재현된 것이다
- `diagnostics` 는 **채점 아님** — 같은 업종을 몫(share)으로 본 진단값

### 9.3 보고와 커밋

## 10. 남은 미해결 — 이어받아 볼 만한 것

| 문제 | 상태 | 메모 |
|---|---|---|
| 가짜 정책 위약 무반응 (+0.9%) | 미해결 | 프로빙에서 결과 회상 20/20 "모름"이라 암기로는 설명 안 된다. 위약 설계(희소 조건·좁은 범위)가 더 그럴듯하나 가릴 자료가 없다. 재설계해 돌린다면 **새 설계와 읽는 법을 돌리기 전에 등록하고 세 번째 시도라는 사실도 적어라** |
| 지역화폐 장소 이동 비유의 | 구조적 | 거주 동 비중 base 0.766(천장), 역외 소비 base 0.0596(여지 작음). Stage2 후보 조회가 거주·직장 앵커 기반이라 역외 소비가 원래 적다 |
| P012 크기가 실측의 절반 | 구조적 | 하루 총액 앵커. **겨냥하지 마라**(§2.2 ③) |
| 제외업종 무반응 (n=4~8) | 관측 부족 | 2,000명 규모가 필요하다 |
| HO-3 배관 | 수정 완료, 홀드아웃엔 미적용 | `score_policy.apply_policy_eligibility` 가 정책 JSON 의 적격 명세를 읽는다. 홀드아웃은 다시 채점하지 않는다 |
| 런 간 변동이 CI 에 안 담김 | 알려진 한계 | 복제런 1회로 폭을 쟀다. 결론은 부호로만 낸다 |
