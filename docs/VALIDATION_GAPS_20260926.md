# 정책 시뮬레이션 검증 공백과 다음 실험 (2026-09-26)

사용자 목표는 모든 정책에서 행동의 **방향과 대략적 크기**를 실측과 비교하고, 그 결과로 범용 프롬프트를 선택하는 것이다. 정적 코드 경로가 38/38개라는 사실은 출력·원문 추정량의 일치를 의미하지 않는다. `scripts/report/all_indicators_table.py --json-out ... --md-out ...`로 현황을 재생성한다.

## 원문 대조 후 판정

현재 보관된 결과에서 **크기를 직접 차감할 수 있는 지표는 0개**다. 원문에서 검증된 실측 수치가 있어도 모집단·기간·대조 설계·결과변수가 다르면 차감하지 않는다. 결과값이 없거나 원문 수치가 없는 경우를 숫자 0으로 채우지 않는다. 어제의 `%p 오차 합 29.52`, 오늘 중간값 `10.60`은 비교 대상의 정의를 정정하면서 사라졌다. 성능 개선 수치가 아니다.

## 다음 런의 선행 조건

1. **이번 P012 28일 런**의 500명·28일 원장과 그래프 기반 per-agent 자료를 보존한다. 정책 적용, 잔고, 실패, 캐시백 누적을 확인한다. 결과는 월별 외부 크기 검증이 아닌 반응·문턱·회계 진단으로 표시한다.
2. 각 새 런 전에 원문에 있는 **대상, 기간, 결과변수, 분자·분모, 추정량, 대조군**을 채점표에 기록한다. 모든 조건이 맞기 전에는 숫자 오차를 내지 않는다. 시민당 반복 관측은 시민 단위로 재표집한다.
3. 월별 정책 지표에는 온전한 달과 시행일을 확인한다. `score_policy.py`는 P012 지급액·상한 도달률을 수령자 분모로 계산하고, 달력 월말/정책 월 초 시행 및 시민별 전 날짜 State 관측이 어긋나면 적중을 주지 않는다.
4. 범용 후보는 정책 이름이나 실측 결과 수치·부호를 프롬프트에 넣지 않고, 동일 시민·동일 환경·동일 무작위 시드에서 비교한다. 선택에 사용한 정책은 개발 자료로 기록하고, 별도 정책/시기 자료로 방향·크기·위약 안정성을 확인한다. 현재 v5는 기준 후보이지 검증 완료된 최적해가 아니다.
