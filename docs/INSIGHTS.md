# 실험하면서 알게 된 것들

`HANDOFF_CODEX.md` 가 "무엇을 어떻게 이어받나"라면, 이 문서는 **"해 보니 이렇더라"** 다.
대부분은 비싸게 배웠다 — 잘못된 결론을 내렸다가 되돌린 것들이다.

---

## 1. 가장 큰 교훈 — 실패의 대부분은 프롬프트가 아니라 배관이었다

프롬프트를 고쳐야 할 것처럼 보인 실패를 열한 번 추적했는데, **거의 전부가 배관 결함**
이었다. 몇 가지만:

| 보인 것 | 실제 원인 |
|---|---|
| 가짜 정책에 대상 업종이 **반대로** −10.5% | `[환급]` 표시가 **아무 POI 에도 안 붙었다.** 에이전트에겐 쓸 수 있는 가게가 하나도 없는 셈이라 그 업종을 피할 이유가 됐다 |
| 지역화폐 장소 이동 0/3 | 정책문은 "사는 곳 자치구 안에서만"인데 **구 밖 가게에도 표시가 붙었다.** 제약이 전달된 적이 없다 |
| 홀드아웃 적격업종 몫이 천장(0.9872) | 채점기가 **다른 정책(P012) 기준의 백필값**을 읽고 있었다 |
| 위약이 세 번 연속 실패 | 전부 우리 **대조군 설계** 결함 — 워밍업 오염, 확진자 28% 급감 구간, 서로 다른 창 비교 |

**교훈** — "모델이 못 한다"로 결론 내리기 전에 **에이전트가 실제로 본 텍스트를 렌더해
보라.** 시뮬을 돌리지 않고 프롬프트 블록만 그리는 데 1분이면 된다. 홀드아웃을 돌리기
전에 이걸 했더니 `업종 제한 없음 · [쿠폰] 표시 POI에서만 사용` 이라는 자기모순이
나왔다 — 안 봤으면 그대로 돌아갔다.

### 따름정리 — 텍스트와 구조화된 표시가 어긋나면 표시가 이긴다

산문으로 "구 안에서만 쓸 수 있다"고 써 놔도, 후보 목록에서 구 밖 가게가 `[지역]` 으로
표시돼 있으면 에이전트는 표시를 따른다. 반대도 마찬가지 — 표시가 아예 없으면 산문이
뭐라 하든 그 업종을 피한다. **자연어 지시와 구조화된 신호를 반드시 일치시켜라.**

## 2. 기준선 런 없이는 아무것도 읽을 수 없다

홀드아웃에서 **정책이 없는데도** 대상 업종(마트) 몫이 +16.1% **유의하게** 올랐다.
3차 유행이 시작되면서 외식을 줄이고 장을 보는 방향으로 움직인 것이다. 정책 런은
+37.6% 였다.

기준선 런이 없었다면 **+37.6% 를 통째로 정책 효과로 읽었을 것이다.** 실제 정책 효과는
차분한 +21.5%p 다.

**교훈** — 같은 창·같은 워밍업·같은 표본으로 **정책만 뺀 런**을 반드시 같이 돌려라.
비용은 두 배지만, 없으면 숫자를 읽을 수가 없다. 위약이 세 번 실패한 것도 결국
"대조군이 다른 창에 있었다"는 한 가지 문제였다.

## 3. 표본을 키우는 것은 "개선"이 아니라 "가려내기"다

프롬프트를 한 글자도 안 고치고 n 만 200 → 500 으로 올렸더니:

- **거리두기** 1/4 → **3/4** 로 좋아졌다. 소매가 +13.5% → **+5.1%** 로 실측 **+4.2%** 에 붙었다
- **지역화폐** 1/3 → **0/3** 으로 나빠졌다. 유의했던 역외 소비 −26.4% 가 **+9.2% 로 부호가 뒤집혔다**

같은 조작인데 한쪽은 좋아지고 한쪽은 나빠졌다. 즉 n 을 키우는 일은 성능을 올리는 게
아니라 **작은 표본에서 나온 결과 중 어느 것이 실재이고 어느 것이 우연이었는지 가리는
일**이다. 거리두기의 점추정은 실재였고, 지역화폐 LV-3 의 유의한 적중은 우연이었다.

**교훈** — 작은 표본의 "적중"을 성과로 보고하지 마라. 특히 **하나만 적중한 경우**는
우연일 확률이 높다.

## 4. 값싼 불확실성 지표 두 개가 큰 오판을 막았다

런을 여러 번 돌릴 예산이 없을 때, 한 런 안에서 공짜로 얻을 수 있는 것들이다.

### 4.1 반분일치 (split-half)

표본을 반으로 갈라 양쪽에서 부호가 같은지 본다. 비용 0.

섭동런에서 적립업종이 **−11.4% (CI 가 0 을 배제)** 로 나와 "부호가 뒤집혔다"고 기록
했는데, **반분일치가 깨져 있었다.** 나중에 같은 조건으로 다시 돌리니 **+2.9%** 가 나왔다.
재현되지 않았다.

이 하나 때문에 2차 선별 전체의 전제가 흔들렸다. **CI 가 0 을 배제해도 반분일치가
깨졌으면 믿지 마라.**

### 4.2 복제런 — 같은 설정을 한 번 더

본런과 **완전히 같은 설정**을 한 번 더 돌렸다.

```
본런  +3,321 (+10.1%)  CI[+885, +5,882]   base 32,861
복제  +4,934 (+15.1%)  CI[+2,239, +8,211] base 32,712
```

- 무정책 구간 base 가 **0.45% 차이** — 기초 수준은 거의 그대로 재현된다
- 그런데 **점추정은 50% 차이**가 난다

**교훈** — 우리가 쓰는 CI 는 **한 런 안에서** 에이전트를 복원추출한 것이라 **런 간 변동을
담지 못한다.** LLM 샘플링이 결정론이 아니므로 같은 설정도 런마다 다르다. 복제런 한 번이
모든 수치의 해석을 바꿨다. **예산이 허락하면 가장 중요한 수치 하나만이라도 복제하라.**

## 5. 영가설 지표는 설계가 까다롭다

"이 지표는 안 움직여야 한다"는 방어선 지표가 실험의 신뢰도를 지탱하는데, 두 번 헛발을
디뎠다.

### 5.1 "CI 가 0 을 포함한다"로 판정하면 잡음이 이긴다

후보 v4 가 영가설 지표를 "통과"했는데, 평균은 v1 과 똑같고 **CI 가 더 넓었을 뿐**이었다.
잡음이 큰 후보가 저절로 유리해진다.

→ **동등성 검정(TOST 꼴)** 으로 바꿨다. CI 가 기준선 ±10% 밴드 **안에** 들어와야 적중.

### 5.2 base 가 작으면 구조적으로 통과 불가

홀드아웃 영가설로 `late_night_share`(심야 결제 비중)를 골랐다가, 돌리기 전 합성 원장
예행에서 잡았다.

```
base ≈ 0.006 (심야 결제 0.6%)  →  밴드 ±0.0006
그런데 n=200 몫 지표의 CI 반폭은 0.013~0.027
```

**밴드가 측정 잡음보다 좁다.** 진짜 무변이어도 통과할 수 없다. base 가 큰 지표
(`home_dong_spend_share` base 0.747, `total_spend_paired` base 33,000)로 교체했다.

**교훈** — 영가설 지표를 고를 때 **밴드 폭과 CI 반폭을 미리 비교하라.** 다른 런의 분산을
쓰면 돌리기 전에 계산할 수 있다.

## 6. 요일을 맞춰라. 비용을 아끼려다 교란을 산다

페르소나의 **주말/평일 소비비가 1.47배**이고 평일 안에서도 금요일이 높다. 처음에는
비용 때문에 "양쪽 다 평일이면 된다"로 타협해 무정책 목·금 vs 정책 화·수 같은 창을
썼는데, 요일 효과가 정책 효과와 같은 크기로 섞였다.

요일을 정확히 맞추려면 창이 길어져 런당 비용이 오르지만(9일 → 12일), **확인런처럼
절대 수치를 내는 단계에서는 타협하면 안 된다.** 요일 정합 창으로 다시 돌린 뒤에야
거리두기 소매가 실측에 붙었다.

**교훈** — off/on 의 **요일 구성이 같아야** 한다. 같은 레짐 안에 들어가야 하고, 레짐
경계가 창 안을 가르면 안 된다.

## 7. 구조적 제약은 "몫(share)"으로 우회할 수 있다

이 시뮬은 하루 총액이 페르소나 앵커에 묶여 있다. 그래서 한 업종이 오르면 다른 업종이
빠진다 — 금액 수준에서 보면 효과가 서로 상쇄돼 잠겨 보인다.

거리두기 n=500 에서:

```
금액으로   소매 +573 (+5.1%)  CI[−990, +1,999]      비유의
몫으로     소매 0.3117 → 0.3338 (+7.1%)  CI[+0.0028, +0.0413]   유의
```

**같은 데이터인데 몫으로 보면 "음식점에서 소매로 옮긴다"는 구조가 선명해진다.**
총액 제약이 약분되기 때문이다.

**교훈** — 총액에 구조적 상한이 있는 시뮬이라면 **금액과 몫을 함께 재라.** 다만 몫은
사전등록한 지표여야 하고, 사후에 "금액이 안 나오니 몫으로 보자"는 안 된다. 우리는
홀드아웃 사전등록에 몫 지표를 넣었고, 확인런에서는 **채점하지 않는 진단값**으로만 남겼다.

## 8. 사전등록은 코드로 굳혀야 지켜진다

말로 "기준은 이렇다"고 적어 두면 결과를 보고 해석이 흔들린다. 2차 판정 기준을
`scripts/sim/rank_round2.py` 로 구현해서, 결과 JSON 을 먹이면 승자가 나오게 했다.

실제로 도움이 됐다 — 후보 하나가 일부 기준을 충족했을 때 "그러면 얘가 승자인가?"로
기울 뻔했는데, 코드가 **"네 후보가 다 끝나기 전에는 판정 보류, v5 결과가 없으면 실격
규칙의 기준선이 없다"** 를 그대로 찍어 줬다.

**교훈** — 판정 로직에 **미완 상태의 분기**까지 넣어라. "아직 판정할 수 없다"를 코드가
말해 주면 조급함에 지지 않는다.

## 9. LLM 시뮬 특유의 것들

### 9.1 직접 프로빙이 위약보다 싸고 결정적이다

"모델이 정답을 외워서 맞히는 것 아닌가"(lookahead bias)를 검정하려고 **가짜 정책 위약**
을 만들었다. 실재하지 않는 정책에 기전대로 반응하는지 보는 것인데, 런 하나에 3~4시간
걸리고 결과도 애매했다.

대신 **익명화된 정책 블록만 보여 주고 모델에게 직접 물었다.** 몇 분 만에 끝났고 훨씬
강한 답을 얻었다.

```
결과 회상   P012·P015·P013·P090 전부 0/5 — 20/20 "모름"
식별        가짜 정책 3/5 "실재" > 진짜 정책 0~2/5 (그마저 이름은 틀림)
```

**핵심은 가짜 정책을 대조군으로 넣은 것이다.** 존재한 적 없는 정책을 실재한다고 답한
비율이 진짜보다 높으므로, "식별했다"는 답변 자체가 **작화**임이 드러난다. 대조군이
없었으면 "2/5 는 알아본다"로 잘못 읽었을 것이다.

그리고 외우고 있는 숫자가 없으면 "외운 결과를 재생한다"는 가설은 성립하기 어렵다.

**교훈** — 누출을 걱정한다면 **먼저 직접 물어보라.** 싸고, 대조군을 붙이면 결정적이다.
다만 이건 **명시적 회상**만 재는 검사다 — 말로 못 꺼내면서 행동이 기울 가능성은 남는다.

### 9.2 같은 사실이 네 번 반복되면 지배 신호가 된다

가짜 정책 프롬프트에 "받을 수 없다"가 배경·기전 줄·개인 상태·판단 원칙에 **네 번**
나왔다. 대상 업종이 오히려 줄었다. 한 번으로 줄이니 사라졌다.

**교훈** — 프롬프트를 조립식으로 만들면 같은 사실이 여러 블록에서 중복된다. **렌더해서
중복을 세어 보라.**

### 9.3 thinking 을 끄지 않으면 답이 잘린다

EXAONE 4.5 는 기본이 thinking ON 이다. 끄지 않으면 추론 서문이 토큰을 다 먹고 JSON
파싱이 깨진다. 프로빙 첫 시도에서 40건 전부 추론 서문만 나오고 답이 없었다.

```python
{"chat_template_kwargs": {"enable_thinking": False}}
```

### 9.4 익명화해도 기전에는 반응한다

`EXP_POLICY_ANONYMOUS=1` 로 정책 이름을 지우고 기전 라벨(`[업종 한정 할인권]`)만
남겨도, 모델은 기전 서술만으로 업종별로 갈라 반응했다. **이름이 아니라 구조를 읽는다.**

## 10. 실험 운영에서 배운 것

### 10.1 로그를 grep 으로 거르면 실패가 사라진다

```bash
python -u run_simulation.py ... 2>&1 | stdbuf -oL grep -E "^  Day|TOTAL"
```

이렇게 해 두면 traceback 이 grep 에 삼켜진다. 게다가 grep 이 아무것도 못 찾으면 종료
코드 1 을 내고 `set -e` 가 스크립트를 죽인다 — **실패했다는 흔적조차 안 남는다.**
런 하나가 33분간 죽어 있었는데 로그가 비어 있었다.

**교훈** — **런마다 전문을 파일로 남기고**, 화면에는 요약만 보여라. 실패해도 다음 칸으로
넘어가게 하고 어디서 죽었는지 남겨라.

### 10.2 워밍업 3일

`KNOWS_POI` 방문 이력이 0 에서 시작해 초반 며칠에 **상승 드리프트**가 생긴다. 창 앞에
워밍업 3일을 두고 채점에서 뺀다. 위약이 처음 실패한 원인 중 하나가 이것이었다.

### 10.3 재사용할 수 있는 런은 재사용하되, 근거를 먼저 적어라

B단계에 필요한 v5 런 두 건이 이미 있어서 재사용했다. GPU 26시간을 아꼈다. 다만
**돌리기 전에** "창·지표·표본이 문자 그대로 같고, 이 런들은 2차 선별보다 먼저 돌았으므로
결과를 보고 고른 것이 아니다"를 기록했다. 사후에 적으면 체리피킹과 구분이 안 된다.

## 11. 이 프로젝트에서 실제로 확인된 것

### 11.1 기전 중립 프롬프트가 작동한다

**같은 문장 한 벌**로 서로 다른 기전에 갈라 반응했다. 가장 강한 증거는 총소비다.

| 기전 | 새 돈인가 | 총소비 변화 |
|---|---|---|
| 지갑 (긴급재난지원금) | 그렇다 | **+12.6%** (앵커를 뚫었다) |
| 할인 (지역화폐) | 아니다 | **+3.2%** (동등성 밴드 안) |
| 할인·환급 (8대 소비쿠폰, 홀드아웃) | 아니다 | **밴드 안** |

프롬프트는 어디에도 "지갑이면 총소비가 는다"고 적지 않았다. **"쓸 수 있는 돈이 늘기도
하고, 같은 돈으로 더 살 수 있게 되기도 하고"** 라는 대칭 서술만 있다. 모델이 기전
서술을 읽고 갈랐다.

### 11.2 "닿지 않으면 평소와 같다"가 판별 문장이다

이 한 줄이 없으면 정책이 있다는 이유만으로 전부 움직인다. 거리두기 런에서 규제를
뭉뚱그려 전부 줄이지 않고 **음식점은 내리고 소매는 올린** 것이 이 문장의 몫이다.
채점표에 *"'제약이면 다 줄어든다'로 수렴한 프롬프트를 잡는다"* 고 적어 둔 판별 지표를
통과했다.

### 11.3 크기는 프롬프트가 아니라 창 길이에 달렸다

P012 적립업종이 실측의 절반(0.49배)인데, 원인은 **관측 창**이다. KDI 는 한 달을 쟀고
우리는 정책 **2일**을 쟀다. 캐시백은 실적을 쌓아 문턱을 넘는 누적 기전이라 한 달 누적이
2일보다 클 수밖에 없다.

나머지 지표는 모두 **0.5~2.0배 대역 안**이다(0.69·1.21·1.18·1.73). 크기를 프롬프트로
겨냥한 적이 없는데도 그렇다.

**교훈** — 크기가 안 맞으면 **프롬프트를 의심하기 전에 창을 의심하라.** 그리고 크기를
맞추려고 프롬프트에 방향이나 수치를 넣는 것은 순환 검증이다(§12).

## 12. 내가 저지른 실수 — 같은 함정을 피하라

### 12.1 방향 지시를 프롬프트에 넣을 뻔했다

2차 후보 v7 에 *"조건에 닿지 못하겠다고 판단하면 **그 때문에 줄이지는 않는다**"* 를
넣었다. 섭동런에서 −11.4% 가 나온 걸 보고 **그 음수를 막는 문장**을 쓴 것이다.

수치를 쓰지 않았으니 괜찮다고 생각했는데 아니다. **방향도 금지 대상이다.** 게다가
그 대상이 우리가 채점하는 지표였고, 금지한 방향이 정답의 반대쪽이었다.

사용자가 규칙을 다시 짚어 주고 나서야 알아차렸고, **판정 결과를 보기 전에** v7·v9 를
제외했다. 그리고 공교롭게도 그 −11.4% 는 재런에서 재현되지 않았다 — **없는 병에 쓴
방향 지시**였던 셈이다.

**교훈** — "이 문장이 결과를 특정 방향으로 밀어붙이는가"를 자문하라. 밀어붙인다면,
그 방향이 우리가 아는 정답 쪽인지 확인하라. 그렇다면 쓰면 안 된다.

### 12.2 결과를 보기 전에 기록하는 습관

위 실수를 기록할 때 **A단계 7/8, 마지막 런 11/12일 시점**이라는 것을 함께 적었다.
결과를 본 뒤에 적으면 "점수가 나쁘니 제외했다"와 구분이 안 된다. 판정에 영향을 주는
결정은 **반드시 결과 이전에 기록하고 시점을 남겨라.**

### 12.3 저장소를 지우는 커밋을 만들어 올렸다

복구 스크립트가 `rm -f .git/index && git read-tree HEAD` 를 하는데, 그 시점에 HEAD
트리를 못 읽어 **인덱스가 비었다.** 그 상태로 커밋하니 최상위 트리에 항목이 1개뿐인
커밋이 됐고 — 저장소를 통째로 지우는 커밋 — 그걸 푸시했다.

내용은 blob 에 남아 있어 되살렸지만, **파괴적 작업 뒤에는 결과를 검증했어야 했다.**
지금은 인덱스가 100건 미만이면 스크립트가 멈춘다.

**교훈** — 인덱스·트리를 재구성하는 작업 뒤에는 **건수를 세어 보라.** 한 줄이면 된다.

## 13. 다시 한다면 순서를 이렇게 하겠다

1. **지표·창·후보를 사전등록한다.** 판정 로직까지 코드로 짠다
2. **영가설 지표의 검정력을 미리 계산한다** — 밴드 폭 vs CI 반폭
3. **합성 원장으로 채점 경로를 예행한다** — 단, `elig` 같은 필드를 임의로 채우면 실제
   배관 결함이 숨는다. 실제 백필 규칙으로 만들어라
4. **프롬프트를 오프라인 렌더해서 읽는다** — 중복·모순·표시 누락
5. **요일을 맞춘 창**으로, **기준선 런을 반드시 같이** 돌린다
6. 작은 표본으로 거르되, **적중 하나를 성과로 보고하지 않는다**
7. **가장 중요한 수치는 복제한다**
8. 크기가 안 맞으면 **창을 먼저 의심한다**
9. 실패는 그대로 적는다. **정직한 실패가 한 정책에 맞춘 성공보다 낫다**
