# 활동 선택과 실행 계약의 분리

2026-09-20. 기존 v5/v19/v20/v21을 그대로 사용하는 엔진과 다른 실험 구조다.
프롬프트 단독 성능 향상이나 실제 정책 효과 검증 완료로 해석하지 않는다.

## 변경 이유

v14는 원문 일정 82/96, 공개한 시간 조정 후 91/96으로 사전 기준에 미달했다.
과거 약국 소비 비중으로 현재 복약 사실을 생성하기도 했다. v15의 v20/v21은 각 32/32
일정 형식을 통과했지만, 집 안의 하천 산책·산책의 건강 업종 분류·사용 불가한 온라인
거래에 정책지갑 사용 등의 오류가 남았다. 단순 형식 검사나 긴 원문 인용은 충분하지 않았다.

## 새 역할 분담

1. 정책·환경 공급자는 실제 제도 조건과 시민의 현재 상태를 제공한다. 공통 프롬프트에는
   정책 이름, 요구되는 효과 방향, 실측 효과 크기를 넣지 않는다.
2. v22는 정해진 활동 사전에서 활동·장소·시각을 선택한다. 활동 설명이나 구매 필요를
   자유 서술로 만들어 실행 상태에 넣지 않는다. 사전에는 무료 외출, 집/직장 활동,
   온라인 주문 검토, 여러 업종의 구매 검토가 있다. 구체적 약속은 입력 원문 근거가 있는
   공급자 확장 활동으로 제공한다.
3. 실행기는 활동 뜻·장소 조합을 확인한다. 시간 조정은 기존과 같이 이벤트당 최대 10분,
   원문·변경량·실행안을 모두 보존한다. 미지의 활동을 임의로 다른 업종으로 바꾸지 않는다.
4. 구매 단계는 제공된 상품/묶음 가격과 사용처에서 실제 선택을 한다. 구입 안 함은 0원으로
   남기고, 무료 활동을 유료 POI로 바꾸지 않는다. 현재의 자금 및 잔액 취득 순서를 검증한다.
5. 평가기는 같은 시민·달력·초기 상태의 on/off 차이를 계산한다. 결제 재원 변화, 자산 취득,
   명목 소비를 구분하며 결과의 방향이나 크기를 계획 단계의 정답으로 되돌려 넣지 않는다.

`validate_action_planner.py` 전용 실험이다. v22는 기존 Stage1 자유 서술 파서의 드롭인
대체물이 아니므로 기존 `SIM_PROMPT_VARIANT` 목록에 등록하지 않았다. 실제 지출 엔진에
연결하기 전에 별도 통합 검사가 필요하다.

## 무엇을 검증하는가

유한한 행동 사전으로 장소·활동 설명 모순과 임의 복약 서술을 없애는 부분은 **구조적 제약의
효과**다. 이를 모델의 무제약 사실 추론 성공률로 세지 않는다. v16 개발 실험에서는 폐쇄된
카페 활동을 사전에서 제거하지 않는다. 원문의 폐쇄 사실을 보고 모델이 피하는지 별도로
검사한다. 평가용 폐쇄 조건은 모델 요청에서 제외한다. 확정 약속과 근무는 명시된 원문
근거와 함께 실행 표기를 제공하며, 모델이 선택한 실제 시각/활동이 맞는지 검사한다.

직접 생성과 1,024토큰 추론 모드를 같은 16개 개발 입력, 두 seed로 비교한다. 일정 실행
가능성·명시 조건 준수·비용으로 선택하고 지출 증가율로 고르지 않는다. 알려진 정책과
사용했던 시민을 포함하므로 새 정책 일반화의 증거가 아니다. 미사용 24명 확인 표본은 보류한다.

## 결제와 자산 회계

`asset_transaction_v1`은 단가가 주어진 후보에서 선택한다. 선불 잔액 취득은 현금→자산 이동,
상품·서비스 구입은 소비다. 자기 재원과 할인/지급 재원의 장부가를 나누고, 지갑을 일부 쓴 뒤
잔여 장부가도 남긴다. 할인 재원 부담자가 공공인지 민간인지 자동 추정하지 않는다.
9개 합성 개인 조건×2 seed의 18개 응답이 가격·잔액·사용처·순서를 통과했고 원문 설명도
읽었다. 이는 구매가 확정된 개인의 회계 가능성 검사이며, 정책 때문에 수요가 증가한다는
실증 검증이 아니다. 과거 `transaction_v2`의 가격 일치 검사 누락은 새 계약에서 막았다.

## 남은 한계

- 활동 사전 밖의 행동은 공급자 확장이 필요하다. 어휘 제한을 범용 인간 행동 전체로 부르지 않는다.
- 집 식사의 식재료 재고, 품목 수량, 욕구 발생·충족과 소득/자금 유입을 아직 장기적으로 추적하지 않는다.
  현재 집 식사 선택을 실제 식료품 재고 존재의 증거로 세지 않는다.
- 주어진 인접 통근 시간은 확인하지만 모든 POI 경로·체류 시간·영업시간을 계산하지 않는다.
- 실제 메뉴 가격 없이 역사적 평균 영수증액을 개인 상품 가격으로 바꾸지 않는다.
- 가격이 있는 구매 선택과 완전한 일별 소비 원장을 연결한 후에도, 외부 연구와 개인/가구,
  기간·처치·대조군·결과 분모를 맞추기 전에는 효과 크기 검증 완료를 주장할 수 없다.

## 지리 입력 수정

기존 `build_dong_centroids.py`와 `build_hub_signature.py`는 동 이름만으로 코드를 덮어썼다.
실제로 강남구 신사동 좌표가 코드 기준 자료와 약 6.57km 달랐다. 공유 코드 371개 중
1km 초과 차이는 2개이며, 모든 차이가 이름 충돌 때문이라고 단정하지 않는다.

새 참조 묶음은 읽기 전용 Neo4j Dong 코드별 좌표 427개와 코드별 상점 업종 집계로 만들었다.
이는 상점 좌표 평균이며 행정경계 도형의 중심이나 과거 특정일의 상권 복원이 아니다.
기존 결과·참조 파일은 보존했다. 새 컨텍스트 준비는 코드 기준 출처를 요구하고, 실험별
참조 폴더를 명시한다. 기존 이름 기반 빌더도 관측된 중복 이름을 조용히 덮어쓰지 않도록 했다.
