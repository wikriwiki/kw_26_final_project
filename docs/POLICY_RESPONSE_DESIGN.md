# 정책 반응 디지털 트윈: 최종 결과 도출 명세

이 문서는 결과를 본 뒤 지표를 고르는 것을 막기 위한 분석 기준이다. 첫 적용 범위는 **소비지원 정책에 대한 집단별 생활 변화와 표현된 정책 입장**이다. 구매·정책지갑 실행 기록으로 분석 가능한 범위를 먼저 완성한다.

## 1. 산출물과 주장 수준

최종 산출물은 다음 세 가지다.

1. 기준 시나리오 대비 정책 시나리오의 집단별 오프라인 구매액·본인 부담액 차이.
2. 집단별 정책 거래 관측률·이용률·입장 측정률과 측정된 사람의 찬반 분포.
3. 사용 불가능한 업종/사용처의 거래를 관측한 집단과 그렇지 않은 집단의 입장 분포 비교.

1은 모형 안에서의 시나리오 차이, 2는 합성 에이전트의 표현 분포, 3은 관측된 연관성이다. 3을 불편의 인과효과로 해석하지 않는다. 외부 설문 검증 전 산출물의 `claim_level`은 `simulation_scenario_only`다. 실제 여론 예측 정확도라는 제목을 붙이지 않는다.

## 2. 실험 단위와 비교 조건

- 분석 단위: 에이전트. 거래 횟수가 많은 사람에게 찬반 표를 더 주지 않는다.
- 집단: 정책 적용 전 정한 에이전트→집단 명부를 사용한다. 정책 경험 이후 집단을 재분류하지 않는다.
- 기준/정책 실행: 같은 초기 인구·초기 상태·외생 환경·모델·소비 알고리즘을 고정하고 대상 정책만 변경한다. DB는 별도로 격리한다.
- 기간: 시작~종료일을 양끝 포함한다. 입장 평가는 종료일 다음 Dawn에서 읽는다. 평가일에 새로 발생한 지출은 관측 기간 지출에 포함하지 않는다.
- 반복: 동일 시드로 짝지은 기준/정책 실행을 하나의 반복으로 취급한다. 우선 1쌍으로 배선 검증 후 최소 3쌍을 목표로 한다. 3쌍은 정확도 보증이나 충분한 통계 검정력이라는 뜻이 아니다.
- 시드 번호만 같다고 공통난수가 보장되는 것은 아니다. LLM 서빙과 각 난수 발생기까지 실제 통제가 확인돼야 한다.
- 프롬프트 민감도 실험은 별도 실험군으로 실행한다. 같은 프롬프트의 시드 변동과 다른 프롬프트의 변동을 섞어 표본 수를 늘리지 않는다.

현재 분석기는 날짜·에이전트 명부·실행 ID·소스·모델·증거 해시를 검사한다. 초기 그래프와 전체 서빙 설정의 동일성, 시드가 실제 엔진에 적용됐는지는 자동 입증하지 못한다. 실행 설계의 선언 사항으로 남기고 보고서에 표시한다.

## 3. 확정 지표와 분모

집단 인구를 N, 관측 기간 내 정책 관련 거래 기록이 있는 사람을 O, 정책지갑 결제액이 양수인 사람을 U, 유효한 입장이 있는 사람을 M이라 한다.

| 지표 | 계산 | 허용 해석 |
|---|---|---|
| 평균 구매액 차이 | 에이전트별 (정책 총구매액−기준 총구매액)의 집단 평균 | 모형 내 관측 기간 오프라인 지출 변화 |
| 평균 본인 부담액 차이 | 에이전트별 (정책 본인부담−기준 본인부담)의 집단 평균 | 모형 내 현금 부담 변화. 온라인 제외 |
| 거래 관측률 | O/N | 정책 관련 거래를 기록한 비율. 정책 인지율 아님 |
| 정책 이용률 | U/N | 정책지갑 사용 비율. 찬성률 아님 |
| 입장 측정률 | M/N | 이 관측 기간 근거로 입장을 확보한 비율 |
| 찬반 분포 | 각 입장 인원/M | 측정된 사람의 입장 분포. 전체 인구 여론 아님 |
| 사용 불가 거래와 반대의 연관 | 두 거래경험 집단 각각의 반대 인원/측정 인원 | 기술적 연관. 경험의 인과효과 아님 |

코드는 분자와 분모를 함께 출력한다. 찬반은 `support`, `oppose`, `mixed`, `uncertain`이며 `mixed`를 자동으로 조건부 찬성으로 번역하지 않는다. 미측정은 다섯 번째 결측 상태로 유지한다. 정책 거래가 없는 사람도 N에서 제외하지 않는다.

관측 기간 밖 근거를 인용한 기존 입장은 이번 연구의 측정자로 포함하지 않는다. 관측 기간 안에 측정한 입장이 이후 유지되는 것은 허용한다. 측정일과 기간 해석은 별도 경험 보고서의 `as_of`로 감사한다.

## 4. 결과를 내지 않는 조건

- 명부 인원 누락, 상충하는 중복 완료 결과, 손상된 JSON/해시, 타인·미래 근거.
- 기준 실행에 대상 정책이 존재하거나 정책 실행에 대상 정책이 전혀 없음.
- 서로 다른 소스/모델을 같은 비교로 묶음, 동일 실행 또는 시드를 독립 반복으로 재사용.
- 과거 정책 전용 영수증 형식으로 기준 실행 지출을 비교하려 함.
- 관측 마지막 날과 입장 평가일을 같은 날짜로 잡음.

작은 집단과 적은 측정자의 분포는 기본 5명 기준으로 억제한다. 이는 익명성을 증명하지 않는다. 모든 시드 결과와 측정률을 함께 제시한다. 평균만 보고 부호 반전을 숨기지 않는다. 반복별 최솟값~최댓값은 신뢰구간으로 표기하지 않는다.

## 5. 생활 경험과 평가의 연결

현재 사실 계약은 구매액·본인 부담·구매 상태·정책 결제·모델상 사용 가능 여부다. 이를 인용한 짧은 이유는 주관적 표현으로 유지한다.

‘퇴근길에서 못 쓴다’, ‘대기가 길다’, ‘신청 절차가 어렵다’를 분석하려면 각각 다음 실행 데이터가 먼저 필요하다.

| 향후 평가 축 | 필요한 환경 데이터 | 완료 전 처리 |
|---|---|---|
| 접근성 | 출퇴근 경로, 시간 예산, 영업시간, 실제 대체 선택지 | 결과에서 미지원 |
| 이용 절차 부담 | 신청 시도, 단계별 조건, 처리시간, 성공/실패 | 결과에서 미지원 |
| 분배 공정성 | 자신이 인지한 비교 집단·혜택 정보와 출처 | 전지적 정보로 의견 생성 금지 |
| 정책 인지/이해 | 정보가 전달된 사건, 이해 확인 | 거래 관측률로 대체 금지 |

이 축을 지금 프롬프트만 추가해 출력하지 않는다. 환경의 실행 판정→사건 계약→집계 지표가 완성된 축부터 확장한다. 추가 분석기는 LLM을 호출하지 않는다.

## 6. 외부 검증 설계

정책별 설문 원문, 질문 날짜, 응답 범주, 집단 정의, 집단별 표본 수·가중치 유무를 확보한다. 정책 ID·집단·설문시점·응답범주·비율·표본수·출처를 검증 데이터의 필수 열로 고정한다. 기사 댓글 감성을 대표 여론의 정답으로 사용하지 않는다.

학습/선택용 정책과 최종 홀드아웃 정책을 정책 단위로 나눈다. 같은 정책의 다른 집단을 양쪽에 나눠 일반화 성능으로 제시하지 않는다. 홀드아웃 결과를 보고 프롬프트를 바꾸면 새 검증 집합이 필요하다.

- 일차 지표: 설문과 의미가 일치하는 범주에 대해 집단별 분포 오차 `0.5 × Σ|예측 비율−실측 비율|`. 범주 매핑을 먼저 고정한다.
- 병행 지표: 집단별 찬성 비율 절대오차(퍼센트포인트), 측정률, 최악 집단 오차, 시드별 범위.
- 비교 기준: 전체 설문 비율을 모든 집단에 적용한 단순 기준, 페르소나만 제시한 정적 응답 기준.
- 생활 시뮬레이션의 기여: 동일 예산에서 정적 응답 대비 홀드아웃 오차가 개선되는지 확인한다. 사건 근거를 제거하는 비교는 별도 통제 실험으로 구성한다.

범주를 일치시킬 수 없는 질문은 같은 성능 수치로 합치지 않는다. 측정자만으로 계산한 예측 분포의 선택 편향을 측정률과 함께 공개한다. 실제 정답 데이터가 없으므로 이번 구현은 외부 성능 수치를 생성하지 않는다.

## 7. 바로 사용할 분석 경로

1. `policy_response_design.example.json`을 복사해 실제 에이전트 명부와 실행 경로를 넣고 실행 전 고정한다. 예제의 값은 실행 결과가 아니다.
2. 같은 초기 조건에서 기준/정책 실행을 별도 DB·출력 디렉터리로 완료한다. 종료일 다음 날도 실행해 입장을 얻는다.
3. 아래 명령으로 검증·짝 비교·집단 집계·반복 범위를 JSON에 저장한다.

```powershell
python scripts/sim/analyze_policy_response.py --design <설계.json> --out <실행폴더밖의결과.json>
```

출력에는 설계 해시와 원본 파일 해시가 포함된다. 최종 보고서 순서는 ‘측정 대상과 주장 수준 → 표본/결측 → 생활 변화 → 입장 분포 → 경험과 입장의 연관 → 반복 안정성 → 미지원 영역’으로 고정한다. 대표 발언은 보조 사례이며 수치의 증거를 대신하지 않는다.

구현 검증은 합성 고정 자료로 수행한다. 금액의 짝 차이, 평가일 지출 제외, 이용하면서 반대하는 경우, 미측정, 잘못된 명부·기간·시드·구형 자료 거부를 확인한다. 실제 프로젝트 정책에 대한 결과와 성능은 아직 산출하지 않았다.
