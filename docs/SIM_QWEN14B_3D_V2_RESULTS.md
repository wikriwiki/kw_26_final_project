## 1. 본 풀런(v2)의 핵심 차이점

이전 풀런(v1)에서 시각화 점검 시 **카페 이벤트에 치킨집 POI**가 매칭되는 등 카테고리 mismatch가 광범위 확인되어, 다음 두 버그를 수정한 후 처음부터 재실행한 결과.

| # | v1 버그 | v2 수정 |
|---|---|---|
| ① | `resolve_dong()` 가 `len(dong)==10`만 valid. Neo4j Dong 코드는 **8자리** (행정안전부 표준). LLM이 정확한 코드 emit해도 모두 invalid 처리되어 home_dong 강제 복귀 → 외출 지리적 다양성 손상 | `len(dong)==8` 로 정정. resolve_dong_FB 카운터 100%→0% |
| ② | Stage 2 `valid_pois` 가 **모든 이벤트 후보를 flat union**으로 검증. LLM이 order 0(카페)에 order 5(한식집)의 POI를 넣어도 valid 통과 → **카테고리 매칭 광범위 깨짐** + 환각 카운터 거짓 0.4‰ | **Per-order 검증**. `cands_by_order[pick.order]` 안에서만 valid. `fb_order_mismatch` 카운터 추가로 진단 |

추가 보정:
- Stage 1 SYSTEM 프롬프트: "10자리" → "8자리", 예시 zone 코드 정정
- SYSTEM_S2 프롬프트: 0-base order 명시 + 예시 `{order:0, order:2}`
- `merge_to_final_events`: `cat=직장 + anchor=zone:work_dong` 같은 LLM 흔한 패턴을 category 기준으로 처리

### 3.2 해석

- **환각 보정 0.5‰ → 104.4‰**: v1에서 0.5‰로 보였던 환각률은 거짓이었음. 다른 order의 후보풀에 우연히 그 POI가 있어서 "valid"로 통과되며 카테고리 매칭이 깨진 상태였음. v2에서는 진짜 환각 (해당 order의 후보풀에 없는 POI) **10.4%** 가 검출되어 random Top-5로 보정 후 적재됨.
- **카테고리 정합성 회복**: 이제 카페 이벤트에는 카페 카테고리 POI만, 식사·한식 이벤트에는 한식 POI만 들어감.
- **missing_fill 192‰ → 31‰**: v1에서 LLM이 잘못된 order에 정답을 넣어도 "정답"으로 인정되어 누락 처리 안 됐던 게, v2에서는 진짜 누락만 채움.
