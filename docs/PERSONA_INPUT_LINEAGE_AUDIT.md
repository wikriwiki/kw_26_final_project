# 시민 입력의 세대 혼합과 복원 비교

기존 개발12명과 새 시민 확인24명의 고정 입력을 읽기 전용으로 감사했다.
36명 중33명에서 현재 생활 서술과 NVIDIA UUID가 새 원본의 순번−1 레코드와 모두
정확히 일치했다. 이33명의 원본 평일 소비 기준은 현재 고정 입력과 모두 달랐다.
직업 문자열은32명에서 달랐고, 두 종류의 비어 있지 않은 NVIDIA UUID가 서로 다른
시민은26명이었다. 직업 문자열 차이만으로 의미상 모순이라고 판정하지 않는다.
다만 전기설비 기술사/해병대 장교, 전시 보조/한식 조리사처럼 명백한 직업 혼합도 확인했다.

[전체 감사값](experiment_evidence/persona_lineage_audit.json)은 exact ID 변환 가설과
원본 해시를 포함한다. 이는 같은36명만의 감사이며 전체 모집단의 발생률 추정이 아니다.
원본을 찾지 못한3명은 별도 미해결 상태로 남기며 정상이라고 간주하지 않는다.

## 재현 가능한 원인

`load_persona_to_neo4j.py`는 생활 서술·새 UUID·매칭 수준만 갱신한다.
`--bump-seq`는 JSONL의0기반 순번을 DB의1기반 순번으로 바꾼다. 기존 직업·정량 값·
이전에 적재한 NVIDIA 취미/요약은 그대로 남는다. 더 오래된 `load_fusion_to_neo4j.py`도
직업을 갱신하지 않는다. 소스 코드와 실제 식별자/원문 일치가 이 혼합 경로를 뒷받침한다.
ID 보정 자체가 잘못됐다고 단정하는 것이 아니라, 다른 생성 세대의 일부 필드만 교체한
상태가 문제다. 공유 DB나 과거 고정 입력은 수정하지 않았다.

일부 Google Drive 경로는 파일 메타데이터의 크기보다 실제 읽힌 바이트가 짧았다.
완전하게 읽힌15,000행 서술 파일과14,881행 기존 시민 백업만 사용했다.
새 `read_complete`는 크기·수정시각 변화, JSON 오류, 중복 ID를 거부한다.
이전 로더의 JSON 오류 무시와 입력 배치 크기를 갱신 성공 수로 표시하는 관행도
후속 운영 적재에서는 그대로 사용하면 안 된다. 이번에는 해당 로더를 실행하지 않았다.

## 별도 입력 복원 실험

`persona_v1`은 기존12명·96조건을 모두 유지하는 입력 교정 묶음 비교다.
공통 v24,512추론 토큰,30분 시각 문법,seed44001,온도0.2는 market_v1과 같다.

- 원래 시민 백업의 ID·연령대·성별·직업 일치 후 생활 서술을 복원한다.
- 기존 NVIDIA 확장 서술은 감사 원본에 보관하고 이번 모델 입력에서는 제외한다.
- 현재 정량 값·장소·정책·상품·초기 상태는 유지한다. 개인 실측이 아닌 합성 기준임을 표시한다.
- 근무 POI가 없는 것을 `직장 없음`으로 쓰지 않고 근무 장소 미제공으로 표시한다.
- 기존12명 중1명은 원래 거주 동과 연결된 주거 POI 동이 다르다. 이 차이는 기본적으로
  준비를 거부하며, 이번에는 기존 공간 조건을 유지하는 명시적인 가정과 감사 기록을 넣었다.

96조건의 시민 블록 외 모든 문구와 상태·메뉴가 이전 입력과 같은지 독립 비교했다.
12명의 구조화된 정량·장소 필드도 동일하다. 이전 결과의 부호나 지출액은 선별 기준이 아니다.
원문96개를 모두 검토하며, 입력 교정 성공이 실제 행동 검증 완료를 뜻하지 않는다.
등록 파일: `data/experiments/validation_persona_v1_development.json`.
입력 SHA256: `d6d590f0c47dea614acfbbdcbfd00da0779dafc8f0d73098439063cb915a0949`.

## 남은 구조적 한계

원본의 생활 서술도 합성된 선호 가정이다. 소스가 같다고 현실의 진실성이 보장되지는 않는다.
기존 근무 활동 사전은 여전히 근무 POI 존재에 묶여 있고, 학교·이동 직업·고정 근무 일정과
재고·반복되는 일상 수요는 부족하다. 이 입력 교정은 해당 문제를 해결한 것으로 세지 않는다.
이전384/384 실행 통과와 행동→결제 소비 차이는 원본 그대로 보존하되,
정합적인 개인 행동이나 현실 정책 효과를 입증한 결과로 승격하지 않는다.
