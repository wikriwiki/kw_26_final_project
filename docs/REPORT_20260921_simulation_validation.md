## 한 줄

**"어떤 프롬프트가 정책 효과를 가장 잘 재현하는가"를 묻기 전에, 우리 시뮬레이터가 그걸 잴 수 있는 상태인지를 먼저 확인했고 — 아니었습니다.** 그 원인을 하나씩 찾아 고치는 중입니다.

## 1. 무엇을 검증하고 있나

시뮬레이션이 만든 정책 효과를 **실제 논문·보고서의 측정값**과 맞대봅니다.

| 기전 | 정책 | 칸의 날짜 | 현실 대응 | 정답지 |
|---|---|---|---|---|
| `cashback` | P012 카드 실적 캐시백 | 2021-10-25 | 2021 상생소비지원금 | 기획재정부·KDI (2022.9) |
| `grant` | P013 정책지갑 지급 | 2020-05-14 | 2020 1차 긴급재난지원금 | KDI FOCUS |
| `local_voucher` | P014 할인 구매 상품권 | 2020-09-23 | 지역사랑상품권 | 조세재정연구원 (2020) |
| `distancing` | (정책 아님 · 사회 배경) | 2020-11-24 | 수도권 거리두기 2단계 | 서울연구원 (2021.4) |

한 시민의 하루를 **정책 없음 / 정책 있음** 두 번 돌리고 차이를 봅니다.
같은 사람·같은 날짜라서 요일이나 개인차가 섞이지 않습니다.

정답지는 **17개 지표**로 정리돼 있습니다(적립업종 지출, 음식점 지출, 거주동 소비 비중 등).

## 2. 검증은 세 층입니다

```
A층  파이프라인이 온전한가      계약·물리·회계 검사
B층  프롬프트를 가를 수 있는가   후보 간 비교
C층  실측 정답에 수렴하는가      정답지 대조
```

**층을 건너뛸 수 없습니다.** A가 깨지면 B의 수치가 무의미하고, B에서 프롬프트를 못 고르면 C의 결과에 주인이 없습니다.

| 층 | 상태 |
|---|---|
| **A 파이프라인** | ✅ 검증됨 — 계획 유효율 100%, 게이트·회계·물리 독립 감사 통과 |
| **B 프롬프트 분별** | ⚠️ 설계는 맞으나 **아직 못 가름** |
| **C 실측 대조** | ⚠️ 17개 중 9개 산출 가능, **부호가 정해진 지표 0개** |

## 3. 최근 실험 결과 (v9 ~ v18)

### 3-1. 시뮬레이터에 "필요"가 하나뿐이었습니다

가장 큰 발견입니다. 96칸 **전부**가 같은 필요 하나만 가지고 있었습니다.

```json
"needs": [{"id": "laundry", "fulfilled_by": ["provided_laundry"]}]
"resources": {"detergent_dose": {"opening_quantity": 0}}
"quote_receipts": {"quote:home_online_goods": {"detergent_dose": 10}}
```

세탁 하나이고, **온라인 주문 90분 뒤 도착으로 집에서 충족**됩니다.
입력의 가정문이 직접 말하고 있었습니다 — *"다른 물품·식재료·열량·가사 전체의 재고는 아직 모델링하지 않는다."*

**이 하나가 관측된 모든 것을 설명했습니다.**

| 관측 | 설명 |
|---|---|
| 구매 71건 중 46건이 온라인 세제 (65%) | 유일한 필요 |
| 11개 업종 중 7개가 한 번도 안 팔림 | 그 업종에 필요가 없음 |
| 매장 취식 192칸에 1건 | 배고픔이 모델링 안 됨 |
| 거리두기 효과가 실측과 반대 부호 | **줄어들 매장 취식이 0건** |

### 3-2. 끼니 필요를 넣자 기준선이 크게 좋아졌습니다

세탁과 똑같은 구조를 끼니에 적용했습니다(재고·소비·보충·선택적 필요).
**프롬프트는 한 글자도 안 바꿨습니다.**

```
                        기존        끼니 추가 후
칸당 구매 건수           0.31        0.75
최다 품목                세제 77%    groceries 45% (세제 22%)
부여된 업종 구성과의 거리   0.80        0.53
```

> **"부여된 업종 구성과의 거리"** 는 정답지가 아니라 **그 시민 자신의 입력에 적힌 소비 구성**과의 차이입니다. 정답을 보고 맞춘 게 아니라 내부 일관성을 잰 것이라 순환 검증이 아닙니다.

### 3-3. 그런데 계획이 물리적으로 불가능해졌습니다

식재료가 0인데 집밥을 두 끼 계획했습니다. 장보기도, 외식도, 배달도 없이.
**자원 게이트가 96칸 중 46칸을 막았습니다.**

프롬프트로 고치려고 **세 가지를 사전등록하고 차례로 시험했습니다.**

| 무엇을 바꿨나 | 막힌 칸 (96 중) |
|---|---:|
| 대조 (현행 v25) | 44.8 |
| 자원 검사 **어구**를 명시 | 46.0 |
| 요구를 JSON에서 **산문**으로 | 44.5 |
| 계획 구성 **순서**에 자원을 넣음 | 44.25 |

**넷이 전부 같은 자리입니다.** seed 안의 흔들림(42~47)보다 작습니다.

그리고 모델의 사고 기록을 읽어보니 — **이미 이해하고 있었습니다.**

> *"Also, meal stock starts at 0, but groceries gives 3 meals immediately."*

재고 0인 48칸 중 22칸의 사고에 `groceries`가, 26칸에 `delivery`가 나오고 **빈 사고는 0건**입니다. **알면서 계획엔 반영하지 않습니다.**

### 3-4. 게이트 판정을 돌려주자 처음으로 움직였습니다

말을 바꾸는 대신 **틀렸다는 사실**을 알려줬습니다.

```json
{"event_id": "event:3", "time": "16:00", "resource": "meal_stock",
 "maximum_available": 0, "required": 1}
```

```
바퀴      막힌 칸    감소
0          46        —
1          44       −2
2          33      −11
3          21      −12
4          17       −4
```

**46 → 17.** 96칸 중 79칸이 물리적으로 가능해졌습니다(82%).
바뀐 방향도 맞았습니다 — `home_meal −9 · home_delivery +9 · groceries +3`.

**프롬프트로는 못 고치는 것을 되먹임으로는 고칩니다.** 다만 한 번이 아니라 네 번이고, 아직 17칸이 남습니다.

### 3-5. 그래도 집 밖으로는 안 나갑니다

늘어난 구매가 **장보기와 배달** — 둘 다 집에서 끝나는 해법이었습니다.
그래서 **집에서 끝낼 수 없는 볼일**을 하나 넣어봤습니다(미용·건강·교육·여가 중 그 시민 자신의 구성에서 가장 큰 업종).

```
zone 전용 서비스 구매   0 → 1건        (88칸 중 1건)
zone 사건 비율         0.107 → 0.127
```

**세탁도 끼니도 선택적인데 하고, 볼일은 선택적인데 안 합니다.** 차이는 하나뿐입니다:

```
세탁   온라인으로 집에서 끝난다      → 한다
끼니   배달·장보기로 집에서 끝난다   → 한다
볼일   해당 장소에 가야 한다        → 미룬다
```

**여덟 개의 프롬프트 축, 되먹임 루프, 두 번의 필요 모형 변경으로도 움직이지 않았습니다.**
`zone 사건 비율`이 v3부터 v18까지 **0.105 → 0.127**입니다.

### 3-6. 정답지 지표는 아직 하나도 정해지지 않았습니다

기준선을 고친 뒤 프롬프트를 다시 겨뤘습니다.

```
            후보당 칸 수    부호가 정해진 지표
v16              74              0 / 9
v17             283              0 / 9      ← 칸을 네 배로 늘렸는데도
```

**칸을 늘려도 안 되는 이유는 사람이 그대로이기 때문입니다** — seed를 늘리면 같은 열두 명을 다시 뽑을 뿐입니다.

검정력 계산이 처음부터 말하던 값입니다:

```
3,000원짜리 기전 효과를 80% 검정력으로 보려면   53명
후보 둘의 차이를 보려면                        후보당 106명
```

**열두 명은 어느 선에도 못 미칩니다.**

## 4. 지금 돌고 있는 것 — v18

**명단을 열둘에서 예순으로 늘렸습니다.**

```
Neo4j 의 14,560명 중 60명 추출 (기존 12명 제외 · 평일 소비분위 층화)
→ 480칸 (60명 × 4기전 × on/off) · 끼니 필요 포함
→ 후보 v25 · v34 각각 계획 → 게이트 → 수정 3바퀴 → 결제
```

**이번 물음:** *부호를 말할 수 있는 지표가 하나라도 생기는가.*

후보를 가르는 건 106명을 요구하므로 **기대하지 않는다고 미리 적었습니다.** 예순은 기전 효과 선(53명)은 넘고 후보 비교 선(106명)은 못 넘습니다.

> 진행: v25 계획 480칸 완료(36분), 수정 루프 진행 중. 완료 예상 **오늘 12시경**.

## 5. 팀이 알아야 할 것

### 잘 되고 있는 것

- **파이프라인은 믿을 만합니다.** 실패 행을 빼거나 0으로 메우지 않고, 물리적으로 불가능한 계획은 게이트가 모델 호출 전에 막습니다
- **모든 판정을 결과 보기 전에 git에 커밋**했습니다. 커밋 시각이 증거입니다
- **거짓 성공을 두 번 잡았습니다** — 공정 지표(구매를 더 함)를 통과했으나 정답지에서는 나빠진 후보, 그리고 구간이 너무 좁아 성급했던 제 판정 하나
- **기준선이 실제로 좋아졌습니다** — 세제 쏠림 77% → 22%, 구성 거리 0.80 → 0.53

### 솔직히 안 되고 있는 것

- **정답지 17개 지표 중 부호가 정해진 것이 0개입니다.** 9개는 값이 나오고 8개는 구조적으로 산출 불가입니다
- **에이전트가 집 밖으로 안 나갑니다.** 이것이 거리두기·지역화폐 지표를 원천적으로 막고 있고, 프롬프트로는 안 고쳐졌습니다
- **아직 실측과 크기를 맞대지 않았습니다.** 단위·기간·분모가 달라 정렬이 필요합니다

### 산출 불가 8개의 이유 (표본 문제가 아닙니다)

| 지표 | 왜 |
|---|---|
| 캐시백 문턱 도달·1인 평균 캐시백·한도 도달 | **월 단위 회계** — 하루로는 정의되지 않음 |
| 긴급재난지원금 순효과 | 우리 off 팔이 곧 '지급 전'이라 기준선 없음 |
| 가전·가구 vs 이·미용, 준내구재 vs 대면서비스 | 카탈로그에 그 업종 구분 없음 (최고가가 커트 20,000원) |
| 카페 지출 감소 | 무정책 팔 카페 지출이 **0원** |
| 상권 유형 순위 | 장소에 상권 태그 없음 |
