## 0. 먼저 — 한국은행 보고서가 한 일 (요약)

두 개의 효과를 두 개의 방법으로 쟀다.

| 효과 | 관점 | 데이터 | 방법 | 결과 |
|---|---|---|---|---|
| **매출 증대** | 사용처(소상공인) | 6개 카드사 사업자별 월매출 패널 (22.1~26.1) | **PSM-DID** (성향점수매칭 + 이중차분) | 사용처가 비사용처보다 월매출 **+2.91%** (범위 1.46~3.76%), 재정투입 대비 **30.9%** |
| **소비 진작** | 가계(개인) | 자기보고 서베이 2회 (동일인 패널) | **MPC 추정** (Kan et al. 2017) | 한계소비성향 **0.20**, 소득 1분위 0.25 > 5분위 0.17, 1차 0.21 > 2차 0.18 |
| (종합) | 거시 | 산업연관분석 | — | 2025 GDP **+0.12%** |

핵심 이질성(우리가 재현해야 할 "모양"):
- **업종**: 잡화점 +8.3%, 음식점 +5.8%, 여가 +5.4% (양(+)) / **학원 −9.3%, 병·의원 −5.9% (음(−))**
- **시점**: 7월 +8.4% → 11월 +0.3% (초기 집중 후 급감쇠)
- **소득**: 낮을수록 MPC 높음 (역진성)
- **품목**: 내구재·준내구재·여가는 신규소비 큼 / 비내구재·교육·의료(필수재)는 작음

## 1. 우리 시뮬과의 대응 관계 — 무엇을 그대로 하고, 무엇이 더 강한가

| 보고서 | 우리 시뮬 | 비고 |
|---|---|---|
| 사업자 = 분석 단위 | **POI = 분석 단위** (INCLUDES에 매출·coupon_eligible 기록) | 1:1 대응 |
| Treat = 사용처(1)/비사용처(0) | **coupon_eligible** (가맹점 CSV + 룰) | 이미 구현됨 |
| Post = 정책 전/후 | 런의 정책 시행일 전/후 day | 구현됨 |
| 반사실(counterfactual)을 **PSM으로 근사** | **같은 시드 OFF/ON으로 진짜 반사실 생성** | ⭐ **우리가 더 강함** |
| 가계 MPC는 **서베이로 우회**(대조군 못 만들어서) | **OFF/ON 총소비 차이로 MPC 직접 산출** | ⭐ 보고서의 최대 한계를 우리가 해결 |
| 카드 지급분(70%)만 관측, 상품권 과소추정 | 시뮬은 지급수단 무관 전량 관측 | ⭐ 과소추정 없음 |
| 시군구 간접 파급효과 제외 | Huff 광역이동으로 일부 포착 가능 | 확장 여지 |

**한 줄 요지**: 보고서가 "데이터 한계로 못 한 것(진짜 반사실, 가계 MPC 직접추정, 상품권 효과)"을
우리 시뮬은 **구조적으로 할 수 있다**. 이것이 시뮬을 쓰는 이유이자 백테스트의 세일즈 포인트다.

## 2. 환경 하이퍼파라미터 — 어떻게 설정하나 (핵심)

### 2-1. 황금률: "정책 없는 세계로 맞추고, 정책은 얹기만 한다"

가장 중요한 원칙이다. 하이퍼파라미터는 **정책 효과를 만들어내는 손잡이가 되어선 안 된다.**
그러면 연극이 아니라 낭독(정해진 대본 읽기)이 된다. 파라미터는 **무대**만 실제처럼 짓고,
정책 효과라는 **대사는 배우(에이전트)가 스스로** 말하게 해야 한다.

구체적으로: 모든 파라미터는 **정책 OFF 상태의 기저 통계**로 고정하고,
정책 ON에서도 **그 값을 한 글자도 바꾸지 않는다**. 정책 효과는 오직
"봉투(사용처 제한 지원금)가 구조에 추가됨"에서 **내생적으로** 나와야 한다.

### 2-2. 파라미터를 3종류로 나눈다 (ABM 표준: fixed / calibrated / held-out)

| 종류 | 무엇 | 어떻게 정하나 | 예시 |
|---|---|---|---|
| **A. 데이터 고정** | 실측에서 직접 온 값. 튜닝 대상 아님 | 데이터 그대로 | 페르소나 분포(BDC), 동별 건단가(unit_price.json), POI 가격밴드, **정책 스펙(지급액·대상·사용처·기간)**, 가맹점 라벨 |
| **B. 캘리브레이션** | 자유 파라미터. **정책과 무관한 기저 6지표**로만 맞춤 | 정책 OFF 런이 시공간·지니를 재현하도록 조정 | ANCHOR_PROPENSITY(0.70), 가격 basket 클램프[0.8,1.25], Huff β, 봉투 소진율 |
| **C. Held-out (검증 대상)** | **정책 효과 지표. 절대 파라미터로 두지 않음** | 건드리지 않음 — 시뮬이 창발로 만들고 보고서와 비교만 | 매출 β, MPC 0.20, 소득 역진성, 업종 순위, 시간 감쇠 |

**절대 금지 목록** (있으면 백테스트 무효):
- "쿠폰 MPC = 0.20이 되도록" 소비성향을 조정하는 것
- "음식점이 오르도록" 특정 업종에 가점을 주는 것
- 정책 ON일 때만 propensity 클램프·가격 탄력을 바꾸는 것
- preflight가 행동 파라미터를 건드리는 것 (이미 중립성 원칙으로 차단됨 — `policy_preflight.py`)

### 2-3. 실제로 설정해야 할 환경값 (정책 효과와 무관한 것들)

이것들은 "무대 크기"라 정해야 하지만, 정책 효과의 크기를 결정하진 않는다:

| 환경값 | 권장 설정 | 근거 (보고서에서) |
|---|---|---|
| **런 기간** | 정책 전 ≥30일 + 후 ≥60일 (이상적 전1년+후100일) | DID엔 평행추세 확인용 사전기간 필수. 사용액 8주내 90% |
| **정책 시행 타이밍** | 사전기간 중반 이후 1개 시점 | Post 더미 기준. 보고서는 7.4 발표시점부터 반응 관측 |
| **시드 수** | ≥3 (신뢰구간) | 시뮬 표본오차 → 구간추정 |
| **정책 강도** | **실제값 그대로** (1차 15만/2차 10만, 사용처 30억↓) | A(데이터 고정). 임의 조정 금지 |
| **감쇠 파라미터** | windfall 4단계는 **캘리브레이션 아님** — 프롬프트 서술일 뿐, 크기는 LLM 자율 | 시간 감쇠(7월→11월)를 심지 않고 창발로 |

## 3. "실제와 비슷했다"를 어떻게 입증하나 — 6단계 프로토콜

핵심 프레임: 우리는 **소비의 '수준'이 아니라 정책이 만든 '변화'**를 보고서와 맞댄다.
수준(총소비·시공간 분포)은 이미 기존 6지표로 검증됐고, 이번에 볼 것은
"정책 → 변화"의 재현이다. (§POLICY_BACKTEST_RESEARCH.md의 3층 구조와 동일 철학)

### Step 0. 사전 등록 (런 돌리기 전)
합격 지표·대역을 **미리 문서에 못박는다**. 사후에 유리한 지표만 고르는 것(cherry-picking) 차단.
→ 아래 표가 그 초안.

### Step 1. 기저 재현 확인 (환경이 옳다는 전제)
정책 OFF 런이 **기존 6지표**(시간대 cosine 0.857, 공간 0.944, 소비 Gini 등)를 재현하는가.
실패하면 무대가 틀린 것 → 정책 효과 논할 자격 없음. (이게 §2-2의 B 캘리브레이션 게이트)

### Step 2. 평행추세 확인 (DID의 생명)
정책 **이전** 기간에 사용처 POI와 비사용처 POI의 매출 추세가 **나란한가**(parallel trend).
보고서 <그림 11>의 핵심 가정. 시뮬에서 사전기간 두 그룹의 월매출 기울기 차이를 검정 →
유의하게 벌어지면 안 됨. (통과해야 Step 3의 β가 의미)

### Step 3. 매출 증대 — 시뮬 PSM-DID로 β 추정 → 보고서와 비교
보고서 회귀식을 **그대로** 시뮬 데이터(INCLUDES)에 적용:
```
Y_it = α + β·(Treat_i × Post_t) + μ_i(POI 고정효과) + λ_t(월 고정효과) + ε
Y = log(POI 월매출),  Treat = coupon_eligible,  Post = 정책 후
```
- PSM 매칭 변수: 업종(L1)·입지(동)·(가능하면 가격밴드=규모 프록시)
- **합격**: 시뮬 β ∈ [1.46%, 3.76%] (보고서 방법론 스팬), 1차 목표 2.91%±1.5%p
- **보너스 (우리만 가능)**: 같은 시드 OFF의 "진짜 반사실" β_true와 PSM-DID β를 비교 →
  DID 방법론 자체의 편의를 측정 (학술적 부가 기여)

### Step 4. 소비 진작 — 시뮬 MPC 직접 산출 → 보고서와 비교
보고서는 서베이로 우회했지만 우리는 반사실로 직접:
```
MPC = (ON 총소비 − OFF 총소비) / 지급액        ← 진짜 신규 유발분 (대체분 자동 제거)
```
- **합격**: MPC ∈ [0.19, 0.42] (선행연구 스팬), 보고서 점추정 0.20 근처
- **부호 재현 (더 중요)**: 소득 1분위 MPC > 5분위 MPC (역진성), 1차 > 2차

### Step 5. 이질성 "모양" 재현 (인과 구조를 맞췄다는 증거)
절대수준보다 **패턴의 방향·순위**가 맞는지가 핵심:
- 업종: 음식점·잡화 **양(+)** / 학원·병의원 **음(−)** ← 부호 정합
- 시점: 초기 집중 후 감쇠 (7월 최대 → 11월 소멸) ← 곡선 상관
- 품목: 내구·준내구·여가 > 필수재 ← 순위 Spearman

### Step 6. Placebo (거짓양성 방어)
정책이 **없던** 기간에 같은 파이프라인 → β ≈ 0, MPC ≈ 0. "아무 데서나 효과를
찾아내는 기계"가 아님을 자가 증명.

### 합격 기준표 (사전 등록용 초안)

| # | 지표 | 보고서 값 | 시뮬 합격 대역 | 종류 |
|---|---|---|---|---|
| 1 | 매출 β (PSM-DID) | 2.91% (1.46~3.76) | [1.46%, 3.76%] | 핵심 |
| 2 | 재정투입 대비 전이 | 30.9% (16.1~39.8) | [16%, 40%] | 핵심 |
| 3 | MPC | 0.20 (0.19~0.42) | [0.19, 0.42] | 핵심 |
| 4 | 소득 역진성 | 1분위>5분위 | 부호 일치 | 필수 |
| 5 | 업종 부호 | 음식·잡화(+)/학원·병원(−) | 부호 정합률 ≥ 4/5 | 필수 |
| 6 | 시간 감쇠 | 초기집중 | 단조감소 재현 | 필수 |
| 7 | 평행추세 | (가정) | 사전기간 무차이 | 게이트 |
| 8 | Placebo | 0 | \|β\| < 1% | 게이트 |

## 4. 정직한 한계 (검토 시 반드시 같이 볼 것)

| 한계 | 설명 | 대응 |
|---|---|---|
| **소득 역진성 일부 내장** | 우리 INCOME_PRIOR(하 0.90…상 0.58)가 평상시 MPC 역진성을 이미 가짐. → 쿠폰 역진성 부호는 부분적으로 구조에서 옴 | "부호 재현"은 약한 증거로, "**기울기 크기**와 쿠폰 MPC **절대수준**"을 강조. INCOME_PRIOR는 정책 무관 문헌값(Jappelli-Pistaferri)이지 쿠폰값 아님을 명시 |
| 업종 음(−) 효과(학원·병원) | 보고서: 가처분소득↑ → 큰 병원 이동 등. 우리 시뮬에 이 대체 메커니즘이 약할 수 있음 | 재현 실패 시 "시뮬의 한계"로 정직 보고 (숨기지 않음) |
| 소득 tier 근사 | 2차 "상위10%"를 tier '상'으로 근사 (INCOME_ASSIGNMENT_PLAN v2 전) | 정밀 소득 백분위 도입 후 재검증 |
| 상품권/선불 지급분 | 우리는 전량 시뮬하지만 보고서 β는 카드 70%만 → **직접 비교 시 스케일 주의** | 재정투입 대비(%)로 비교하면 지급수단 무관 |
| 사용처 커버리지 26% | 가맹점 CSV가 POI의 26%만 매칭 → 나머지 룰 fallback | merchant_stats.py에서 이미 평가·문서화 |

```
         · 평행추세 검정  · PSM-DID β  · MPC(OFF/ON차)  · 업종·소득·시간 이질성  · placebo

```

## 6. 한 문단 요약 (발표용)

> "우리는 정책 효과를 **하이퍼파라미터로 심지 않는다.** 모든 파라미터는 정책이 없는 평상시의
> 서울 통계(시공간 분포·소비 불평등)로만 고정하고, 정책은 실제 스펙 그대로 '봉투'로 얹을 뿐이다.
> 그 위에서 에이전트들이 스스로 반응해 만들어낸 매출 증대율·한계소비성향·업종별 명암을,
> 한국은행이 실제 카드·서베이 데이터로 추정한 값(β 2.91%, MPC 0.20, 음식·잡화↑/학원·병원↓)과
> 맞대본다. 합격선은 런을 돌리기 전에 문서로 못박았다. 게다가 한국은행이 데이터 한계로 서베이로
> 우회했던 가계 MPC를, 우리는 같은 시드의 '진짜 반사실 세계(OFF)'와 비교해 직접 계산한다 —
> 이것이 시뮬레이션만이 할 수 있는 일이다."
