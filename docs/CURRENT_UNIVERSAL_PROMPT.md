# 현재 범용 프롬프트 후보

최종 확정판이 아니다. v24 활동 선택과 v4 결제 선택을 별도 단계로 실행한다.
정책·사회 배경·개인 상태·상품 가격·지갑 사용 자격은 별도 입력이다.
공통 문구에는 특정 정책의 반응 방향이나 실측 효과 수치를 넣지 않는다.

## 활동 선택 v24

```text
입력의 시민 한 사람이 오늘 무엇을 할지 선택한다.
개인의 생활과 취향, 오늘의 의무, 이용 가능한 자금·장소, 적용되는 제도와 사회 환경을 함께 판단한다.
과거 지출 비중과 평균 소비는 경향이다. 오늘의 구매 할당량이나 치료·복약·고장·예약 사실이 아니다.
특정 정책의 성공이나 사회 전체 효과를 목표로 삼지 않는다. 상황에 따라 유지·대체·연기·생략할 수 있다.

활동 목록은 실행 가능한 선택의 뜻을 정해 둔 사전이다. 필요한 활동만 골라 하루 계획을 세운다.
구매 검토 활동은 반드시 산다는 뜻이 아니다. 실제 장소·상품 가격·자금 조건을 확인하는 결제 단계에서
구매 여부와 재원을 정한다. 무료 활동이나 집에서의 온라인 구매 검토도 각각의 활동으로 표현한다.
목록에 없는 진단·의무·경험을 새로 만들지 않는다. 제공된 확정 약속과 근무 조건은 지킨다.
집에서의 업무는 remote_work, 사무실 업무는 office_work이다. 근무지 주소만으로 출근을 확정하지 않는다.
각 활동의 허용 장소 중 실제 머무는 장소를 고른다. 가까운 거리인지와 주어진 통근 소요시간을 고려한다.

출력은 events 배열을 가진 JSON 하나다. 각 항목은 time, activity_id, anchor 세 필드만 가진다.
time은 그 장소에서 활동을 시작하는 HH:MM 시각이며 시간순으로 놓는다. 이웃 활동 간 최소 20분,
집·직장 사이에는 주어진 통근 시간을 확보한다. 명시된 약속·출근 시작 시각을 맞춘다.
평일 6~10개, 주말 4~8개이며 첫째와 마지막 장소는 residence다.
활동 수를 채우려고 외출이나 구매를 추가하지 않는다. 집안 활동을 선택할 수도 있다.
자유로운 활동 설명, 이유, 금액, 소비 의향 점수는 생성하지 않는다. 선택한 활동의 의미는 사전 그대로다.

오늘 하루의 계획이므로 아침 활동만 나열하고 끝내지 않는다. 저녁과 하루 마무리까지 고려한다.
먼저 입력에 명시된 일정의 실행 표기에 있는 활동·장소·시각을 계획에 놓고,
그 전후에 이 사람에게 맞는 일상 선택을 배치한다. 약속 전 도착·대기는 약속 활동 자체와 다르다.
업무를 일찍 시작한다고 정해진 출근 시각의 업무 항목을 없애지 않는다.
일찍 사무실에 도착하면 office_prepare로 준비하고 명시된 시각에 office_work를 시작한다.
업무가 끝나면 office_finish로 퇴근 준비를 표현할 수 있다. 귀가까지 주어진 이동 시간을 남긴다.
명시된 고정 일정이 없으면 이 사람의 상황에 맞게 시각을 선택한다.

활동을 출력하기 전에 이 사람의 하루 전체를 먼저 정한다. 확정된 의무, 오전 일상,
오후 일상, 저녁과 마무리의 순서를 잡은 뒤 필요한 변화 지점만 events에 남긴다.
같은 장소에서 같은 일을 이어 가면 항목을 반복하지 않는다. 오전의 사소한 활동으로
항목 수를 다 쓰지 말고 하루 뒤쪽의 선택을 표현할 자리를 남긴다.
취침 준비는 그 사람의 주된 수면에 들어가기 위한 활동이다. 잠깐의 휴식은 home_leisure다.
집 체류 시간은 재택근무 가능 여부가 아니다. 장소 후보의 설명은 오늘 가야 할 일정이 아니다.
제약을 쉽게 피하려고 재택근무 허용, 휴무, 조기 퇴근, 새 의무를 확정 사실로 가정하지 않는다.
명시되지 않은 근무 방식은 직업과 주어진 생활 정보 안에서 일관되게 선택하고,
다른 활동을 끼워 넣기 위해 근무 장소를 반복해서 바꾸지 않는다.
월별 행동 빈도는 매일 해야 할 의무가 아니다. 오늘 구매하지 않거나 외출하지 않는 것도
이 사람의 필요·선호·시간·자금에 따른 선택이어야 한다. 특정 선택을 기본 정답으로 삼지 않는다.
```

추론512토큰, 온도0.2, 30분 간격과 주어진 고정 시각의 실행 문법을 함께 시험 중이다.
이는 프롬프트 단독 실험이 아니다. 시간 사후 보정 없이 원문과 독립 사실 검사를 기록한다.

## 결제 선택 v4

```text
시민 한 사람의 현재 상황에서 오늘 무엇을 사고 어떤 재원을 쓸지 선택한다.
개인의 생활·취향·확정된 필요와 의무, 자금, 활동 목적, 후보의 실제 품목·수량·가격,
적용되는 제도와 환경을 함께 고려한다. 과거 지출 비중은 경향이지 오늘 채울 할당량이 아니다.
특정 제도의 성공이나 사회 전체 소비 변화를 목표로 하지 않는다. 유지·대체·연기·미구매 모두 가능하다.
구매 검토 활동이나 후보의 존재만으로 구매를 확정하지 않는다. 지금의 부족·질병·고장·예약은
입력에 명시된 것만 사실이다. 모르는 재고나 긴급한 필요를 새로 확정하지 않는다.

후보 하나의 price_won은 표시된 품목·수량 전체 가격이다. 다른 품목·수량·가격을 만들지 않는다.
각 이벤트에서 후보 하나 또는 구매 안 함을 고른다. 온라인·오프라인, 사용 자격은 후보 정보를 따른다.
현재 보유 잔액과 직접 선택한 선불 취득으로 얻을 잔액만 쓸 수 있다. 미래에 받는 돈은 현재 자금이 아니다.
선불 취득은 자기 현금을 자산으로 바꾸는 선택이며 상품 소비가 아니다. 최대 취득량은 오늘 채울 목표가 아니다.
현재 상황·실제 이용 가능성과 자금 여유에 맞게 취득하지 않거나 필요한 단위 수를 선택한다.

이번 실행 조건은 취득 제안이 하루 내내 사용 가능하고 하루 중 추가 현금 유입이 없다는 것이다.
선택한 선불 잔액은 처음 쓰는 이벤트 직전에 실행기가 취득한다. 오늘 쓰지 않는 취득은 구매 종료 후 처리한다.
취득 비용도 현재 자기 돈에서 지불한다. 하루의 현금 구매액과 선불 취득 비용 합이 현재 현금을 넘으면 안 된다.

출력은 acquisition_units와 purchases만 있는 JSON이다.
acquisition_units는 입력 offer ID별 취득 단위 수다. 취득하지 않으면 0이며 한도를 넘지 않는다.
purchases는 입력 이벤트 순서의 고정 배열이다. 모든 이벤트에 id, candidate_id, wallet_spend를 적는다.
candidate_id=null이면 wallet_spend={}이다. 지갑을 쓰지 않으면 {}이며 현금으로 가격 전액을 지불한다.
지갑을 쓰려면 해당 후보의 eligible_wallets 안에서 ID와 사용 금액을 적는다. 쓰지 않는 지갑은 적지 않는다.
지갑 사용액 합은 상품 가격을 넘지 않으며, 각 지갑의 보유·취득 잔액에서 앞선 사용액을 뺀 범위를 지킨다.
상품 가격에서 지갑 사용액 합을 뺀 정확한 나머지는 실행기가 현금으로 계산한다. 현금 금액을 따로 생성하지 않는다.
특정 재원을 먼저 쓰라는 규칙은 없다. 자유로운 설명문·구매 이유·새로운 사실·다른 필드는 생성하지 않는다.
```

결제는 현재 정적 하루 제안·일중 소득0 가정에서만 검증했다. 취득 가능 지갑의 표현 제약과
독립 원장 검사를 사용한다. 현재 v18 고정 일정을 사용한 가상 가격 실험이며 실제 수요·
역사적 정책 효과 크기의 검증 완료가 아니다. 코드 원문이 우선하며 결과는 진행 기록을 따른다.
