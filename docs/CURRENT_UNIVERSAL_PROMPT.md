# 현재 범용 프롬프트 후보

현재 고정 후보는 활동 v25와 결제 v7이다. 아래 문구는 실제 실행 모듈에서 그대로 추출했다.
추가 반복에서 배송 전에 세탁하는 불가능한 계획1개가 발견되어 전체 미시 검증 승격은
보류한다. [실패 원문과 검사 범위](DAILY_CONDITIONS_V2_REPEATS.md)를 우선 확인한다.
특정 정책 이름·기대 행동 방향·실측 효과 목표를 공통 지시에 넣지 않는다. 시민·제도·사회
배경·가격·사용 자격·의무·재고는 별도 입력이며, 수치 사실과 정책 효과의 정답을 구별한다.

계획96/96과 후속 결제96/96, 자원 사실8/8을 통과해 추가192조건 반복에 사용한다.
현재 적격성은 제공된 조건 안에서 실행·회계·재고가 일관된다는 의미다. 현실 정책 효과의
방향·크기까지 검증한 최적판은 아니다. 무료 식사의 자원, 상품 범위, 미래 수요와 환급 및
실제 다일 행태 등 남은 한계는 [비교 결과](DAILY_CONDITIONS_V1_EXPERIMENT.md)에 기록했다.
[추가 반복 등록](DAILY_CONDITIONS_V2_REPEATS.md)에 따라 문구를 고정하고 안정성을 확인한다.

## 활동 선택 v25

```text
입력에 주어진 시민 한 사람의 오늘 하루를 선택한다.
그 사람의 생활·선호, 확정된 의무, 현재 필요·재고·자금, 장소와 상품, 제도와 사회 배경을 함께 고려한다.
사회 전체의 소비나 제도의 성과를 목표로 삼지 않는다. 평균 지출과 과거 비중은 오늘 채울 할당량이 아니다.
관측 사실과 명시된 실험 가정 안에서 선택하며, 없는 의무·휴무·재택 허가·부족·질병·과거 경험을 만들지 않는다.

먼저 확정된 일정과 이동 시간을 배치하고, 그 전후에 필요한 일상과 저녁 마무리를 정한다.
같은 장소에서 같은 일을 계속하면 하나의 항목으로 표현한다. 준비 활동만으로 본래 일을 끝냈다고 보지 않는다.
확정 일정이 없는 시간에는 사용 가능한 대안 중 이 사람에게 맞는 것을 선택한다.
필요를 지금 충족하거나 보유품으로 해결하거나 대체·연기·생략할 수 있다. 후보의 존재는 구매 의무가 아니다.
daily_conditions가 있으면 활동에 필요한 자원을 실제 사용 전 확보할 수 있는지 확인한다.
물품을 주문해도 명시된 도착 전에는 사용할 수 없다. 같은 재고를 여러 번 사용하거나 미래 입금을 당겨 쓰지 않는다.
구매 검토는 최종 구매와 다르며, 다음 결제 단계가 실제 상품 선택과 지불을 확정한다.

출력은 events 배열을 가진 JSON 하나다. 각 항목은 time, activity_id, anchor만 포함한다.
활동 사전의 ID와 허용 장소를 사용한다. 시각은 해당 장소에서 활동을 시작하는 HH:MM이고 시간순이다.
이웃 항목은 최소20분 간격이며 입력의 더 긴 이동시간·장소 유지 구간·확정 시작 시각을 지킨다.
평일6~10개, 주말4~8개이며 첫 항목과 마지막 항목은 residence다. 아침부터 저녁 마무리까지 표현한다.
활동 수를 채우려고 구매·외출·반복을 추가하지 않는다. 집 체류 시간은 재택근무 가능 여부가 아니다.
자유 설명, 이유, 소비 의향, 금액을 출력하지 않는다.
```

활동 원문 SHA256: `5e8dbb02eeeab70964ef4d781975e842a7caebb981b98d5f446d2d9d8ee34a87`.
실험은30분 시각 문법과 확정 일정·장소 구간을 따로 적용한다. 위 문구의 최소20분 간격은
표현 계약의 하한이고, 이 실험에서는 더 강한30분 격자가 적용된다. 출근·등교 적격성을
공통 문구만의 학습 성과로 해석하지 않는다.

## 결제 선택 v7

```text
입력의 시민 한 사람이 오늘 무엇을 사고 어떤 재원을 쓸지 선택한다.
개인의 생활·선호·확정된 필요와 의무, 자금·시간, 활동 목적, 제공된 상품·서비스,
제도와 환경을 함께 고려한다. 평균 소비와 지출 비중은 경향이며 오늘 채울 할당량이 아니다.
특정 제도의 성공이나 사회 전체 소비 변화를 목표로 하지 않는다. 유지·대체·연기·미구매가 가능하다.
구매 검토와 후보의 존재만으로 구매를 확정하지 않는다. 입력에 없는 부족·질병·고장·예약·재고를
새 사실로 만들지 않는다. 명시된 확정 구매도 없는 자금이나 차입을 만들어 내지는 못한다.

cash는 현재 사용할 수 있는 자기 현금이다. wallet_balances_won은 지갑 ID별로 지금
결제에 사용할 수 있는 전체 잔액이다. 해당 지갑으로 앞서 지출한 금액만큼 이후 잔액이 줄어든다.
빈 지갑 객체는 보유 잔액이 없다는 뜻이다. 미래 입금은 지금 쓸 수 없다.
offers는 현금을 내고 선불 잔액을 취득하는 제안이다. unit_cash_cost는 한 단위의 현금 비용,
unit_face는 그 한 단위 취득으로 늘어나는 사용 가능 잔액, max_units는 취득 상한이다.
offers={}이면 취득 제안이 없고 acquisition_units={}이다. 상품 후보와 취득 제안은 별개다.
취득량은 상한을 채우는 목표가 아니다. 이 사람의 이용 가능성과 자금 여유를 고려해 선택한다.
선불 취득은 자산 교환이며 상품 소비가 아니다. 취득 비용도 현재 현금에서 지불한다.

events는 오늘의 구매 검토 기회이고 candidates는 각 기회의 상품·서비스 후보다.
후보의 price_won은 표시된 품목·수량 전체 가격이다. 없는 상품·수량·가격을 만들지 않는다.
각 기회에서 후보 하나 또는 미구매를 선택한다. eligible_wallets에 있는 지갑만 그 거래에 쓸 수 있다.
지갑 사용액 합은 상품 가격을 넘지 않는다. 나머지는 실행기가 현금으로 정확히 계산한다.
취득 비용과 모든 현금 결제의 합은 현재 현금 이하이고, 각 지갑도 실제 잔액을 초과할 수 없다.
현재 자금으로 결제할 수 없는 후보는 선택하지 않는다. 특정 재원을 먼저 쓰라는 규칙은 없다.

입력의 실행 가정은 제안이 하루 내내 유효하고 일중 현금 유입이 없다는 것이다.
선택한 선불 취득은 첫 사용 직전에, 오늘 쓰지 않는 취득은 구매 종료 후 실행한다.
출력은 acquisition_units와 purchases만 있는 JSON이다. acquisition_units에는 각 offer ID별
취득 단위 수를 적는다. 미취득은 0이다. purchases는 모든 events를 입력 순서대로 포함한다.
각 구매 항목은 id, candidate_id, wallet_spend다. 미구매는 candidate_id=null, wallet_spend={}이다.
지갑을 사용하면 지갑 ID와 사용액을 적고, 사용하지 않는 지갑은 적지 않는다.
자유로운 설명·이유·금액 필드를 추가하지 않는다. 짧게 현재 재원과 시간순 선택을 점검한다.

daily_conditions가 있으면 명시된 재고, 활동별 사용량, 상품 수령량과 도착 지연을 함께 확인한다.
지금 사지 않아도 보유량이 충분할 수 있고, 물품을 샀더라도 도착 전 활동에는 사용할 수 없다.
선택된 일정의 실제 자원 사용을 시간순으로 충당해야 한다. 이 단계에서 일정을 삭제하거나 바꿀 수 없다.
선택하지 않은 활동의 필요는 미충족 상태로 남을 수 있으며 이를 지출 할당량으로 해석하지 않는다.
입력에 없는 자원·추가 배송·대체 상품을 만들어 모순을 메우지 않는다.
```

결제 원문 SHA256: `d95fb1678702e6b14bc0daf63199f64e3d3d4a668518acd27fc8c36e3b923d0f`.
회계용 원가와 평가 정답은 모델 입력에서 제외한다. 모델에는 사용 가능 잔액을 제공한다.
현재 하루 내 유효한 선불 제안·일중 소득 유입 없음 가정은 한계이며, 다일 실험에서 그대로
숨겨 재사용하지 않는다. 원문 모듈과 실행별 동결 설정·요청 파일이 최종 기준이다.
