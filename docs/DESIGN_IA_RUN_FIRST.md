# 정보구조 전환 — 기능 우선에서 실행 우선으로

> 디자인 기준은 `docs/DESIGN_SPEC_WEB_CONSOLE.md` 가 그대로 유효하다. 이 문서는 **정보구조와 라우팅**만 다룬다.

## 1. 무엇을 바꾸는가

**지금 (기능 → 실행 선택)**
```
사이드바: 정책설정 · 실행모니터 · 결과 · 시각화
           ↓ 각 화면 안에 run 선택기가 따로 있다
```
같은 run 을 보려면 화면을 옮길 때마다 다시 고른다. 화면마다 선택 상태가 따로 놀고,
"지금 무엇을 보고 있는가"가 화면 안쪽에 묻힌다.

**바꿀 것 (실행 선택 → 기능)**
```
메인: 시뮬레이션 목록 (완료 · 진행중 · 중단) + 새로 만들기
        ↓ 하나를 고른다
작업공간: 그 실행에 대한 개요 · 모니터 · 결과 · 시각화
```
run 은 **한 번만 고른다.** 이후 모든 화면이 그 run 에 매여 있다.
사이드바는 "지금 이 실행의 무엇을 볼지"를 고르는 자리가 된다.

이건 프로젝트/워크스페이스 전환 패턴이다. 실행이 명사고 기능이 동사다.

## 2. 라우팅

| 경로 | 화면 | 셸 |
|---|---|---|
| `/` | **시뮬레이션 목록** (메인) | 셸 없음 — run 컨텍스트가 아직 없다 |
| `/new` | 새 시뮬레이션 만들기 (정책 선택·설정 → 실행) | 셸 없음 |
| `/runs/:runId` | 개요 — 이 실행이 무엇인지 한 장 요약 | run 셸 |
| `/runs/:runId/monitor` | 실행 모니터 | run 셸 |
| `/runs/:runId/results` | 결과 | run 셸 |
| `/runs/:runId/visualize` | 3D 시각화 | run 셸 (전체블리드) |
| `/runs/:runId/policy` | 이 실행에 적용된 정책 (읽기 전용) | run 셸 |

**구 경로는 새 구조로 넘긴다** (§9 `deep-linking` — 공유된 링크가 죽으면 안 된다):
`/results?run=X` → `/runs/X/results`, `/visualize?run=X&day=D` → `/runs/X/visualize?day=D`,
`/monitor` → `/` (run 미지정이므로 목록으로).

## 3. 메인 페이지 — 시뮬레이션 목록

**단일 목적: 어떤 실행을 볼지 고른다.** 그 외의 것을 두지 않는다.

기본 노출 (1차 블록 4개 이하):
1. 제목 + 목적 한 문장 — "확인할 시뮬레이션을 고르세요."
2. **새 시뮬레이션 만들기** — 화면의 유일한 primary 버튼
3. 실행 목록 — 상태별로 묶는다: **진행중 → 완료 → 중단**
4. 비어 있으면 빈 상태 + 만들기 유도 (§8 `empty-states`)

목록 한 줄에 담을 것 (그 이상은 넣지 않는다):
- 실행 이름 · 상태 뱃지(**정상 완료에는 뱃지를 달지 않는다**, §7b)
- 기간 (일 수), 대상자 수
- 적용 정책 이름 (없으면 "무정책")
- 마지막 갱신 시각

진행중인 실행은 진행률을 함께 보인다. 분모를 모르면 막대를 그리지 않는다.

**중단된 실행을 숨기지 않는다.** 왜 중단됐는지, 어디까지 있는지 적는다.
`rescue` 처럼 하루치만 있는 실행도 목록에 남고, 열면 "있는 것만" 보여준다.

## 4. run 셸 (작업공간)

사이드바 구성이 바뀐다.

```
┌──────────────────┐
│ ← 모든 시뮬레이션 │  ← 목록으로 돌아가기. 항상 맨 위
├──────────────────┤
│ BASE            ▾│  ← 현재 실행 + 전환 드롭다운
│ 완료 · 7일 · 200명│     (목록까지 가지 않고 바꿀 수 있다)
├──────────────────┤
│ ▣ 개요           │
│ ∿ 실행 모니터     │
│ ▥ 결과           │
│ ▢ 시각화         │
│ ▤ 정책           │
└──────────────────┘
```

- **run 식별자를 사이드바 상단에 고정 표시한다.** 어느 화면에 있든 "무엇을 보는 중인지" 한눈에 보인다
- 기존 접힘/펼침 동작(56px 레일 ↔ 240px)은 그대로. 접힘 상태에서는 run 이름 첫 글자만
- run 전환 드롭다운은 §9 `state-preservation` — 전환해도 **보던 기능 화면을 유지**한다.
  결과를 보다가 다른 run 으로 바꾸면 그 run 의 결과로 간다
- 실행별로 없는 기능은 **숨기지 않고 비활성 + 이유를 표시** (§9 `empty-nav-state`).
  예: 시각화 데이터가 없는 run 은 "시각화" 항목이 회색 + "지도 데이터 없음"

## 5. 각 화면에서 걷어낼 것

run 을 셸이 소유하므로 **화면 안의 run 선택기는 전부 제거한다.** 중복이다.

| 화면 | 제거 | 남김 |
|---|---|---|
| 결과 | 상단 "실행 선택" 칩 그룹 | 지표·차트·표 |
| 모니터 | run 선택기 | 진행·병목·실패 |
| 시각화 | 상단바의 run 라벨 중복 | "결과로" 복귀 |
| 정책 | 정책 목록에서 **고르는** 기능 | 이 실행에 적용된 정책 **표시** |

정책 화면의 성격이 바뀐다. 기존에는 "정책을 골라 검증"하는 편집 화면이었는데,
**실행에 적용된 정책을 확인하는 읽기 화면**이 된다. 정책을 고르고 검증하는 일은
`/new`(새 시뮬레이션 만들기)로 옮긴다 — 그게 정책이 실제로 쓰이는 시점이다.

## 6. 새 시뮬레이션 만들기 `/new`

단계는 셋. 한 화면에 다 펼치지 않고 순차 노출한다 (§8 `progressive-disclosure`, `multi-step-progress`).

1. **정책 고르기** — 기존 정책 목록 + "무정책(대조군)" 선택지
2. **설정 확인** — 기간·대상자 수·분위별 지급액. 검증 실행
3. **실행** — 검증 통과 시에만 활성

각 단계에 뒤로 가기가 있어야 한다. 마지막 단계 전까지는 아무것도 일어나지 않는다.

> **실행 트리거의 안전장치는 그대로다.** `DESIGN_SPEC` B8 — 이미 도는 run 이 있으면
> 서버 측 lock 으로 막고, 누가 언제 잡았는지 화면에 표시한다. UI 비활성화만으로는 미달이다.
> 지금은 API 가 없으므로 **버튼을 두되 눌리면 "아직 연결되지 않았습니다"** 로 명시한다.
> 되는 척하지 않는다.

## 7. 통과 조건

- `/` 에서 run 을 고르면 그 run 의 화면들로만 이동한다. 화면 안에 run 선택기가 없다
- 사이드바 어디서나 현재 run 이 보인다. 접힘 상태에서도
- run 을 바꿔도 보던 기능이 유지된다
- 구 경로(`/results?run=X` 등)가 새 경로로 넘어간다
- 데이터 없는 기능은 비활성 + 이유 표시. 빈 화면을 그리지 않는다
- `DESIGN_SPEC` §9 기계 검증 전부 유지: gradient·backdrop-filter·overflow-x 0건, 375/768/1024/1440 가로 스크롤 0, 본문 AAA 7:1
