# 실행 사건 기반 판단: 무결성·복구 보강 보고서

기준: `fe039529d05543f0c4ce7d5514f488fa7571a6bc`, 작업 브랜치 `codex/fe039529-execution-audit`.
앞선 소비 정산·경험 연결 수정 위에 적용한 v2 보강이다. 기관 납품 인증이나 인간 반응 예측 성능을 보증하는 보고서는 아니다.

## 구현한 계약

1. **행동과 사실 분리**: 선택 당시 요청과 환경 정산 영수증을 별도 보존한다. 잘못된 LLM 결제 요청은 진단이며, 시민이 실제로 거절당한 사건으로 바꾸지 않는다.
2. **기억 경계**: 에이전트·실행 ID, 날짜, 스키마, 해시, 금액 정합성을 검사한다. 손상된 JSON을 빈 기억으로 대체하지 않는다. 다음 Dawn에는 과거 관측만 최대 8건·관측 부분 5,000문자로 제한한다.
3. **근거 대조**: 입장에는 사건 ID·실제 페르소나 필드 외에 1~3개 구조화된 사실 주장이 필요하다. 금액, 본인 부담액, 구매 상태, 정책 결제액, 모델상 사용 가능 여부를 원본과 타입까지 대조한다. 실패한 입장은 기각하며 정상 계획을 다시 생성하지 않는다.
4. **추적성**: 입장별 당시 근거 사본을 보존한다. 기억 창에서 오래된 사건이 빠져도 기존 입장의 근거를 감사할 수 있다. 짧은 자연어 이유는 `subjective_unverified`이며 의미 전체의 사실성이나 인과성이 인증된 것은 아니다.
5. **원자적 저장**: runner의 계획·방문 기억·State·완료 결과를 하나의 Neo4j 트랜잭션으로 저장한다. 에이전트 잠금 후 완료 여부를 다시 확인한다. 장소 누락 등에 따른 활동 저장 건수 불일치는 예외로 처리한다. 기존 독립 호출자까지 자동으로 원자성이 생기는 것은 아니다.
6. **복구**: State에 완료 결과를 함께 보존하는 outbox를 둔다. DB 커밋 후 로컬 metrics 저장이 실패해도 재실행은 완료 결과를 읽어 LLM 재호출을 피한다. 다른 실행 또는 구형 State가 같은 에이전트·날짜를 차지하면 덮어쓰기를 거부한다.
7. **출력 검증**: 실행별 예정 에이전트 명부와 결과를 대조한다. 누락, 손상, 상충 중복, 혼합 실행·소스, 근거 오류가 있으면 정상 보고서 출력을 차단한다. 완전히 같은 중복 행만 제거한다. 미측정을 중립으로 채우지 않고 이전 입장의 측정일을 유지한다.

추가 LLM 단계는 없다. 기존 Stage1 응답의 선택적 메타데이터를 검증하며 입력·출력 토큰과 저장량은 증가할 수 있다. 검증 가능한 사실 필드를 추가했다고 주관적 이유가 사실로 승격되지는 않는다.

## 출처와 무결성 범위

- 사건·관측·입장·완료 결과·최종 보고서에 정규 JSON SHA-256을 기록한다.
- 시뮬레이터 하위 Python 소스, 선택한 환경변수, Stage1 시스템/사용자 프롬프트 해시, 응답 모델 ID를 기록한다.
- 소스 해시는 프로세스별로 캐시한다. 실행 중 코드를 수정하지 말고 프로세스를 재시작해야 한다.
- 해시는 전자서명이 아니다. 데이터와 해시를 함께 바꿀 수 있는 운영자의 위조를 막지 않는다.
- 입력 그래프 전체, 데이터셋 버전, 모델 가중치·서빙 옵션 전체는 아직 지문에 포함되지 않는다. 완전한 재현성에는 별도 고정 데이터/모델 manifest가 필요하다.
- 작은 집단은 기본 5명 미만일 때 집단명·입장 분포를 억제한다. 차분 공격까지 막는 익명성 보장은 아니다.

## 실행 및 마이그레이션

기존 DB의 같은 날짜를 자동 업그레이드하지 않는다. 별도 DB에서 새 `SIM_RUN_ID`와 `SIM_OUTPUT_DIR`로 실행한다. 구형 증거를 새 해시로 감싸 검증 자료로 취급하지 않는다.

runner는 출력 디렉터리에 `cohort_YYYY-MM-DD.json`을 생성한다. 재개할 때 명부나 실행 지문이 다르면 중단한다. 정식 집계 예:

```powershell
python scripts/sim/report_experience.py --run-dir <실행디렉터리> --day 2026-09-15 --cohort <실행디렉터리>/cohort_2026-09-15.json --group-by income --out <보고서.json>
```

`--allow-degraded`는 결측·기각이 있는 진단 보고서를 `release_status=blocked`로 저장할 때만 사용한다. 혼합 실행이나 상충 중복은 이 옵션으로도 허용하지 않는다. `validated_simulation_export`는 이 데이터 계약을 통과했다는 뜻이며 실제 여론 예측 검증과 다르다. 과거 `report_experience.build_report` 함수는 탐색용 호환 API다. 정식 결과는 위 CLI 또는 `experience_export.build_report`를 사용한다.

## 검증과 남은 범위

단위 테스트는 금액/타입 오류, 손상·외부 근거, 거짓 사실 주장, 중첩 자료 변경, 중복/명부 누락, 원자 파일 저장 실패, 트랜잭션 실패와 완료 결과 복구를 포함한다. 두 날짜 runner 테스트는 실제 소비·판단 연결을 실행하되 DB/LLM 경계는 대체한다.

```powershell
python -m pytest tests/unit tests/integration -q --disable-warnings --tb=short
```

실제 DB 테스트는 `tests/integration/test_experience_neo4j.py`에 있다. 별도 폐기 가능한 DB의 `NEO4J_TEST_URI`를 명시해야 실행하며, 필요하면 `NEO4J_TEST_USER`, `NEO4J_TEST_PASSWORD`, `NEO4J_TEST_DATABASE`를 설정한다. 운영용 NEO4J 설정으로 자동 접속하지 않는다. 테스트가 만든 UUID 식별자에 한해서 정리한다. 계획/State/outbox 동시 롤백, 완료 결과 재사용, 다른 실행 거부, 존재하지 않는 POI의 저장 실패를 실제 DB에서 확인하는 경로다.

이번 로컬 검증 결과는 **211 passed, 3 skipped**다. 실제 Neo4j 연결이 없어 통합 테스트 3개는 skip되었다. GPU 모델 실행, 운영 모델의 메타데이터 출력률, 실제 DB 부하·경합·장애 복구 성능은 아직 측정하지 않았다.

현재 환경 계약은 구매와 grant 정책지갑이다. 이동 시간·대기·재고·접수 거절·대화 전달을 실제 사건으로 만들 수 있는 환경 실행기는 추가 구현이 필요하다. Night2 사회적 상호작용 전체의 원자적 재개는 이번 트랜잭션 범위 밖이다. 이 항목들이 없는 상황에서 퇴근 경로 불편이나 대기 경험을 사실로 제시해서는 안 된다.

기관 배포 판단에는 위 통합 실행 외에도 배포 대상의 접근 권한, 변경 불가능한 감사 기록/서명, 복구 요구, 데이터 반출 기준을 정하고 검증해야 한다. 인간 반응 타당성은 별도로 고정 홀드아웃 정책·집단별 설문과 복수 시드 실험으로 평가해야 한다. 이 수정은 그 평가에 투입할 자료의 추적성과 실패 검출을 강화한다.
