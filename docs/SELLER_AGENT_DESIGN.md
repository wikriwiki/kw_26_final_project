## ⚠️ 구현 에이전트 필수 준수사항 (하드 제약)

1. **소비자 경로에 LLM 호출 추가 금지.** 판매자 효과는 소비자 프롬프트의 O(1) 딕셔너리 룩업(태그 문자열)과 결정론적 배율 곱으로만 전달한다.
2. **시간복잡도 불변.** 판매자 관측 집계는 하루 이벤트 1-pass 누적(dict add)만 사용. 소비자 hot path에 신규 Neo4j/SQLite 쿼리 금지.
3. **모든 판매자 행동은 클램프.** LLM 출력은 반드시 검증·절단(§4.4). 클램프 실패 시 no-op.
4. **feature flag `SELLER_ENABLED`(기본 off).** off일 때 기존 코드 경로와 바이트 단위로 동일 동작이어야 함 (V0 회귀의 전제).
5. 기존 함수 시그니처 변경은 **키워드 인자 추가(기본값 None)** 방식만 허용.

## 1. (Q1) 왜 판매자 에이전트인가 — 목표와 프로젝트 이점

### 1.1 현행 구조의 한계
현재 공급측(POI 540,388개)은 **완전히 정적**이다: 위치·업종·카카오 별점이 고정 속성이고, 수요가 아무리 변해도 가격·프로모션·영업행태가 반응하지 않는다. 그 결과:

- **정책 효과가 open-loop로 절단됨.** P009(지원금) 같은 소비자 정책은 "소비자 지출 증가"까지만 시뮬되고, 그 지출을 받은 상인의 반응(가격 인상 = 정책 효과 잠식, 프로모션 = 증폭)이 없다. 실증 연구(KDI 2020)는 재난지원금의 매출 전이가 업종별로 크게 다르고(대면서비스 미미) 공급측 행태에 좌우됨을 보였다 — 현행 시뮬은 이 이질성을 구조적으로 만들 수 없다.
- **소상공인 대상 정책을 실험할 수 없음.** 임대료 지원·온누리상품권·배달비 지원 등 "상인에게 주는" 정책은 받을 주체가 없다.
- **검증 반쪽.** 지금 검증은 전부 수요측(소비 시공간 분포). 공급측 실측(개·폐업률, 업종 매출 성장)은 재현 대상조차 아니다.
- **경쟁·진입 메커니즘 부재.** 3일 덤프 실측: 소비자 선택 동인은 습관 47.1% + 근접성 36.9%로 고착 — 신규·도전자 점포가 고객을 획득할 채널(광고·품질 개선)이 시뮬에 존재하지 않아 시장이 "동결"돼 있다.

### 1.2 도입 목표 (우선순위순)
1. **폐루프 시장 동학**: 수요 변화 → 상인 관측 → 가격/프로모션 조정 → 수요 재반응. 정책 효과의 2차 파급(잠식/증폭)을 정량화.
2. **정책 실험 공간 2배**: 소비자 정책 + 소상공인 정책(+조합) 모두 시뮬 가능. 최종 산출물(정책 리포트)의 폭 확대.
3. **창발 관찰**: 상권 간 경쟁, 차별화, 부익부(Matthew effect) — CompeteAI(ICML'24 Oral)가 식당 2 × 고객 50 소규모에서도 시장이론과 정합하는 경쟁 창발을 확인했으므로, 우리 스케일(셀 1,800 × 소비자 15,000)에서는 공간 구조까지 얹은 창발을 기대할 수 있다.
4. (Phase 2) 개·폐업 동학 → 젠트리피케이션·상권 흥망 시나리오.

### 1.3 문헌 근거 → 설계 반영
| 논문 | 시사점 | 우리 설계 반영 |
|---|---|---|
| **CompeteAI** (Zhao et al., ICML 2024 Oral, MS) | 판매자 LLM은 가격·메뉴·광고 전략을 창발하며 고객 LLM과 폐루프 형성. 소수 판매자로도 유효 | 판매자=LLM 에이전트 채택, 행동 카테고리(가격/프로모션/광고) 준용 |
| **EconAgent** (Li et al., ACL 2024) | 가계=LLM + 기업=규칙 하이브리드로 거시 정형사실 재현 | rule-based 판매자를 **비교군(3-arm)** 으로 두어 LLM 기여분 분리 |
| **AI Economist** (Zheng et al., 2020) | 시장 참여자+정책자 이중구조 검증 프레임 | 정책(P009) 개입 하 판매자 반응 검증 설계 |
| **Vending-Bench** (Backlund & Petersson, 2025) | LLM 장기 경영은 불안정·폭주 위험 | **유한·클램프 행동공간 + 비용 원장**, 쿨다운, no-op 기본값 |
| **AgentSociety** (Piao et al., 2025) | 대규모 도시 시뮬은 대표 에이전트·배칭으로 스케일 | 동×업종 **대표(상인회) 에이전트** 채택 |

## 2. (Q2) 적정 수 — 규모·배치 설계

### 2.1 설계 원칙 3개
- **P1. 데이터 해상도 = 에이전트 해상도.** 점포 개별 매출 실측은 존재하지 않는다(카드사도 비공개). 매출·개폐업 실측의 최소 단위는 **행정동(또는 골목상권)×업종**. 그보다 잘게 만들면 페르소나가 지어낸 값(hallucination)이 되어 시뮬을 왜곡한다 — 소비자 페르소나가 BDC 실측 분포 표집인 것과 동일 원칙.
- **P2. LLM 예산.** 현행 일 호출 ≈ 15,000(7,500 에이전트×2스테이지). 판매자 추가분은 +10% 이내.
- **P3. 검증 단위 일치.** 검증 정답(개·폐업률, 업종 매출)이 존재하는 단위로 에이전트를 만들어야 검증이 성립한다.

### 2.3 채택안 상세
- 셀 = (행정동 421) × (L1 업종 9: 식사·카페·디저트·주점·편의점·마트·미용·건강·여가). 원시 3,789셀에서 **프루닝: POI ≥ 10개 && 카드소비 비중 > 0** → 예상 1,500~2,200셀.

## 4. 행동 모델 — "실제 소상공인이 하는 행동"에서 도출

### 4.1 도출 원칙
행동공간은 상상이 아니라 **실태조사·실증연구에 기록된 실제 소상공인의 대응 수단**에서 고른다. 채택 기준 3개를 모두 통과해야 한다:
1. **현실성** — 실태조사·실증연구에 해당 행동의 실행 비율/빈도가 기록돼 있을 것 (검증 가능)
2. **전달 가능성** — 기존 소비자 파이프라인에 O(1)·무LLM 결합 채널이 존재할 것 (하드 제약 1·2)
3. **목적 기여** — D1의 세 목표(정책 파급·정책 실험·검증) 중 하나 이상에 직접 기여할 것

> ✅ **전제 구현 완료 (2026-07-03, `scripts/sim/poi_price.py`)** — 판매자 가격 채널의 전제인
> "POI별 가격대"가 소비자 파이프라인에 구현됨: ① 모든 commerce POI에 결정론적 가격대
> (₩/₩₩/₩₩₩ × 동 prior [0.88,1.12]) ② Stage2 후보에 가격 표시 + 잔액 헤더 + 예산-가격 선택 규칙
> ③ 하루 총지출이 장바구니 가격지수에 반응(클램프 [0.8,1.25]) ④ INCLUDES에 price_band/factor 영속화.
> **판매자 A1(가격 조정)은 이 위에 곱으로 합성**: 유효 배율 = poi_price_factor × seller_price_level.
> A1의 "(가격↑↓) 아이콘"은 seller_price_level 편차분만 표시하면 된다.

### 4.2 채택 행동 5종 — 정의 · 현실 근거 · 필수성 · 채널

#### A1. 가격 조정 `price_move ∈ {-1, 0, +1}`
- **정의**: `price_level += 0.05×move`, 클램프 [0.85, 1.15]. 동일 방향 2 tick 연속 후 1 tick 쿨다운.
- **현실 근거**: 원가·수요 변동의 최종 전가 수단. 단, 실제 가격은 **경직적** — 한국은행 가격경직성 분석에서 서비스 부문은 전 부문 중 가격조정빈도가 가장 낮다(메뉴판 비용). 외식업 가격 개정은 연 1~2회 수준.
- **왜 필수인가**: 소비자 지원 정책의 최대 실증 쟁점이 **"지원금이 가격 인상으로 잠식되는가"**(지역화폐·재난지원금 인플레 논쟁)다. 가격 채널이 없으면 이 질문을 시뮬로 던질 수 없고, 정책 효과는 항상 100% 소비자 후생으로 계상되는 낙관 편향이 생긴다. 수요-공급 균형의 최소 요건.
- **소비자 채널**: ⓐ `actual_spent × price_level` (지출 배율) ⓑ Huff `A_j` 페널티 (원거리 수요 회피) ⓒ Stage2 후보 라인에 **가격 아이콘** — `|Δ|≥0.10`일 때만 `(가격↑)`/`(가격↓)` 표기 (+2토큰). ⓒ가 없으면 소비자가 인상을 인지·회피할 수 없어 "인상=공짜 이득" 폭주가 생기므로 반드시 함께 구현.
- **검증 연결**: V1 가격변경빈도가 실측 경직성 대역인지, V3 정책 잠식률.

#### A2. 판촉·할인 `promo ∈ {none, discount, event}`
- **정의**: `discount` = 참여 점포 지출 ×0.9, 지속 1 tick, **쿨다운 2 tick**, 비용 = 셀 매출의 α(기본 3%). `event` = 사은행사(지출 불변, 방문 유인만), 비용 α/2.
- **현실 근거**: 소상공인의 가장 보편적 단기 대응(1+1, 첫손님 쿠폰, 카드사 제휴 할인). 마케팅 문헌의 정설: **가격이 경직적일 때 판촉이 실질가격의 단기 조정 수단**으로 기능한다 — A1의 낮은 빈도와 A2의 높은 빈도가 세트로 현실을 재현.
- **왜 필수인가**: ① 수요 충격에 대한 현실적 1차 대응이 이것이다(가격 개정이 아니라). ② 정책과의 **상호작용 측정**: 지원금 지급 시기에 상인이 할인을 맞추면 정책 효과가 증폭되는지 — 공급 반응이 정책 승수를 바꾸는 대표 사례.
- **소비자 채널**: Stage2 후보 라인 `[세일중]`/`[이벤트]` 태그(참여 점포만, §4.6) + Huff `A_j×(1+EPS_PROMO)` + 지출 ×0.9.
- **검증 연결**: 태그 노출→선택 전환율 (리뷰 계측과 동일 패턴으로 `promo_seen` 이벤트 필드 로깅).

#### A3. 영업시간 조정 `open_delta ∈ {-1, 0, +1}` (시간 단위, 누적 [−2, +2])
- **정의**: 셀의 영업 시간창을 ±h 확장/축소. 연장 시 운영비 증가(시간당 δ, 원장 반영).
- **현실 근거**: 자영업의 대표적 실질 결정 — 코로나기 영업시간 단축, 최근 심야 연장 경쟁, 인건비 부담에 따른 브레이크타임 도입 등.
- **왜 필수인가**: ① **시간대 활동분포는 우리 1번 검증 지표**(cosine 0.857)인데, 실제 시간대 소비는 공급측 영업시간의 물리적 제약을 받는다(심야 소비는 심야 영업 없이는 불가). 현재는 이 제약이 카테고리 고정 시간창뿐이라 공급이 시간 구조를 바꿀 수 없다. ② 심야상권 활성화/규제 같은 **시간대 타깃 정책** 실험이 가능해진다.
- **소비자 채널**: `visit_window`(카테고리 시간창) 산출 지점에 dong×L1 오버레이 dict 훅 — 야간 시간대 후보 노출/제외. O(1).
- **검증 연결**: V2 **시간대별 매출 비중** vs 상권분석서비스 추정매출의 시간대별 매출 실측(OA-15572) — 새 정답 데이터.

#### A4. 품질·서비스 투자 `quality_invest ∈ {0, 1}`
- **정의**: 투자 시 비용 = 셀 매출의 β(기본 5%)/tick, 효과 `quality_delta += 0.03` (cap +0.30). 미투자 시 자연 감가 −0.01/tick (floor −0.20) — 품질 유지에도 돈이 드는 현실 반영.
- **현실 근거**: 재료 개선·리모델링·서비스 교육. 특히 한국 소상공인에게 **별점 관리는 생존 문제** — 배달앱·카카오·네이버 별점이 노출과 선택을 좌우하는 "별점 경제".
- **왜 필수인가**: ① 우리 시장은 습관(만족 기억) 47%가 지배 — 그 만족의 근원인 **품질이 정적이면 경쟁은 가격 출혈 일변도**로 왜곡된다(CompeteAI가 관찰한 차별화 전략 창발이 원천 봉쇄됨). ② 직전 커밋으로 구축한 **리뷰 계측 인프라와 직결**: `quality_delta`가 별점 표시에 그대로 얹혀 추가 개발이 거의 없다.
- **소비자 채널**: 리뷰 조회(`poi_review_lookup` 포맷 지점)와 후보 라인 별점 표기에 `rating + quality_delta` (클램프 ≤5.0) 오버레이. 기존 리뷰 2-pass 메커니즘이 그대로 전달 채널이 된다. 추가 호출 0.
- **검증 연결**: 별점→매출 탄력성 부호(+), 투자 셀 vs 비투자 셀 재방문율 차이.

#### A5. 지역 마케팅 (광고 슬롯) `marketing ∈ {0, 1}`
- **정의**: 켜면 지속 1 tick, 비용 = 셀 매출의 γ(기본 4%). 효과: 셀 내 최고 별점 POI 1개가 해당 동 주민의 Stage2 후보 목록 마지막 슬롯에 **보장 노출** + `[광고]` 태그.
- **현실 근거**: 이것은 관념이 아니라 **한국 소상공인의 실측 1순위 지출**이다 — 음식점의 97.1%가 배달의민족을 이용하고 매출의 60.5%가 배달플랫폼을 경유하며, 점주 불만 1위가 광고비 부담(오픈리스트/울트라콜 = 문자 그대로 '후보 목록 광고 슬롯' 구조). 오프라인로는 전단지·현수막·지역 SNS.
- **왜 필수인가**: 실측에서 소비자 선택은 습관 47% + 근접 37%로 **한번 형성된 단골 구조가 고착**된다. 현실 시장에서 신규·도전자 점포가 이 고착을 뚫는 유료 인지 채널(광고)이 시뮬에 전무 — 이 채널 없이는 경쟁·진입 동학 자체가 성립하지 않는다. rumor(2.9%)·리뷰(0.2%)와 상보적.
- **소비자 채널**: `build_stage2_candidates_l1_dong` 결과 목록에 광고 POI 1개 삽입(마지막 슬롯 교체, O(1)) + 태그. 선택은 여전히 소비자 LLM의 몫 — 광고는 노출만 산다(현실과 동일).
- **검증 연결**: 광고 노출→선택 전환율이 상식적 대역(수 %)인지 + `ad_seen` 필드 로깅.

### 4.3 공통 제약: 간이 손익 원장 (필수 구성요소)
**비용 없는 행동은 반드시 남발된다**(무료 광고 = 상시 광고). 현실 모방의 최소 장치로 셀별 원장을 둔다:

```
tick 마진 = 시뮬 매출 × (1 − cost_ratio)            # 원가율: 실태조사 업종별
          − 매출 × rent_burden                       # 임대 프록시: 실태조사·발달지수
          − promo비용(α) − quality비용(β) − marketing비용(γ) − 연장운영비(δ×h)
ledger_margin += tick 마진
```
- 관측 프롬프트에 마진을 포함 → LLM이 "출혈 여부"를 스스로 판단(비용 고지가 곧 자기조절 장치).
- `ledger_margin`이 연속 k tick 적자 → (P2) 폐업 트리거의 근거로 사용.
- α, β, γ, δ는 env 파라미터(`SELLER_COST_*`), 초기값은 실태조사 영업이익률과 정합하도록 T1에서 캘리브레이션.

### 4.4 LLM 입출력 스키마 + 클램프
**관측(입력, ~700토큰)**: 페르소나 요약 4줄 + `이번 tick 매출/방문 (직전 대비 Δ%)` + `누적 마진` + `현재 별점(quality_delta 반영)` + `같은 동 타업종 Δ 1줄` + `인접 동 동일업종 Δ 1줄` + `활성 정책 1줄` + 현재 상태(가격/프로모션/영업시간) + **각 행동의 비용 명시**.

**행동(출력) — 이 JSON만 허용, 아니면 no-op**:
```json
{"price_move": -1|0|1, "promo": "none"|"discount"|"event", "quality_invest": 0|1,
 "marketing": 0|1, "open_delta": -1|0|1, "reason": "한 줄"}
```

**SELLER_SYSTEM 프롬프트 (전문)**:
```
당신은 서울 {gu} {dong}의 {category_l1} 업종 상인회 대표다. 관할 점포 {n_poi}곳(프랜차이즈 {franchise_pct}%),
주 고객층 {top_mix}, 상권등급 {hub_class}, 현재 평균 별점 {rating_eff}.
최근 {tick}일 실적: 매출 {sales}원({d_sales:+.0f}%), 방문 {visits}회({d_visits:+.0f}%), 누적 마진 {margin}원.
주변 동향: {competitor_line} {policy_line}
현재 상태: 가격수준 {price_level}, 프로모션 {promo}, 영업시간 {open_delta:+d}h.
선택 가능한 행동과 비용: 가격 ±5%(무료·단 손님 반응 있음) / 할인행사(매출의 3%) / 사은이벤트(1.5%) /
품질투자(5%, 별점 서서히 상승) / 동네 광고(4%, 후보 노출 확보) / 영업시간 ±1h(연장 시 운영비 증가).
당신의 목표는 무리한 출혈 없이 매출과 마진을 유지·개선하는 것이다. 다음 JSON만 출력하라:
{"price_move": -1|0|1, "promo": "none"|"discount"|"event", "quality_invest": 0|1, "marketing": 0|1, "open_delta": -1|0|1, "reason": "한 줄"}
```

**클램프**: 범위 밖·파싱 실패 → no-op + `seller_parse_fail` 카운터. 쿨다운 위반 행동은 해당 필드만 무시.

### 4.5 소비자측 결합 — 4채널 요약 (추가 LLM 0, 전부 O(1))
| 채널 | 코드 위치 | 반영 행동 |
|---|---|---|
| ① 후보 태그·아이콘 | `stage2_poi.py` 후보 라인 렌더 | `[세일중]`/`[이벤트]`/`[광고]` + `(가격↑↓)` + 별점 오버레이 |
| ② 광고 슬롯 | `build_stage2_candidates_*` 결과 후처리 | A5 보장 노출 (마지막 슬롯 교체) |
| ③ Huff 매력도 | `mobility.py` `suggest_hubs()` | `A_j' = A_j × (1 + EPS_PROMO×promo_share − EPS_PRICE×(price−1))`, dong 가중평균, EPS_PROMO=0.10, EPS_PRICE=0.15 |
| ④ 지출·시간창 | `merge_to_final_events()` / `visit_window` | `actual_spent × price_level` (할인 참여점포 ×0.9), `spent_base` 병기 / 영업시간 오버레이 |

### 4.6 셀 내 이질성 — 결정론적 분배
promo/광고 참여 점포 = 셀 내 POI 중 `sha1(poi_id+day)%100 < 참여율π`. π = 40 + 20×(별점 p75 초과) − 20×프랜차이즈(본사 정책) [%]. 광고 슬롯 POI = 셀 내 별점 최상위(동률 시 리뷰수). seed 고정 → 재현성.

### 4.7 제외한 행동과 이유 (정직한 스코프)
| 행동 | 실제로 존재하나 제외한 이유 |
|---|---|
| 고용 조정 | 시뮬에 노동시장 없음(에이전트 직장 고정) — 효과 전달 채널 부재 |
| 메뉴·상품 개편 | POI의 L1/L2 카테고리가 정적 — P2에서 sub_category 전환으로 확장 가능 |
| 배달 도입 | 소비가 "방문" 기반 구조 — 배달은 이동 없는 소비라 별도 채널 설계 필요(P2) |
| 입지 이전 | 개·폐업(P2)으로 근사 |
| 리뷰 답글 | 별점 자체가 안 변해 효과 채널 모호 — A4(품질→별점)에 흡수 |

### 4.8 하루 루프 통합 지점 (run_simulation.py)
```
[기존] 에이전트별: Stage1 → Stage2 → merge_to_final_events → write_plan
   └─ (신규 a) merge 직후: cell_acc[(dong,L1)] += {sales, visits}   ← in-memory 1-pass
[기존] 하루 종료
   └─ (신규 b) seller_pool.end_of_day(day, cell_acc):
        원장 갱신(전 셀) → due 셀만(스태거) obs 생성 → LLM 배치 호출(~600)
        → 파싱·클램프 → 상태 갱신 → effects 맵 4종 재계산(dict)
        → Neo4j 배치 기록(UNWIND 1회)
```

### 4.9 성능 예산 (검산)
| 항목 | 증가분 |
|---|---|
| LLM 호출 | +600/일 (+4%) · 입력 ~700tok → 일 +0.42M tok (로컬 GPU 여유) |
| 소비자 경로 | 태그/아이콘/슬롯 dict 룩업 O(1)·지출 곱 1회 — 측정 불가 수준 |
| 메모리 | cell_acc ~2천 키 dict, effects 맵 4종 — 수 MB |
| Neo4j | 일 1회 UNWIND ~600행 — 무시 가능 |

### 4.10 Neo4j 스키마
```cypher

// tick마다 UNWIND 1회:
MERGE (s:Seller {sid: row.sid}) SET s += row.state   // §3.3 필드
CREATE (d:SellerDecision {sid: row.sid, day: row.day,
        obs_sales: .., obs_visits: .., d_sales_pct: .., margin: ..,

        reason: .., price_level_after: .., quality_delta_after: ..})
CREATE (s)-[:DECIDED]->(d);
// 소비자 이벤트(INCLUDES)에 노출 계측 병기: promo_seen, ad_seen, price_icon_seen  ← 리뷰 계측(review_seen)과 동일 패턴
```

| 레벨 | 질문 | 방법·정답 데이터 | 합격 기준 |
|---|---|---|---|
| **V0 회귀** | 기존 검증이 깨지지 않는가 | 정책 무개입 14일 런 ON vs OFF, `validate_backup_new.py` 6지표 | Δ시간대 cosine ≤0.01 · Δ공간 cosine ≤0.02 · Δ소비 Gini ≤0.02 |
| **V1 미시 정합** | 반응 방향·빈도가 실제와 맞는가 | 셀별 (매출Δ, 행동) 로그 부호 검정 + 행동 빈도 | 수요↑ 셀의 가격↑∨프로모션↓ 정합률 ≥70% · 가격변경은 드물고(서비스 가격경직성 정합, tick당 5~30% 대역) 판촉은 빈번 · promo 비중 시계열 안정(원장 자기조절 확인) |
| **V2 분포 재현** | 공급측 실측 분포를 재현하는가 | ⓐ 셀 매출 성장 분포 vs 상권분석서비스 분기 성장(OA-22172) ⓑ **시간대별 매출 비중 vs 추정매출 시간대 실측(OA-15572)** ⓒ 별점→매출 탄력성 부호 ⓓ (P2) 개·폐업률 | cosine ≥0.8 · JSD ≤0.1 (기존 지표 함수 재사용) |
| **V3 자연실험 앵커** | 정책 충격 반응 크기가 실측과 맞는가 | **KDI(2020) 재난지원금: 카드매출 증가 = 투입의 26.2~36.1%, 대면서비스 효과 미미** vs 시뮬 P009 매출 lift + 가격 잠식률 | lift/투입 ∈ [15%, 50%] 완충대역 + 업종 이질성 방향 재현 |
| **Ablation 3-arm** | LLM 판매자의 기여분은 | 동일 시드: ① seller-OFF ② rule-seller(매출Δ 부호 따라 기계적 조정) ③ LLM-seller | ③이 ② 대비 V2·V3 동등 이상 + 전략 다양성(reason 텍스트 클러스터 수) |

- **행동별 검증 짝**: A1↔가격빈도·잠식률 / A2↔`promo_seen` 전환율 / A3↔시간대 매출 비중 / A4↔별점-매출 탄력성 / A5↔`ad_seen` 전환율. 모든 행동이 자기 검증 지표를 갖는다.
- V3가 **가장 강한 주장**: "우리 시뮬의 정책→매출 전이율이 실제 재난지원금 실증 추정 범위 안" — 발표·논문 핵심 문장.
- 재사용: cosine/JSD/Gini 함수는 `validate_korea.py`의 순수함수 그대로 import. 노출 계측은 리뷰 계측(`review_seen`) 패턴 재사용.
- 신규: `scripts/sim/validate_seller.py` (T8).
