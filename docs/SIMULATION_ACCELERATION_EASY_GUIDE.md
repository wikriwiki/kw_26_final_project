# 예측의 품질을 지키면서 시뮬레이션을 빠르게 만드는 방법

## 우리가 만들려는 것

우리 프로젝트의 목적은 가상의 사람들이 실제 사람처럼 생활하도록 만들어, 정책이 소비와 방문, 감정에 어떤 영향을 주는지 예측하는 것입니다.

빠르게 실행되는 것만으로는 충분하지 않습니다. 실제와 다른 결과를 더 빨리 내놓는다면 좋은 시뮬레이션이라고 할 수 없습니다.

그래서 목표는 다음과 같습니다.

> **사람들의 행동과 감정을 예측하는 품질을 유지하면서, 계산에 걸리는 시간을 줄인다.**

이 문서는 목표 구조를 설명합니다. 현재 개발용 구현은 준비되었으며, 실제 모델의 속도와 정확도는 아직 검증하지 않았습니다.

**현재 진행 상황:** 이제 [개발용 프로그램과 실행 안내](../scripts/sim/fast_decision/README.md)가 준비되었습니다. 작은 AI의 선택지 점수 읽기, 학습 자료 수집, 학습과 비교 평가를 실행할 수 있게 만들었습니다. CPU에서 프로그램 동작을 검사했지만, 실제 EXAONE 모델의 학습과 예측력·속도 검증은 GPU 연결 후 진행해야 합니다. 검증 전에는 작은 AI의 답이 실제 시뮬레이션 결과를 바꾸지 않습니다.

## 1. 지금은 왜 시간이 오래 걸릴까요?

현재 프로그램은 사람마다 오늘 무엇을 할지, 어디를 방문할지 등을 AI에게 묻습니다. 방문 장소를 결정할 때는 소비액과 만족도 등도 함께 판단합니다.

한두 사람이라면 괜찮지만, 많은 사람의 여러 날을 반복해서 계산하면 AI를 기다리는 시간이 쌓입니다. 데이터를 읽고 저장하는 데에도 시간이 걸립니다.

먼저 어느 부분이 오래 걸리는지 측정해야 합니다. 음식점 선택을 빠르게 바꾸더라도 다른 부분에서 대부분의 시간을 쓰고 있다면 전체 실행은 크게 빨라지지 않을 수 있습니다.

## 2. 평범한 식사는 간단하게 처리해도 될까요?

항상 그렇지는 않습니다. 예를 들어 직장인 민수가 매일 같은 식당에 간다고 해 보겠습니다.

| 오늘의 상황 | 시뮬레이션이 놓치면 안 되는 점 |
|---|---|
| 별다른 변화 없이 단골 식당에 감 | 평소에도 메뉴·소비액·만족도는 달라질 수 있음 |
| 최근 세 번의 식사에 계속 실망함 | 작은 불만이 쌓여 단골을 바꾸는 계기가 될 수 있음 |
| 피곤한 날 멀리 있는 식당을 추천받음 | 새로운 곳에 대한 관심과 피로가 충돌할 수 있음 |
| 다른 동네에서 사용할 수 있는 쿠폰을 받음 | 방문 지역과 소비가 달라질 수 있지만, 반드시 바뀌는 것은 아님 |

우리 코드에서는 방문 만족도가 기억과 기분·피로에 반영되고, 이 상태가 이후 행동과 사람 사이의 상호작용에도 영향을 줍니다.

따라서 **“단골 식당이니까 대충 처리해도 된다”는 규칙은 사용하지 않습니다.**

## 3. 어떻게 빠르게 만들까요?

두 가지 방법을 순서대로 적용합니다.

### 먼저, AI의 판단은 그대로 두고 기다리는 시간을 줄입니다

반복해서 읽는 동일한 식당 정보를 재사용하고, 데이터 조회를 효율적으로 바꾸고, 서로 독립적인 AI 요청은 함께 처리합니다.

이는 같은 일을 더 효율적으로 실행하는 방법입니다. 이 단계에서도 데이터가 빠지거나 처리 순서가 달라져 결과에 영향을 주는지 확인합니다.

어제의 방문 결과를 그대로 복사하거나 오늘의 감정 변화를 생략하는 방식은 아닙니다.

### 그다음, 검증된 범위에서 작은 AI가 일부 판단을 맡습니다

큰 EXAONE에 모든 결정을 맡기는 대신, 작은 EXAONE이 잘 처리할 수 있다고 확인된 상황을 맡깁니다. 어렵거나 낯선 상황은 큰 EXAONE이 처리합니다.

```text
오늘의 상태·기억·정책·방문 후보 확인
                    ↓
       중요한 변화나 복잡한 조건이 있나요?
          ┌─────────┴─────────┐
         있음                없음
          ↓                   ↓
    큰 EXAONE이 판단     작은 EXAONE이 판단 시도
                              ↓
                    검증된 기준을 만족하나요?
                       ┌──────┴──────┐
                      예            아니오
                       ↓              ↓
                  결과 사용     큰 EXAONE이 다시 판단
                       └──────┬──────┘
                              ↓
                  동일한 검증·정산·기억·감정 갱신
```

여기서 “작은 AI”는 LG가 완제품으로 제공하는 Jev 같은 판단 모듈을 뜻하지 않습니다. 공개된 경량 EXAONE을 우리 목적에 맞게 연결하고 필요하면 추가 학습하는 개발안입니다. Jev와 같은 속도나 성능이 보장되는 것은 아닙니다.

## 4. 작은 AI에는 어디까지 맡기나요?

처음에는 **이미 만들어진 하루 계획 안에서 음식점 등 방문 장소를 고르는 부분**부터 실험합니다. 하루 계획 전체와 야간 상호작용까지 한꺼번에 바꾸지는 않습니다.

작은 AI의 결과를 쓰려면 식당 선택뿐 아니라 관련 소비액과 만족도 등도 충분히 잘 처리하는지 확인해야 합니다.

예를 들어 작은 AI가 식당은 잘 골라도 모든 식사의 만족도를 비슷하게 계산한다면 사용할 수 없습니다. 그러면 사람들의 기분이 지나치게 일정해지고, 불만 때문에 행동을 바꾸는 상황이 사라질 수 있기 때문입니다.

초기에는 아래 상황을 큰 EXAONE에 맡깁니다.

- 정책이나 지원금의 변화가 오늘 선택에 영향을 줄 수 있는 상황.
- 불만이 쌓이거나 기분·피로가 크게 변한 상황.
- 약속·추천·예산 조건이 서로 충돌하는 상황.
- 정보가 부족하거나 작은 AI가 충분히 검증되지 않은 상황.

검증을 통과한 범위가 늘어나면 작은 AI의 역할도 넓힐 수 있습니다.

## 5. 작은 AI가 잘 판단하는지는 어떻게 확인하나요?

AI가 스스로 “확신합니다”라고 말하는 것만으로 믿지는 않습니다. 별도로 남겨 둔 사례에서 실제로 얼마나 잘 처리하는지 확인합니다.

또한 **여러 식당이 비슷하게 마음에 드는 상황**과 **정보가 부족해서 고르기 어려운 상황**을 구분해야 합니다. 전자는 자연스러운 취향의 다양성입니다. 매번 한 식당만 고르게 만들면 현실과 멀어질 수 있습니다.

추가 학습이 필요하면 기존 EXAONE의 결정과 검토된 사례를 활용합니다. 다만 큰 AI도 틀릴 수 있으므로, 큰 AI의 답을 그대로 따라 하는 것만으로 현실 예측력이 좋아졌다고 판단하지 않습니다.

## 6. 무엇이 유지되어야 성공인가요?

다음 두 질문에 모두 답해야 합니다.

> 기존 시뮬레이션의 중요한 특성을 보존했나요?
>
> 실제 관측자료와 비교했을 때 예측력이 나빠지지 않았나요?

| 확인할 것 | 쉽게 말하면 |
|---|---|
| 실제 매출·방문 예측 | 실제 어느 지역에서 얼마나 소비하고 방문했는지 여전히 잘 맞추는가? |
| 행동의 다양성 | 단골 방문과 새로운 장소 탐색이 한쪽으로 쏠리지 않는가? |
| 소비의 차이 | 소득·지역·예산에 따른 차이가 유지되는가? |
| 감정의 흐름 | 실망이 쌓이고, 기분이 회복되고, 이후 선택이 바뀌는 과정이 유지되는가? |
| 정책에 대한 반응 | 정책 효과의 크기와 집단별 차이를 왜곡하지 않는가? |
| 전체 실행 시간 | 작은 AI를 추가한 비용까지 포함해 실제로 빨라졌는가? |

평균만 확인하지 않습니다. 전체 평균이 비슷해도 저소득층의 소비나 불만이 큰 사람들의 행동을 더 못 맞춘다면 문제가 있습니다.

얼마나 작은 차이까지 허용할지는 실험 전에 정합니다. 결과를 본 뒤 유리한 기준으로 바꾸지 않습니다. 지금은 허용 오차와 목표 속도를 아직 확정하지 않았습니다.

## 7. 감정 분석에서는 무엇을 조심해야 하나요?

프로그램 안의 기분·피로·만족도와, 실제 사람의 말이나 설문에서 확인한 감정은 구분해야 합니다.

프로그램 안에서 “불만족 → 기분 하락 → 다음 방문 변화”가 자연스럽게 이어지는지는 확인할 수 있습니다. 하지만 그것만으로 실제 사람의 감정을 정확히 예측한다고 말할 수는 없습니다.

실제 감정 분석 성능을 확인하려면 감정이 평가된 리뷰·설문 같은 관측자료가 필요합니다. AI가 스스로 만든 설명을 정답으로 삼아 같은 AI를 평가하지 않습니다.

이 자료가 부족하다면 **감정의 흐름이 일관적인지 확인한 결과**와 **현실의 감정을 맞춘 결과**를 나누어 보고합니다.

## 8. 어떤 순서로 개발하나요?

1. **현재 상태 측정** — 지금 얼마나 느리고, 실제 자료를 얼마나 잘 맞추는지 기준을 기록합니다.
2. **실행 방식 개선** — 모델의 역할은 유지하며 데이터 조회와 요청 처리를 빠르게 합니다.
3. **작은 AI 답안 비교** — 같은 상황을 작은 AI에도 보여 주되, 시뮬레이션에는 기존 결과만 반영합니다.
4. **별도 시뮬레이션 비교** — 동일한 초기 상태에서 작은 AI의 결정을 실제 반영한 버전도 끝까지 실행합니다.
5. **통과한 범위만 적용** — 예측·감정 품질을 유지하면서 빨라진 범위만 사용합니다.

3번만으로는 부족합니다. 오늘의 작은 차이가 며칠 뒤 기억과 감정을 크게 바꿀 수 있어서, 4번처럼 전체 기간을 비교해야 합니다. 우연에 따른 차이도 있으므로 여러 번 반복합니다.

품질이 나빠지면 해당 범위는 큰 EXAONE으로 돌립니다. 이미 잘못 달라진 기억과 감정은 모델만 바꾼다고 복구되지 않으므로, 필요하면 문제가 생기기 전 저장 상태에서 다시 실행합니다.

## 우리가 지금 결정한 것과 아직 확인할 것

**결정한 원칙:** 현실 예측력과 감정·행동 품질이 우선입니다. 실행 방식 개선부터 시작하고, 작은 AI는 검증된 범위에서만 사용합니다.

**아직 확인할 것:** 실제 평가자료의 범위, 허용 가능한 오차, 사용 가능한 GPU, 현재 병목, 실제 속도 개선 폭입니다. 경량 모델을 붙이는 것만으로 몇 배 빨라진다고 약속하지 않습니다.

상세 구현과 평가 항목은 [기술 설계도](SIMULATION_ACCELERATION_DESIGN.md)에 정리되어 있습니다.
