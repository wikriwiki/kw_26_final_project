# v53 Stage2 기술 화면 사전등록 (2026-09-26)

정책 효과를 측정하기 전에 Stage2가 실제 후보 중 장소와 결제액을 생성하는지 본다. 새 그래프 초기화나 정책 팔 실행은 하지 않는다. A100에 남아 있는 완료된 P012 그래프는 **읽기 전용으로 후보를 조회**하고, 조회 결과는 입력 파일에 동결한다. 모델은 기존 8000 포트 서버를 사용한다. 이 실험은 보관된 P012 런이나 P015를 재실행하지 않는다.

입력은 완료된 v53 출력 방식 화면의 **무정책** 48개 문맥이다. 네 배경(`cashback`, `grant`, `local_voucher`, `distancing`)마다, 일반 출력·온도 0과 JSON Schema·온도 0의 Stage1 원시응답이 둘 다 유효하고 각 일정에 외부 이벤트가 하나 이상 있는 문맥을 찾는다. `selection_seed`와 `case:aid`의 SHA256 순서대로 살펴보고 각 배경에서 후보 풀이 두 일정 모두 하나 이상 채워진 첫 3개를 채택한다. 같은 문맥에서 두 Stage1 출력을 짝지으므로 총 12문맥, 24개 Stage2 시도가 목표다. POI 후보, 페르소나, 일정, 상태, 시스템 프롬프트와 코드 지문을 모델 호출 전에 동결한다. 그래프의 이후 상태는 호출에 반영하지 않는다.

Stage2는 생산 v53 중립 시스템 문구, 일반 생산 JSON Schema, 첫 시도 온도 0.7·상한 2,200토큰, 최대 2회 재시도, 출력 한도 도달 후 3,200토큰 상한을 그대로 사용한다. 최근 방문 기억과 선택적 리뷰는 이 동결 화면에서 빈 값으로 둔다. 각 모델 원시응답과 오류를 즉시 JSONL에 보존한다. 성공 여부와 함께 후보 밖 장소 보정, 다른 이벤트 후보 선택, 누락 선택 채움, 금액 자동 대체를 **각각** 기록한다. 완전 실패가 0/24가 아니면 더 큰 기술 검증으로 진행하지 않는다. 0/24여도 작은 화면이므로 95% 신뢰도나 정책효과 정확도를 주장하지 않는다. 일정 길이는 두 출력 프로토콜과 함께 달라져 길이의 인과 효과를 식별하지 못한다.

원본 Stage1·그래프 상태·코드의 출처 차이를 명시한다. 2021/2020년 배경에 현재 완료된 P012 그래프의 정적 POI와 관측 후 인지도·만족도가 섞여 있으므로 이 시험은 정책 행동 검증이나 역사적 재현이 아니다. 고정된 후보와 출력 길이에서 Stage2 기술 실패를 찾는 용도로만 사용한다. 출력 파일은 G:와 C: 별도 보관소에 SHA256으로 보존한다.
