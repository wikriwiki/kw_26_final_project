# 계획은 집에서 되는 변형만 고른다 — 그리고 그것이 정답지 지표를 막는다

**2026-09-21** · 근거 v18 계획 480칸 × 2후보 · 결제 334칸

---

## 한 문장

**구매 가능한 활동 17개 중 11개가 480개 계획에 단 한 번도 나오지 않는다.**
그리고 빠진 11개는 전부 **집 밖에서 해야 하는 것**이다.

## 숫자

```
v25 · 계획 480개 · 구매 활동이 계획에 들어간 횟수

  쓰인 것                         안 쓰인 것 (0회)
  home_delivery       115회        shopping          매장 쇼핑
  home_online_goods    95회        meal_takeaway     포장
  groceries            14회        cafe_dine_in      카페 매장
  meal_dine_in          ?회        cafe_takeaway     카페 포장
  office_delivery       ?회        convenience       편의점
  dessert               1회        hair              미용
                                   health_goods      건강
                                   leisure_service   여가
                                   education_service 교육
                                   other_service     기타
                                   bar               주점
```

**같은 업종 안에서도 갈린다.**

```
쇼핑    home_online_goods  95회   ·   shopping (매장)     0회
식사    home_delivery     115회   ·   meal_takeaway       0회
디저트  (없음)                    ·   cafe_dine_in        0회
```

집에서 끝나는 변형은 쓰이고, 밖으로 나가야 하는 변형은 안 쓰인다.
v34(금지어를 지운 판)도 같다 — 오히려 `dessert` 까지 0회가 된다.

## 카탈로그 탓이 아니다

```
walk · outdoor_leisure · library · meal_dine_in · cafe_dine_in · groceries ·
hair · health_goods · leisure_service · education_service · bar ...
                                      전부 60명 / 60명 의 활동 사전에 있다
```

**고를 수 있는데 안 고른다.** 구조가 막는 것이 아니라 선택이다.
그러므로 이것은 프롬프트가 닿을 수 있는 자리다.

---

## 이것이 왜 정답지 지표를 막는가

결제 후보는 **계획에 들어간 활동에서만** 만들어진다. 계획에 `hair` 가 없으면
결제 단계에 미용 후보가 없고, 미용은 영원히 0원이다.

v18 결제 334칸에서 실제로 이렇다.

```
업종      후보로 뜬 칸   후보 품목수   실제 구매
식사          117칸       140개      118건
마트           75칸        75개       68건
쇼핑           50칸        50개       29건
디저트          1칸         1개        1건
건강            0칸         0개        0건   ← 제시조차 안 됨
교육            0칸         0개        0건   ← 제시조차 안 됨
기타            0칸         0개        0건   ← 제시조차 안 됨
미용            0칸         0개        0건   ← 제시조차 안 됨
여가            0칸         0개        0건   ← 제시조차 안 됨
주점            0칸         0개        0건   ← 제시조차 안 됨
편의점           0칸         0개        0건   ← 제시조차 안 됨
```

**열한 업종 중 일곱이 제시조차 되지 않는다.** 시민 입력에 적힌 카드 실측 구성은
`마트 45%, 식사 30%, 건강 18%, 기타 7%` 인데, 건강과 기타는 살 수가 없다.

### 그래서 구성 거리에는 바닥이 있다

구성 거리는 **부여된 구성**과 **산 구성**의 총변동거리다. 살 수 없는 업종의 몫은
어떤 프롬프트로도 못 채우므로, **거리에는 프롬프트가 못 내려가는 바닥**이 있다.

v21 의 주 지표를 구성 거리로 사전등록했는데, **그 지표는 이 바닥에 눌려 있다.**
후보가 옳은 일을 해도 거리가 안 줄어들 수 있다.

### DS-1 이 도달 불가능한 이유도 같다

실측 −14.1% 는 **매장 취식 붕괴**가 배달 증가를 압도한 값이다.
`meal_dine_in` 은 480칸에서 손에 꼽고 `cafe_dine_in` 은 0회다.
**붕괴할 대상이 계획에 없다.** [BASELINE_COMPOSITION.md](BASELINE_COMPOSITION.md) 가
"무정책 팔에 줄어들 매장 취식이 없다"고 적은 것의 상류가 여기다.

## 그러므로 재야 할 것

**계획에 들어간 서로 다른 집 밖 구매 활동의 수.**

```
                     v25      v34     최대
집 밖 구매 활동 종류    2        1       11
```

이 지표는

- **프로브의 바닥에 눌리지 않는다** — 계획 단계에서 끝난다
- **순환이 아니다** — 정답지의 부호도 크기도 쓰지 않는다. 그 사람 카탈로그에
  있는 것을 쓰는지만 본다
- **정답지 지표의 상류다** — 늘어야 매장 취식·소매가 물릴 대상이 생긴다

**다만 이것을 맞히는 것이 정답을 맞히는 것은 아니다.** 상류가 열려야 하류를
잴 수 있다는 것이지, 열리면 맞는다는 뜻이 아니다.

## v21 후보가 겨눈 자리와 맞는가 — 맞는다

```
v37   9행에서 `대체·` 를 지운다
```

`대체` 는 **필요를 다른 방법으로 채워도 된다는 포괄 허가**다. 끼니를 배달로,
구매를 온라인으로 바꾸는 것이 정확히 이 허가에 기대는 행동이다.
집 변형이 집 밖 변형을 대신하는 자리를 정면으로 겨눈다.

```
v36   3행에서 `평균 지출과 과거 비중은 오늘 채울 할당량이 아니다.` 를 지운다
```

그 카드 실측 구성이 **집 밖 업종을 가리키는 유일한 입력**이다. 그것을 할인하는
문장을 지운다.

**두 후보 다 옳은 자리를 겨누고 있었다. 내가 잰 것이 틀렸다.**

## 문법 탓도 아니다 — 오히려 집 밖에 자리를 더 준다

카탈로그는 아니라고 위에서 적었다. 남은 의심은 **제약 디코딩 문법**이었다.
문법이 `hair` 를 허용하지 않으면 모델은 고르고 싶어도 못 고른다.

v18 의 문법 60개를 열어 각 활동이 몇 자리에 나오는지 셌다.

```
활동                     허용한 문법      자리 수
  ---- 집 밖 ----
meal_dine_in             60/60          2,642
meal_takeaway            60/60          2,642
cafe_dine_in             60/60          2,642
cafe_takeaway            60/60          2,642
dessert                  60/60          2,642
groceries                60/60          2,642
convenience              60/60          2,642
shopping                 60/60          2,642
hair                     60/60          2,642
health_goods             60/60          2,642
leisure_service          60/60          2,642
education_service        60/60          2,642
other_service            60/60          2,642
bar                      60/60          2,642
  ---- 집 안 ----
home_delivery            60/60          2,360
office_delivery          31/60          1,460
home_online_goods        60/60          2,360
```

**열넷 전부가 모든 문법에 있고, 자리 수는 집 안(2,360)보다 집 밖(2,642)이 더 많다.**

그러므로 배제된다.

| 설명 | 배제 근거 |
|---|---|
| 카탈로그에 없다 | 열넷 전부 60명 **모두의** 활동 사전에 있다 |
| 문법이 막는다 | 열넷 전부 60/60 문법에 있고 자리도 더 많다 |
| 자원이 모자란다 | 자원 게이트는 계획 **뒤**에 돈다. 계획 단계에서는 걸리지 않는다 |

**남는 것은 모델의 선택뿐이다.** 기회는 더 많은데 안 고른다.
그것이 프롬프트가 닿을 수 있는 자리라는 뜻이고, v36·v37·v38 이 겨누는 자리다.

> 이 확인이 없었으면 v21 이 실패했을 때 "프롬프트로는 안 된다"와
> "애초에 못 고르게 돼 있었다"를 구분할 수 없었다. 이제 구분된다.

## 그 3.3% 는 누구인가 — 이미 나가고 있던 사람이다

v36 이 기각된 뒤, 집 밖 구매가 떨어지는 칸이 v25 와 **한 칸도 겹치지 않는다**는 것을
봤다. 칸은 우연이지만 **사람은 우연이 아니었다.**

재직자만 골라, 한 런 안에서 통근 시간을 견줬다.

```
v25   재직자 34명 중 나간 적 있음 11명 (32%)
      통근  56.6분 (나감) 대 30.4분 (안 나감)   차이 +26.2분   뒤섞기 p=0.0001
      비재직자 26명 중 나간 적 있음  1명 (4%)

v36   재직자 34명 중 나간 적 있음 10명 (29%)
      통근  54.7분 (나감) 대 32.3분 (안 나감)   차이 +22.4분   뒤섞기 p=0.0002
      비재직자 26명 중 나간 적 있음  0명 (0%)
```

**서로 다른 프롬프트로 돌린 두 런에서 독립적으로 같은 결과가 나온다.**

다른 특징은 갈리지 않는다.

```
평일 집 체류   11.7h 대 12.3h      거의 같다
평일 소비액    124,404 대 112,606   거의 같다
이동성 분위     5.5 대 5.6          거의 같다
통근 분         52.1 대 21.4        ← 두 배 넘게 다르다
```

## 그러므로 기전은 이것이다

**모델은 구매를 위해 나가지 않는다. 이미 하고 있던 이동에 구매를 붙일 뿐이다.**

통근이 길면 하루에 이동 다리가 있고, 그 다리에 마트나 식당이 붙는다.
통근이 짧거나 직장이 없으면 붙일 다리가 없고, 필요는 배달·온라인으로 간다.

이 하나로 전부 설명된다.

- **왜 96.7% 의 계획에 집 밖 구매가 없나** — 대부분은 붙일 이동이 없다
- **왜 집 변형이 이기나** — 이동이 필요 없는 쪽이 항상 가능하다
- **왜 DS-1 이 안 움직이나** — 매장 취식은 이동을 요구하는데 그 이동이 안 생긴다
- **왜 비근무자에게 격차가 몰렸나**([HOME_HOURS_IS_NOT_DWELL.md](HOME_HOURS_IS_NOT_DWELL.md))
  — 그들에게는 통근조차 없다

## 그리고 프롬프트의 어느 줄인지도 가리킨다

```
6행  먼저 확정된 일정과 이동 시간을 배치하고, 그 전후에 필요한 일상과
     저녁 마무리를 정한다.
```

**하루는 확정된 의무를 뼈대로 세워지고, 나머지는 그 앞뒤에 끼워진다.**
이동을 요구하는 필요는 붙을 의무가 없으면 자리를 못 얻는다.

v36(3행)·v37(9행)·v38(셋)은 모두 **무엇을 고를지**를 건드린다.
6행은 **하루를 어떤 순서로 세울지**를 정한다. 아직 아무도 그 줄을 건드리지 않았다.

> v37·v38 이 기각되면 다음 후보는 6행이다. 그때는 이 문서가 근거가 된다.
> 다만 v36 에서 본 것처럼 **비율은 상수였다** — 6행을 건드려도 상수가 움직인다는
> 보장은 없고, 그것도 돌려 봐야 안다.
