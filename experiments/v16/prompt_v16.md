**날짜 2026-09-21** · **상태** 완료 — **무효. 새 기준선에서도 못 가른다**

---

## 왜 지금 다시 겨루나

**지금까지의 프롬프트 비교는 전부 퇴화된 기준선에서 했다.**

```
옛 기준선 (v3 ~ v12)
  구매 30건 / 96칸 · 그중 home_online_goods 23건 (77%)
  11개 업종 중 7개가 한 번도 안 팔림
  부여된 구성과의 거리 (사람별) 0.80
```

구매의 4분의 3이 **자원 시나리오가 강제한 세제 하나**였다.
그런 곳에서 프롬프트를 견주면 **무엇을 바꿔도 세제는 그대로**이므로 차이가 안 난다.

```
새 기준선 (끼니 필요 + 되먹임 수정)
  구매 58건 / 77칸 · groceries 26 (45%) · 세제 13 (22%)
  부여된 구성과의 거리 (사람별) 0.53
```

**행동 공간이 열렸다.** 이제 프롬프트가 움직일 여지가 있는지가 처음으로 물어진다.

## 후보 v34 — 근거가 남은 수정 둘을 합친다

```

     (v25 는 '구매·외출·반복'을 지목했다)
     → 구매 비율 +2.21 SE · 칸 채우기 없음 · 외출 폭증 없음

v33  … 자원이 있어야 하는 일은 그 자원을 확보하는 일과 함께 배치하거나
     자원이 필요 없는 다른 방법을 고르고 …
     → 게이트 기준으로는 무효였으나 해가 없었다 (44.25 대 44.8)
```

**서로 다른 문장 한 줄씩이다.** 검사가 정확히 두 줄만 다름을 강제한다
(`test_no_third_change_sneaked_in`).

정책 이름·업종·방향·수치가 하나도 없다.

### 이 라운드가 답한 것

**"기준선이 퇴화해서 못 갈랐던 것인가"** 에 대한 답은 **아니오**다.

기준선을 고쳤는데도(세제 77% → 22%, 구성 거리 0.80 → 0.48) 여전히 못 가른다.
**seed 하나에 74칸으로는 17개 지표 중 어느 것도 부호가 정해지지 않는다.**

이것은 프롬프트의 문제가 아니라 **표본의 문제**이고,
[NOISE_AND_POWER.md](../NOISE_AND_POWER.md) 가 처음부터 말하던 것이다 —
부호를 말하려면 칸이 훨씬 많아야 한다.
