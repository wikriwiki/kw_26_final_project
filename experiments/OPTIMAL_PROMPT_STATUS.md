## 한 줄

**형식 계약에서는 v45 가 최선이고 그것은 확실하다. 정답지 수렴에서는 아직
어느 프롬프트가 나은지 모르고, 오늘 그 이유가 프롬프트가 아니라 표본이라는
것이 드러났다.**

## 확실한 것 — 형식 계약

```
v5   261/384   68.0%
v45  340/384   88.6%   (세 번 측정 평균)
개선 109 · 악화 14 · 순증 +95칸 · p < 0.000001
```

+20.6%p 이고 런 자체의 이동(30칸)의 3.2배다. 그리스디(temperature 0)에서는
v45 가 **361/384 = 94.0%** 이고, 등록된 관문까지의 25칸 중 **21칸이 샘플러이고
4칸이 프롬프트**다.

## 오늘 흔들린 것 — 그 20.6%p 가 본런을 못 움직인다

v50 의 두 팔이 **같은 사흘**을 200명씩 돌았다. 팔마다 600계획이다.

```
          본런 Stage1 실패    실패율
v5              14           2.33%
v45             15           2.50%
```

**관문에서 20.6%p 였던 차이가 여기서는 0.17%p 다.** 14 대 15 는 잡음 안이라
어느 쪽이 낫다고 적지 않는다 — 적을 수 있는 것은 **20%p 짜리 차이가 여기 없다**는
것뿐이다. 관문은 첫 출력을 고치지 않고 채점하고, 본런은 재시도·복구가 흡수한다.

## 오늘 드러난 진짜 병목 — 표본

거리두기는 **프롬프트를 한 글자도 고치지 않고** n 을 200 → 500 으로 올린 것만으로
부호 적중이 1/4 → 3/4 이 됐다. 그래서 검출력을 역산했다.

```

DS-1     -14.1%        155      충분 ✔
P012-4      —          144      충분 ✔
P012-1   +20.8%        231      1.2배
EM-2     +11.1%        278      1.4배
EM-3      +7.3%        615      3.1배
DS-2      +4.2%     10,013     **20.8배**
LV-2        —       75,134    **151.8배**
P016 C1  +6.957%    14,597     **29.2배**
```

**지표 10개 중 8개가 지금 표본으로 정답지 효과를 검출하지 못한다.**
DS-2 는 효과 468원에 표준편차 16,723원 — 효과가 잡음의 2.8%다. **프롬프트는
잡음을 줄이지 않으므로 이 비율은 거의 그대로다.**

## 오늘 고친 프롬프트 입력 결함 둘

프롬프트 본문이 아니라 **모델에게 들어가는 정책 블록**에서 나왔다.

```
① 영문 기전 코드 누출    "[price_discount] 서울사랑상품권" ← P012 는 "[캐시백]" 인데
                        P014·P015·P090(위약)·P008 만 영문이었다. 하필 부호 적중이
                        가장 낮은 정책들이다

② 개인 한도 누락         sector_voucher.status() 가 업종 이름만 적고 1인 누적 한도를
                        빠뜨렸다. 농할(P016)은 1만원 한도가 핵심 제약인데 안 보였다
```

둘 다 방향 어휘를 넣지 않았고 단위 테스트가 그것을 고정한다. **효과 판정은
별도 라운드가 한다** — 결함을 없앤 것과 그것이 점수를 올리는 것은 다른 이야기다.


## 규칙 — 오늘도 지킨 것

- 사전등록을 **실행 전에** 커밋한다. v51·v52 는 v50 의 v45 팔이 채점되기 전(21:12)에 박았다
- 결과를 보고 지표나 합격선을 고치지 않는다. P016 의 채점 계획은 **결과가 하나도
  없는 상태에서** 검출력만 보고 정했다
- 정답지의 수치·방향을 프롬프트에 넣지 않는다. 단위 테스트가 막는다
- 못 잰 것은 '못 쟀다'고 적는다. 검출력 부족과 "효과가 없다"는 다른 말이다

> 이 문서가 적는 것은 여기까지다. **형식에서는 v45 가 최선이고, 정답지에서는
