# 실험 v18 — 명단을 열둘에서 예순으로

**날짜 2026-09-21 사전등록** · **상태** 실행 · **후보 v25 · v34 (새 후보 없음)**

---

## 왜 명단인가

열일곱 라운드에서 지표 하나도 정하지 못했다. v17 이 그 이유를 못 박았다.

```
v16   후보당 74칸  · 아홉 지표 전부 0을 지남
v17   후보당 283칸 · 아홉 지표 전부 0을 지남    ← 칸을 네 배로 늘렸는데도
```

**seed 를 늘리는 것은 같은 열두 명을 다시 뽑는 것**이라 사람 간 분산이 줄지 않는다.
[NOISE_AND_POWER.md](../NOISE_AND_POWER.md) 가 처음부터 계산해 둔 값이 이것이다.

```
3,000원짜리 기전 효과를 80% 검정력으로   53명
후보 둘의 차이를 보려면                  후보당 106명
```

**열둘은 어느 선에도 못 미친다. 예순은 첫 줄을 넘고 둘째 줄은 못 넘는다.**

## 명단을 어떻게 뽑았나

```
1  prepare_persona_cohort  Neo4j 의 14,560명 중 60명
                           기존 12명 제외 · 평일 소비분위로 층화
2  prepare_neutral_contexts   480칸 (60 × 4기전 × on/off)
3  prepare_typed_contexts
4  prepare_action_contexts
5  프로필                     duty 는 페르소나의 job 에서, 재고는 홀짝 0/2
                              (원래 열두 명이 쓴 규칙 그대로)
6  prepare_daily_conditions   세탁 + 끼니 필요
```

**결과를 보기 전에 뽑았고**, 뽑는 규칙에 정답지가 들어가지 않는다.
분위 할당은 `{1:4, 2:8, 3:5, 4:6, 5:6, 6:6, 7:6, 8:7, 9:6, 10:6}` 이다.

### 도중에 걸린 빗장 하나

`reference_preflight` 가 지리 참조 파일에 **"이름이 아니라 코드로 결합했다"는 증언**을
요구하며 멈췄다. 파일은 실제로 코드 기반이었다 — 키가 전부 8자리 동 코드다
(centroids 373/373, hub_signature 40/40, 비코드 0).

**빗장을 끄지 않고 증언을 채웠다.** 기계로 확인한 사실만 적었고 확인 방법도 함께 남겼다.

## 사전등록

| | 내용 |
|---|---|
| 설계 | 60명 × 4기전 × on/off = **480칸**, seed 70001, 후보 둘 |
| 원본 | `/data/cohort60/source_meal.json` (sha256 `105a0e03…`) |
| 실행 | 계획 → 게이트 → 수정 3바퀴 → 조립 → 결제 (양쪽 동일) |

### 판정

| | 기준 |
|---|---|
| **지표가 정해진다** | 부호를 말할 수 있는 지표가 **하나라도** 생긴다 |
| **후보를 가른다** | 그 지표에서 두 후보가 다르다 |
| **여전히 무효** | 예순으로도 전부 0을 지난다 |

> **둘째 줄은 기대하지 않는다.** 검정력 계산이 후보 비교에 106명을 요구하는데
> 예순이다. **첫째 줄이 이번의 물음**이다 — 기전 효과의 부호가 처음으로 정해지는가.

### 부 지표

구성 거리(사람별) · 게이트 막힘 · 칸당 구매 · 안 산 업종 수 ·
그리고 **매장 취식 건수** — 열두 명에게는 없던 사람이 예순 명에는 있을 수 있다.

### 이 실험이 답하지 않는 것

- **최적 프롬프트** — 후보는 v16 에서 마감했다. 새 후보가 없다
- 실측 **크기** — 부호가 정해져도 크기는 별개다
- 모집단 일반화 — 예순도 서울 1,400만의 표본으로는 작다

지표별 전수 대조는 [indicator_view_v18.md](indicator_view_v18.md) 에 그래프로 있다.

### 하마터면 잘못 적을 뻔한 것 — DS-1

v34 의 DS-1 이 스무 라운드 만에 처음으로 구간이 0을 제외한 것처럼 보였다.
**두 가지가 걸렸고 둘 다 기각 사유다.**

**하나. 하한이 뽑기 잡음이었다.**

```
2,000회 · 칸만 재추출       +83.6  [+1.4, +304.4]    0 제외
4,000회 · 칸만 재추출       +83.6  [+0.0, +320.0]    경계
4,000회 · 시민 통째 재추출   +83.6  [-4.7, +325.6]   0 지남
```

v18 은 복제가 하나라 블록 붓스트랩이 `len(runs) > 1` 조건에서 꺼지고 **칸만
재추출하는 옛 방식으로 조용히 되돌아가 있었다.** v7 에서 판정을 철회하게 만든
바로 그 조건이다. `pool_indicators.py --cluster` 를 붙여 고쳤다.

**둘. 그 수가 잰 것은 배달이다.**

```
v34 거리두기 칸          무정책 → 정책
  home_delivery            10  →  19
  meal_dine_in              1  →   1
  식사 금액           140,000 → 257,000원   (+83.6%)
```

정책 팔 식사 20건 중 19건이 배달이다. 실측 −14.1% 는 **매장 취식 붕괴가 배달
증가를 압도한 값**인데 우리 기준선에는 붕괴할 매장이 없다.
[BASELINE_COMPOSITION.md](../BASELINE_COMPOSITION.md) 가 9/20 에 이미 적어 둔 자리다.

### 칸이 어디서 새는가

```
설계          480칸
게이트 도달    480칸   (계획 단계 유실 0)
조립          v25 334 · v34 341
결제 유효     v25 328 · v34 339
```

**480칸 중 v25 146칸(30%)·v34 139칸(29%)이 수정 3바퀴로도 자원 게이트를 통과하지
못했다.** 열두 명 때가 17.7% 였으니 나빠졌다. 명단이 넓어지면서 재고 0으로 시작하는
사람이 늘어난 것으로 보이나, 이 라운드로는 확정할 수 없다.

곁가지로 조립 집계의 `never_feasible` 이 `96 - kept` 로 박혀 있어 60명에서 −238을
찍고 있었다. 보고용 필드라 분석에 쓰이진 않았고, 실제 코호트 크기를 읽도록 고쳤다.

## 검증은 어떻게 진행되는가

```
같은 사람 · 같은 날짜 · 같은 프롬프트
   ├─ off 팔   정책 문구 없음
   └─ on  팔   정책 문구 있음
        차이를 지표로 환산 → 실측 부호·크기와 대조
```

1. **계획** — 후보 프롬프트로 하루 일정을 낸다
2. **자원 게이트** — 모델 호출 전에 물리적으로 불가능한 계획을 막는다
3. **수정 3바퀴** — 막힌 칸에 부족분을 되먹여 다시 계획하게 한다
4. **조립** — 끝내 불가능한 칸을 빼고 행렬을 맞춘다
5. **결제** — 실제 품목·금액·결제수단을 고른다
6. **채점** — 합산해 한 번 나누고, 95% 붓스트랩 구간을 붙인다

## 이 검증이 유효하다고 말할 수 있는가 — 부분적으로만

**유효하다고 말할 수 있는 것**

- **대조가 성립한다.** on/off 가 같은 사람·같은 날짜이고, 60쌍 전부 내용이 다르다
- **사전등록이 결과보다 앞선다.** 판정선·취소 조건이 커밋 시각으로 증명된다
- **순환이 없다.** 실측 부호·크기·공식이 프롬프트에 들어가지 않으며 금지어 단위
  테스트로 고정돼 있다
- **잡음 바닥이 있다.** 같은 팔 다른 씨앗 거리를 영가설로 쓴다

**유효하다고 말할 수 없는 것**

- **부호를 가리지 못한다.** 아홉 지표 전부 구간이 0을 지난다. 검정력 계산이 요구하는
  106명(후보 비교)에 예순은 못 미친다
- **크기를 맞댈 수 없다.** 카탈로그는 낱개 단가(최고가 커트 20,000원)이고 실측은
  카드매출이다. 비율 대 비율로만 본다
- **여덟 지표는 구조적으로 못 낸다.** 월 단위 회계(P012-3·4·6, EM-2)와 업종 계층
  부재(P012-5, EM-4, DS-6)다. 표본을 늘려도 나오지 않는다
- **행렬이 30% 불완전하다.** 조립에서 뺀 칸이 무작위로 빠졌다는 보장이 없다
- **DS-1 은 이 기준선에서 도달 불가능하다.** 붕괴할 매장 취식이 없다

> **요약: 설계는 유효하고 실행도 유효하나, 예순 명은 결론을 낼 힘이 없다.**
> v18 이 답한 것은 "부호가 정해지는가"이고 답은 **아니오**다.
