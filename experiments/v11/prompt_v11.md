# 실험 v11 — 같은 요구를 같은 자리에 적는다

**날짜 2026-09-21 사전등록** · **상태** 실행 · **프롬프트 v25 동결**
**대조군은 v10 의 v25 팔** (같은 프롬프트 · 같은 seed · 원본만 다름)

## v10 이 남긴 것

시스템 프롬프트를 고쳐도 아무 일이 없었다.

```
막힌 칸 / 96        66001  66002  66003  66004   평균
v25 (현직)            46     47     42     44    44.8
v32 (범위 명시)        46     45     46     47    46.0
```

"배치하는 **모든** 활동에 대해"라고 못 박아도 모델은 자기가 고른 `home_meal` 에
자원 검사를 걸지 않는다.

## 찾은 비대칭

두 요구가 **서로 다른 자리에** 적혀 있었다.

```
세탁   "실험 가정: provided_laundry는 집에서 세탁 1회를 하는 활동이며,
        실제 시작 전에 세제 1회분이 있어야 한다."     ← JSON 앞, 산문 한 줄

끼니   meal_stock · activity_consumption · assumptions   ← JSON 필드 안에만
```

**모델은 문장으로 읽을 수 있는 요구는 지키고, 필드에서 추론해야 하는 요구는 무시한다.**
세제는 재고 0이면 온라인으로 주문한다. 끼니는 재고 0이어도 집밥을 두 끼 계획한다.

`add_meal_need.py` 가 자원·소비·견적·필요는 채우고 **증거 줄만 만들지 않았다.**
세탁과 같은 구조라고 했는데 한 조각이 빠져 있었다.

## 무엇을 바꾸나 — 문장 하나, 같은 형식

```
실험 가정: home_meal은 집에서 한 끼를 드는 활동이며,
          실제 시작 전에 집에 있는 식재료 한 끼분이 있어야 한다.
```

세탁 문장과 **구조가 같다**. 들어가는 자리도 같다(JSON 앞).

**어디서 먹으라고도, 무엇을 사라고도 하지 않는다.** 검사로 막았다
(`test_the_evidence_line_names_no_place_and_no_product`) — 음식점·카페·외식·마트·
장보기·배달이 전부 금지어다. 장을 보든, 나가서 먹든, 시키든, 선택적 끼니를 거르든
전부 이 문장을 만족한다.

> **프롬프트가 아니다.** 시스템 프롬프트는 양쪽 팔 모두 v25 다.
> 바뀌는 것은 **입력에서 같은 사실을 어디에 적느냐**뿐이다.

### 기록만 하는 것

장보기 · 매장 취식 · 포장 · 배달 · 집밥 감소 중 무엇으로 풀었는지 센다.
**점수로 쓰지 않는다.** 어느 해법이 낫다고 정하는 순간 유도가 된다.

### 왜 이것이 v5 와 다른가

v5 도 "JSON 안의 사실을 산문으로 올린다"였고 실패했다. 다른 점은 둘이다.

1. **잣대가 다르다.** v5 의 주 지표는 도달 비율(칸당 0.1 수준, 위약 흔들림 0.094)이었다.
   여기는 막힌 칸 수이고 **46 대 0 규모**다
2. **작동하는 짝이 있다.** 세탁은 같은 형식으로 적혀 있고 **실제로 지켜진다.**
   v5 에는 비교할 짝이 없었다

그래도 실패할 수 있다. 그때는 **문장의 자리가 아니라 다른 것이 원인**이라는 뜻이고,
남은 후보는 `home_meal` 이 계획에서 채움 활동으로 쓰인다는 것이다.
