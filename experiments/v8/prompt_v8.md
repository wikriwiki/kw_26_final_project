# 실험 v8 — 양이 아니라 구성

**날짜 2026-09-20 사전등록** · **상태** 실행 · **후보** v25(현직) · v31(구성 빗장 겨냥 교정)

## v7 이 가르쳐 준 것

v30 은 구매 비율을 **+2.21 SE** 올려 사전등록 기준을 통과했다. 그런데 늘어난 구매가
전부 배달로 갔고, 정답지 지표는 **더 나빠졌다**.

```
                    v25    v30
부호 일치             1      0
부호 반대 (구간 0 제외)  0      2      ← DS-1, DS-3
```

**양을 늘리는 공정 지표로는 정답에 가까워지지 않는다.** 그래서 이번 주 지표는
양으로 이길 수 없는 것이어야 한다.

## 진단 — 기준선의 구성이 에이전트 자신의 설정과 다르다

무정책 192칸에서 산 것이 **71건**이고 그중 **46건이 같은 온라인 세제**다.
자원 시나리오가 `provided_laundry` 에 세제를 요구해서 사는 것이지 소비 행동이 아니다.

```
부여된 구성 (그 사람 입력)  식사 29.4 · 마트 25.0 · 쇼핑 14.2 · 건강 12.8 · 교육 6.5 · 편의점 6.0 ...
실제로 산 구성             쇼핑+마트 77.9 · 식사 22.1 · 나머지 0

한 번도 안 산 업종  건강 · 교육 · 기타 · 디저트 · 미용 · 여가 · 주점  (11개 중 7개)
```

정답지와 비교한 것이 아니다. **그 사람에게 부여된 구성과 그 사람이 산 것**을
비교한 것이므로 **순환이 아니다.**

이것이 DS-1(매장 취식 0건이라 제한이 물릴 대상 없음)·DS-4(카페 0원)·
P012-5(미용 0건)를 한꺼번에 설명한다.

## 무엇을 바꾸나 — v30 과 같은 수법, 다른 빗장

```
v25   평균 지출과 과거 비중은 오늘 채울 할당량이 아니다.
v31   평균 지출과 과거 비중은 오늘 채울 할당량이 아니라
      이 사람이 평소 어디에 돈을 쓰는지를 말해 준다.
```

빗장의 부정문(**할당량이 아니라**)은 남는다. 더하는 것은 **그 구성이 무엇인지**뿐이다.
지금 프롬프트는 "할당량이 아니다"까지만 말하고 그것이 무엇인지 말하지 않아서
모델이 통째로 무시한다.

**정답지가 재는 업종을 하나도 지목하지 않는다** — 음식점·카페·미용·여가·가전·준내구재가
전부 금지어다. 검사로 막았다(`test_it_names_no_sector_the_answer_keys_measure`).

| | 내용 |

### 별도 확인 — 정답지 17개 지표

주 지표가 성공해도 **정답지 지표가 나빠지면 채택하지 않는다.** v7 에서 그렇게 해서
v30 을 버렸다. 특히 볼 것:

- **DS-1** — 매장 취식이 생기면 거리두기가 물릴 대상이 생긴다. 다만 **이것이 성공
  조건은 아니다.** 구성이 맞아도 정책 반응은 별개다
- **부호 반대(구간 0 제외)가 v25 의 0 보다 늘면 채택하지 않는다**

### 이 실험이 답하지 않는 것

- 구성이 맞으면 정답에 수렴한다 — 모른다. **잴 수 있게 되는 것**과 **맞는 것**은 다르다
- 세제 인공물을 어떻게 없앨지 — 그건 시나리오 설계이지 프롬프트가 아니다
- 최적 프롬프트 — 한 축이다
