# 정답지 라운드 2 사전등록 — 검출되는 지표에만 GPU 를 쓴다

**작성 2026-09-22 22:15 · 실행 전 커밋** · v50·v51·v52 뒤에 돈다

---

## 이 라운드가 있는 이유

검정력을 역산해 보니 **지표 10개 중 8개가 지금 표본으로 정답지 효과를 검출하지
못한다**([SAMPLE_IS_THE_BINDING_CONSTRAINT.md](../SAMPLE_IS_THE_BINDING_CONSTRAINT.md)).
검출되지 않는 지표에 프롬프트 후보를 더 던지는 것은 GPU 를 버리는 일이다.

그래서 이 라운드는 **표본을 지표에 맞춘다.** 프롬프트를 새로 만들지 않는다.

## 무엇을 재는가 — 검출되는 것만

```
지표       실측         필요 n    쓸 n    왜 넣는가
DS-1      -14.1%        155      500    지금도 검출된다. 프롬프트 차이가 보이는 자리
P012-1    +20.82%       231      500    1.2배 모자랐다. 500 이면 닿는다
P012-4    47,880원      144      500    지금도 검출된다
DS-4        —           378      500    1.2배 모자랐다
```

**빼는 것과 그 이유를 먼저 적는다.**

```
DS-2   필요 n 약 10,000   효과 468원 대 표준편차 16,723원 — 표본으로 못 닿는다
LV-2   필요 n 약 75,000   몫 0.0021 대 0.2055 — 지표 설계를 바꿔야 한다
EM-3   필요 n 약 615      값이 원문 본문에서 확인되지 않는다 (p4 의 11.1 은 예산 규모)
LV-3   필요 n 약 2,980    정답지에 숫자가 없다 — 방향만 있다
```

**이것들을 '실패'로 적지 않는다.** 재지 못하는 것이다. 그 구분을 채점에 남긴다.

## 설계

```
정책   ① 거리두기 (DS-1·DS-4)      창은 v50 과 같다 — 2020-11-17:18 → 11-24:25
       ② 상생소비 P012 (P012-1·P012-4)  창은 result_FINAL 과 같다

인원   500명. 위 표의 필요 n 을 전부 덮는 가장 작은 수다
팔     v50 이 고른 현행 프롬프트 하나 · 대조로 v5 하나
소득   끈다. 창이 짧아 지갑 한계 안이다
```

**팔을 둘만 둔다.** 셋을 두면 GPU 시간이 정책마다 1.5배가 되고, 검출되는 지표가
넷뿐이라 후보를 늘려도 읽히는 칸이 늘지 않는다.

## 합격선 — 결과를 보기 전에 정한다

```
주      네 지표에서 |시뮬 − 실측| 이 v5 보다 줄어든 지표의 수
        3개 이상 → 현행 프롬프트가 정답지에 더 가깝다고 적는다
        2개      → 갈렸다. 현행 유지
        1개 이하 → v5 가 더 가깝다

부      부호 적중 수가 줄지 않는다 (지금 v5 기준 DS-1·DS-4 적중, P012-1·P012-4 적중)
```

**런 간 이동을 넘는 것만 읽는다.** DS-1 은 0.2%p, DS-2 는 13.1%p 였다
([v5_replication.md](../v50/v5_replication.md)). P012 의 런 간 이동은 아직 재 본
적이 없으므로 **이 라운드에서 v5 팔이 그 역할을 겸한다** — `result_FINAL` 과
같은 창·같은 프롬프트이므로 두 번째 관측이 된다.

## 사전등록한 예측

**바뀌는 지표가 1~2개일 것이다.** 근거: 관문의 +20.6%p 가 본런 실패율을
2.33% → 2.50% 로밖에 못 움직였다([gate_does_not_move_production.md](../v50/gate_does_not_move_production.md)).
형식 준수와 업종별 금액은 다른 것이다.

**그리고 n 을 200 → 500 으로 올린 것이 프롬프트보다 크게 작용할 것이다.**
거리두기에서 이미 한 번 그랬다(1/4 → 3/4, 프롬프트 불변).

## 이 라운드가 답하지 못하는 것

**크기 검증이 아니다.** `audit_2026_09_20` 이 대상·기간·결과·분모·대조군이
호환될 때만 배수를 비교하라고 했고, 원문 창은 한 달~40주이고 우리 창은 이틀이다.
여기서 재는 것은 **어느 프롬프트가 실측 쪽에 더 가까운가**이지 배수가 아니다.

**한 런이다.** 거시 런의 런 간 변동은 DS-1 에서만 재 봤다(0.2%p). 다른 지표는
이 라운드의 v5 팔이 두 번째 관측이 되어 처음으로 재진다.

## GPU 비용을 미리 적는다

```
거리두기  500명 × 12일 × 2팔   v50 의 200명 12일이 팔당 약 4.2시간 → 약 21시간
P012     500명 ×  6일 × 2팔                                    → 약  5시간
                                                          합계 약 26시간
```

**이 비용이 정당한지 먼저 판단해야 한다.** 대안은 거리두기를 빼고 P012 만
돌리는 것이다(약 5시간). 그 경우 읽히는 지표는 P012-1·P012-4 둘이고,
합격선은 "둘 다 가까워지면 채택"으로 바뀐다.

> 실행 전에 이 문서를 커밋한다. 결과를 보고 지표를 고르거나 합격선을 고치지 않는다.
