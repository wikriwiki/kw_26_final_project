# 집에서 못 하는 일을 시켜도 열 번에 한 번만 한다

**2026-09-22 03:10** · v27 계획 480칸 · 볼일 규칙 제한 해제판

---

## 숫자

볼일은 **그 활동 하나로만** 채울 수 있게 돼 있다. 배달로도, 온라인으로도 안 된다.
그런데 계획에 그 활동이 들어가는 비율이 이렇다.

```
볼일로 받은 활동      계획에 들어간 칸 / 전체 칸
  groceries            26 / 216   (12%)
  meal_dine_in         18 / 168   (11%)
  health_goods          1 /  56   ( 2%)
  other_service         1 /  24   ( 4%)
  convenience           0 /   8   ( 0%)
  education_service     0 /   8   ( 0%)
  ─────────────────────────────────────
  전체                 46 / 480   (10%)
```

**열 번에 한 번이다.**

## 왜 그런가 — 프롬프트가 허락한다

```
9행  필요를 지금 충족하거나 보유품으로 해결하거나 대체·연기·생략할 수 있다.
     후보의 존재는 구매 의무가 아니다.
```

볼일은 `mandatory: false` 로 들어간다. **미루거나 생략하는 것이 규칙 안에서 정당하다.**
그리고 모델은 열에 아홉을 그렇게 한다.

## 이것이 지금까지의 모든 결과를 다시 설명한다

```
v23   볼일 있음 · 집 밖 있는 칸 49/480      = 10%
v27   볼일 있음 · 볼일 수행     46/480      = 10%
v25   볼일 없음 · 집 밖 있는 칸 16/480      =  3%
```

**천장은 볼일의 유무가 아니라 선택적 필요에 대한 10% 수행률이다.**

- v23 이 16칸을 49칸으로 올린 것은 **볼일을 준 덕**이다
- v25R 에서 프롬프트가 더 못 올린 것은 **수행률이 문장이 아니라 다른 것에 매여 있기 때문**이다
- v27 에서 매장 식사 볼일 21명을 줬는데 거리두기 칸에 3건만 나온 것도 같은 비율이다

## 그리고 의무는 다르게 취급된다

같은 모델이 **근무**는 빠뜨리지 않는다.

```
근무 누락    직업 있는 296칸 중 24칸 (8%)  → 수행률 92%
볼일 수행    480칸 중 46칸 (10%)           → 수행률 10%
```

**`mandatory: true` 인 것은 92% 하고, `mandatory: false` 인 것은 10% 한다.**
모델은 둘을 분명히 다르게 다룬다.

---

## 그러므로 다음 실험은 이것이다

**볼일을 `mandatory: true` 로 준다.**

이것이 유도인가를 먼저 따진다.

| 유도인가 | 판단 |
|---|---|
| 정책 효과의 방향을 지시하는가 | **아니다.** 볼일은 정책과 무관하게 주어지고, on/off 양 팔에 똑같이 있다 |
| 실측 수치를 프롬프트에 넣는가 | **아니다.** 프롬프트는 v25 그대로다 |
| 하루의 내용을 지정하는가 | **그렇다.** 근무 일정을 지정하는 것과 같은 종류다 |

세 번째는 유도가 아니라 **시나리오 설계**다. 근무·통근·재고를 지정하는 것과
같은 층위이고, 그것들은 이미 지정돼 있다. **선택적 볼일만 지정에서 빠져 있었다.**

> 다만 **얼마나 줄어드는가는 여전히 모델이 정한다.** 거리두기가 켜졌을 때
> 의무인 매장 식사를 포기하는지, 포장으로 바꾸는지, 그대로 하는지는
> 시나리오가 정하지 않는다. **DS-1 이 재는 것은 그쪽이다.**

## 이 문서가 남기는 경계

**10% 수행률 자체는 틀린 것이 아닐 수 있다.** 사람도 미룬다.
다만 그 값이 **문장으로 조절되지 않고**(v25R), **볼일의 종류와도 거의 무관하며**
(마트 12% · 식사 11%), **의무 여부에서만 크게 갈린다**(92% 대 10%)는 것이
이 시뮬레이터의 성질이다.

정답지에 닿으려면 그 성질 위에서 설계해야 한다.
