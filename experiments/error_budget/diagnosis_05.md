## diagnosis_03·04 의 비관을 일부 뒤집는다

앞선 진단은 "세 층 모두 상수라 정책이 닿지 않는다" 고 했다. 스칼라(①)와
가맹몫(②)에 대해서는 맞다. **③에 대해서는 틀렸다.**

정책 전 창(10-21·22)과 정책 후 창(10-25·26)을 **같은 에이전트 안에서** 맞댔다.

```
지표                        정책 전      정책 후     변화      부호검정
Stage2 계획액 (이벤트 산물)   69,839  ->  76,652   **+9.76%**  286:214 p=0.0015  **다르다**
소비성향 스칼라                 0.70  ->    0.70      +0.34%   184:176 동점140 p=0.712
총액 max(앵커,계획)          130,418  -> 133,512      +2.37%   234:223 동점 43 p=0.640
이벤트 수                      11.5  ->    11.5      -0.05%              p=1.000
계획이 앵커를 넘은 금액           57  ->     667              **동점 490/500**
```

**에이전트는 정책에 반응하고 있다.** 스칼라로는 아니고 **계획 금액**으로 —
같은 이벤트 수(11.5 → 11.5)를 유지하면서 **쓰는 금액을 키운다.**
그리고 그 반응이 `max(앵커, 계획)` 에서 **사라진다**(+9.76% → +2.37%).
500명 중 **490명이 계획이 앵커를 못 넘는다.**

## 이것이 왜 결정적인가 — 프롬프트가 닿는 유일한 통로다

```
프롬프트 -> 이벤트    문턱 격자에서 적립 이벤트 3.75 -> 4.67 (24% 변동) — **닿는다**
이벤트   -> 계획액    Stage2 가 이벤트에 가격을 매긴다 — 닿는다
계획액   -> 총액      max(앵커,계획) 에서 **버려진다**   ← 여기가 끊겨 있다
```

스칼라 통로는 죽었다(범위를 3배 넓혀도 답 불변, calib_02). **그러나 이벤트
통로는 살아 있고, 그 끝이 회계에서 잘려 있었다.** 프롬프트 최적화가 의미를
갖는 곳은 여기다.

## 고침 — 수준은 앵커가, 변동은 계획이

```
현재   total = max(anchor, planned)                       계획이 0.7% 만 이긴다
고침   total = anchor x clamp(planned / (REF x anchor))   REF = 무정책 창의 계획/앵커 평균
```

`REF` 도 클램프도 **정답지를 안 보고** 정한다 — REF 는 무정책 창에서 관측된
평균 몫(0.8012), 클램프는 그 창의 비율 분포 **5~95 분위**(0.194~2.799)다.
효과가 큰 쪽을 고르지 않기 위해 규칙을 먼저 정하고 숫자를 나중에 읽었다.

**앵커를 지키는 이유**: 앵커는 BDC 소비분위에 묶인 값이고, 이 시뮬의 실증
근거 전체가 거기 걸려 있다. 클램프를 풀면 `total = planned/REF` 가 되어
전달률은 +9.76% 로 올라가지만 **앵커가 통째로 사라진다.** 한 지표 2~3%p 를
얻으려고 실증 기반을 버리지 않는다.
