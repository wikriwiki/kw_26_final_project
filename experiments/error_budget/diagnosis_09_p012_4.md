# P012-4 의 분모를 확인해야 한다 — 1.87배가 말해 주는 것

**2026-09-24 21:00** · 산술만. GPU 0

---

## 실측값을 거꾸로 풀면

```
1인 평균 캐시백  47,880원
캐시백률         10%
-> 문턱 **초과분**  478,800원
우리 문턱 중앙     584,180원
-> 초과분이 문턱의 **82%**
-> 그 사람은 2분기 월평균의 약 **1.87배**를 썼다
```

## 1.87배는 전체 소비자의 평균일 수 없다

전 국민이 평소의 1.87배를 쓰는 일은 없다. **이 값의 분모는 "모든 소비자" 가
아니라 "캐시백을 실제로 받은 사람" 일 가능성이 높다.**

```
상생소비지원금은 카드사에 **신청**해야 참여한다
그리고 캐시백은 **문턱을 넘긴 사람만** 받는다
-> 47,880원의 분모 = 신청하고 넘긴 사람
```

## 우리는 전원을 분모로 잰다 — 같은 양이 아니다

```
우리 P012-4   모든 에이전트의 평균 캐시백
정답지        (아마) 받은 사람의 평균 캐시백
```

**EM-2 에서 겪은 것과 같은 종류다 — 답이 아니라 자가 다르다.**
그때는 적격 판정이 다른 정책 기준이었고, 여기는 분모가 다르다.

## 그래서 28일 창으로도 P012-4 는 안 맞는다

```
우리 28일 투영 위치   문턱의 0.93~0.96  -> 넘는 사람이 적고, 넘어도 조금 넘는다
문턱 대비 1.10 이면   캐시백  5,841원
문턱 대비 1.82 여야   캐시백 47,902원  (정답지)
```

**창은 "넘는 사람이 생기는가" 를 답하지 "얼마나 넘는가" 를 못 답한다.**
분모를 안 맞추면 28일을 돌려도 P012-4 는 한 자릿수 만원이 나올 것이다.

## 확인할 것 — 원문을 다시 읽어야 한다

```
· KDI 2022.9 의 47,880원이 **수급자당**인지 **전체 대상자당**인지
· 그 수치의 모집단이 신청자인지 전 국민인지
```

**이것은 우리 시뮬의 문제가 아니라 눈금의 문제일 수 있다.** 확인 전에는
P012-4 를 "못 맞힌 지표" 로 적지 않는다 — **"자를 확인해야 하는 지표"** 로 적는다.

```
               (score_policy 의 cashback_per_capita 에 분기를 더한다)

```
