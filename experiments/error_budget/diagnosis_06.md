# 문턱에 닿을 수 없다 — 관측 창이 짧아 정책의 유인이 작동하지 않는다

**2026-09-24 18:30** · 돌고 있는 본런(plan_v5)의 그래프에서 직접 잼 · n=400~480

---

## 무엇을 쟀나

상생소비지원금의 유인은 **문턱**이다 — 이번 달 적립업종 실적이 2분기 월평균의
103% 를 넘겨야 비로소 적립이 시작된다. 그러면 반응은 **문턱 언저리**에 몰려야
한다. 그래서 정책 시작 직전(10-20) 에이전트들이 문턱의 어디쯤 있는지 쟀다.

```
문턱 대비 위치   중앙 0.64 · 10% 0.60 · 90% 0.69      <- 놀랍도록 좁다

문턱의 60% 미만      26 ( 5.4%)
60~85%             454 (94.6%)
85~100% (언저리)      0 ( **0.0%** )   <- 유인이 무는 구간이 **비어 있다**
이미 초과             0 ( 0.0%)
```

## 닿을 수 있기는 한가

```
문턱               중앙 701,583원
정책 시작 시 누적    중앙 445,851원
하루 증가          중앙  21,616원
남은 거리          중앙 243,561원

평소 속도로 문턱까지   중앙 **11.0일**
관측 창에 남은 날      **6일** (10-21 ~ 10-26)
6일 안에 닿는 사람     37 / 400 = **9.2%**
```

**91% 는 관측 창 안에 문턱을 못 넘는다.** 넘을 수 없는 문턱은 유인이 아니다.

## 정책 파일이 이미 이렇게 적어 두었다

`data/neo4j_load/policies/P012.json` 의 notes:

> **28일이어야 하는 이유** — 문턱이 월 단위(2분기 월평균×1.03)라 14일에는
> 앵커의 절반도 안 쌓여 **도달 불가**. 28일이면 약 93%까지 올라가 "평소대로면
> 겨우 못 넘고 조금 더 쓰면 넘는다" 는 **실제 한계 유인**이 작동한다.
> 관측: 무정책 2021-10-01~10-14 + 정책 2021-10-15~10-28 (28일 연속)

**우리가 돌린 창은 9일(10-18~10-26)이고 정책일은 이틀뿐이다.** 파일이 필요하다고
적어 둔 28일의 3분의 1도 안 된다. 그리고 실제로 64% 에서 멈췄다 — 파일이 예고한
그대로다.

## 그래서 지금까지의 결과가 다시 읽힌다

```
계획액 정책 반응  +9.76% (p=0.0015)   <- 문턱 반응이 아니다. "정책이 있으니 조금 더"
소비분위별 증가율  58~64% 로 균일       <- 문턱 제도라면 언저리에 몰려야 한다
P012-1           +1.90% 대 실측 +20.82%
```

**부호는 맞고 크기가 작은 이유가 여기 있다.** 정답지가 잰 +20.82% 는 문턱을
넘기려는 한계 지출을 포함한 값이고, 우리 에이전트에게는 그 한계 유인이
**존재한 적이 없다.**

## 프롬프트로는 못 고친다

후보 넷을 시험했고 셋이 기각됐다(p=0.678 / 1.000 / 0.798). 그 결과들이
이제 다르게 읽힌다 — **넘을 수 없는 문턱을 더 잘 설명해 줘도 행동은 안 바뀐다.**
프롬프트가 제 몫을 못 한 것이 아니라, 반응할 유인 자체가 창 밖에 있었다.

이것은 이미 겪은 벽과 같은 모양이다.

```
P010 역진의 벽   E40/E15 = 0.48 (필요 2.67)   — 필요한 배수에 못 미쳐 기전 불발
P012 문턱의 벽   문턱까지 11일 (남은 날 6일)   — 필요한 날수에 못 미쳐 기전 불발
```

## 해야 할 일

**관측 창을 28일로 늘린다.** 정책 파일이 그렇게 적어 두었고, 그 근거(월 단위
문턱)도 적혀 있다. 지금 창으로는 프롬프트를 아무리 손봐도 정답지에 못 간다.

```
비용   28일 x 500명 · 하루 약 70분 -> 약 33시간
대안   없다. 문턱이 월 단위인 이상 창을 줄이면 유인이 사라진다
```

**돌고 있는 9일 런은 끝까지 돌린다** — 회계 고침(EXP_PLAN_DRIVES_TOTAL)을 같은
창의 기존 읽기(result_r2_v5)와 맞대는 데는 그대로 쓸 수 있다. 다만 그 런의
P012-1 이 실측에 가까워지리라 기대하지 않는다. **창이 문제이지 회계만의
문제가 아니기 때문이다.**

## 먼저 확인할 것 — 28일이면 정말 93% 에 닿는가

파일의 "28일이면 약 93%" 는 추정이다. 우리 런의 실측 증가 속도로 다시 계산한다.

```
하루 증가 중앙 21,616원 · 28일이면 605,248원
10-01 시작 누적 0 가정 -> 문턱 701,583원 대비 **86%**
```

86% 면 "겨우 못 넘는" 자리이고, 그것이 파일이 말한 한계 유인이 작동하는
지점이다. **추정이 대체로 맞다.** 다만 우리 속도로는 93% 가 아니라 86% 이므로,
그 차이가 결과를 가를 수 있다는 것도 함께 적어 둔다.
