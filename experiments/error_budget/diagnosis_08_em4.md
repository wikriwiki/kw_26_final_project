# EM-4 과반응 — 가장 큰 오차(61.10%p)의 첫 진단

**2026-09-24 20:25** · arm A 읽기 + 프롬프트 본문 · 아직 시험 안 함

## 무엇이 과한가

```
실측   준내구재 증가율 - 대면서비스 증가율 = **+7.20%p**
우리   +45.8% - (-22.5%)                 = **+68.30%p**   (9.5배)
```

**방향은 맞다**(준내구재가 더 오른다). 순위 지표로는 **적중**이다.
문제는 크기다. 그리고 두 쪽 다 과하다 — 준내구재가 너무 오르고 대면서비스가
너무 내린다.

## 프롬프트 본문을 세어 보면

```
낱말 수     준내구재 23회 · 대면서비스 20회      -> 거의 균형
```

본문만 보면 치우치지 않았다. **그런데 이벤트 예시 JSON 안을 보면 다르다.**

```
예시에 나오는 준내구재   가전 · 전기밥솥 · 운동화 · 신발 · 의류 · 목돈   **6종**
예시에 나오는 대면서비스  미용실 · 병원                                 **2종**
```

**구체 예시가 3대 1로 준내구재 쪽이다.**

예시가 행동을 끌어당긴다는 것은 이 프로젝트에서 이미 측정됐다 —
`daily_propensity` 가 예시값 0.72 근처(0.68)에 **54%** 몰렸다. 구체적인 물건
이름(전기밥솥·드라이기·운동화)은 추상적인 업종 목록보다 훨씬 강하게 끌어당긴다.

## 후보가 될 수 있는 형태 — **대칭 회복**이지 크기 조정이 아니다

```
할 것     대면서비스 쪽에도 같은 수준의 구체 예시를 준다
          (예: "미뤄둔 스케일링", "안경 도수 바꾸기" 같은 급)
안 할 것  준내구재 예시를 **빼서** 반응을 줄이는 것
```

**왜 이 구분이 중요한가.** 예시를 빼서 크기를 맞추면 그건 정답지를 보고 크기를
깎는 일이다. 예시의 **비대칭을 없애는 것**은 프롬프트 안에서 정당화되는 변경이고,
그 결과 크기가 어떻게 되든 그것은 모델이 답한 것이다.

## 정직하게 — 내가 이걸 왜 봤는지

**정답지가 어긋나 있어서 봤다.** 그러니 "우연히 비대칭을 발견했다" 고 말하지
않는다. 다만 발견한 뒤에 하는 조치를 **대칭 회복**으로 제한하면, 크기를 정답지에
맞추는 일은 아니다. 그 선을 지키는 것이 핵심이고, 시험으로 못 박는다.

```
시험 1  준내구재 예시 수가 **줄지 않았는가** (빼서 맞추는 것을 막는다)
시험 2  덧대는 예시에 수치·방향 지시가 없는가
시험 3  두 군의 구체 예시 수가 같아졌는가
```

## 그런데 먼저 확인할 것이 있다 — 환경 교란

arm A 의 창은 **2020-05-07/08 -> 05-14/15**, 코로나 한복판이다.
대면서비스 -22.5% 가 정책 때문인지 **그 시기의 거리두기 때문**인지 가르지 않았다.

```
정책 때문이면   프롬프트/모델 문제
시기 때문이면   환경이 맞게 작동한 것이고 EM-4 의 '과함' 은 창 선택의 문제다
```

**이것을 가르기 전에는 후보를 만들지 않는다.** 무정책 기간에도 대면서비스가
같은 폭으로 내리는지 보면 된다 — arm A 자료로 잴 수 있다.
