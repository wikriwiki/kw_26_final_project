# 실험 v19 — 부여된 집 체류 시간을 부정문에서 사실로

**날짜 2026-09-21 사전등록** · **상태** 실행 · **후보 v35**
**대조는 v18 의 v25 팔** (같은 60명 · 같은 seed · 같은 원본)

---

## 찾은 것 — 순환이 아닌 기준이 하나 더 있었다

에이전트는 **자기 평일 집 체류 시간을 입력에서 듣는다.**

```
행태: 배달 6일/월, 평일 집 체류 15.2h, 주말 집 체류 9.7h, 이동성 분위 1
```

그런데 계획은 그보다 훨씬 오래 집에 둔다.

```
부여된 평일 집 체류   평균 12.1h   (범위 8.6 ~ 18.3)
계획이 낸 집 체류     평균 17.7h   (범위 11.0 ~ 24.0)
차이                 +5.6h · 중앙값 +4.5h
480칸 중 427칸(89%)이 자기 숫자보다 두 시간 넘게 더 집에 있다
```

**이것이 여덟 라운드 동안 못 움직인 집 밖 행동의 정체다.** 그리고 정답지가 아니라
**그 사람 자신의 입력**과 비교한 것이므로 순환이 아니다.

## 프롬프트는 그 숫자를 부정할 때만 언급한다

```
v25   집 체류 시간은 재택근무 가능 여부가 아니다.
```

**무엇이 아닌지만 말하고 무엇인지는 말하지 않는다.** v30(빗장)·v31(지출 구성)과
같은 모양이고, 그중 v30 은 실제로 움직였다.

```
v35   집 체류 시간은 재택근무 가능 여부가 아니라 이 사람이 보통 하루를
      어디서 보내는지를 말해 준다. 오늘 채울 할당량은 아니지만
      하루를 배치할 때 참고한다.
```

**양방향이다.** 18.3h 를 부여받은 사람은 **더** 집에 있어야 한다.
한쪽으로 미는 낱말(나가·외출을 늘·줄여·더 많이·적게)을 검사로 막았다.
장소·업종·정책도 하나도 없다.

## 사전등록

| | 내용 |
|---|---|
| 설계 | 60명 × 4기전 × on/off = 480칸, seed 70001 |
| 원본 | `/data/cohort60/source_meal.json` — v18 과 같다 |
| 대조 | **v18 의 v25 팔 그대로.** 다시 돌리지 않는다 |
| 실행 | 계획까지. 주 지표는 계획에서 나온다 |

### 출발점 (v18 의 v25)

```
집 체류 차이 (계획 − 부여)   평균 +5.6h · 중앙값 +4.5h
2시간 초과 칸                427 / 480  (89%)
zone 사건 비율               v3~v18 내내 0.105 ~ 0.127
```

### 판정 — 주 지표는 집 체류 차이

| | 기준 |
|---|---|
| **성공** | 평균 차이가 **+3.0h 이하**로 줄고(현재 +5.6h), 2시간 초과 칸이 **70% 이하**로 |
| **부분** | 줄었으나 위 선에 못 미침 |
| **실패** | 차이가 그대로이거나 늘어남 |

**성공을 취소하는 조건**

| | |
|---|---|
| 빈 외출 | 집 체류가 줄었는데 **구매가 안 늘면** 나가기만 한 것이다. 칸당 구매를 함께 본다 |
| 칸 채우기 | 계획당 사건 수가 뚜렷이 늘면 빗장이 깨진 것이다 |
| 과잉 교정 | 부여값보다 **적게** 집에 있는 칸이 크게 늘면 반대로 민 것이다. 절댓값 차이로도 본다 |
| 계약 파손 | 계획 유효가 480/480 아래로 |

### 왜 이번엔 잴 힘이 있나

```
지금까지의 주 지표      구매 20~100건짜리 비율 → 구간이 [-100, +300]
이번 주 지표            480칸의 시간 차이 · 평균 +5.6h · 89%가 2h 초과
```

**표본이 칸 단위이고 신호가 크다.** 부호가 정해지지 않아 열여덟 라운드를 끌어온
정답지 지표와 달리, 이 지표는 처음부터 분명하다.

### 이 실험이 답하지 않는 것

- **정답에 수렴하는가** — 집 체류를 맞추는 것은 내부 일관성이지 정책 효과가 아니다
- 집을 덜 지키면 정답지 지표가 정해지는가 — **모른다.** 그건 다음 물음이다

## 결과

**계획 480칸 전부 유효. 그리고 완전히 평평하다.**

```
                        대조(v25)     v35        성공선
부여된 평일 집 체류       12.1h        12.1h
계획이 낸 집 체류         17.7h        17.7h
차이 (계획 − 부여)        +5.6h        +5.6h      ≤ +3.0h
2h 넘게 초과한 칸         427/480      424/480    ≤ 70%
                          (89%)        (88%)
계획당 사건 수            9.01         9.12
```

**사전등록 판정: 기각.** 두 선 어느 쪽도 넘지 못했다. 취소 조건은 하나도 걸리지
않았다 — 칸 채우기도, 과잉 교정도, 계약 파손도 없다. 그냥 아무 일도 일어나지 않았다.

### 그런데 이 기각은 후보의 기각이 아니다

결과를 적으려고 격차가 어디에 몰려 있는지 갈라 보다가 목표 자체가 무너졌다.

**첫째, 직장은 제대로 배치되고 있었다.** 근무가 들어간 칸에서는 평균 8.9시간이다.
480칸 중 58%만 근무가 있는데, 그건 이 코호트의 42%가 무직·은퇴·주부·학생이기 때문이다.

**둘째, 부여값을 사람의 직업으로 가르면 이렇다.**

```
직업 있음 (296칸)   부여 집 체류 11.1h
직업 없음 (184칸)   부여 집 체류 13.6h
                    ────────────────
                    차이 2.5h
```

전업 근로자와 무직·은퇴자가 **2.5시간밖에 차이 나지 않는다.** 수면을 포함한 진짜
체류 시간이라면 8시간 가까이 벌어져야 한다. 같은 사람 안에서도 70대 은퇴자의
주말 집 체류가 9.7h 다.

원천은 KT 텔레콤의 `tel_home_wd_time` 이고, 우리 계산기는 첫 항목 이전과 마지막
항목 이후를 전부 집으로 쳐서 **밤 9시간을 자동으로 더한다.**

**한쪽은 24시간 분할이고 다른 쪽은 아니다. 이 비교는 처음부터 성립하지 않았다.**
자세한 것은 [HOME_HOURS_IS_NOT_DWELL.md](../HOME_HOURS_IS_NOT_DWELL.md) 에 적었다.

> 위의 "왜 이번엔 잴 힘이 있나"가 틀린 이유가 이것이다. 신호는 컸지만
> **그 신호가 무엇의 신호인지**를 확인하지 않았다. DS-1 에서 실측이 매장 취식을
> 재는데 우리 식사 칸의 95%가 배달이었던 것과 같은 종류의 어긋남이다.

### 살아남는 것 — 정의가 분명한 결함 하나

같은 측정에서, 부여값과 무관하게 판정할 수 있는 것이 하나 나왔다.

```
직업 있음 · 계획에 근무 있음   272칸
직업 있음 · 계획에 근무 없음    24칸   ← 8%
```

**직업이 있는 사람의 평일 계획 296칸 중 24칸에 근무가 통째로 빠져 있다.**
평일이고, 그 사람에게 직장이 있고, 계획에 직장이 없다. 창이나 정의의 문제가 아니다.
v21 의 부 지표로 기록한다.

### 카탈로그는 범인이 아니었다

```
walk · outdoor_leisure · library · meal_dine_in · cafe_dine_in · groceries ...
                                            전부 60명 / 60명 에게 있다
```

집 밖 활동은 전원에게 열려 있고, 실제로 무직자 계획에 `walk` 가 2시간짜리 덩어리로
들어간다. **못 고르는 것이 아니라 고르지 않는 것**이므로, 구조가 막고 있다는 설명은
여기서 배제된다.
