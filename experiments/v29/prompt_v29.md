## 왜 이 라운드인가

[COUPLING_IS_THE_CEILING.md](../COUPLING_IS_THE_CEILING.md) 가 어제 계획한 다음 단계를
돌리기 전에 기각했다. "볼일을 자원에 건다"는 이미 돌아가 있었고 그 값이 11.5% 였다.

같은 문서가 진짜 병목을 지목한다.

```
DS-1 이 4건·2건 위에 서 있던 이유

  수행률이 낮아서가 아니다        11% 는 자원에 걸린 볼일의 정상값이다
  식사 볼일을 받은 사람이 적어서다  60명 중 21명 · 팔당 21칸 · 21 x 11% = 2건
```

**그러므로 이 라운드는 비율을 올리려 하지 않는다. 분모만 키운다.**

## 무엇을 바꾸는가 — 셋뿐이다

| | v27 | v29 |
|---|---|---|
| 볼일 업종 | 그 시민이 가장 많이 쓰는 업종 | **전원 `meal_dine_in` 지정** |
| 시나리오 | 네 개 (480칸) | **거리두기 하나** (240칸) |
| 계획 복제 | 1회 | **2회** (씨앗 2개, 240 x 2 = 480칸) |

**프롬프트는 v25 그대로다.** 한 글자도 안 고친다. v36~v39 넷이 기각됐고
[THE_TEN_PERCENT_CEILING.md](../THE_TEN_PERCENT_CEILING.md) 가 문장으로는 안 움직인다는
것을 보였으므로, 이 라운드는 프롬프트를 후보로 올리지 않는다.

**볼일은 선택으로 준다.** v28 은 `required_activities` 에 넣었고 문법이 강제해서
"갈 것인가"라는 물음 자체가 사라졌다(양 팔 100%/100%). 같은 실수를 반복하지 않는다.

## 이것이 유도인가 — 미리 따진다

| 물음 | 답 |
|---|---|
| 정책 효과의 방향을 지시하는가 | **아니다.** 볼일 문장은 양 팔에 글자까지 동일하다 |
| 실측 수치·공식이 프롬프트에 들어가는가 | **아니다.** v25 를 그대로 쓴다 |
| 업종 선택 규칙이 바뀌는가 | **그렇다.** "관측된 최대 업종" → "전원 동일 지정" |

세 번째는 숨길 것이 아니라 적을 것이다. 출처 파일에 `forced_activity: meal_dine_in`,
`rule: "Assigned uniformly, not read from the citizen's own mix"` 로 박힌다.
**본인 지출에 식사가 0%인 시민도 그 값 그대로 기록된다.**

> 지정이 만들 수 있는 것은 **분모**이고, 만들 수 없는 것은 **방향**이다.
> 양 팔이 같은 볼일을 받으므로, 거리두기 팔에서 그것을 포기하는지 아닌지는
> 전적으로 모델이 정한다. DS-1 이 재는 것이 바로 그것이다.

## 합격선 — 결과를 보기 전에 정한다

**0. 분모 관문 (먼저 통과해야 나머지를 읽는다)**

```
무정책 팔 매장취식 건수 >= 20건 (복제 2회 합산)
```

미달이면 **DS-1 판정을 적지 않는다.** "분모 미달"로 끝내고, 이 라운드는
지정이 분모를 못 만든다는 결과로 기록한다.

기대값은 179칸 x 9.5% x 2복제 ~ 34건이다. 9.5% 는 v27 의 거리두기 무정책 팔에서
매장식사 볼일을 실제로 수행한 비율(2/21)이다.

**이 관문은 지난 네 라운드를 전부 막는다.** 같은 자로 재 보면 이렇다.

```
        매장·포장 무정책 팔    기여 시민
  v18        1건                2명
  v20        0건                0명
  v23        4건                5명
  v27        2건                3명
```

**1. 주 지표**

```
매장취식 금액의 정책 전후 변화 — 시민 군집 짝지은 붓스트랩 구간이 0을 제외한다
```

**2. 반드시 함께 적는 것 — 두 정의를 나란히**

실측 `음식점` 이 배달을 포함하는지 아직 확인 못 했다
([DS1_SIGN_MATCHES_WHEN_ALIGNED.md](../DS1_SIGN_MATCHES_WHEN_ALIGNED.md)).
그래서 **한 정의를 골라 적지 않고 둘 다 적는다.**

```
DS-1 (매장·포장만)    시뮬 ___   vs 실측 -14.1
DS-1 (배달 포함 전체)  시뮬 ___   vs 실측 -14.1
```

## 이 라운드가 합격해도 말할 수 없는 것

**크기가 맞았다는 말은 이 라운드의 합격선이 아니다.** 정렬이 확정되기 전에는
어느 정의가 실측과 짝인지 모르고, 짝을 모르면 크기 비교는 의미가 없다.

```
이 라운드가 줄 수 있는 것   분모. 그리고 그 위에서 부호가 재현되는지
이 라운드가 못 주는 것      크기 일치 판정. 정렬 확인이 먼저다
```

부호가 맞고 구간이 0을 제외해도, 보고서에는 **"정답지 하나의 부호를 두 복제에서
재현했다"**까지만 적는다.

## 실패로 적을 것

- 무정책 팔 매장취식 20건 미만 → **분모 미달.** 지정으로도 분모가 안 만들어진다
- 구간이 0을 지남 → **미정.** 분모는 생겼으나 효과가 안 갈린다
- 두 복제의 부호가 갈림 → **재현 실패.** v18 에서 한 번 겪은 자리다
