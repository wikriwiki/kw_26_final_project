## 한 줄로

LLM 에이전트 1만여 명에게 서울의 하루를 살게 하고, **거기에 실제 정책을 넣었을 때
현실에서 관측된 것과 같은 방향·같은 크기로 소비가 움직이는지**를 잰다.
그 답을 가장 잘 맞히는 **프롬프트를 찾는 것**이 이 폴더의 일이다.

```
에이전트가 하루 계획을 짠다  →  그 계획대로 소비한다  →  정책을 켜고 다시 돌린다
                                                        ↓
                                        정책 있을 때와 없을 때의 차이
                                                        ↓
                                    실제 연구가 측정한 값과 맞는가?
```

## 무엇을 채점하는가 — 정책 여섯과 정답지

각 정책의 **원문·정답지·대조지표**는 [`data/policy_raw_data/`](../data/policy_raw_data/)
에 정책별 폴더로 정리돼 있다. 아래는 그 요약이다.

| 정책 | 무엇 | 정답지 | 기전 |
|---|---|---|---|
| **P010** 민생회복 소비쿠폰 | 2025 전 국민 15~45만원 | 한국은행 이슈노트 2026-13 | 지갑 |
| **P012** 상생소비지원금 | 2021 카드 실적 캐시백 | 기획재정부·KDI (2022.9) | 실적 환급 |
| **P013** 긴급재난지원금 | 2020 1차 전 국민 지급 | KDI FOCUS 281호 | 지갑 |
| **P014** 지역사랑상품권 | 할인 구매 상품권 | 조세재정연구원 (2020) | 가격 할인 |
| **P015** 8대 소비쿠폰 | 2020 업종별 할인·환급 | **봉인** (홀드아웃) | 할인 |
| **거리두기** | 2020-11 수도권 2단계 | 서울연구원 정책리포트 322호 | 사회 배경 |

**기전이 다르면 기대도 다르다.** 지갑(P010·P013)은 새 돈이 들어오니 총액이 늘어야
하고, 할인(P014)은 총액이 아니라 **어디서 쓰는가**가 움직여야 한다. 프롬프트가
"정책 = 돈 더 씀" 으로 뭉뚱그리면 이 차이에서 틀린다.

> **실측값은 프롬프트에 들어가지 않는다.** 방향도 크기도 모델에게 주지 않으며,
> 금지어 단위 테스트가 그것을 고정한다. 정답지 수치는 채점에만 쓴다.

## 검증은 세 층이고, 건너뛸 수 없다

```
A층  파이프라인이 온전한가      계약·게이트·회계·물리 독립 감사
B층  프롬프트를 가를 수 있는가   후보 간 사전등록 비교
C층  실측 정답에 수렴하는가      정답지 대조
```

A 가 깨지면 B 의 수치가 무의미하고, B 가 못 가르면 C 에서 어떤 프롬프트를 쓸지
고를 수 없다. **지금 위치는 이렇다.**

| 층 | 상태 |
|---|---|
| **A** 파이프라인 | **검증됐다.** 계약·게이트·회계 감사 통과 |
| **B** 프롬프트 분별 | **가를 수 있게 됐다.** v5 → v45 에서 형식 준수 +20.6%p (p<0.000001) |
| **C** 정답지 수렴 | **진행 중.** v50 이 v45 를 정답지에 대고 처음 재는 중 |

**크기 검증은 아직 성립하지 않았다.** 감사 주석(`MAGNITUDE_CRITERION.audit_2026_09_20`)
이 대상·기간·결과·분모·대조군이 호환될 때만 배수를 비교하라고 못 박았다.
지금 채점은 **부호**로 한다.

## 프롬프트 계보 — 어디까지 확정됐나

```
v5   ─── 1차 확정판 (홀드아웃까지 마친 것)
 │
 ├─ v40  캐시백 오염 제거          거리두기 입력에 들어가던 캐시백 문장을 걷었다
 ├─ v42  형식 결함 다섯 고침        집·직장의 끼니 31건, 출퇴근 24건, 'reason' 오타 23건 …
 └─ v45  지갑형 어휘 제거          쿠폰·바우처·정책 잔액 → 기전 중립 표현
      │
      ├─ v46·v47   기각 (유의하게 나빠졌다)
      ├─ v48·v49   미정 (재현되지 않았다)
      └─ v51·v52   ← 지금 사전등록됨
```

**확정된 것** — v5 → v45 는 형식 계약 통과를 이만큼 올렸다.

```
v5   261/384   68.0%
v45  340/384   88.6%   (세 번 측정 평균 356 · 326 · 339)
개선 109 · 악화 14 · 순증 +95칸 · p < 0.000001
```

**확정되지 않은 것** — 등록된 95% 관문(365/384)은 못 넘었다. 다만 그리스디
(temperature 0)로 재면 v45 는 **361/384 = 94.0%** 이고, 관문까지의 25칸 중
**21칸이 샘플러이고 4칸이 프롬프트**다. 자세한 것은
[GREEDY_SPLITS_THE_RESIDUAL.md](GREEDY_SPLITS_THE_RESIDUAL.md).

## 이 실험의 어려운 점 — 라운드마다 배운 것

**① 자기모순의 존재가 고침의 정당성을 보증하지 않는다.** 넷을 찾아 넷 다 고쳤는데
앞의 둘이 +95칸, 뒤의 둘이 −17칸을 냈다.

**② 규칙보다 예시가 세다.** 예시를 없앤 후보는 66.7% → 7.3% 로 무너졌고, 예시를
시각순으로 정렬한 후보는 간격 위반을 세 배로 만들었다.

**③ 검출력을 먼저 재야 한다.** 192칸에서 "조금 나아졌다"로 보인 것이 384칸에서
"유의하게 나빠졌다"였다.

**④ 런 자체가 요인이다.** 같은 프롬프트가 런마다 30칸(관문)·13.1%p(거시 지표)
움직인다. 그보다 작은 차이는 읽을 수 없다.
[v50/v5_replication.md](v50/v5_replication.md)

## 폴더 읽는 법

```
vN/prompt_vN.md    사전등록 — 설계·지표·합격선. **실행 전에 커밋한다**
vN/result_vN.md    결과 — 등록한 합격선에 대고 판정한 것
vN/graph_vN.md     정책별 결과 그래프와 수치표
```

**폴더 번호와 프롬프트 번호는 다르다.** 폴더 `v1` 은 첫 번째 실험이지 프롬프트 v1 이
아니다. 각 폴더 머리에 그때 쓴 프롬프트 이름이 따로 적혀 있다.

수치는 전부 [`data/experiments/scoring_table.json`](../data/experiments/scoring_table.json)
과 각 런의 원문에서 온다. 손으로 적지 않는다.

## 후보를 라운드에 걸기 전에 — 탐침

전체 라운드는 12일 × 200명 × 두 팔이다. **무력한 후보를 그렇게 태우지 않는다.**
동결된 맥락에서 그 한 줄만 넣고 빼 같은 시민을 두 번 부른다(48 호출).

```
scripts/sim/scope_fact_probe.py    후보를 CANDIDATES 에 자료로 등록해 돌린다
```

**판정은 쌍별 부호 검정이다.** "계획이 달라졌나"(changed)는 관문이 못 된다 —
temperature 0.7 에서는 아무 줄이나 끼워도 토큰 경로가 갈려 계획이 달라진다.
동점 수를 반드시 함께 읽는다(24쌍이 사실 11쌍일 수 있다).

## 지키는 규칙

- **사전등록을 실행 전에 커밋한다.** 커밋 시각이 증거다
- **결과를 보고 그 결과를 막는 문장을 쓰지 않는다** (순환 검증 금지)
- **정답지의 수치·방향을 프롬프트에 넣지 않는다.** 단위 테스트가 고정한다
- **홀드아웃(P015)은 한 번만 쓴다.** 이미 썼으므로 다시 열지 않는다
- **못 잰 것은 '못 쟀다'고 적는다.** 검출력 부족과 "효과가 없다"는 다른 말이다
- **읽을 런은 가장 큰 표본으로 고른다.** 규칙이 정책마다 다르면 유리한 런을 고르게 된다
- **채점 창은 정책 시행일을 사이에 두어야 한다.** 전수 시험이 지킨다
  (`tests/unit/report/test_every_window_straddles_its_policy.py`)
- **다른 자로 잰 값은 세지 않는다.** 지우지 않고 '못 셈' 으로 남겨 이유를 보인다
