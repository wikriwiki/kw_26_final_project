# 실험 v17 — 같은 비교를 네 seed 로

**날짜 2026-09-21** · **상태** 완료 — **무효. 네 seed 로도 못 가른다**

---

## v16 이 무효였던 이유

기준선은 고쳤다(세제 77% → 22%, 구성 거리 0.80 → 0.48). 그런데도
**아홉 지표 전부 구간이 0을 지났다.**

이유는 분모다.

```
v16   후보당 seed 1개 · 조립 74~76칸 · 구매 17~28건
```

**구매 스무 건 남짓으로 비율을 내면 구간이 그렇게 넓다.**
그리고 블록이 하나뿐이라 **블록 붓스트랩을 쓸 수 없었다** — 칸만 재추출했고,
그 구간이 실제보다 좁다는 것은 이미 확인한 바 있다(v7 철회).

## 무엇을 바꾸나 — 프롬프트는 안 바꾼다

```
후보      v25 · v34        v16 과 같다. 새 후보 없음
seed      1개 → 4개        69001 ~ 69004
수정 바퀴  4 → 3           v14 에서 4바퀴는 4칸만 줄였다. 비용은 3바퀴와 같다
구간       칸 붓스트랩 → 블록 붓스트랩 (블록 4개)
```

**표본만 늘린다.** 이것이 [NOISE_AND_POWER.md](../NOISE_AND_POWER.md) 가 처음부터
말하던 것이고, 열여섯 라운드를 거쳐 그것 말고는 남은 것이 없다는 것을 확인했다.

## 사전등록

| | 내용 |
|---|---|
| 설계 | 96칸 × seed 4 = 계획 384칸, 후보 둘 |
| 원본 | `action_source_meal.json` (끼니 필요 포함) |
| 실행 | 계획 → seed 마다 [게이트 → 수정 3바퀴 → 조립 → 결제] |
| 구간 | **블록(seed) 을 먼저 재추출하고 그 안에서 칸을 재추출** |

### 판정

| | 기준 |
|---|---|
| **v34 채택** | 부호를 말할 수 있는 지표가 v25 보다 많고, **부호 반대가 늘지 않는다** |
| **v25 유지** | 그렇지 않다 |
| **무효** | 네 seed 로도 어느 쪽도 부호를 말할 수 없다 |

**무효가 나오면 그대로 적는다.** 그때 남는 결론은 **"열두 명으로는 이 지표들을
가릴 수 없다"** 이고, 그것은 프롬프트가 아니라 **명단 크기**의 문제다.

### 부 지표

구성 거리(사람별) · 게이트 막힘(수정 전, seed별) · 칸당 구매 · 안 산 업종 수.

### 이 실험이 답하지 않는 것

- **실측 크기와 맞는가** — 부호가 정해져도 크기는 별개다
  ([ESTIMAND_ALIGNMENT.md](../ESTIMAND_ALIGNMENT.md))
- 모집단 일반화 — 열두 명이다. seed 를 늘려도 **이 열두 명에 대한 정밀도**다
- 집 밖 행동 — v15 에서 무엇으로도 안 움직였다

## 그래서 남는 결론

사전등록에 미리 적어 둔 그대로다.

> **열두 명으로는 이 지표들을 가릴 수 없다.**

이것은 프롬프트가 아니라 **명단 크기**의 문제다. 칸을 네 배 늘려도 안 되는 이유는
**구매 건수**가 늘어난 것이 아니라 **사람이 그대로**이기 때문이다 —
seed 를 늘리면 같은 열두 명을 다시 뽑을 뿐이다.

[NOISE_AND_POWER.md](../NOISE_AND_POWER.md) 가 계산해 둔 값이 이것이다.

```
한 기전의 on/off 차이를 80% 검정력으로 보려면
   3,000원   53명
   1,000원  476명
후보 둘의 차이를 보려면  3,000원  후보당 106명
```

**열두 명은 그 어느 선에도 못 미친다.**
