## 이 라운드는 채점표가 지정한 실험이다

`scoring_table.json` 의 `MAGNITUDE_CRITERION` 이 남은 과제를 하나로 좁혀 두었다.

```
P012 적립업종   0.49배 (실측 +20.82% · 우리 +10.1%)
적힌 원인       창 길이 — KDI 는 한 달, 우리는 정책 2일
적힌 처방       워밍업 3일 + 무정책 7일 + 정책 14~21일. 프롬프트는 v5 그대로
적힌 주의       "창이 길어지면 배수가 1 쪽으로 움직일 것"을 먼저 등록하고 돌려라
```

> ### 감사 주석이 이 라운드의 격을 정한다
>
> 같은 파일의 `audit_2026_09_20` 이 역사적 판정보다 **우선한다**고 명시한다.
>
> ```
> status            "magnitude validation not established"
> horizon_mismatch  2일과 한 달의 크기 차이를 기간 때문이라고 단정하지 않는다.
>                   대상·기간·결과·분모·대조군이 호환될 때만 배수 비교한다
> outcome_mismatch  전체 카드매출과 INCLUDES 기반 방문 지출은 같은 결과가 아니다
> ```
>
> 그러므로 **이 라운드는 검증이 아니라 가설 시험이다.** 창을 늘렸을 때 값이
> 어느 방향으로 얼마나 움직이는지를 잰다. 배수가 대역에 들어와도
> **"크기가 검증됐다"고 적지 않는다** — 호환표가 아직 안 채워져 있다.

**그 처방을 그대로 돌리면 엉뚱한 이유로 실패한다는 것을 먼저 확인했다.**
[THE_PURSE_RUNS_DRY.md](../THE_PURSE_RUNS_DRY.md) — 소득이 없어 28일이면 3분의 2가
빈털터리가 된다. 그래서 이 라운드는 **소득을 켜고** 돈다.

무정책 7일과 정책 21일이 **둘 다 온전한 주**다. 요일이 어긋나면 주말/평일 소비비
1.47배가 정책 효과를 덮는다 — 1단계에서 실제로 덮었다.

**두 번 돈다.** 같은 창에 정책을 안 실은 런을 함께 돌려 표류를 뺀다
(result_FINAL 이 `PLACEBO_TIMING` 으로 한 것과 같다). 21일 창에서는 표류가
2일 창보다 훨씬 크게 쌓이므로 이 대조가 없으면 아무것도 못 읽는다.

## 합격선 — 결과를 보기 전에 정한다

**0. 지갑 관문 (먼저 통과해야 나머지를 읽는다)**

```
정책 구간 마지막 날(11-14) 잔고 0 인 사람 < 20%
```

넘으면 **소득이 부족했던 것**이고, 이 라운드는 순효과 판정을 적지 않는다.
소득 없는 28일 런에서는 이 값이 67% 였다.

**1. 주 지표 — 배수의 '변화'이지 배수의 '값'이 아니다**

```
P012-1 순효과가 2일 창의 +11.5%p 보다 커진다
동시에 개인 내 쌍체차 CI 가 0 을 제외한다
```

배수(순효과 ÷ 20.82)는 **참고로 적되 합격 판정에 쓰지 않는다.** 감사 주석이
호환성 확인 전에는 나누지 말라고 했다. 이 라운드가 답하는 물음은
**"창을 늘리면 값이 커지는가"**이고, 그 답은 배수 없이도 나온다.

**함께 반드시 적을 것 — 호환표**

```
           KDI (2022.9)                    우리 (v30)
대상       카드 사용 성인                    200 에이전트
기간       2021-10 한 달                    정책 21일
결과       적립업종 카드매출                  elig_spend_paired (방문 기반)
분모       (원문 확인 필요)                  무정책 7일 창
대조군     (원문 확인 필요)                  같은 창 무정책 런
```

**빈칸이 있는 한 배수는 참고값이다.** 채워지면 그때 비교한다.

**2. 방어선 — 함께 봐야 한다**

```
P012-2 제외업종이 움직이지 않아야 한다 (실측 +2.85%, 유의 안 섬)
```

적립업종만 오르고 제외업종이 가만히 있어야 "정책에 반응했다"이고,
둘 다 오르면 그냥 돈이 많아진 것이다. **소득을 켠 라운드에서는 이 방어선이
평소보다 중요하다.**

## 실패로 적을 것 — 미리 적어 둔다

| 결과 | 무엇으로 적는가 |
|---|---|
| 순효과가 2일 창보다 크지 않다 | **창 길이가 원인이 아니었다.** 채점표의 진단이 틀린 것이고 그것도 결과다 |
| 잔고 0 이 20% 를 넘는다 | 소득이 부족했다. 순효과는 읽지 않는다 |
| 적립·제외가 함께 오른다 | 소득이 정책 효과를 흉내 냈다. **이 라운드를 폐기한다** |
| 순효과가 실측을 크게 웃돈다 | 위쪽으로 벗어난 것도 실패다. 소득이 민 것인지 먼저 본다 |

## 유도가 아닌 이유

| 물음 | 답 |
|---|---|
| 프롬프트를 고치는가 | **아니다.** v5 그대로다. 이 라운드에 후보는 없다 |
| 실측 수치가 모델에 들어가는가 | **아니다.** 배수 대역은 채점 기준이고 모델 입력이 아니다 |
| 소득이 결과 쪽으로 미는가 | 양쪽 런에 똑같이 켠다. 정책 런과 대조 런이 같은 소득을 받는다 |

소득은 **없는 쪽이 가정이었다.** 사람은 번다. 없애 둔 것을 되돌리는 것이지
결과를 향해 손대는 것이 아니다.

> 다만 소득이 **캐시백 지표를 위쪽으로 밀 수 있다**는 것은 인정하고 시작한다.
> 쓸 돈이 많으면 문턱(2분기 월평균 대비 103%)을 넘기 쉽다. 그래서 대조 런을
> 같은 소득으로 돌리고, 방어선 지표(제외업종)를 합격 조건에 넣는다.
