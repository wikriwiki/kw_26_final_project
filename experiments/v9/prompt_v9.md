# 실험 v9 — 프롬프트를 동결하고 필요 모형을 바꾼다

**날짜 2026-09-21** · **상태** 완료 — **필요를 줬더니 계획이 물리적으로 불가능해졌다**

---

## 왜 프롬프트를 건드리지 않나

여덟 라운드에서 프롬프트 축을 여덟 번 바꿨고 전부 움직이지 않았다.
이유를 찾았다 — [WHY_PROMPTS_CANNOT_MOVE_THIS.md](../WHY_PROMPTS_CANNOT_MOVE_THIS.md).

**96칸 전부가 필요를 딱 하나 가진다.** `laundry` 이고, 자원은 세제 하나이며,
**온라인 주문으로 집에서 충족된다.** 입력의 가정문이 직접 말한다 —
"다른 물품·식재료·열량·가사 전체의 재고는 아직 모델링하지 않는다."

그리고 `home_meal` 은 **채널도 자원 소비도 없다. 집밥이 공짜다.**

```
활동 사전 26개 중 자원이 걸린 것    provided_laundry 하나
home_meal                        purchase_channel None · 소비 자원 없음
```

**프롬프트는 있는 필요를 어떻게 다룰지를 바꿀 뿐 없는 필요를 만들 수 없다.**
만들라고 적으면 유도이고, 프롬프트 자신이 "없는 의무·부족을 만들지 않는다"를 금지한다.

## 무엇을 바꾸나 — 세탁과 똑같은 구조를 끼니에

```
meal_stock        집에 있는 끼니 수        (시민 index 홀짝으로 0 / 2 — 세제와 같은 규칙)
home_meal         이제 한 끼분을 쓴다
quote:groceries   세 끼분을 채운다 (같은 자리에서 바로)
needs[meals]      집에서 들 수도, 밖에서 들 수도 있다. desired_count 2, 선택적
```

끼니 선택지는 **그 칸의 활동 사전이 정한다** — `home_meal` · `home_delivery` ·
`meal_dine_in` · `meal_takeaway`. 직장이 있으면 직장 선택지도 함께 들어간다.

> **순환이 아닌 근거** — 재고는 세제와 같은 규칙(홀짝 0/2)으로 정했고,
> 정답지가 재는 업종을 보고 고른 것이 하나도 없다. 검사로 막았다
> (`test_no_answer_key_sector_is_singled_out`). "음식점을 사라"가 아니라
> **"끼니를 든다"** 이고, 어디서 들지는 모델이 고른다.

## 사전등록

| | 내용 |
|---|---|
| 설계 | 같은 12명 × 4기전 × on/off = 96칸, seed 4개(65001~65004), 두 팔 = 계획 768칸 |
| **프롬프트** | **양쪽 모두 v25. 한 글자도 다르지 않다** |
| 다른 것 | 필요 모형 하나뿐. 계약·게이트·seed·결제 프롬프트 전부 동일 |
| 결제 | 네 seed 모두 |

### 출발점 (v8 의 v25, 192칸 무정책 팔)

```
meal_dine_in          1 건        ← 주 지표
zone 사건 비율         0.105       ← 여섯 라운드 고정
총 구매               69 건 · 그중 온라인 세제 45 건 (65%)
한 번도 안 산 업종      건강·교육·기타·디저트·미용·여가·주점 (11개 중 7개)
```

### 판정

**주 지표 — 무정책 팔의 `meal_dine_in` 건수**

| | 기준 |
|---|---|
| **성공** | 매장 취식이 **20건 이상** (192칸 기준). 거리두기가 누를 대상이 생긴다 |
| **부분** | 1건 초과 20건 미만 — 생기긴 했으나 제약이 물리기엔 얇다 |
| **실패** | 여전히 한 자릿수. 필요를 줘도 집에서 해결한다 |

20건은 **거리두기 제한이 통계적으로 물릴 최소치**로 잡았다. 실측 −14.1% 를
±5%p 로 가르려면 대략 그 정도 분모가 필요하다. 정답지의 **값**이 아니라
**분모 요구량**에서 나온 수이므로 순환이 아니다.

**부 지표**

| | |
|---|---|
| zone 사건 비율 | 0.105 에서 올라가는가. 판정선 ±0.03 (v6 이 세운 경계) |
| 구성 거리 | **사람별 평균**으로 본다(합산은 v8 에서 불안정했다). 부여된 구성에 가까워지는가 |
| 안 산 업종 수 | 7개에서 줄어드는가 |

**성공을 취소하는 조건**

| | |
|---|---|
| 과잉 소비 | 구성 거리가 **멀어지면** 필요를 준 것이 아니라 지출을 부풀린 것이다 |
| 세제 쏠림 유지 | 총 구매만 늘고 세제 비중이 그대로면 끼니가 아니라 양만 는 것이다 |

### 17개 지표는 보고만 한다

**이번 라운드는 프롬프트를 고르지 않는다.** 양쪽이 같은 프롬프트다.
정답지 지표는 **"이제 잴 수 있게 되었는가"** 를 보려고 싣는다.
DS-1·DS-4 가 미결에서 벗어나는지가 관심사이지, 그것이 성공 조건은 아니다.

### 이 실험이 답하지 않는 것

- **최적 프롬프트** — 프롬프트를 안 건드린다. 이 라운드는 **프롬프트를 고를 수 있게
  만드는 것**이 목적이다. 성공하면 v10 에서 다시 프롬프트를 겨룬다
- 필요가 생기면 정답에 수렴한다 — 모른다. **잴 수 있게 되는 것**과 **맞는 것**은 다르다
- 끼니 외의 업종 — 건강·미용·여가는 여전히 필요가 없다. 한 번에 하나씩 본다

## 결과 — 게이트가 절반을 막았다. 그리고 그것이 답이다

두 팔 모두 계획 **384/384 유효**. 그런데 결제 단계에서 갈렸다.

```
자원 게이트 (계획 → 결제 사이, 모델 호출 전)
        seed65001  65002  65003  65004
laundry      0      0      0      1     ← 대조
meal        46     46     45     45     ← 처치, 96칸 중
```

**막힌 46칸이 전부 `meal_stock` 0 인 시민이다** (그 시민들의 48칸 중 46칸).
재고 2인 시민은 48칸 전부 통과했다.

### 왜 불가능한가

```
예시 (재고 0)
  08:00 home_prepare · 09:00 수업 · 15:00 walk
  16:00 home_meal   ← 재고 0, 필요 1
  17:00 home_leisure · 18:00 home_chores
  19:00 home_meal   ← 재고 −1, 필요 1
  20:00 home_sleep
```

**식재료가 0인데 집밥을 두 끼 계획했다.** 장보기도, 외식도, 배달도 넣지 않았다.

전체로 봐도 같다.

```
meal 팔 계획의 끼니 활동 (seed 65001)
  재고 0 인 시민   home_meal 102 · office_meal 11 · groceries 8 · meal_dine_in 4 · home_delivery 3
  재고 2 인 시민   home_meal  75 · office_meal 23 · groceries 1 · home_delivery 2
```

**재고 0인 시민이 재고 2인 시민보다 집밥을 더 계획한다**(102 대 75).
재고를 전혀 보지 않는다는 뜻이다.

### 그런데 프롬프트는 이미 그렇게 하라고 말하고 있다

```
v25:  daily_conditions가 있으면 활동에 필요한 자원을 실제 사용 전 확보할 수 있는지 확인한다.
```

**세제는 제대로 처리한다** — 온라인으로 주문한다. 끼니는 안 한다.
차이는 세탁이 `provided_laundry`(주입된 확정 활동)이고 끼니는 **모델이 자유롭게 고르는
보통 활동**이라는 점이다. 모델이 자원 검사를 **주어진 활동에만** 적용하고
**자기가 고른 활동에는 적용하지 않는다.**

### 사전등록한 판정

주 지표(`meal_dine_in` 20건 이상)는 **읽지 않는다.** 행렬이 불완전하기 때문이다 —
v1 에서 정한 규칙이고, 여기서 예외를 두면 게이트를 만든 의미가 없다.

참고로만 적으면 48칸에 4건이었다(기존 192칸에 1건). **비율로는 늘었으나
그 계획들이 물리적으로 불가능하다.**

### 그래서 이번 라운드의 진짜 결과

**필요를 주는 것만으로는 안 된다. 모델이 그 필요를 계획에서 존중해야 한다.**
그리고 그것은 **프롬프트가 닿는 곳**이다 — 이미 있는 지시를 지키지 않는 것이므로,
"정책 결과를 유도"하는 것이 아니라 **계약 준수**다.

**그리고 신호가 크다.** 막힌 칸 46 대 0 이다. 여덟 라운드 동안 잡음에 묻혀
아무것도 못 가르던 것과 다르다. **v10 은 이것을 겨냥한다.**
