# 프롬프트 후보 — 문턱을 **금액이 정해지는 자리**로 보낸다

**2026-09-24 08:10** · 사전등록 · 결과 보기 전

---

## 측정이 가리킨 자리

```
Stage2 계획액   +9.76%  p=0.0015   ← 정책에 반응한다
소비성향 스칼라   +0.34%  p=0.712    ← 안 한다
이벤트 수        -0.05%  p=1.000    ← 개수는 그대로
```

개수가 같은데 금액이 는다. **금액을 정하는 것은 Stage2 다**(`actual_spent`).
그런데 Stage2 가 정책에 대해 받는 것은 후보 목록의 `[적립]` 꼬리표 하나뿐이다.
문턱이 얼마고 얼마 남았는지는 **Stage1 에만** 있다.

```
Stage1 이 받는 것   "적립업종 이번달 누적 X원 / 3% 문턱 Z원 | 문턱까지 W원 남음
                     (이번 달 N일 남음 · 하루 평균 P원 페이스) | 못 넘기면 혜택 사라짐"
Stage2 가 받는 것   후보 줄의 "[적립]" 다섯 글자
```

Stage2 의 "소비액 설정" 절은 통째로 **지원금 지갑 회계**다 — 어느 지갑으로
낼지. 캐시백 정책에는 지갑이 없으므로 그 절 전체가 해당 없음이고, 대신 들어갈
것이 아무것도 없다.

## 후보

`EXP_S2_THRESHOLD=1` 이면 Stage2 페르소나 헤더에 **Stage1 이 이미 받은 그 줄**을
붙인다. 그리고 한 문장을 덧댄다.

```
(돌아오는 돈은 다음 달이므로 오늘 쓸 수 있는 돈이 는 것은 아니다.
 어차피 할 지출로 문턱이 저절로 넘어가는 사람도, 넘길 일이 없어
 신경 쓰지 않는 사람도 있다.)
```

**새 사실을 만들지 않는다.** Stage2 가 스스로 문턱을 계산하면 두 단계가 어긋날
수 있어, 계산은 Stage1 쪽 한 곳에서만 한다 — 시험이 그것을 막는다
(`threshold =`·`/ days_left` 같은 계산이 블록에 있으면 실패).

**방향을 지시하지 않는다.** 덧댄 문장은 오히려 **사실대로 김을 뺀다** —
캐시백은 오늘 돈을 늘려 주지 않는다. 그리고 반응하지 않는 사람이 있다는 것을
명시한다. 시험이 "더 써·늘리·권장" 류를 막는다.

## 왜 이것이 유도가 아닌가

정책이 있다는 사실과 문턱 수치는 **제도 자체의 공개 조건**이고 이미 Stage1 이
받고 있다. 우리가 하는 것은 **같은 사실을 판단이 일어나는 자리로 옮기는 것**
뿐이다. 정답지의 수치(+20.82% 등)도, 방향도 넣지 않는다.

## 예측과 판정

```
1차  Stage2 계획액의 정책 반응이 현행 +9.76% 보다 **커진다**
     쌍별 부호검정 · 양측 (반대로 줄 수도 있다 — 김을 빼는 문장이 들어 있다)
2차  그 반응이 총액을 거쳐 P012-1 로 나와야 한다.
     단 총액 통과는 EXP_PLAN_DRIVES_TOTAL 이 켜져 있어야 의미가 있다
판정 **총 오차가 줄어야 성공이다.** P012-1 만 좋아지고 다른 지표가 나빠지면 기각
```

## 무엇이 이 후보를 죽이나

```
· 탐침에서 계획액이 안 갈리면 -> 무효. 본런에 안 올린다
· 반응이 반대(감소)로 나오면 -> 김 빼는 문장이 과했다는 뜻. 그 문장만 빼고 재탐침
· P012-1 이 실측(+20.82%)을 **넘어서면** 과교정이다. 문장을 조이는 것이 아니라
  왜 넘쳤는지를 먼저 적는다 — 정답지에 맞춰 문구를 깎으면 끼워 맞추기다
```

## 순서

이 후보는 **혼자서는 반쪽이다.** 계획액이 더 움직여도 `max(앵커,계획)` 이
4분의 3을 버리면 총액에 안 나온다. 그래서 `EXP_PLAN_DRIVES_TOTAL`(회계)과
**함께** 켜는 것이 이 후보의 제자리다. 회계만 켜면 지금 있는 +9.76% 만
통과하고, 프롬프트만 켜면 늘어난 반응이 다시 버려진다.
