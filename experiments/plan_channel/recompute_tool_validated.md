## 검증 — 옛 읽기를 그대로 재현한다

`p013_out_of_sample.md` 에 적힌 수를 목표로 삼았다. 창은 **수가 말해 줬다**:
OFF 131,881 은 05-07(131,906)·05-08(131,855) 의 평균 131,880.5 이고,
ON 131,825 는 05-14(131,471)·05-15(132,179) 의 평균이다 — 둘 다 목·금이다.
기준선은 문서에 없어서 **내가 골랐다**(05-04~06 월·화·수).

```
                     옛 문서      이 도구      자
현행  −0.04%         131,825     131,825     incl_online   <- 딱 맞는다
현행  +0.32%         132,308      +0.32%     personal      <- 백분율이 딱 맞는다
고침  +9.03%         143,790     143,740     incl_online   (+8.99%)
```

**세 수가 다 맞는다.** 마지막 0.04%p 차이는 기준선 날짜를 내가 달리 고른 몫이다.

## 그런데 재현하면서 드러난 것 — 옛 문서는 **두 자를 섞었다**

```
131,881  은 incl_online (가게+배송 전부) 의 수다
+0.32%   는 personal (분리 뒤 가게 몫) 의 백분율이다
```

한 줄에 나란히 적혀 있었다. 그래서 "131,881 → 132,308" 이라는 조합은 **어느
런에도 없는 수**다. 같은 자로 읽으면 이렇다.

```
자              현행      고침      실측 EM-3 +7.30% 대비 오차
incl_online    −0.04%   +8.99%    **1.69%p**
personal       +0.32%   +9.11%      1.81%p
instore        −0.46%   +8.91%      1.61%p
```

**결론은 안 바뀐다** — 어느 자로 읽어도 현행은 0 근처고 고침은 +9% 언저리이며
실측 +7.30% 에 붙는다. 그러나 **현행의 부호는 자에 따라 갈린다**(−0.46 ~ +0.32%).
도구가 이제 셋을 함께 찍고, 부호가 갈리면 그렇다고 말한다.

## 도구가 스스로 막는 것

```
기준선이 비교 창과 겹치면      거부한다 (그 팔의 계획/기준선이 1 로 못 박힌다 = 순환)
클램프가 40% 넘게 물면         요일종류를 의심하라고 말한다
기준선 결손이 10% 넘으면       날짜를 늘리라고 말한다
SCALE                          무정책 창의 수준이 보존되도록 **푼다** (고를 여지 없음)
```

SCALE 을 푸는 것이 중요하다. 고침이 수준을 통째로 밀어 올리면 정책 효과와 구별이
안 된다. 조건 하나(무정책 창 수준 보존)에 미지수 하나라 값이 유일하게 정해지고,
**정답지를 보지 않는다.** 백분율은 SCALE 에 불변이다(분자·분모가 같이 곱해진다) —
그러니 SCALE 은 자유도가 아니라 읽기 편하라고 두는 눈금이다.

## 가장 중요한 단위시험

`test_앵커가_약분되지_않는다` — 기준선을 `REF × 앵커` 로 잡으면
`앵커 × 계획/(REF×앵커) = 계획/REF` 가 되어 **앵커가 사라진다.** 엔진 쪽에서 한 번
저지른 실수이고 다시 셈 쪽에서도 똑같이 저지를 수 있다. 계층이 다른 두 사람이 같은
반응을 보일 때 고침 총액의 비가 앵커의 비를 지키는지로 확인한다.

`test_섞인_요일_기준선이_클램프를_문다` — 금·토를 섞어 기준선을 세우면 평일 창의
비가 0.66 으로 내려앉는 것을 값으로 보인다. 평일만으로 세우면 1.00 이다.
