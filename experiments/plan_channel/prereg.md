# 사전등록 — 계획의 정책 반응을 총액에 통과시키면 오차가 주는가

**2026-09-24 07:30** · 본런은 아직 안 돌았다 · 근거 `../error_budget/diagnosis_05.md`

---

## 무엇을 바꾸나 — 회계 한 줄. **프롬프트는 v5 그대로.**

```
현재   total = max(anchor, planned)
고침   total = anchor x clamp(planned / 그 사람의 기준 계획액, 0.5, 2.0) x 0.88144
```

기준선은 **그 런의 워밍업 3일(10-18·19·20)** 에서 잰 개인별 평균 계획액이다.
**두 비교창(10-21·22 / 10-25·26) 밖**이라 비교를 오염시키지 않는다.

클램프와 SCALE 은 **정답지를 안 보고** 정했다 — 앵커와의 순위상관을 현행의
90% 이상 지키는 가장 넓은 구간이 [0.5, 2.0] 이고(92% 보존), SCALE 은 무정책
창의 총액 평균이 현행과 같아지게 하는 값이다.

## 왜 — 정책은 이미 닿고 있었다

라운드2 런(r2_v5)의 같은 에이전트 쌍을 맞대면

```
Stage2 계획액   69,839 -> 76,652   **+9.76%**  286:214  p=0.0015
소비성향 스칼라    0.70 ->   0.70       +0.34%  동점 140  p=0.712
총액            130,418 -> 133,512     +2.37%  동점 43   p=0.640
```

계획이 앵커를 이기는 경우가 **23.7%** 뿐이라 반응의 4분의 3 이 먹힌다
(0.237 x 9.76% = 2.31% ~ 관측 +2.37%). **기전이 산술로 닫힌다.**

## 미리 적는 예측

```
1차  P012-1 이 현행에서 **커진다.**
     같은 자료 재계산으로는 +2.37% -> +5.41%, 오차 18.45 -> **15.41%p** (-3.04%p)
     런에서 그만큼 나오리라는 보장은 없다 — 계획 자체가 다시 뽑히기 때문이다
2차  **총 오차가 줄어야 성공이다.** 이 고침은 모든 에이전트의 하루 총액을
     바꾸므로 EM-3·DS-1·DS-2 도 함께 움직인다. P012-1 만 좋아지고 나머지가
     그만큼 나빠지면 **기각한다**
3차  P012-2(새 눈금 n=500)·P012-5 값이 처음으로 나온다
```

## 무엇이 이 실험을 죽이나

```
· 관문에서 총액이 하나도 안 달라지면 -> 경로가 안 걸린 것. 본런 안 돌린다
· 관문에서 수준이 25% 넘게 흔들리면  -> 폭주. 본런 안 돌린다
· 총 오차가 안 줄면                  -> 기각. 회계를 되돌린다
· P012-1 이 오히려 **실측을 넘어서면**(+20.82% 초과) 과교정이다.
  클램프를 좁히는 것이 아니라 **왜 넘쳤는지**를 먼저 적는다 —
  정답지에 맞춰 클램프를 조이면 그때부터는 맞춘 것이 아니라 끼워 맞춘 것이다
```

## 순환이 아니다

바꾸는 것은 **회계**고 재는 것은 원장이다. 계획액은 에이전트 자신의 이벤트
산물이지 측정 공식이 아니다. 기준선은 정책 **전** 날짜에서만 잰다. 프롬프트는
한 글자도 안 바꾼다 — 그래서 이 런의 차이는 온전히 회계의 것이다.

## 이 다음이 프롬프트 최적화다

이 고침이 서면 **프롬프트 -> 이벤트 -> 계획액 -> 총액 -> 지표** 통로가 이어진다.
이벤트 채널은 프롬프트에 반응한다는 것이 두 번 측정됐다(문턱 격자에서 적립
이벤트 3.75 -> 4.67, 24% 변동 · 정책 반응 +9.76%). 스칼라 채널은 죽었지만
(`../split_anchor/calib_02.md`) **이 통로는 살아 있다.** 통로를 이어 놓고
프롬프트를 손대는 것이 순서다.
