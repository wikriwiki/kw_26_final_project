  1차 (v48 런)   개선 51 · 악화 31 · 순증 +20 · p=0.0352   유의
  2차 (재현)      개선 40 · 악화 36 · 순증  +4 · p=0.7310   검출력 부족
  합산 (768칸)    개선 91 · 악화 67 · 순증 +24 · p=0.0669   유의하지 않다

사전등록에 이렇게 적어 두었다.

> v49 replaces v45 as the incumbent **only if this run also puts it above v45 with an
> interval excluding zero.**

**둘째 런이 0 을 포함한다. 그러므로 v49 는 v45 를 대체하지 않는다.**

방향은 두 런에서 유지됐고(+20, +4) 합산도 +24 다. **버리지 않고 미정으로 남긴다** —
없다고 적을 근거도 없다.

## 왜 그 아래를 못 가리는가

**같은 프롬프트 v45 를 384칸으로 세 번 쟀다.**

```
v47 런   356/384   92.7%
v48 런   326/384   84.9%
v49 런   339/384   88.3%

평균 340.3 · 범위 30칸 · 표준편차 15.0칸
```

그리고 두 런 사이에서 **76칸이 뒤집혔고 그 이동 자체가 유의했다**(−30, p=0.0008).
**런이 하나의 요인이다.**

```
런 이동         30칸 (표준편차 15칸)
─────────────────────────────────
v5  → v45      +95칸   ← 런 이동의 3.2배. 읽힌다
v45 → v49      +24칸   ← 합산해도 런 이동 아래. 못 읽는다
v45 → v48       +9칸   못 읽는다
v45 → v47      −17칸   못 읽는다 (한 런의 관측)
```

**내가 계산한 최소검출차(384칸에서 21칸)는 런 안의 불일치에서 나온 값이고,
런 사이의 이동은 거기에 없었다.** 설계를 그만큼 낙관적으로 잡았다.

전부 **빼거나 고쳐 쓴 것**이고, 방향이나 수치를 더한 문장은 하나도 없다.

## 다섯 라운드에서 배운 것

**① 자기모순의 존재가 고침의 정당성을 보증하지 않는다.** 넷을 찾아 넷 다 고쳤는데
앞의 둘이 +95칸, 뒤의 둘이 −17칸을 냈다.

**② 규칙보다 예시가 세다.** v10 은 예시를 없애 66.7% → 7.3% 로 무너졌고, v47 은
예시를 시각순으로 정렬해 간격 위반을 세 배로 만들었다. 이 프롬프트에서 예시는
설명이 아니라 **본보기**다.

**③ 검출력을 먼저 재야 한다.** 192칸에서 "+4, 조금 나아졌다"로 보인 것이 384칸에서
"−17, 유의하게 나빠졌다"였다. 그리고 384칸에서 "+20, 유의"로 보인 것이 재현되지
않았다. **표본을 키우기 전에 적었다면 두 번 틀리게 적었을 것이다.**

**④ 런을 요인으로 넣어야 한다.** 같은 프롬프트가 30칸을 움직인다. 앞으로 이 파일럿
에서 20칸짜리 주장을 하려면 **런을 복제 단위로 삼은 설계**가 필요하다 — 칸을 늘리는
것으로는 안 된다.
