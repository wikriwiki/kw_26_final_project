# 관문에서 얻은 20.6%p 가 본런 실패율에서는 보이지 않는다

**2026-09-22 21:50** · v50 두 팔의 같은 3일 · 팔마다 600계획 · **v45 팔은 아직 돌고 있다**

---

## 이 글이 쓰이는 시점

v50 의 v45 팔은 3/12 일차다. **정답지 채점은 아직 없다.** 여기서 보는 것은
채점 결과가 아니라 **두 팔이 같은 날짜에 낸 Stage1 실패 기록**이고, 그것은
정답지와 무관한 형식 지표다. v50 의 일회 평가 규칙을 건드리지 않는다.

## 숫자

두 팔이 같은 사흘(2020-11-14·15·16)을 200명씩 돌았다. 팔마다 **600계획**이다.

```
          실패   실패율    time 필드   JSON 파싱   zone 앵커 0개
v5         14    2.33%        8           6            0
v45        15    2.50%       12           2            1
```

**차이가 1건이다.** 관문에서 v5 → v45 는 68.0% → 88.6% 로 **+20.6%p** 였다.
본런에서는 2.33% → 2.50% 다.

## 왜 이렇게 되는가

관문과 본런이 **같은 것을 재지 않는다.**

```
관문    원문 계약 — 모델의 첫 출력을 고치지 않고 그대로 채점한다
본런    생산 파이프라인 — 실패하면 재시도하고, 고칠 수 있으면 고친다
```

관문이 잡는 위반 대부분(zone 앵커에 '직장' 카테고리, reasoning 누락, 20분 간격)은
본런에서 **재시도나 복구가 흡수한다.** 그래서 첫 출력 품질이 20%p 달라져도
최종 실패율은 거의 같다.

## 검출력 — 이 비교로 말할 수 없는 것

**말할 수 없다.** 14 대 15 는 잡음 안이다.

```
관측 차이      1건
잡음 눈금      √(14+15) ≈ 5.4건
time 필드 차이 4건 (8→12) · 잡음 눈금 √20 ≈ 4.5건
```

**어느 쪽도 읽을 수 없다.** v45 가 본런에서 더 낫다고도, 더 나쁘다고도 적지
않는다. 적을 수 있는 것은 **관문의 +20.6%p 가 여기서 비슷한 크기로 나타나지
않는다**는 것뿐이고, 그것은 위 표만으로 충분하다 — 20%p 짜리 차이였다면
600계획에서 120건 가까이 벌어졌어야 한다.

## 곁가지 — v45 가 더 빨랐다

같은 사흘, 같은 200명이다.

```
        11-14    11-15    11-16     합
v5      1,097초   1,065초    956초   3,118초
v45     1,015초  1,004초    857초   2,876초
                                    -242초 (-7.8%)
```

사흘 다 v45 가 빨랐다(3/3). 다만 **세 쌍으로는 유의를 말할 수 없다**(부호검정
p=0.25). 방향만 적어 둔다 — 재시도가 줄면 빨라지는 것이 자연스럽고,
JSON 파싱 실패가 6 → 2 로 준 것과 방향이 맞는다.

## 그래서 프롬프트 작업의 방향

`PROMPT_FINAL_v45.md` 는 관문을 **전제**라고 적었고 정답지 수렴이 목표라고 했다.
이 관측이 그 말을 숫자로 뒷받침한다.

```
관문을 더 올리는 일     본런 실패율을 거의 움직이지 못한다 (2.3% → 2.5%, 잡음 안)
정답지에 가까워지는 일   아직 한 번도 v45 로 재 본 적이 없다 — v50 이 그것을 재는 중
```

**v51·v52 는 여전히 돌릴 값어치가 있다.** 다만 그것이 재는 것은 관문의 잔여이지
정답지 수렴이 아니다. 그 구분을 사전등록에 이미 적어 두었다.

> 이 문서가 적는 것은 여기까지다. 두 팔이 같은 사흘에 낸 실패가 14 대 15 이고,
> 그것은 잡음 안이며, **관문의 20.6%p 가 본런에서 같은 크기로 나타나지 않는다**는 것.
