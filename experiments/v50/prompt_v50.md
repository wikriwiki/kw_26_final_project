# v50 사전등록 — v45 를 정답지에 대고 처음으로 잰다

**작성 2026-09-22 16:20 · 실행 전 커밋** · 거리두기 12일 창 · 200명 · v5 대 v45 · GPU 는 v30 뒤

---

## 여태 빠져 있던 것

관문 라운드를 다섯 번 돌려 v45 를 만들었다. 그런데 **v45 를 정답지에 대고 잰 적이
한 번도 없다.** 정답지에 대고 잰 기록은 전부 v5 다.

```
stage5 (v5 · n=500 · 12일 창)
  DS-1   −9.7%   실측 −14.1%   hit
  DS-2   +5.1%   실측  +4.2%
  DS-4  −13.7%
  DS-3   순위 hit

stage3 (v5 · n=200 · 같은 창)
  DS-1   −7.0%   DS-2  +13.5%   DS-4  −17.3%
```

**관문은 전제이고 정답지 수렴이 목표다.** 관문을 20%p 올린 프롬프트가 정답지에서
더 나은지는 **아직 모른다.** 이 라운드가 그것을 잰다.

## 설계 — 한 변수

```
창      window_stage3 그대로   day0 2020-11-13 · 시작 2020-11-14 · 12일
        무정책 2020-11-17:11-18 (화·수) · 정책 2020-11-24:11-25 (화·수)
        요일 정합 창이다 — 1단계 창은 주말이 무정책 쪽에만 들어가 부호를 오염시켰다

인원    200명 — stage3 과 같은 n 이어야 나란히 놓을 수 있다
정책    거리두기. environment 가 규제를 실어 오고 정책 JSON 은 없다
소득    끄고 돈다. 12일은 지갑 한계(중앙 25.9일) 안이다

두 런   A: SIM_PROMPT_VARIANT=v5     B: SIM_PROMPT_VARIANT=v45
```

**stage3 의 −7.0% 와 비교하지 않는다.** 서버·모델이 그때와 같다는 보장이 없으므로
v5 를 같은 조건에서 다시 잰다. 관문 라운드에서 배운 그대로다.

## 무엇을 채점하는가

사전등록된 거리두기 지표 넷 중, 감사 주석이 **추정량이 호환된다고 본 둘**을 주로 본다.

```
주   DS-1  식사 업종 지출 변화   실측 −14.1%
     DS-2  소매 업종 지출 변화   실측  +4.2%
부   DS-3  순위 (소매 > 식사)    — '제약이면 다 줄어든다'로 수렴한 프롬프트를 잡는 지표
     DS-4  카페 지출 변화
```

## 합격선 — 결과를 보기 전에 정한다

```
주 지표   v45 의 DS-1·DS-2 가 v5 보다 실측에 가깝다
          |시뮬 − 실측| 이 두 지표 모두에서 줄어든다

부 지표   DS-3 순위가 v45 에서도 유지된다 (v5 는 stage5 에서 맞혔다)
```

**사전등록한 예측.** v45 가 **조금 가깝거나 비슷할 것이다.** 근거와 한계를 함께 적는다.

- 가까워질 근거: v45 는 거리두기 입력에서 캐시백 문장을 걷어냈다. 이 런에 캐시백은
  없으므로 그 문장은 순수한 잡음이었다. 그리고 계약 통과율이 68% → 88.6% 이므로
  **살아남는 칸이 늘어 추정이 덜 흔들린다.**
- 안 가까워질 근거: 형식 준수와 정책 반응은 다른 것이다. 관문을 20%p 올린 것이
  업종별 금액을 실측 쪽으로 옮길 이유는 없다.

**두 가능성이 모두 그럴듯하므로 구간을 좁게 적지 않는다.**

## 이 라운드의 규칙 — 순환 검증을 막는다

**결과를 보고 v45 를 고치지 않는다.** 이것은 **일회 평가**다.

```
v45 가 더 가깝다   → 거시 작업의 현행을 v45 로 올린다
v5 가 더 가깝다    → 거시 작업은 v5 로 유지한다. v45 는 관문용으로만 남는다
비슷하다           → v5 를 유지한다. 바꿀 근거가 없다
```

어느 경우에도 **이 결과를 보고 프롬프트에 문장을 더하거나 빼지 않는다.**
`ROUND2_CIRCULARITY_AUDIT` 이 v7 을 제외한 이유가 그것이다 — 결과를 보고 그 결과를
막는 문장을 쓴 것.

## 이 라운드가 답하지 못하는 것

**크기 검증이 아니다.** 감사 주석(`audit_2026_09_20`)이 대상·기간·결과·분모·대조군이
호환될 때만 배수를 비교하라고 했다. 여기서 재는 것은 **두 프롬프트 중 어느 것이
실측에 가까운가**이고, 그 거리가 검증 기준을 통과하는가는 아니다.

**그리고 한 런이다.** 관문 라운드에서 같은 프롬프트가 30칸을 움직이는 것을 봤다.
거시 런의 런 간 변동은 아직 재 본 적이 없으므로, **이 결과도 한 런의 관측으로
적는다.** 재현은 다음 라운드의 몫이다.
