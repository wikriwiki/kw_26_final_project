# v40 사전등록 — 캐시백을 다른 정책의 입력에서 걷어낸다

**작성 2026-09-22 09:20 · 실행 전 커밋** · 원문 계약 관문 전용 · GPU 는 v30 뒤

---

## 프롬프트 탐색은 닫히지 않았다

나는 앞서 "프롬프트 탐색은 이미 닫혔다"고 적었다. **틀렸다.** 같은 기록이 이렇게 말한다.

```
ROUND2_A_VERDICT.B단계   "기동하지 않았다"
_validation_v3.result    "Both candidates failed the preregistered raw-contract gate;
                          no macro rollout started."
```

v5 도 v10 도 사전등록한 관문을 **통과하지 못했다.** 닫힌 것은 "v7~v9 가 v5 를 이기지
못했다"까지이고, **v5 자신이 통과한 적이 없다.**

## v5 의 결함은 이미 진단돼 있었다

`docs/VALIDATION_ARCHITECTURE_V3.md` 의 1순위 항목이다.

> v5는 p012 본문 중 daily_propensity 블록만 교체 | 무정책·지원금·거리두기 입력에도
> **캐시백 문턱, 10%, 특정 사용처 및 구매 예시가 공통 시스템 지시로 들어간다.**

세어 보니 이렇다.

```
p012 시스템 프롬프트            10,651자
v5 가 갈아 끼우는 블록             678자  (6.4%)
v5 가 그대로 물려받는 본문        9,973자  (93.6%)

그 본문에 남는 것   캐시백 5회 · 문턱 6회 · 10% 1회 · 적립 1회
                   grant_kept_share 절 전체 (13줄)
                   "문턱까지 얼마 안 남아 이번 달에 사면 캐시백까지 받겠다 싶어" 라는 구매 예시
```

**거리두기를 재는 런에도, 무정책 기준선에도 이 문장들이 들어간다.**

## v10 은 왜 무너졌나 — 이 후보가 피해야 할 함정

```
                    원문 계약 통과
  v5              128/192  (66.7%)
  v10              14/192  ( 7.3%)      장소 위반 167건
```

v10 의 167건은 전부 `zone:11680521` 이어야 할 자리에 `11680521` 만 쓴 것이다.
v10 이 **구체적인 JSON 이벤트 예시를 없앴기 때문**이고, `docs/VALIDATION_V3_RESULTS.md`
가 다음 후보의 원칙을 적어 두었다.

> "후속 후보는 정책 행동을 유도하는 구매 예시와 출력 형식을 설명하는 예시를
> 구분해야 한다."

## v40 이 하는 일 — 딱 세 곳

| | 무엇 | 왜 |
|---|---|---|
| 뺀다 | `grant_kept_share` 절 전체 (설명·출력 예시·주석) | 자기보고 반사실. 아키텍처 문서가 "생성하지 않는다"고 적었고 엔진에서도 진단용이다 |
| 바꾼다 | "개인별 적립 실적·문턱까지 남은 금액·남은 일수" | → "개인별 정책 상태(대상 여부·남은 혜택·조건 충족 현황)" |
| 바꾼다 | 예시 한 줄의 reasoning | 문턱을 넘기려고 사는 장면을 뺀다. **JSON 구조와 trigger:"policy" 는 그대로 둔다** |

**표에 없는 글자는 v5 와 바이트 단위로 같다.** 단위테스트가 되돌려서 v5 가 나오는지
확인한다(`test_v40_differs_from_v5_only_where_declared`).

```
캐시백 어휘   v5 → v40      캐시백 5→0 · 문턱 6→0 · 10% 1→0 · grant_kept_share 4→0
형식 뼈대                   zone: 20=20 · anchor 28=28 · trigger 19=19
                           residence 6=6 · workplace 4=4 · 이벤트 예시 14개=14개
길이                        10,527 → 9,869자 (-658)
```

## 합격선 — 결과를 보기 전에 정한다

이 라운드는 **원문 계약 관문만** 판정한다. Stage1 파일럿에는 POI 선택·결제·기억
전이가 없으므로 정책 효과는 여기서 읽지 않는다.

```
같은 조건에서 v5 와 v40 을 나란히 돌린다 (192칸씩, 같은 시민·날짜·seed)

  주 지표   v40 의 보정 전 계약 통과율 >= v5 의 통과율
  판정      같거나 높으면 거시 런 자격을 얻는다. 낮으면 기각한다
```

**v5 의 128/192 를 기준으로 삼지 않고 같은 런에서 다시 잰다.** 모델·서버가 그때와
같다는 보장이 없다.

**사전등록한 예측.** 통과율이 **오를 것이다** — 무관한 정책 문장 658자가 빠지면
형식 지시가 상대적으로 진해진다. 틀리면 그대로 적는다.

## 이 라운드에서 판정하지 않는 것

**오염이 걷혔는가는 실험이 아니라 정적 사실이다.** 단위테스트가 이미 0회를
확인했다. 실험으로 확인할 일이 아니다.

**P012 가 손상됐는가는 여기서 못 잰다.** 그리고 손상 가능성이 실재한다 —

> 캐시백의 핵심 사실("문턱을 못 넘기면 이번 달 혜택이 사라진다")이 지금은 **이 오염된
> 본문을 통해서만** 모델에게 닿는다. 런타임 정책 블록은 정책 본문을 280자에서 자르는데
> P012 본문은 358자이고, **잘려 나가는 78자가 정확히 그 사실이다.**
>
> ```
> 잘린 꼬리: "15일에 돌려받는 것이며, 3% 문턱을 넘기지 못하면 이번 달 캐시백 혜택은
>            사라집니다. 돌려받은 캐시백은 나중에 어디서든 쓸 수 있습니다."
> ```

**그러므로 v40 을 거시 런에 올리기 전에 절단을 먼저 고쳐야 한다.** 다만 이 라운드에서는
고치지 않는다 — **한 번에 한 가지만 바꾼다.** 절단이 있는 상태에서 v5 대 v40 을 재야
형식 비교가 한 변수다.

## 실패로 적을 것

| 결과 | 무엇으로 적는가 |
|---|---|
| v40 통과율 < v5 | **기각.** 오염을 빼는 것이 형식도 함께 무너뜨린다 |
| 둘 다 95% 미만 | 사전등록 관문은 여전히 미통과다. v40 이 v5 보다 나아도 **"통과했다"고 적지 않는다** |
| 위반 범주가 v5 와 다른 쪽으로 쏠린다 | 빼면서 건드리지 말아야 할 것을 건드렸다. 범주별로 적는다 |

## 유도가 아닌 이유

| 물음 | 답 |
|---|---|
| 결과 방향을 지시하는 문장을 더하는가 | **아니다. 더하는 문장이 없다.** 빼기만 한다 |
| 실측 수치가 들어가는가 | 아니다. 오히려 정책 수치(10%·문턱)를 **뺀다** |
| 채점 지표를 겨냥하는가 | 이 라운드의 지표는 원문 계약 통과율이다. 정답지와 무관하다 |

> 순환 검증 감사(`ROUND2_CIRCULARITY_AUDIT`)가 v7 을 제외한 이유는 "결과를 보고 그
> 결과를 막는 문장을 썼다"였다. v40 은 **문장을 쓰지 않는다.** 정책 하나에만 맞는
> 문장을 다른 정책의 입력에서 지울 뿐이다.
