# B 팔을 건너뛴다 — 같은 시간에 오차의 77%를 겨눈다

**2026-09-24 05:40** · 되돌릴 수 있다

---

## 무엇을 건너뛰나

`run_p013_ruler.sh` 의 **B 팔**이다. A 팔과 **같은 v5 를 한 번 더** 도는
A/A 복제이고, 주는 것은 EM-2 읽기의 **런 간 이동폭 하나**다. 10시간 든다.

## 왜

```
A 팔 종료 예상        12:30 무렵 (탐침과 GPU 를 나눠 쓰며 하루 70분으로 느려짐)
B 팔을 돌리면        22:30 → 2층 가르기 본런은 내일 06:30 에나 끝난다
B 팔을 건너뛰면      2층 가르기 본런이 오늘 20:30 무렵 끝난다
```

겨누는 크기가 다르다.

```
B 팔이 주는 것   EM-2 한 지표의 잡음대
2층 가르기       P012-1 + P012-2 = 35.67%p  (전체 오차 46.27%p 의 77%)
```

**A 팔은 그대로 끝까지 돈다.** EM-2 의 값 자체는 A 팔이 낸다 — 사용자가 말한
"실측은 있는데 시뮬이 값을 못 내는 것은 우리 문제" 를 푸는 것은 A 팔이고,
B 팔은 그 값에 잡음대를 붙이는 일이다.

## 건너뛴 값

EM-2 의 새 읽기에 **자체 잡음대가 없다.** P012-1 의 런 간 이동 8.2%p 를
보수적 대용으로 쓰고 **보고서에 그렇게 밝힌다.** 자기 잡음대가 아닌 것을
자기 것처럼 쓰지 않는다.

## 어떻게 했나 — A 팔을 건드리지 않는 방법

러너는 `if [ -f "$OUT/score_$TAG.json" ]` 이면 그 팔을 건너뛴다. 그래서
`score_ruler_b.json` 자리에 **표식 파일**을 두었다. 러너 프로세스를 죽이면
A 팔의 파이프(`python | grep | tee`)가 깨져 A 팔까지 죽을 수 있다 — 그래서
아무 프로세스도 건드리지 않았다.

표식 파일은 채점 결과가 **아니다.** 그래서 두 가지를 해 두었다.

```
· 파일 안에 "SKIPPED": true 와 "NOT_A_READING" 을 적었다
· refresh_reports.sh --fetch 가 "SKIPPED" 가 든 파일을 받으면 버린다
  (실제로 한 번 받아 왔다 — 그래서 가드를 넣었다)
```
