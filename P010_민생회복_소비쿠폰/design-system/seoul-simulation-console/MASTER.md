# Seoul Simulation Operations Workbench

## 기준

- 대상: 정책 시뮬레이션을 설계·감시·조사·보고하는 PC 운영자
- 기준 화면: 1440×900, 최소 1280×800
- 제외 범위: 모바일·태블릿 최적화와 관련 증거
- 주 레퍼런스: Palantir Blueprint의 데이터 밀도 높은 데스크톱 작업공간
- 보조 레퍼런스: Palantir Gotham의 객체 중심 탐색과 상황 인식 구조
- 밀도 9/10, 동작 1/10, 시각 변동성 2/10

검색형 디자인 추천에서 제시된 과장된 미니멀리즘·거대 타이포·사이버펑크 폰트는 이 제품과 맞지 않아 사용하지 않는다. 이 제품은 마케팅 랜딩 페이지가 아니라 장시간 사용하는 분석 도구다.

## 시각 언어

- 기본 서체는 로컬 `Noto Sans KR Variable`, 숫자·ID·시간만 고정폭 계열을 쓴다.
- 제목은 20–30px 범위로 제한한다. 화면을 점유하는 hero 문구를 만들지 않는다.
- 배경색 단계보다 1px 구분선, 정렬, 열 너비로 계층을 만든다.
- 기본 모서리는 0–3px다. 알약 모양은 짧은 상태 태그에만 허용한다.
- 그림자와 떠 있는 카드 효과는 사용하지 않는다. 모달·메뉴의 실제 겹침에만 최소 그림자를 허용한다.
- 강조색은 한 화면의 현재 선택, 주 실행 버튼, 활성 시간축에만 쓴다.
- 라이트·다크는 동일한 정보 구조를 유지한다. 다크 테마를 네온 HUD처럼 만들지 않는다.

## 금지 규칙

- 카드 그리드, 카드 안의 카드, 둥근 통계 카드
- 거대한 제목과 장식용 영문 eyebrow의 반복
- AI 제품처럼 보이는 그라디언트, 글로우, 유리 효과, 보라·분홍 조합
- 개발 메모, API 계약, 브라우저/서버 구현 설명, 가짜 데이터 방지 논의를 사용자 화면에 노출
- 기능이 없는 컨트롤을 설명문과 함께 전시
- 같은 상태를 헤더·경고·카드·배지에서 반복
- 모든 도구와 근거를 한 화면에 동시에 노출
- 호버 시 요소 위치·크기 변경

## 허용되는 구조

- 객체 헤더: 한 줄 제목, 상태, ID, 핵심 사실, 마지막 갱신
- 명령 막대: 검색, 필터, 정렬, 한 개의 주 행동
- 데이터 표·행 목록: 고정 열, 탭형 숫자, 선택 행 강조
- 분할 작업공간: 목록 → 세부 → 근거의 top-down drill-down
- 상태 스트립: 전체 폭 한 줄, 아이콘·상태·복구 행동
- 인스펙터: 선택 객체가 있을 때만 표시
- 세부 정보: 기본 접힘, 사용자가 요청할 때 펼침

## 페이지별 원칙

### 시뮬레이션 목록

- 포트폴리오 hero를 제거하고 제목·검색·신규 생성이 한 명령 막대에 있어야 한다.
- 상태 집계는 카드가 아니라 클릭 가능한 얇은 필터 스트립으로 표시한다.
- 실행은 행 목록 또는 표로 비교한다. 설명은 보조 열 한 줄로 제한한다.

### 설정

- 왼쪽 단계 탐색과 오른쪽 편집기 구조를 유지하되 단계 카드를 만들지 않는다.
- 선택지는 세로 행 또는 분할 표로 제공한다.
- 내부 저장 위치나 미연결 구현을 설명하지 않는다. 행동명은 `설계안 저장`처럼 사용자 과업으로 쓴다.

### 실행 상세

- 진행률 hero를 상태 밴드로 축소한다.
- 핵심 수치는 동일 행의 열로 비교한다.
- 시간 기록·설정·근거는 필요 화면으로 drill-down한다.

### 에이전트 조사

- 기본은 대상 목록과 빈 조사 캔버스 두 영역이다.
- 선택 후에만 행동 타임라인과 근거 인스펙터를 연다.
- 조회 API·필수 계약 목록 같은 개발 체크리스트를 화면에 노출하지 않는다.

### 리포트

- 설정, 준비 상태, 이력을 단계 카드가 아니라 연속된 작업 열로 구성한다.
- 해시·URI·manifest 같은 근거는 `진단 상세` 안에 둔다.
- 기본 화면에는 생성 가능 여부와 사용자가 해결할 수 있는 조치만 표시한다.

### 3D 시각화

- 일반 상세 셸 밖의 전용 작전 화면으로 연다.
- 3D 캔버스가 첫 화면의 대부분을 차지해야 한다.
- 상단에는 실행명·현재 일자·재생 상태만, 좌측에는 최소 레이어/필터, 우측에는 선택 에이전트 인스펙터, 하단에는 시간축만 둔다.
- 지도 위 패널은 반투명 카드가 아니라 가장자리 도킹 패널로 만든다.
- 실제 산출물이 없으면 가짜 지도나 가짜 에이전트를 렌더링하지 않는다.

## 접근성과 동작

- 본문 대비 4.5:1 이상, 포커스 링 3px, 색상 외 텍스트 상태 병기
- 키보드 순서는 시각적 top-down 흐름과 같아야 한다.
- 페이지 전환은 120–180ms의 최소 opacity만 허용하며 reduced-motion에서 제거한다.
- 1280px에서도 가로 페이지 스크롤과 중첩 세로 스크롤을 만들지 않는다. 단, 전용 3D 캔버스의 도킹 패널은 독립 스크롤을 허용할 수 있다.

## Critic 질문

각 라운드에서 완료 여부를 묻지 말고 다음을 반복해서 묻는다.

1. 사용자가 지금 결정을 내리는 데 필요하지 않은 문장은 무엇인가?
2. 카드 없이 더 빠르게 비교할 수 있는가?
3. 선택하지 않은 객체의 세부 정보가 미리 노출되어 있는가?
4. 내부 구현 사실이 사용자 언어로 위장해 남아 있는가?
5. 3D 시연에서 지도보다 셸이 더 많은 면적을 차지하는가?
