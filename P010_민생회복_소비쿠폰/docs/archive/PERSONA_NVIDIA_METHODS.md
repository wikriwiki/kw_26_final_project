# NVIDIA 페르소나 결합 — 3가지 방법론 (팀 공유용)

> **TL;DR** — 기존 통계 페르소나는 "숫자만 있고 사람 냄새가 없다"는 문제가 있었습니다.
> 이를 풀려고 NVIDIA Nemotron-Personas-Korea(정성 서사)를 우리 BDC 통계(정량 소비·이동)에
> 결합했고, 결합 방법이 **3가지**입니다. 결론: **B(조건부 부여) 또는 C(B+봉합) 권장.**
> A(순위 짝짓기)는 작은 집단에서 모순 페르소나가 생길 위험이 있습니다.

---

## 1. 왜 하나 (배경)

지금까지 에이전트 페르소나는 **BDC 통계 기반 숫자 묶음**이었습니다.
소비분위·이동거리·배달일수 같은 정량값은 정확하지만 **개성·서사가 없어서**,
LLM에게 "이 사람이 되어 하루를 계획하라"고 줄 때 입력이 빈약하고 결과가 획일적이었습니다.

NVIDIA Nemotron-Personas-Korea는 정반대로 **서사·취미·가치관**은 풍부하지만
소비·이동 같은 행동 수치가 없습니다. → **둘은 상호보완.** 합치면 빈약함이 해소됩니다.

| | 우리 BDC 통계 | NVIDIA Nemotron-Personas-Korea |
|---|---|---|
| 강점 | 동·코호트 단위 **정량**(소비/이동/배달) | 1인 단위 **정성**(서사·취미·가치관) |
| 약점 | 개성·서사 없음 | 행동 수치(금액·이동) 없음 |
| 규모 | 서울 행정동 × 성·연령 | 약 100만 명(한국), KOSIS 기반 |
| 라이선스 | 내부 | CC BY 4.0 (출처 표기 시 사용) |

---

## 2. 핵심 난제: 어떻게 짝지을까

두 데이터엔 공통 ID가 없습니다. "이 NVIDIA 사람"과 "이 통계 집단"을 이을 다리가 필요합니다.
우리가 쓰는 다리는 **SES(사회경제적 지위) 추정치** — 학력·직업·주거를 묶어 0~1로 환산한 값입니다.
**이 SES를 어떻게 쓰느냐가 곧 3가지 방법의 차이**입니다.

---

## 3. 세 가지 방법

### 방식 A — rank-coupling (순위 짝짓기)

```
NVIDIA 사람들을 SES로 줄 세움  ─┐
                               ├─→ 같은 등수끼리 짝짓기
통계 페르소나를 소비수준으로 줄 세움 ─┘
```

- **아이디어**: 같은 집단(구·성·연령) 안에서 NVIDIA는 SES 순위, 통계는 소비 순위로
  각각 정렬한 뒤 **같은 등수끼리 매칭**. "돈 수준으로 줄 세워 짝짓기."
- **장점**: 통계 분포가 그대로 보존됨(모집단이 BDC 공식 통계 = 대표성↑). 단순.
- **단점 (치명적)**: 두 데이터를 **독립이라 가정**하고 강제 결합 → 작은 집단에서
  **모순 페르소나** 발생. 예) 서사는 명품·미식인데 소비는 편의점 수준으로 묶임.

### 방식 A+LLM — 순위 짝짓기 후 모든 페르소나를 LLM이 전수 검증·봉합

```
A로 싸게 짝짓기 → 모든 페르소나를 LLM이 검증(한 사람으로 자연스러운가?) → 모순이면 서사 재서술
```

- **아이디어**: A의 약점은 *매칭*뿐이고 **숫자는 이미 BDC 통계로 정확**하다. 그러니
  숫자는 **절대 안 건드리고**, **모든 페르소나를 LLM이 직접 검증**해 모순이면 LLM이
  **서사(lifestyle)를 숫자와 모순 없게 다시 쓴다**. 예) "고소득 전문직 ↔ 저소비" →
  "전문직이지만 검소·저축 지향"으로 납득되게. 원본 NVIDIA 서사는 보존.
- **룰 안 씀**: 규칙 기반 탐지는 부정확하므로 사전 게이트를 두지 않는다. 프롬프트엔
  **판정 기준(임계값·규칙)을 적지 않고**, LLM이 *무엇을 보고 판단할지*(소비↔직업·학력,
  소비↔서사, 거주지↔서사 지역, 행동↔라이프스타일, 가족·생애단계)만 안내 → 종합 판단.
- **장점**: A의 강점(대표성·정확한 숫자)은 그대로, 약점(서사 모순)을 LLM 종합 판단으로 제거.
- **단점**: **전 페르소나가 LLM 호출**이라 비용↑(룰 게이트보다 호출 많음). 서버 필요
  (부재 시 결정적 stub). 서사를 일부 창작 → "실제 NVIDIA 사람 그대로"는 약화.
- **설계 원칙**: 숫자 = 통계 권위(불변), LLM = 전수 판정 + 서사 봉합. C(방식 B용)가 *숫자*를
  당기는 것과 달리, 여기선 *서사*를 맞춘다(숫자가 BDC 진실이므로). 실행법은 `PERSONA_A_LLM_GUIDE.md`.

### 방식 B — conditional-graft (조건부 부여) ⭐ 권장

```
NVIDIA 사람 1명(진짜 사람)  ─→  그 사람의 동네·SES를 보고
                                "이 사람이라면 소비를 이만큼" 통계를 조건부로 입힘
```

- **아이디어**: 짝짓기가 아니라 **NVIDIA 사람 한 명에서 파생**. 그 사람의 구에서
  동네를 인구비례로 고르고 → 그 지역 대표 소비를 SES로 살짝 보정 → 취미에 맞게
  업종을 조정 → 행동 패턴(배달·이동)을 입힘.
- **장점**: 한 사람한테서 파생하므로 **모순이 원천 차단**됨. 보정은 켜고 끌 수 있어
  끄면 통계 분포 그대로(가장 안전).
- **단점**: SES 보정 폭이 제한적 → 극단 사례(전문직인데 저소비 지역)에서 **잔여 괴리**가 남을 수 있음.

### 방식 C — hybrid (B + 모순 봉합) ⭐⭐ 가장 견고

```
방식 B 결과  ─→  규칙으로 모순 검출  ─→  소비를 SES 방향으로 봉합  ─→  잔여 경고 기록
```

- **아이디어**: B를 돌린 뒤 **규칙으로 모순을 검출**하고 봉합.
  - 검출: ① SES↔소비 괴리 ② 서사↔소비 모순(고급취미↔저소비 / 검소취미↔고소비)
    ③ 직업↔소비(전문직인데 극저소비 — 단 구직·전직·은퇴는 예외 처리)
  - 봉합: 괴리가 크면 소비 수준을 SES 쪽으로 당겨 정합화
  - **감사 로그**: 봉합 후에도 남는 모순은 경고로 기록 → 사후 검증 가능
- **장점**: B의 잔여 모순까지 교정 + **어떤 페르소나가 봉합됐는지 추적 가능.**
- **단점**: 검출 임계값이 휴리스틱 → 실측으로 튜닝 여지.

## 5. 권장안

- **빠른 baseline / 분포 정확성만 중요** → B(보정 끄고)
- **개성 살리되 모순 최소화** → B(보정 켜고)
- **대회·발표용, 품질·검증 추적 중요** → **C 권장**
- A는 비교 실험용으로만 유지 (작은 집단 모순 위험으로 본 생성엔 비권장)
