# 집 체류 시간을 정합 목표로 쓰면 안 된다 — 두 수는 같은 종류가 아니다

**2026-09-21** · 근거 v18 계획 480칸 · v19 계획 480칸 · cohort60 페르소나 60명

---

## 무엇을 철회하는가

v18·v19 는 **"에이전트가 집 밖으로 안 나간다"** 를 결함으로 보고 프롬프트로 고치려 했다.
근거는 이 비교였다.

```
부여된 평일 집 체류   평균 12.1h
계획이 낸 집 체류     평균 17.7h
차이                  +5.6h · 480칸 중 427칸(89%)이 두 시간 넘게 초과
```

**이 비교는 성립하지 않는다.** 두 수가 같은 것을 재지 않는다.

v19 는 이 목표로 사전등록됐고 실패했다. 그 실패는 **프롬프트가 못 움직인다는 증거가 아니라
목표가 잘못 잡혔다는 증거**다. 그러므로 v19 의 결론을 위 형태로 인용하지 않는다.

---

## 어떻게 알았나 — 근로자와 무직자가 2.5시간밖에 차이 나지 않는다

부여값을 사람의 **직업**으로 갈라 보면 이렇다. 계획이 아니라 페르소나의 `job` 으로 가른다.

```
직업 있음 (296칸)    부여 집 체류 11.1h
직업 없음 (184칸)    부여 집 체류 13.6h
                     ────────────────
                     차이 2.5h
```

전업 근로자는 하루 9시간을 직장에서 보내고 통근이 따로 붙는다.
무직·은퇴·주부는 그 시간이 통째로 비어 있다.
**수면을 포함한 진짜 체류 시간이라면 둘은 8시간 가까이 벌어져야 한다.**
2.5시간이라는 것은 이 값이 **하루 24시간을 채우는 양이 아니라는 뜻**이다.

두 번째 단서는 같은 사람 안에 있다.

```
AGT_11110560_F_70대이상_001   70대 이상 · 무직 · 은퇴
  평일 집 체류 15.2h
  주말 집 체류  9.7h
```

주말에 집에 9.7시간만 있으려면 깨어 있는 시간 거의 전부와 수면 일부까지
집 밖에 있어야 한다. 70대 은퇴자에게 그 해석은 성립하지 않는다.

## 우리 쪽 계산기는 밤을 통째로 집에 넣는다

```python
total += pts[0][0] + (24 * 60 - pts[-1][0])
```

첫 항목 이전과 마지막 항목 이후를 전부 residence 로 친다. 계획이 07:00~22:00 을 덮으므로
**9시간의 밤이 자동으로 집 체류에 들어간다.** 그래서 우리 값은 정의상 24시간을 채운다.

부여값은 채우지 않는다. **한쪽은 24시간 분할이고 다른 쪽은 아니다.**

## 그러면 부여값은 무엇인가

추적하면 이렇게 내려간다.

```
프롬프트 "평일 집 체류 15.2h"
  ← neutral_context.py 가 "평일 재택" 을 문자열 치환한 것
  ← dawn_context.py  p['home_h_wd']
  ← 04_agents.py     behavior_home_h_wd = bh['home_hours_weekday']
  ← compare_stats.py ("평일재택(시간)", "home_hours_weekday", "tel_home_wd_time", 1/3600)
```

**원천은 KT 텔레콤의 `tel_home_wd_time` 이고 단위는 초다.** 이름이 원래 "재택"이었다는 것이
v11 부터 모든 프롬프트가 `집 체류시간은 재택근무와 다르다` 를 달고 다닌 이유다 —
모델이 자꾸 재택근무로 읽어서 계속 부정문을 덧대 왔다.

**이 값이 어떤 창에서, 어떤 조건으로 집계됐는지 우리는 모른다.** 위의 두 단서는
그것이 24시간 분할이 아님을 말해 주지만, 무엇인지까지 말해 주지는 않는다.
알아내기 전에는 정합 목표로 쓰지 않는다.

> 이것은 DS-1 과 같은 종류의 실수다. 거기서는 실측이 매장 취식 붕괴를 재는데
> 우리 식사 칸의 95%가 배달이었다. 여기서는 실측이 무엇인지 모르는 창을 재는데
> 우리 값은 24시간을 채운다. **단위·창·분모를 맞추기 전에 크기를 맞대지 않는다**는
> `ESTIMAND_ALIGNMENT.md` 의 규칙이 그대로 적용된다.

## 살아남는 것 — 같은 측정에서 나온, 정의가 분명한 결함 하나

직업으로 가르면 작지만 분명한 것이 보인다.

```
직업 있음 · 계획에 근무 있음   272칸   부여 11.1h  계획 14.7h  차이 +3.6h
직업 있음 · 계획에 근무 없음    24칸   부여 11.6h  계획 21.2h  차이 +9.6h   ← 결함
직업 없음 · 계획에 근무 없음   180칸   부여 13.6h  계획 21.8h  차이 +8.3h
```

**직업이 있는 사람의 평일 계획 296칸 중 24칸(8%)에 근무가 통째로 빠져 있다.**
이건 창이나 정의의 문제가 아니다. 평일이고, 그 사람에게 직장이 있고, 계획에 직장이 없다.

이것은 **부여값과 무관하게** 판정할 수 있으므로 정합 목표로 쓸 수 있다.
목표는 24칸을 0으로 만드는 것이고, 어느 방향으로도 정답지를 참조하지 않는다.

## 카탈로그는 범인이 아니다

혹시 나갈 데가 없어서인가 싶어 60명의 활동 사전을 세어 봤다.

```
walk · outdoor_leisure · library · meal_dine_in · cafe_dine_in · groceries ...
                                              전부 60명 / 60명 에게 있다
```

**집 밖 활동은 전원에게 열려 있다.** 고르지 않는 것이지 못 고르는 것이 아니다.
그리고 실제로 고르기는 한다 — 무직자 계획에 `walk` 가 2시간짜리 덩어리로 들어간다.

```
07:00 home_prepare   10:00 walk(zone)   12:00 home_delivery   15:00 walk(zone)   18:30 home_sleep
```

후보 셋을 집 체류로 재면 완전히 같다. 다만 **집 밖 항목 수만 v34 가 조금 많다.**

```
              근무 있음                    근무 없음
          차이h   집밖항목            차이h   집밖항목
v25       +3.6     0.84              +8.4     0.89
v34       +3.6     0.97              +8.1     1.07     ← 금지어를 뺀 쪽
v35       +3.6     0.87              +8.4     0.89
```

v34 는 18행에서 `구매·외출·반복` 이라는 **금지 대상 나열을 지운** 판이다(v30 의 문장).
집 밖 항목이 0.89 → 1.07 로 움직인다. v35 는 같은 줄의 뒷문장을 **서술로 바꾼** 판이고
아무것도 움직이지 않는다.

> **금지를 지우면 움직이고, 서술을 더하면 안 움직인다.**
> v30 이 구매 비율을 +2.21 SE 움직였던 것과 같은 모양이고,
> v31·v35 가 둘 다 서술을 더해 실패한 것과도 같은 모양이다.
> 다음 후보는 이 규칙을 따른다.

## 이 문서가 바꾸는 것

1. `CURRENT_BEST_PROMPT.md` 의 "18행 뒤 · 여기가 지금 가장 유망하다" 는 **근거를 잃었다**
2. v19 의 결과는 "프롬프트가 집 체류를 못 움직인다"가 **아니라** "목표가 잘못 잡혔다"로 읽는다
3. 다음 라운드의 정합 목표는 **구성 거리**(그 사람 카드 실측 업종 구성)와
   **근무 누락 24칸**이다. 둘 다 그 사람 자신의 입력에서 나오고 창이 모호하지 않다
4. `tel_home_wd_time` 의 집계 정의를 알아내기 전에는 집 체류를 다시 목표로 삼지 않는다
