# 가맹몫이 고정인 한 P012 쌍의 오차에는 **바닥**이 있다 — 17.97%p

**2026-09-24 19:45** · 산술만으로 나온다. LLM·GPU 0회

---

## 우리 모델의 구조

```
offline = 총액 x 0.2535   (고정)
online  = 총액 x 0.7465   (고정)
```

그러므로 **두 지표가 같은 비율로만 움직인다.** 총액이 X% 오르면
P012-1(적립)도 +X%, P012-2(제외, st.online_spent)도 +X% 다.

## 그런데 정답지는 둘이 다르다

```
P012-1 적립업종  **+20.82%**
P012-2 제외업종  **+2.85%** (유의하지 않음)
```

X 하나로 둘을 설명해야 하므로 오차 합은 `|X-20.82| + |X-2.85|` 이고,
**2.85 ≤ X ≤ 20.82 구간에서 이 값은 언제나 17.97%p 로 일정하다.**

```
총액  +1.90%  ->  18.92 + 0.95 = 19.87%p   (현행)
총액  +5.41%  ->  15.41 + 2.56 = **17.97%p**  (회계 고침 재계산값)
총액 +11.84%  ->   8.98 + 8.99 = 17.97%p
총액 +20.82%  ->   0.00 + 17.97 = 17.97%p   (P012-1 을 완벽히 맞혀도!)
```

**바닥 = 실측 두 값의 차(17.97%p) 그대로다.**

## 여기서 나오는 세 가지

**1. 회계 고침은 이미 바닥에 닿았다.** 재계산값 +5.41% 에서 쌍 오차가 17.97%p
   로 최소다. 더 올려도 쌍 전체로는 **제자리**다.

**2. 창(28일)의 값어치를 다시 봐야 한다.** 창은 총액을 올린다. 그러면
   P012-1 은 좋아지고 P012-2 는 정확히 그만큼 나빠진다. **쌍 합계는 안 변한다.**
   창의 값어치는 오차가 아니라 **기전이 작동하는지를 보는 것**에 있다 —
   문턱을 넘는 사람이 생기면 P012-3(문턱 도달자)·P012-4(캐시백 금액)·
   P012-6(한도 도달)이 **처음으로 0 이 아닌 값**을 낸다. 그쪽이 창의 몫이다.

**3. 쌍의 오차를 17.97%p 아래로 내리려면 가맹몫이 움직여야 한다.**
   그것 말고는 방법이 없다. 산술이 그렇다.

## 가맹몫을 움직이는 길 — 이미 있는 반응을 쓴다

`online_share` 를 LLM 에게 묻는 길은 죽었다(`../split_anchor/calib_02.md` —
질문 범위를 3배 넓혀도 답이 0.1448 -> 0.1427). 그러나 **묻지 않아도 되는 길**이 있다.

정책이 오면 계획액이 오른다(+9.76%, p=0.0015). 지금은 그 반응을 **총액**에만
싣고 있다(`EXP_PLAN_DRIVES_TOTAL`). 같은 반응을 **몫**에도 실으면 된다.

```
지금    total = anchor x f(계획)        offline/online 비율은 그대로
고침    total = anchor x f1(계획)       총액은 조금만
        share = share0 x f2(계획)       몫은 더 많이
        offline = total x share · online = total x (1-share)
```

이러면 **적립은 많이 오르고 제외는 조금 오르거나 그대로**가 된다 —
정답지의 모양(+20.82 / +2.85)이 처음으로 재현 가능한 형태가 된다.

**순환이 아니다.** 계획액은 에이전트 자신의 이벤트 산물이고, 측정 공식도 목표
수치도 넣지 않는다. 지금 총액에 싣는 것과 **같은 값을 같은 방식으로** 몫에도
싣는 것뿐이다.

## 다만 정직하게 — 이것은 아직 가설이다

`f1`·`f2` 를 어떻게 가르는지가 자의적이면 그건 끼워 맞추기다. **둘의 배분을
정답지를 안 보고 정할 근거가 필요하다.** 지금 가진 후보는 하나다.

```
f1 (총액)  기존 EXP_PLAN_DRIVES_TOTAL 과 동일 — 앵커 순위상관 90% 보존 규칙으로 이미 정해져 있다
f2 (몫)    남는 반응을 전부 몫으로. 즉 **자유 파라미터를 새로 만들지 않는다**
```

이 배분이 정답지를 향해 조정되지 않는다는 것을 **사전등록으로 못 박고**,
기준 런에서 수준·계층이 보존되는지를 관문으로 확인한 뒤에 돌린다.

## 순서

지금 도는 28일 런이 먼저다 — 그것이 **기전이 작동하는지**를 답한다.
그 답이 있어야 P012-3·4·6 이 값을 내는지 알 수 있고, 몫 고침이 그 위에 얹힌다.

---

# 정정 (19:55) — 위의 "가맹몫을 움직이는 길" 은 **끼워 맞추기였다**

위에서 "총액은 기존 규칙, 남는 반응은 전부 몫" 이면 자유 파라미터를 안 만든다고
적었다. **틀렸다.** 산술로 확인했다.

```
offline = T x s · online = T x (1-s) · s = 0.2535 · k = s/(1-s) = 0.3396
T 가 a%, s 가 b% 오르면   offline ~ a + b · online ~ a - k·b

정답지(+20.82 / +2.85)를 내려면   **a = +7.41% · b = +13.41%**
```

`a` 와 `b` 를 이렇게 고를 근거는 **"정답지가 그렇게 나오게"** 뿐이다.
계획 반응(+9.76%)이 `a=7.41` 과 비슷해 보이는 것은 **우연**이고, 그 우연을
근거로 삼으면 그게 바로 정답지를 보고 맞추는 일이다.

**자료 안에 배분을 정할 근거가 없다.** 계획의 반응은 하나의 수(+9.76%)이고,
그것을 둘로 쪼갤 정보가 계획 자체에 없다 — 원장이 이미 98.65% 적격이라
"계획의 구성이 적격 쪽으로 기울었나" 를 물어도 거의 움직일 자리가 없다.

## 그러면 무엇이 진짜 고침인가 — **자료다**

몫이 파라미터가 아니라 **에이전트의 선택**이 되려면, 고를 수 있는 제외 채널이
그래프에 있어야 한다.

```
지금   백화점·대형마트 POI  337개 / 543,924 (0.06%) · 온라인 채널 **0**
       -> 고를 것이 없으니 몫이 상수일 수밖에 없다
필요   제외 채널이 선택지에 있어야 한다
       그래야 "이번 달엔 마트 대신 동네에서" 가 **행동**으로 나타난다
```

이것은 프롬프트도 회계도 아니고 **자료 문제**다. 그리고 오늘 고칠 수 있는
것이 아니다 — 새 POI 자료를 붙이거나 온라인 채널을 모형에 들이는 일이다.

## 그래서 보고할 한계

```
P012 쌍(적립·제외)의 오차는 **17.97%p 아래로 못 내려간다.**
그 이유는 프롬프트도 회계도 아니라 **제외 채널이 자료에 없기 때문**이다.
회계 고침이 이미 그 바닥에 닿아 있으므로, 이 쌍에 관한 한 더 할 일이 없다.
```

**이것을 "못 고쳤다" 로 적는다.** 배분 파라미터를 하나 넣으면 숫자는 맞출 수
있지만, 그것은 수렴이 아니라 정답지 복사다.

## 남는 것은 창의 몫이다

창(28일)은 쌍의 오차를 못 줄인다(위 산술). 대신 **못 재던 지표 셋**을 처음으로
재게 한다.

```
P012-3  문턱 도달자 비율 > 0        9일 창에서는 도달자가 없어 잴 수 없었다
P012-4  1인 평균 캐시백 (실측 47,880원)
P012-6  한도 10만원 도달 비율 (실측 21.0%)
```

**그쪽이 지금 도는 런의 값어치다.** 쌍의 오차가 아니라 **값이 없던 자리에 값을
만드는 것** — 사용자가 "실측은 있는데 시뮬이 값을 못 내면 우리 문제" 라고 한
바로 그 자리다.
