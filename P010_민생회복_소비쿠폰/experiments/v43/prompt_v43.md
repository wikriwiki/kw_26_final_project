# v43 사전등록 — 잘린 문장을 돌려준다. 프롬프트는 v5 그대로

**작성 2026-09-22 11:40 · 실행 전 커밋** · 200명 · 9일 · 두 런 · GPU 는 v41 뒤

---

## 무엇을 시험하는가

P012 는 여섯 지표 중 실측과 가장 멀다(우리 순효과 +11.5%p · 실측 +20.82%).
지금까지 그 원인으로 적혀 있던 것은 관측 창 길이이고, 그것은 [v30](../v30/prompt_v30.md)
이 시험한다. **이 라운드는 다른 후보를 시험한다 — 모델이 정책을 덜 알고 있다.**

```
P012 본문 358자 · 런타임 정책 블록이 280자에서 자른다

모델이 보는 끝   "…캐시백은 이번 달에 미리 주는 돈이 아니라 다음 달 "   ← 문장 한가운데
잘려 나간 78자   "15일에 돌려받는 것이며, 3% 문턱을 넘기지 못하면 이번 달 캐시백
                혜택은 사라집니다. 돌려받은 캐시백은 나중에 어디서든 쓸 수 있습니다."
```

기전(3% 초과분의 10%)은 앞 280자에 남는다.

> ### 정정 (12:10) — 전제를 과장했다. 돌리기 전에 고친다.
>
> 나는 위에서 "사라지는 것은 놓치면 전부 잃는다는 비대칭 유인"이라고 적었다.
> **틀렸다.** 개인별 정책 상태 블록(`dawn_context._format_cashback_status`, 839행에서
> 주입)이 매일 이렇게 적어 준다.
>
> ```
> - P012: 적립업종 이번달 누적 …원 / 2분기 월평균 약 …원 / 3% 문턱 …원
>         | 초과분의 10% 다음 달 환급, 월 최대 100,000원
>         | 문턱까지 …원 남음 (이번 달 …일 남음 · 하루 평균 …원 페이스)
>         | **못 넘기면 이번 달 혜택은 사라짐**
> ```
>
> 손실 프레임도, 문턱도, 다음 달 환급도 **전부 블록에 있다.** 절단으로만 사라지는
> 것은 둘뿐이다.
>
> ```
> 절단으로만 사라지는 것
>   ① 돌려받는 날짜가 다음 달 15일이라는 것
>   ② **돌려받은 캐시백은 나중에 어디서든 쓸 수 있다는 것**
> ```
>
> ②가 이 라운드가 실제로 시험하는 것이다 — 보상이 **제약 없는 돈**인지 아닌지.
> 모델이 캐시백을 어딘가에 묶인 돈으로 읽으면 그 가치를 낮게 잡는다.
>
> **기대 효과는 내가 처음 적은 것보다 훨씬 작다.** 그대로 적어 둔다.

## 이것이 유도인가 — 먼저 따진다

| 물음 | 답 |
|---|---|
| 문장을 새로 쓰는가 | **아니다.** `P012.json` 에 원래 있던 문장이고 정책 파일은 안 건드린다 |
| 실측 수치가 들어가는가 | 아니다. 들어가는 숫자는 정책의 조건(3%·10%·15일)이지 결과가 아니다 |
| 결과 방향을 지시하는가 | 아니다. "문턱을 못 넘기면 혜택이 사라진다"는 제도의 규칙이다. 쫓을지 말지는 모델이 정한다 |

> **그리고 같은 사실이 지금도 모델에게 닿고 있다** — v5 가 물려받는 오염된 본문의
> "문턱을 못 넘기면 이번 달 혜택은 0원이고, 넘긴 초과분의 10%만 돌아온다" 를 통해서다.
> 이 라운드는 그 사실을 **원래 있어야 할 자리(정책 블록)로 옮기는 것**에 가깝다.
> 그래서 [v40](../v40/prompt_v40.md)(오염 제거)과 이 고침은 함께 가야 한다.

## 설계 — 한 변수

```
창      day0 2021-10-18 · 시작 2021-10-19 · 9일
        워밍업 10-19~10-20 · 무정책 10-21~10-22 · 정책 10-25~10-26
        result_FINAL 이 쓴 창 그대로다 (+11.5%p 가 나온 창)

프롬프트  v5 — 한 글자도 안 고친다. v40·v42 는 이 라운드에 넣지 않는다
소득     끄고 돈다. 9일은 지갑 한계(중앙 25.9일) 안이다
인원     200명 — result_FINAL 과 같은 n

두 런    A 절단 있음 (지금 그대로)   B 절단 없음 (고침)
```

**result_FINAL 의 +11.5%p 와 비교하지 않는다.** 그때와 서버·모델이 같다는 보장이
없으므로 A 를 같은 런에서 다시 잰다. v41(`data/experiments/validation_v41.json`)에서
v5 를 다시 재는 것과 같은 이유다.

## 합격선 — 결과를 보기 전에 정한다

```
주 지표   B 의 P012-1 순효과 > A 의 순효과, 그리고 B 의 CI 가 0 을 제외한다
방어선    P012-2(제외업종)가 A 와 B 에서 모두 움직이지 않는다
```

**사전등록한 예측 (12:10 에 고쳐 적는다).** B 가 A 보다 **조금 높거나 같을 것이다.**
손실 프레임은 이미 개인별 블록에 있으므로 큰 차이를 기대하지 않는다. 남는 것은
"돌려받은 돈은 어디서든 쓸 수 있다"가 보상의 가치를 올리는지다. 틀리면 그대로 적는다.

> 처음에는 "B 가 A 보다 높을 것이다"라고 크게 적었다. 전제를 확인하지 않고 적은
> 예측이고, 확인한 뒤 낮춘다. **결과를 본 뒤가 아니라 돌리기 전이다.**

## 실패로 적을 것

| 결과 | 무엇으로 적는가 |
|---|---|
| B ≈ A | **잘린 78자는 행동을 바꾸지 않았다.** 가장 그럴듯한 결과다 — 손실 프레임이 이미 개인별 블록에 있기 때문이다. 그러면 절단 고침은 위생 문제로만 남고, P012 의 크기는 다른 곳에서 찾아야 한다 |
| B < A | 예측이 틀렸다. 사실을 더 준 것이 오히려 줄였다면 왜인지 원문에서 찾는다 |
| 제외업종이 함께 오른다 | 문턱과 무관한 증가다. 이 고침을 P012 의 답으로 쓰지 않는다 |

## 이 라운드가 답하지 못하는 것

**크기 비교는 하지 않는다.** 감사 주석(`audit_2026_09_20`)이 대상·기간·결과·분모·
대조군이 호환될 때만 배수를 비교하라고 했고, 2일 창과 KDI 의 한 달은 호환되지 않는다.

```
이 라운드가 주는 것   같은 창에서 사실 하나를 돌려주면 값이 이만큼 움직인다
못 주는 것           그 값이 실측과 맞는가
```
