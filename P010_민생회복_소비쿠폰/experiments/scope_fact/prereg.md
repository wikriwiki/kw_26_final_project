# 범위의 산술 한 줄 — 첫 프롬프트 후보. 어디서 잴 수 있는지까지 먼저 적는다

**작성 2026-09-24 03:10 · 실행 전 커밋** · 스위치 `EXP_SCOPE_FACT`

---

## 무엇을 고쳤나

혜택이 붙는 업종이 정해진 정책에서, **범위 밖 업종에 대한 산술**을 한 줄 더한다.

```
캐시백     | 문턱은 적립업종 지출만 센다 — 제외업종에서 줄여도 문턱은 가까워지지 않고,
             거기서 쓴 돈이 환급을 깎지도 않는다
업종한정   | 혜택은 위 업종에서만 붙는다 — 그 밖의 업종에서 줄여도 받는 혜택이 늘지 않고,
             거기서 쓴 돈이 혜택을 깎지도 않는다
```

**두 기전이 같은 스위치로 켜진다.** 같은 가설을 시험하므로 스위치가 갈리면
무엇을 쟀는지 흐려진다.

## 왜 이것인가 — 진단이 가리킨 유일한 자리

`why_it_misses.py` 로 v5 의 빗나감 18개를 이유별로 갈랐다.

```
적중 9 · 유의하지 않다 6(전부 기대 방향) · 밴드 초과 2 · 부호가 반대 1(구조적 불가)
```

**방향이 틀린 자리는 없다.** 표본이 고칠 여섯을 빼면 남는 것은 밴드 초과 둘이고,
위약의 PL-2 가 같은 모양으로 붙는다.

```
P012-2  제외업종 무반응 기대인데 -13.9%   밴드 251% 초과
PT-3    식사 무변 기대인데 +3.1%          밴드 12% 초과
PL-2    위약 대상 아닌 업종 -4.4%
```

셋 다 **한 업종이 오르면 다른 업종이 내려가는** 모양이다. 하루 총액이 한
스칼라(`daily_propensity`)에 묶여 있어 그렇다. 그런데 제도의 산식은 그렇게
말하지 않는다 — 범위 밖에서 줄이는 것은 혜택을 **한 푼도** 늘리지 않는다.
모델이 그 사실을 스스로 세우지 못하는 것으로 보인다.

## 왜 서술이 아니라 산술인가

**P010 역진의 벽에서 이미 확인했다** — 서술 프롬프트는 무효였고 모델은
계산된 사실에만 반응했다. 그래서 "제외업종을 줄이지 마라" 같은 지시가 아니라
문턱·혜택 산식의 성질을 적는다. 무엇을 하라고 말하지 않으며, 범위 밖 업종을
늘리라는 뜻도 아니다.

지키는 선 셋을 시험으로 못 박았다(`tests/unit/sim/test_scope_fact.py`, 41개).

```
방향 지시 금지     '늘려'·'써라'·'더 써'·'많이' 가 렌더에 없다
정답지 수치 금지   2.85 · 20.82 · 25.4 · 11.6 · 6.957 이 없다
측정 공식 금지     밴드·순효과·MPC 가 없다
그리고 **더하기만 한다** — 있던 사실은 바이트가 같다
```

## 어디서 잴 수 있는가 — 돌리기 전에 먼저 쟀다

**P012-2 에서는 못 잰다.** 표본을 먼저 봤다.

```
       관측 n    구간 반폭    동등성 밴드    반폭/밴드
v5        23      1,866        ±841         2.2배
v45       13      1,202        ±763         1.6배
```

**구간이 밴드보다 넓다.** 점추정이 정확히 0 이 되어도 동등성 판정은 통과할 수
없다. 제외업종에 간 사람이 23명뿐이라 그렇고, 채점표가 이미 "2,000명 필요"
라고 적어 두었다. **이 후보를 P012 에 대고 판정하지 않는다.**

**PL-2 에서는 잰다.** 위약의 대상 아닌 업종은 관측 194명이다.

## 설계

```
정책   P090 위약(가짜 업종한정 할인권)
창     무정책 2021-10-07:08(목금) → 정책 2021-10-11:12(월화)
       **정책 파일 notes 의 원래 설계로 되돌린다.** 지금 채점표의 창
       (10-21:22 → 10-25:26)은 양쪽이 모두 발효 기간 안이라 대조가 성립하지
       않는다(window_sits_inside_the_policy_period 에 기록).
런     start 2021-10-04 · day0 2021-10-03 · 9일 · n=200
팔     scope_off (EXP_SCOPE_FACT=0) · scope_on (=1) — **그 한 줄만 다르다**
```

## 등록하는 판정

```
주 지표  PL-2  대상 아닌 업종. scope_on 의 |평균| 이 scope_off 보다 작다
             (0 에 가까워진다). 두 팔이 같은 창이므로 환경 드리프트는 약분된다
부 지표  PL-1  대상 업종 증가. **잃으면 안 된다** — lookahead 검정이 여기 걸려 있다
읽지 않음 동등성 적중 여부. 이 창은 확진자가 762 → 547 로 28% 줄어 절대 수준에
             드리프트가 섞인다. **팔 사이 차이만 읽는다**
```

## 등록하는 예측

**PL-2 의 |평균| 이 줄 것이다.** 다만 **얼마나 줄지는 적지 않는다** — P090 의
런 간 이동을 재 본 적이 없다. 그래서 이 라운드의 scope_off 팔이 기존
`result_2026_09_15` 와 같은 창·같은 n 이 되어 **런 간 이동의 첫 추정**을 겸한다.
이동이 팔 사이 차이보다 크면 **읽지 않는다**고 미리 적어 둔다.

**PL-1 은 지켜질 것이다.** 이 줄은 대상 업종에 대해 아무 말도 하지 않는다.

- 이 라운드는 P012·P015·P016 의 판정에 쓰지 않는다 — 위약 한 정책이다
- **방향 15/15 을 지켜야 한다.** 고치려다 이미 맞은 것을 망가뜨리면 손해다

## 전체 라운드 전에 탐침을 먼저 돌린다

**후보를 만들었다고 라운드를 돌리면 안 된다.** P010 역진의 벽에서 서술
프롬프트가 무효인 것을 이미 겪었다 — 문장을 더해도 행동이 한 글자도 안
달라지는 일이 실제로 있었다. 그러면 9일 × 200명 × 두 팔이 통째로 낭비다.

그래서 먼저 묻는다. **이 줄이 아무것도 바꾸지 않는가.**

```
탐침   동결된 파일럿 맥락의 캐시백 셀 12명. 그 한 줄만 넣고 빼서 두 번 부른다
호출   12명 × off/on × 시드 2 = 48
읽는 것 changed(계획이 달라진 시민 수) · 소비성향 delta · 제외업종 이벤트 delta
```

시드를 둘 쓰는 이유 — 한 시드만 보면 "달라졌다" 가 시드 잡음인지 그 줄
때문인지 못 가른다.

**등록하는 중단 규칙: `changed` 가 0 이면 이 후보를 버리고 라운드를 돌리지
않는다.** 무력한 줄을 들고 GPU 를 쓰지 않는다.

탐침은 돌고 있는 본런(`p013_ruler`)과 GPU 를 함께 쓴다 — 48 호출이고 워커를
4 로 눌렀으므로 방해가 크지 않다. 전체 라운드는 본런이 끝난 뒤 큐에 넣는다.

> 실행 전에 이 문서를 커밋한다. 결과를 보고 지표·창·판정식을 고치지 않는다.
