# v5 는 방향을 이미 맞힌다 — 빗나간 자리는 프롬프트의 것이 아니다

**2026-09-24** · `scripts/report/why_it_misses.py` · 잴 수 있는 지표 18개를 이유별로 갈랐다

---

## 부호 적중표만 보면 잘못 읽는다

전 정책 부호 적중이 44% 다. 그 숫자만 보면 "프롬프트를 고쳐야겠다" 가 된다.
그런데 **X 안에 서로 다른 세 가지가 섞여 있고, 고치는 방법이 전혀 다르다.**

```
① 부호가 반대다              → 프롬프트가 고칠 수 있는 유일한 자리
② 부호는 맞는데 유의하지 않다   → 표본. 프롬프트를 고쳐도 구간이 안 좁혀진다
③ 동등성 밴드를 넘었다         → 폭. 방향이 아니라 크기의 문제다
```

갈라 보면 이렇다.

```
적중                 9
유의하지 않다          6      ← **여섯 다 점추정이 기대 방향**
밴드 초과             2
부호가 반대           1      ← P012-6 뿐이다
```

## 하나뿐인 '부호가 반대' 는 구조적으로 불가능한 자리다

```
P012-6  한도 10만원 도달 비율 > 0 (실측 21.0%)   점추정 0.0000
```

캐시백 한도는 **월 10만원**이고 우리 창은 **이틀**이다. 라운드2 결과 문서가
이미 적어 두었다 — "한도 10만원 도달 — 두 팔 모두 구간 [0.0, 0.0]. 이틀로는
구조적 불가". 프롬프트를 어떻게 쓰든 이틀에 10만원 캐시백을 채울 수 없다.

**그러므로 v5 가 방향을 틀린 자리는 사실상 없다.** 잴 수 있는 15개(적중 9 +
유의하지 않다 6)가 전부 기대 방향이다.

## '유의하지 않다' 여섯은 표본의 문제다

```
지표      점추정        구간                      |평균|/반폭
DS-1     -930        [-1,930, +50]            0.94   ← 거의 닿았다
DS-4     -403        [-1,029, +135]           0.69
LV-3     -0.0060     [-0.0161, +0.0045]       0.58
P012-1   +624        [-674, +2,216]           0.43
DS-2     +364        [-1,984, +2,676]         0.16
LV-2     +0.0021     [-0.0166, +0.0196]       0.12
```

`|평균|/반폭` 이 1 을 넘으면 구간이 0 을 안 지난다. DS-1 은 0.94 로 **거의
닿았다** — n 을 조금만 올리면 넘어간다. 실제로 거리두기는 프롬프트를 한 글자도
고치지 않고 n 을 200 → 500 으로 올린 것만으로 부호 적중이 1/4 → 3/4 이 됐다.

**프롬프트는 구간을 좁히지 않는다.** 이 여섯 자리에서 후보를 가르면 잡음을
프롬프트의 성질로 적게 된다.

## 남은 진짜 자리 — 밴드 초과 둘은 같은 기전이다

```
P012-2   제외업종 무반응이 기대인데 -13.9%      밴드 ±841 · 구간 끝 2,953 — 251% 초과
PT-3     식사 무변이 기대인데 +3.1%            밴드 ±1,110 · 구간 끝 1,248 — 12% 초과
```

그리고 여기에 위약의 PL-2(대상 아닌 업종 -4.4%)가 같은 모양으로 붙는다.
채점표가 그 원인을 이미 적어 두었다.

> 하루 총액이 페르소나 앵커에 묶여 있어 마트가 오르면 다른 업종에서 빠진다.
> 식사가 가장 큰 업종이라 그 몫을 흡수했다.

**한 업종이 오르면 다른 업종이 내려간다 — 하루 총액이 한 스칼라에 묶여 있다.**
Stage1 이 `daily_propensity`(0~1) 하나를 내고 Stage2 가 그 안에서 나눠 쓰는
구조라 그렇다. 같은 뿌리가 다른 자리에도 보인다.

```
P012-1  적립업종이 +1.9% 밖에 못 오른다 (실측 +20.82%)
        총액이 안 늘면 한 업종이 크게 오를 자리가 없다
```

## 그런데 이 자리도 말로는 안 움직인다

이미 겪은 것이 있다 — **P010 역진의 벽**: 서술 프롬프트는 무효였고 모델은
**계산된 사실에만** 반응했다. 그리고 **순환 검증 금지**: 측정 공식을 모델
입력으로 넣으면 안 된다(MPC·소진율이 입력이었던 사례).

그러므로 다음 후보는 이 둘을 동시에 지켜야 한다.

```
해도 되는 것   정책이 선언한 사실을 계산해서 보여 주기
              (예: 지갑 잔액은 평소 예산과 별개다 — 실제로 독립 지갑이다)
하면 안 되는 것  "총액을 늘려라" 같은 방향 지시
              측정 공식(순효과·MPC·밴드)을 입력으로 넣기
```

## 그래서 지금 순서

```
1  표본을 올린다        여섯 중 넷이 자릿수 하나 안이다. p013_ruler 가 첫 걸음
2  런 이동을 잰다       올린 표본에서 후보를 가르려면 자가 있어야 한다
3  제로섬을 건드린다     밴드 초과 둘 + 위약 PL-2 가 같은 뿌리다.
                     **계산된 사실**로만 접근한다
4  방향은 이미 맞다     고치려다 망가뜨리지 않도록, 후보는 방향 15/15 을 지켜야 한다
```

> 이 문서가 적는 것은 여기까지다. **v5 가 방향을 틀린 자리는 구조적으로 불가능한
> 하나뿐이고, 빗나감 여섯은 표본, 둘은 하루 총액이 한 스칼라에 묶인 제로섬이며,
> 그 자리조차 서술로는 안 움직인다는 것을 이미 한 번 확인했다.**
