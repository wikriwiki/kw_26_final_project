# 실험 v20 — 검정력이 요구한 명단 크기로

**날짜 2026-09-21 사전등록** · **상태** 대기(v18·v19 뒤) · **후보 v25 · v34 (새 후보 없음)**

---

## 왜

[NOISE_AND_POWER.md](../NOISE_AND_POWER.md) 가 처음부터 적어 둔 값이다.

```
한 기전의 on/off 차이를 80% 검정력으로     53명
후보 둘의 차이를 보려면                   후보당 106명
```

지금까지 돈 것은 **열둘**과 **예순**이다. **둘째 줄을 넘은 적이 없다.**

```
라운드      명단    결과
v3 ~ v17     12     부호가 정해진 지표 0개
v18          60     부호가 정해진 지표 0개
v20         120     ← 처음으로 106명 선을 넘는다
```

## 사전등록

| | 내용 |
|---|---|
| 설계 | 120명 × 4기전 × on/off = **960칸**, seed 71001, 후보 둘 |
| 실행 | 계획 → 게이트 → 수정 3바퀴 → 조립 → 결제 (양쪽 동일) |
| 비용 | 계획만 후보당 약 75분. 전체 약 4시간 |

### 판정

| | 기준 |
|---|---|
| **후보가 갈린다** | 부호를 말할 수 있는 지표에서 두 후보가 다르다 |
| **지표는 정해지나 후보는 같다** | 부호가 정해진 지표가 생겼으나 둘이 같다 |
| **여전히 무효** | 120명으로도 전부 0을 지난다 |

> **셋째 줄이 나오면 그것도 결론이다.** 검정력 계산이 요구한 표본을 채웠는데도
> 정해지지 않는다면, 남은 설명은 **효과가 계산에 쓴 3,000원보다 작다**는 것이다.
> 그때는 필요 표본을 다시 계산해 적는다.

### 이 실험이 답하지 않는 것

- **최적 프롬프트** — 후보는 v16 에서 마감했다
- 실측 **크기** — 부호가 정해져도 크기는 별개다
- 집 밖 행동 — v19 가 따로 답한다

## 실행 중 고침 (2026-09-21 15:13, 결과 보기 전)

**행렬이 960칸이 아니라 950칸이다.**

첫 두 시도(13:19·14:06)에서 SGLang 이 제약 디코딩 문법을 컴파일하다 C++ abort 로
죽었다. 계획기는 그것을 모르고 죽은 서버의 timeout 을 `eligible=False` 로 기록했다.
두 시도 모두 전량 폐기했다 — 빈 값이 아니라 틀린 값이기 때문이다.

`scripts/sim/preflight_grammars.py` 를 붙여 돌리기 전에 각 칸의 문법을 fork 로
격리해 컴파일해 본다. 컴파일되지 않는 칸은 빼고 시작한다.

```
칸 960 · 서로 다른 문법 480 · 컴파일 불가 5 → 제외 10칸 (1.0%)
```

**제외된 10칸은 전부 on/off 짝이다** (사람 2명 × 기전 5개). 양쪽 팔이 함께 빠지므로
대조는 깨지지 않고, 잃는 것은 480쌍 중 5쌍이다.

자세한 것은 [GRAMMAR_CRASH_INCIDENT.md](../GRAMMAR_CRASH_INCIDENT.md) 에 적었다.
이 축소는 **결과를 보기 전에** 기록한다.

### 사전등록이 물은 것 — "명단을 키우면 지표 부호가 정해지는가"

**정해진다. 그리고 그것이 좋은 소식이 아니다.**

```
DS-1     실측 -14.1     시뮬 +169.2  [+40.0, +533.3]   ← 구간이 0을 제외한다
```

열두 명에서도 예순 명에서도 아홉 지표 전부 0을 지났다. 백스무 명에서 하나가
갈렸고, **갈린 그 하나가 부호가 반대다.**

이유는 세어 보면 한 줄이다.

```
거리두기 칸 · 무정책 62 · 정책 67
  매장·포장   0 →  0        한 건도 없다
  배달       13 → 35
  정책 팔 식사 35건 중 배달 35건 (100%)
```

**+169.2% 는 배달 35건 위에서 계산된 값이다.** 실측 −14.1% 는 매장 취식 붕괴가
배달 증가를 압도한 값인데, 우리에게는 붕괴할 매장이 0건이다.

자세한 것은 [POWER_WITHOUT_ALIGNMENT.md](../POWER_WITHOUT_ALIGNMENT.md) 에 적었다.

### 이 라운드의 결론

**검정력은 정렬을 고쳐 주지 않는다.** 상류(계획에 매장 취식이 생기는가)가 열리기
전에는 표본을 키울수록 틀린 답이 확신을 얻을 뿐이다.

그래서 다음 표적은 명단 크기가 아니라 상류다 — v21~v24 가 그쪽을 판다.
